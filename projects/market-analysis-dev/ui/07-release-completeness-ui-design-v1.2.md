## 1. 修订结论与边界

v1.2 不覆盖或改写 v1.0、v1.1。它在新路径 `ui/release-completeness-v1.2/` 交付 49 组 SVG/PNG，并通过独立生成器与验证器将机器事实和人工判断分离：

- `verify-assets.mjs` 只登记文件、尺寸、哈希、可计算布局约束、文本契约、对比度和不可变输入；
- `review-manifest.json` 只允许 `machine_validation.status=machine_passed`；
- `independent_visual_review.status=pending`，固定 04 的角色内自查不能替代根协调独立视觉审查；
- 不存在 `visual_inspection=passed`、`manual_visual_inspection=passed` 或由生成器自动写入的人工结论。

视觉资产使用确定性 SVG 并导出 PNG，以保证简中、状态、坐标、响应式尺寸、文本大小和真相边界可复核。这是 UI 设计原型，不是业务前端、真实数据连接或运行时实现。

## 5. 390 / 320 独立移动布局

移动资产不再将 390 画面缩放到 320。每个尺寸都是独立 SVG 根视口和独立 PNG：

- 390：`width=390`、`height=844`、逻辑视口 390×844、scale 1；
- 320：`width=320`、`height=844`、逻辑视口 320×844、scale 1；
- 正文最低 16 CSS px；辅助信息最低 14 CSS px；核心操作 52px，高于 44px 触控门；
- URL、中英文混排和长状态可换行，页面无整体横向滚动；
- 底部操作不遮挡正文或安全说明；
- 公开页面的真相条拆为三行，保证 320 内完整呈现；
- 私有页面只保留一个“演示数据 · 用户提供”真相标签。

七个页面：方向、技术栈、市场趋势、工作台输入、工作台关系、差距未知、数据权利。每个页面都提供 390 和 320 两份独立资产。

## 6. 真正 200% 放大证据

`28-accessibility-zoom-200` 使用可计算的两组布局：

| 项目 | 100% | 200% |
|---|---:|---:|
| 逻辑视口 | 720×900 | 720×900 |
| 正文 | 16px | 32px |
| 触控组件 | 44px | 88px |
| 布局 | 双列摘要 | 单列回流 |
| 整页横滚 | 否 | 否 |
| 组件遮挡 | 否 | 否 |

验证器从 SVG 数字属性复算 `rendered = base × 2`，而不是仅搜索“200%”文案。放大态保留目标、证据、路线未生成和两个操作的顺序，焦点语义不变。

## 8. 账号、导出和真相边界

### 8.1 AC27 账号隔离

页面 09 同屏提供：游客、登录、退出、当前账号 A、切换到账号 B、切换影响提示。账号 B 的私有可见记录明确为 0，并说明账号 A 的演示记录在账号 B 不可见。这里是目标态交互证据，不代表账号服务已接通。

### 8.2 AC29 双导出

人类可读摘要与机器可读数据是两个独立按钮，不是单选项。两项分别显示格式、范围、版本、生成时间、下载状态和重试；一项失败不阻断另一项。

### 8.3 运行历史

真相态 01 中的“部分失败、失败、已停用”均标记为允许呈现的状态示例，同时显示“无运行历史”。当前 connector 为 0，不得把状态示例解释为真实遥测、刷新、失败或恢复事件。
