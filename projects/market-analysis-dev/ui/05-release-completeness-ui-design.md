## 1. 设计结论

本增量设计把 Frontend Career Radar 定义为一套“证据型职业决策工作台”，不是招聘聚合站、课程商城、能力评分器或通用后台。核心顺序固定为：

`01 职业方向总览 → 02 技术栈全景 → 公共证据 → 私有输入 → 个人证据 → 差距与路线 → 历史 → 数据权利`

设计使用低噪声浅色界面、直接标签、细边框和可追溯图形。每一页只回答一个主问题；所有结论就近显示数据身份、样本量、来源覆盖、时间、规则版本和 `as_of`。无证据时显示“未知”，不生成个人分数、市场份额、岗位排名或“已掌握”。

本文件是设计说明与原型契约；同目录 PNG 是待审核视觉画板。它们不代表业务已实现、真实来源已接通或前端已解冻。

## 3. 视觉语言与设计 Token

### 3.1 视觉方向

- 关键词：极简、克制、专业、理性、透明、可信。
- 背景以中性浅灰为主，白色内容面承载数据；尽量使用分隔线和留白而非卡片墙。
- 桌面首屏最多 3 个主视觉区；移动端一次只暴露一个主要任务。
- 旧版青紫识别感保留为辅助，不继承巨大 KPI、能力百分比、薪资指数、星级排名和无来源增长率。
- 不使用霓虹、玻璃拟态、赛博朋克、机器人、奖杯、皇冠、战斗力或证券终端式噪声。

### 3.2 色彩

| Token | HEX | 用途 |
|---|---|---|
| `canvas` | `#F6F8FA` | 页面背景 |
| `surface` | `#FFFFFF` | 主内容面 |
| `surface-muted` | `#F0F3F6` | 次级区、表格表头 |
| `text-primary` | `#17212B` | 主文字 |

| `unknown` | `#7A8493` | 未知／无证据 |

颜色只作冗余：每个状态同时使用图标、形状和文字。

### 3.3 字体、网格与动效

- 中文：`PingFang SC / Microsoft YaHei / Noto Sans CJK SC / sans-serif`。
- 数字：启用表格数字；长版本号和 SHA 允许逐段换行。
- 桌面：H1 28/36、H2 20/28、正文 14/22、辅助 12/18。
- 移动：H1 24/32、H2 18/26、正文不小于 16/24、辅助 14/20。
- 间距：4、8、12、16、20、24、32、40、48px。
- 圆角：输入与按钮 8px、内容面 10px、抽屉与对话框 12px。
- 阴影仅用于浮层：`0 8px 24px rgba(23,33,43,.10)`。
- 焦点环：2px `#2563EB`，外偏移 2px，不被容器裁切。
- 动效：150–220ms；支持减少动效，加载不可只用无限旋转表达。

## 4. 全局框架

### 4.1 桌面 1440×1024

- 224px 紧凑侧栏，按“公共研究 / 个人工作区 / 账号与数据”分组。
- 主内容使用 12 列网格，最大内容宽度 1168px。
- 顶部固定 48px 真实性条：数据模式、版本、`as_of`、来源覆盖、当前状态。
- 页面结构：标题与一句结论 → 主图形或主任务 → 筛选与口径 → 等价表格 → 证据抽屉。

### 4.2 平板 1024×768

- 侧栏折叠为 64px 图标栏；标题与真实性条分两行。
- 图形与详情改为上下排列；矩阵可局部横向滚动，但页面不整体横滚。
- 始终提供“切换为列表／数据表”。

### 4.3 移动 390×844 与 320×844

- 单栏内容；底部导航为“方向 / 技术栈 / 工作台 / 个人 / 更多”。
- 证据抽屉变为全屏详情；筛选进入底部抽屉。
- 表格转语义行卡；每行保留字段名，不仅显示值。
- 触控目标至少 44×44px；危险操作与普通操作至少间隔 12px。
- 软键盘出现后，输入、错误、隐私说明、提交与取消仍可滚动到达。
- 320px 下 URL、SHA、中英文混排可断行，页面不得整体横向滚动。

## 5. 页面原型

### 5.1 页面 01：职业方向总览

- 主标题旁显示 `获批历史研究快照 · 证据截止 2026-08-03`。
- 主视图为方向坐标图，右侧同步方向列表；坐标轴是解释维度，不是好坏。
- 节点大小=直接证据数，描边=置信度；键盘选中后显示定义、价值、层级、证据与限制。
- 比较最多 3 个方向，使用对齐矩阵，不产生综合分。
- 主操作固定为“查看该方向的技术栈”。

### 5.2 页面 02：技术栈全景

- 面包屑固定显示 `01 职业方向总览 → 02 技术栈全景`。
- 能力地图固定按 `P0 → P1 → P1-AI → P2 → 观察项` 排列。
- 8 类能力域完整出现；AI 增量不能越过 Web 基础与工程质量。
- 个人证据叠加层默认关闭；开启后只显示已确认／可核验证据和未知。
- 页面常驻说明：`这里展示职业市场能力，不是本产品技术选型。`

### 5.3 页面 03：市场证据与趋势

- 样本集合使用四段式切换：旧研究目的样本、持续技术源、持续招聘源、用户提供目的样本。
- 默认真实状态：`招聘运行时来源 0 · 尚无可执行招聘实例`。
- `n/N` 点图取代百分比；中国、公开远程、边界样本分区。
- 7/30/90 日趋势带样本量、来源覆盖、缺失天数、规则版本、`as_of`。
- 每张图右上角提供“查看数据表”。

### 5.4 页面 04：来源与质量

- 主矩阵把来源政策 `allow/conditional/manual_only/disabled` 与运行时 `未配置/校验中/已启用/正常/部分失败/失败/已停用` 分成两列。
- 顶部真实摘要：`60 条来源记录 · 16 个端点裁决 · 13 个 P0/allow 技术端点 · 招聘实例 0 · 运行时连接器 0`。
- Greenhouse、Lever、Ashby 标记 `条件模板 · 尚缺公司/board/site 允许清单`。
- 仅提供查看研究依据、覆盖缺口和原链接；没有启用连接器或绕过限制按钮。

### 5.5 页面 05：信息源工作台

- 六步步骤器：粘贴 → 保存模式 → 双轴分类 → 摘要 → 对照 → 合并。
- 输入 1–100,000 Unicode；URL-only 不自动抓取；超长不截断。
- 保存模式用互斥选项：`仅本次处理（推荐）` / `保存到私有档案`。
- 敏感信息确认只显示类别和大致位置，不回显完整值。
- 来源渠道与内容类型是两个独立控件，各自显示建议、候选、置信度、依据和人工确认。
- 结果关系限定为新增、印证、重复、冲突、证据不足、不适用。
- 失败保留原输入；摘要成功但保存失败显示“未保存，可安全重试”。

### 5.6 页面 06：个人证据档案

- 顶部只显示 `未知 / 部分有证据 / 存在冲突`，不显示竞争力分数。
- 证据阶梯为阅读、练习、项目、生产、同行审查，表示证据类型而非人的等级。
- 每条记录明确显示：未知、用户自述、用户已确认、可外部核验、系统推断、冲突。
- 操作：接受、编辑、拒绝、标未知、查看历史、删除。

### 5.7 页面 07：差距与成长路线

- 顶部并列展示三项输入：已确认目标、公共要求版本、个人证据。
- 任一缺失，主区域显示“当前差距保持未知”和待补项。
- 差距矩阵显示要求、证据、判断类型、置信度、影响、来源、推翻条件。
- 路线依赖图与可执行列表并列；每步包含证据产物、投入区间、依赖与复评条件。
- 删除证据或公共快照变化后显示“需要重算”，仍可查看当时依据。

### 5.8 页面 08：未来方向与历史

- 系统推断统一使用虚线菱形、紫色标签和“可能失效”说明。
- 历史时间线同时保存公共快照、个人事实版本、路线调整和同步冲突。
- 当前版本与历史版本可并排，支持打开“当时依据”。
- 不出现薪资、晋升、Offer 或成功保证。

### 5.9 页面 09：账号与数据权利

- 数据清单按仅本次处理、私有原文、结构化证据、目标、路线、确认历史、第三方处理记录分组。
- 导出同时提供人类可读摘要和机器可读数据。
- 单条证据删除先展示受影响差距／路线和重算范围。
- 删除账号使用独立危险对话框；默认焦点在“取消”。
- 对话框明确：登录立即失效、活动数据目标 24h 内删除、备份最长 30 天到期。

### 5.10 页面 10：质量、刷新与恢复

- health、readiness、公共来源、私有服务、同步、导出分行显示。
- 状态完整覆盖 live、empty、not_ready、stale、degraded、partial、failed、offline、seed_demo、no-source、no-evidence。
- 静态回退只说明内容可读，不证明服务就绪或数据最新。
- 允许重试检查、局部重试、查看上一版本和错误详情；没有服务重启、强制发布或绕过校验。

## 6. 关键流程原型

### 6.1 工作台六步

`输入正文 → 选择保存模式 → 敏感/权利确认 → 双轴人工确认 → 摘要与关系对照 → 逐条合并或拒绝`

- 任一步失败都回到可恢复状态并保留输入。
- 处理期间步骤器播报阶段变化，不逐字播报字符数。
- 合并前显示公共研究与个人档案的目标位置。

### 6.2 个人证据到路线

`候选证据 → 用户逐条确认 → 证据版本形成 → 差距重算 → 路线草案 → 用户调整/确认 → 历史留痕`

- 用户确认不等于外部核验。
- 冲突证据不支持差距结论，先进入裁决。

### 6.3 删除与重算

`选择证据 → 展示影响 → 二次确认 → 删除进行中 → 重算 → 成功/部分失败/重试`

- 删除对话框默认焦点在取消。
- 失败时显示删除与重算分别处于什么状态；不得用一个成功 Toast 掩盖后续重算失败。

### 6.4 同步、导出与账号删除

`查看设备与版本 → 解决冲突 → 同步 → 选择导出范围 → 生成文件`。

账号删除是独立流程，不与单条证据删除共用确认框。

每张图必须有标题、结论、口径、样本量、来源覆盖、时间、筛选、数据模式和“查看数据表”。Tooltip 只补充信息。

| 分层能力地图 | 能力、层级、方向、版本、地区、证据状态 |
| 样本内计数点图 | 要求类别、样本组、n、N、地区、岗位层级 |
| 7/30/90 趋势 | 日期、事件数、样本量、覆盖源、缺失日、规则版本、as_of |
| 来源政策×运行时 | 来源、政策、运行时、最近成功、失败、权利边界 |
| 双轴分类 | 渠道、内容类型、建议、候选、置信度、确认状态 |
| 研究关系矩阵 | 用户主张、研究结论、关系、依据、确认状态 |
| 证据阶梯 | 证据、类型、事实状态、时间、核验状态 |
| 差距证据矩阵 | 目标要求、个人证据、判断、置信度、来源、推翻条件 |

## 8. 状态系统

### 8.1 真相态

| 状态 | 视觉 | 文案重点 |
|---|---|---|
| live | 实心圆 + 深青标签 | as_of、覆盖、缺失、规则版本 |
| empty | 空框 + “0 条” | 当前条件、筛选、来源覆盖；不是市场为零 |
| not_ready | 时钟 + 灰标签 | 缺少服务／来源、可重试项 |
| stale | 琥珀时钟 | 24/48h 阈值、最近成功、失败原因 |
| degraded | 双层版本图标 | 正在使用上一已核验版本 |
| partial | 半填充圆 | 成功项、失败项、影响范围 |
| failed | 叉号 + 红文字 | 保留内容、错误原因、重试/返回 |
| offline | 断链图标 | 本地可读、待同步、恢复动作 |
| seed_demo | 斜纹底 | 演示数据，不代表真实来源或用户 |
| no-source | 空插头 | 政策候选、条件缺口、运行时 0 |
| no-evidence | 空心盾牌 | 未知、待补证据、可执行下一步 |

### 8.2 组件状态

按钮、输入、筛选、节点、标签、表格行、抽屉、对话框均覆盖：默认、悬停、焦点、按下、选中、禁用、加载、成功、待确认、警告、错误。危险操作必须同时出现警示图标、明确后果和“危险操作”文字。

## 9. 无障碍契约

- 设计目标为 WCAG 2.2 AA；正式审计前不写“完全符合”。
- 每页唯一 H1，标题层级连续，提供跳到主要内容。
- 全流程可键盘完成；关闭抽屉／对话框后焦点回到触发项。
- 图形节点具备名称、角色、状态和操作说明，并有列表／表格替代。
- 加载、保存、同步、删除、重算和错误恢复通过礼貌 live region 播报。
- 表单标签常驻；错误摘要链接到字段；必填与后果可感知。
- 200% 放大时不遮挡、不丢操作；移动端正文不小于 16px。
- 颜色对比目标：正文 ≥4.5:1，大字与图形关键边界 ≥3:1。

## 10. 演示数据与真实性标记

视觉稿只使用三种数据身份：

1. `获批历史研究快照`：截止 2026-08-03，核心目的样本 10（中国 4 / 公开远程 6）和边界样本 2。
2. `演示数据 · 用户提供`：脱敏虚构材料，不代表真实用户、个人能力或已保存档案。
3. `目标态演示 · 当前未接通`：展示未来 live、账号、同步和持续来源，不代表运行时实现。

所有新版画板均需就近出现：`研究清单已批准 · 运行时来源 0 · 招聘实例 0`。

允许展示 `React 9/10`、`TypeScript 8/10` 等历史样本计数，但必须紧邻：`本次目的抽样样本内，不是市场份额`。

## 12. 原型连线

1. `01 方向节点 → 查看技术栈 → 02 指定方向能力地图 → 查看市场证据`。
2. `05 粘贴 → 保存模式 → 敏感确认 → 双轴确认 → 摘要/关系 → 合并`。
3. `06 证据确认 → 07 差距重算 → 路线确认 → 08 当时依据`。
4. `09 设备同步 → 导出 → 单条删除/账号删除 → 10 恢复说明`。
5. 任一失败态可进入错误详情、上一已核验版本或局部重试，不进入服务重启、强制发布或绕过校验。
