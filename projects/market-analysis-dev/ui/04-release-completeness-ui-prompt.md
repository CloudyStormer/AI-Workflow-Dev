## START OF COPYABLE DESIGN PROMPT

你是一名擅长复杂数据产品、证据型决策系统、隐私体验和无障碍设计的资深 UI/UX 设计师。请为 **Frontend Career Radar（前端职业成长雷达）** 生成一套完整、高保真、可用于后续产品评审和前端实现的响应式 Web UI 设计图片。

产品不是营销官网、招聘聚合站、课程商城、AI 聊天机器人或通用后台模板。它帮助前端开发者按固定顺序先理解职业方向，再理解技术栈全景；之后查看招聘／技术证据、提交自己的材料、建立个人证据档案，并在事实与推断严格分层的前提下获得差距、路线、未来方向和历史变化。

请直接输出设计图片或可交互原型，不输出前端代码，不选择 React、Vue、图表库、后端、数据库、模型、云平台或部署方案。所有页面、导航、操作、状态、图表、错误、隐私与无障碍文案使用完整简体中文。

### 1. 设计目标

1. 固定并强化认知顺序：**01 职业方向总览 → 02 技术栈全景**，任何个人推荐、招聘列表、学习路线或 AI 热点都不得插入两者之间。
2. 让用户快速区分公共研究与私有个人空间；公共事实、用户确认事实、来源观点、系统推断、未知和冲突不能混写。
3. 让数据密集页面仍然极简、干净、有逻辑：少文字块、强结构、强可视化、低噪声，每页只突出一个主要判断问题。
4. 让所有数字都能回到样本集合、来源、地区、层级、时间、规则版本和 `as_of`；目的抽样永远不画成市场份额。
5. 让来源政策状态与运行时状态成为两个独立轴；已批准研究清单不等于已接入连接器。
6. 无个人证据时诚实显示未知，不生成竞争力分数、伪精确能力雷达、缺口断言或“已掌握”。
7. 让用户对输入正文、保存、第三方处理、同步、导出和删除拥有清楚、逐项、可撤销的控制。

### 2. 不可违反的真实性与产品边界

#### 2.1 市场与来源边界

- 旧研究快照证据截止日为 2026-08-03，核心目的样本 10 个：中国大陆一线城市 4 个、公开远程 6 个；另有边界样本 2 个。样本不随机，明显偏中高级，不能推断岗位总量、市场份额、薪资或全国情况。
- 中国、全球／远程、AI 增量必须分区；远程不等于全球任意地点可申请。
- `9/10`、`8/10` 等只能表达“本次目的样本内计数”，不能转换为百分比、市场排名或行业总体。
- 来源政策四态：`allow / conditional / manual_only / disabled`；运行时另行显示 `未配置 / 校验中 / 已启用 / 正常 / 部分失败 / 失败 / 已停用`。两个轴不得合成一个绿点。
- 当前真实状态：13 个 P0/allow 原子端点均为技术源；招聘 ATS 的 Greenhouse、Lever、Ashby 只是条件模板，尚无获批公司／board／site；运行时真实来源、招聘实例和连接器均为 0。
- 不得在默认画板写“实时招聘已接入”“今日已采集”“覆盖全国招聘”“已连接 Greenhouse／Lever／Ashby”。需要展示未来完整态时，必须标 `目标态演示 · 当前未接通`。
- 受限商业招聘平台、中国公司站、登录／验证码／付费／robots／API／版权受限来源，不得出现绕过限制、自动登录或隐藏接口抓取操作。

#### 2.2 个人事实与推断边界

个人记录只允许以下状态，并始终显示状态文字：

- `unknown`：未知／尚无信息；
- `user-stated`：用户自述，未确认或未核验；
- `user-confirmed`：用户已确认，但不等同外部核验；
- `externally-verifiable`：存在可核验项目、文档、指标、证书或审查材料；
- `system-inferred`：系统基于证据推断，必须显示依据、置信度和失效条件；
- `conflict`：多份材料冲突，等待用户裁决。

摘要、关键词命中、简历措辞、一次练习和用户确认都不能自动升级成“已掌握”。目标、市场要求或个人证据任一缺失时，差距和路线保持未知。

#### 2.3 数据与隐私边界

- 用户输入支持“仅本次处理”或“保存到私有档案”；默认不长期保存第三方文章／招聘完整正文。
- 保存第三方内容时只保留必要元数据、最小摘要、允许的短摘录和用户确认的结构化证据；不公开再分发全文。
- 简历、经历、项目原文只有在用户明确选择保存后进入私有档案。
- 向第三方模型或外部服务发送前，必须披露接收方、数据范围、用途、保存／训练边界和撤回方式，并取得本次明确选择；未同意时发送次数为 0。
- 多账号严格隔离。保存、跨设备同步、导出和删除属于登录后的私有能力；游客只能浏览公共研究。
- 删除证据后需显示受影响的差距／路线并触发可解释重算；删除账号后登录立即失效，活动数据目标 24 小时内删除，备份最长 30 天到期。

### 3. 信息架构与全局导航

#### 3.1 一级导航顺序

1. **01 职业方向总览**
2. **02 技术栈全景**
3. **市场证据与趋势**
4. **来源与质量**
5. **信息源工作台**
6. **个人证据档案**
7. **差距与成长路线**
8. **未来方向与历史**
9. **账号与数据权利**

桌面使用克制侧栏或紧凑顶部导航；01、02 必须连续、编号、固定在最前。其余按“公共研究”“个人工作区”“账号与数据”分组。移动端底部导航优先显示“方向、技术栈、工作台、个人、更多”，但从任一入口进入职业内容时仍保持 01 → 02。

#### 3.2 全局身份条

每个公共页面顶部显示紧凑真实性条：

- 内容模式：`获批研究快照 / 真实来源快照 / 上一已核验快照 / 静态回退 / seed_demo / 暂不可用`；
- 快照版本、内容 SHA 短码、证据截止日、`as_of`、最近成功刷新；
- 来源覆盖：启用数／获批候选数／失败数／缺失数；
- 简短口径：`本雷达已接入来源样本趋势，不代表全市场`；
- 运行状态：`live / empty / not_ready / stale / degraded / failed / offline`。

每个私有页面顶部显示另一个紧凑条：账号、同步状态、最近成功同步、未保存变更、数据保存模式。公共来源状态不能冒充个人数据已同步，个人服务在线也不能证明公共市场数据最新。

#### 3.3 页面统一层级

`页面标题 + 一句准确结论 → 主图形／主任务 → 筛选与解释 → 等价表格 → 证据／状态详情`。首屏避免卡片墙；最多一个主色 CTA。证据详情桌面为右侧抽屉，移动端为全屏页，关闭后焦点返回触发元素。

### 4. 全局真实性状态契约

| 状态 | 用户可见名称 | 必须展示 | 禁止表达 |
|---|---|---|---|
| `live` | 当前来源快照可用 | `as_of`、最近成功、来源覆盖、缺失来源、规则版本 | “全市场实时”“零遗漏” |
| `empty` | 当前条件下 0 条 | 已生效筛选、样本集合、来源覆盖、重置操作 | “市场没有需求” |
| `not_ready` | 数据尚未就绪 | 未就绪原因、缺少服务／来源、可重试项 | 伪空图表、默认 0 |
| `stale` | 数据可能过期／不得称当前 | 超过 24／48 小时的真实阈值、最近成功、失败原因 | “最新”“刚刚刷新” |
| `degraded` | 正在使用上一已核验版本 | 旧版本、真实 `as_of`、当前失败范围、重试 | 静默回退或当前成功 |
| `partial` | 部分来源／步骤成功 | 成功项、失败项、影响范围、局部重试 | 用一个成功绿点掩盖失败 |
| `failed` | 当前无可用结果 | 错误原因、保留内容、重试／返回 | 清空用户输入或伪造结果 |
| `offline` | 当前离线 | 本地可读内容、待同步操作、恢复后动作 | 已同步、已保存到服务端 |
| `seed_demo` | 演示数据 | `演示数据 · 不代表真实来源或用户` | 与 live 混合、作为完成证据 |
| `no-source` | 尚无可执行来源 | 政策候选、条件缺口、运行时 0 | 已接入、当前覆盖 |
| `no-evidence` | 暂无个人证据 | 待补证据、未知状态、可执行下一步 | 分数、已掌握、明确缺口 |

状态同时发生时按 `failed/not_ready > degraded/stale > partial > live/empty` 展示最高优先级结论，详情列出所有状态。状态永远包含图标、形状和文字，颜色只作冗余。

### 5. 关键页面设计

#### 页面 01：职业方向总览

**用户问题：我有哪些职业方向可以考虑，它们的证据和限制是什么？**

- 展示 8 个方向：产品型前端／应用工程、平台／设计系统／DevEx、AI 应用前端／AI 产品工程、数据可视化／实时交互、跨端／桌面／移动、全栈产品协作、Web 质量工程、UX Engineering／设计开发融合。
- 主图使用“方向坐标图 + 方向列表”的双视图。二维轴仅是解释维度，不是好坏、热度或岗位排名。节点大小映射当前直接证据数，描边映射置信度，图标与文字保证非颜色表达。
- 选中方向后显示：定义、用户价值、适用层级、主要能力域、市场证据信号、事实类型、置信度、已知限制、失效条件。
- 支持最多 3 个方向比较，用对齐矩阵比较价值、层级、能力、证据、限制；不生成综合总分。
- 主操作 `查看该方向的技术栈`，进入页面 02 并保留方向上下文。
- 无个人证据时不自动推荐“最适合你”。

状态：默认、加载、选中、键盘聚焦、比较、证据不足、当前条件 0 条、not_ready、stale、degraded、partial、seed_demo、等价列表。

#### 页面 02：技术栈全景

**用户问题：这个方向需要怎样的能力结构，先后关系是什么？**

- 面包屑固定为 `01 职业方向总览 / {方向} → 02 技术栈全景`。
- 核心用“分层能力地图”，从左到右／移动端从上到下固定为：P0 → P1 → P1-AI → P2 → 观察项。
- 覆盖 8 类完整能力域：Web 平台；框架与状态／数据范式；工程化；产品质量；设计与协作；方向专项；AI 增量；观察项。
- 能力节点显示规范名称、方向、层级、优先级、版本、地区、证据数、事实类型；展开显示可验证行为、证据、反证、未知和失效条件。
- 提供“当前方向／全部方向”“初级／中级／高级／Staff·负责人”“地区”“证据状态”筛选。
- 明示 `这里展示职业市场能力，不是本产品技术选型`。
- AI 能力分为工具使用、输出审核、AI 产品构建，且不得越过 Web 基础与工程质量。
- 个人证据叠加层默认关闭；开启后只显示已确认／可核验证据与未知，不改变公共技术全景的排序。

状态：通用基线、指定方向、层级切换、一项能力多方向复用、版本过期、观察项、非法筛选、partial、等价表格、320px 纵向折叠。

#### 页面 03：市场证据与趋势

**用户问题：哪些变化来自哪些样本，它们是否适用于我的地区和层级？**

- 顶部按样本集合分区：获批旧研究目的样本、持续技术来源样本、持续招聘来源样本、用户提供目的样本。不得静默合并。
- 招聘视图使用 `要求类别 × 样本组` 并列点图／条形图，直接显示 `n/N`；中国、全球／远程、边界样本分区。
- 趋势视图支持 7／30／90 日，图表同时显示样本量、来源覆盖、缺失天数、规则版本、`as_of`；标题只能写 `本雷达已接入来源样本趋势`。
- 技术变化分“新增、版本升级、弃用、安全、breaking、观察项”，显示版本／tag／日期／来源，不把 GitHub 活跃度当岗位需求。
- 层级覆盖点阵显示初／中／高／Staff，样本不足用空心状态和文字，不显示 0% 需求。
- 远程约束矩阵显示国家／地区、时区、工作许可、税务／合同和披露状态。
- 任一图形可切换等价数据表；点击打开证据抽屉。

默认真实画板必须显示 `招聘运行时来源 0 · 尚无可执行招聘实例`。可以另外提供目标态画板，但必须显著标 `目标态演示 · 当前未接通`。

#### 页面 04：来源与质量

**用户问题：哪些来源在政策上允许，哪些真的已接入，当前数据还能信到什么程度？**

- 使用“来源政策轴 × 运行时轴”矩阵：政策为 allow／conditional／manual_only／disabled；运行时为未配置／校验中／已启用／正常／部分失败／失败／已停用。
- 当前摘要显示：60 行来源记录、16 个原子端点裁决、13 个 P0/allow 技术原子端点、3 个 P0/conditional 招聘 ATS 模板、获批招聘实例 0、运行时连接器 0。
- 来源行字段：身份、所有者、地区、语言、内容类型、政策决定、决定原因、权利摘要、允许／禁止用途、robots／条款／API 状态、刷新节奏、最近成功／失败、保留策略、署名回链、停用条件。
- Greenhouse／Lever／Ashby 必须显示 `条件模板 · 仍需公司/board/site 允许清单`；不得出现“启用连接器”按钮。
- 受限来源仅允许 `查看研究依据`、`查看覆盖缺口`、`返回原链接`；不提供绕过、强制抓取、登录态复用。
- 质量区显示来源覆盖、失败、过期、缺失天数、去重规则、规则版本、下架／关闭事件和静态回退；不生成无依据的综合可信度分。

状态：当前研究态、目标运行态演示、来源未配置、24h 可能过期、48h 不得称当前、单源失败、全部刷新失败、条款变化、条件未满足、manual_only、disabled、数据表。

#### 页面 05：信息源工作台

**用户问题：我提供的内容是什么，它与公共研究和我的个人档案有什么关系？**

设计为六步工作流，不做聊天气泡：

`1 粘贴内容 → 2 选择保存模式 → 3 确认双轴分类 → 4 查看摘要 → 5 对照研究／个人证据 → 6 决定是否合并`

输入区：

- 多行输入支持 1–100,000 个 Unicode 字符；标签覆盖文章、搜索摘录、招聘／面试要求、简历、经历和项目材料。
- 只输入 URL 时提示粘贴正文，不自动抓取。
- 可选元数据：标题、URL、平台／发布方、作者、发布日期／未披露、采集日期、地区、岗位层级、备注。
- 实时字符计数；超限不截断；长文本支持拆分建议。
- 保存模式卡：`仅本次处理`（推荐默认）与 `保存到私有档案`；说明关闭会话、同步、导出、删除差异。
- 权利确认：有权用于个人研究；不获得再发布权。
- 检测姓名、联系方式、证件、地址、雇主机密时，在处理或外发前阻断确认；只显示类别与大致位置，不回显完整敏感值。

双轴分类：

- 来源渠道：搜索引擎、招聘平台、公司招聘页、媒体／文章平台、社区／社交、GitHub／技术文档、学校／培训、用户原创、其他／未知。
- 内容类型：文章／报告、职位描述、面试要求／经验、简历、工作／学习经历、项目证据、技术发布、其他／未知。
- 每轴分别显示建议、候选、置信度、识别依据和缺失元数据；用户确认／纠正前状态为待确认，不允许永久合并。

结果区：

- 最小必要摘要、结构化事实候选、来源观点、技术／能力信号、时间／地区／层级、待核验项。
- 与公共研究关系只允许：新增证据、相互印证、重复、冲突、证据不足、不适用。
- 用户招聘／面试材料进入 `用户提供目的样本`，不并入公共市场总体。
- 个人证据候选逐条接受、编辑、拒绝或标未知；批量操作展开差异。
- 冲突左右并列，不静默覆盖获批研究或个人历史。

完整状态：初始、编辑中、空白、URL-only、接近上限、超长、权利未确认、敏感信息待确认、仅本次／保存选择、分类低置信／多候选／未知、用户已纠正、处理中、取消、成功、部分成功、重复、冲突、失败、重试、重新处理、旧结果被替代、删除确认、已删除、离线、会话将丢失、外部处理待授权、未保存写入超时。

失败永远保留原输入；分类／摘要失败不得自动确认或保存错误结果。处理中的状态更新使用可感知步骤器，不用无限动效作为唯一反馈。

#### 页面 06：个人证据档案

**用户问题：系统知道哪些关于我的事实，哪些仍未知，证据强度如何？**

- 顶部显示 `个人判断状态：未知／部分有证据／存在冲突`，不显示竞争力分数。
- 分区展示目标方向／层级、个人事实、能力映射、证据来源、时间与版本、本人贡献、公开限制、确认人／时间、历史版本、删除状态。
- 用“证据阶梯”解释阅读／收藏、练习、独立项目、生产结果、同行审查；阶梯表示证据类型，不是人的固定等级。
- 每条证据显示 unknown／user-stated／user-confirmed／externally-verifiable／system-inferred／conflict。
- 用户逐条接受、编辑、拒绝、标未知、查看历史、删除；危险操作需要明确后果和取消。
- 无证据时显示待补清单和进入工作台入口，不显示空雷达或 0 分。

#### 页面 07：差距与成长路线

**用户问题：基于已确认目标、市场要求和个人证据，我接下来应补什么？**

- 差距比较的三项输入必须同时可见：用户确认目标方向／层级、当前公共能力要求版本、用户确认或可核验证据。
- 任一输入缺失时显示未知和待补项，不生成伪精确分数。
- 差距矩阵字段：目标要求、当前证据、判断类型、置信度、影响、来源、可推翻条件、最后重算原因。
- 路线使用依赖图 + 可执行列表，不是课程商城。每一步包含能力、建议证据产物、完成判定、投入区间、依赖、关联来源、复评条件。
- 用户可确认、调整顺序、暂停、恢复、删除；系统推断与用户确认明显分开。
- 删除证据、公共快照变更或规则变更后显示 `需要重算`，保留旧结论的“当时依据”。

状态：目标缺失、证据缺失、部分差距、冲突阻断、路线草案、用户确认、暂停、完成待核验、需重算、重算失败、离线未同步。

#### 页面 08：未来方向与历史

**用户问题：市场和我的路径发生了什么变化，未来建议基于什么？**

- “未来方向”只能基于 7／30／90 日已接入来源趋势、用户目标和能力邻接关系；固定标记 `系统推断`、置信度、限制和失效条件。
- 不作岗位、薪资、晋升、Offer 或成功保证。
- 历史时间线同时保留：公共快照版本、来源覆盖变化、技术／岗位新增或过期、个人事实版本、差距重算、路线调整、用户确认／拒绝、同步冲突。
- 每个历史节点可打开“当时依据”：公共快照、个人证据版本、规则版本、确认记录、发生时间、发现时间。
- 支持当前与历史版本并排比较；不静默改写过去。

#### 页面 09：账号与数据权利

**用户问题：哪些数据被保存、发给谁、如何同步、导出和删除？**

- 游客状态明确只能浏览公共研究；登录后才能保存、同步、个性化、导出、删除。
- 数据清单按“仅本次处理、已保存私有原文、结构化证据、目标、差距／路线、确认历史、第三方处理记录”分组。
- 显示最近同步、设备列表、未同步变更、同步冲突、重试状态；两个在线设备在下一次成功同步后目标 10 秒内收敛。
- 导出提供人类可读摘要和机器可读数据，显示范围、版本、生成时间和下载状态。
- 删除单条证据显示将重算哪些差距／路线；删除账号使用独立危险流程，默认焦点在取消，展示 24h 活动数据与最长 30 天备份语义。
- 第三方处理记录显示提供方、字段范围、目的、状态、同意时间和撤回入口；没有授权时显示“未发送”。

#### 页面 10：质量、刷新与恢复说明

**用户问题：当前公共／私有能力是否真正可用，失败时哪些内容仍可信？**

- 分开显示服务 health、数据 readiness、公共来源刷新、私有用户服务、同步与导出能力。
- 显示版本、SHA、`as_of`、最近成功、失败范围、过期阈值、规则版本、来源覆盖和演示数据隔离。
- 公共单源失败可使用上一已核验版本；全部来源失败不生成“当前趋势”。
- 私有服务失败时公共研究仍可读，但保存、整合、差距与同步明确不可用。
- 分类／摘要失败保留输入；个人写入超时标 `未保存／待确认`，幂等重试只写一次。
- 静态回退只证明可读内容存在，不证明服务就绪、持续来源、账号或同步可用。
- 允许动作：重试检查、只重试失败区域、查看上一版本、查看错误详情、返回；不提供服务重启、强制发布、绕过校验或来源启用按钮。

### 7. 视觉方向

- 关键词：极简、克制、专业、理性、透明、可信、数据密集但不压迫。
- 参考研究仪表板、严谨编辑系统和现代数据产品；不要证券终端噪声、营销英雄区、赛博朋克、霓虹、玻璃拟态、卡片墙、巨大 KPI。
- 使用大面积中性浅背景、白色／极浅表面、细边框、少阴影。优先通过网格、留白、分隔线、排版和直接标签建立层级。
- 建议颜色：背景 `#F6F8FA`，表面 `#FFFFFF`，主文字 `#17212B`，次文字 `#667085`，边框 `#DDE3EA`，主操作深青 `#0F766E`，信息蓝 `#2563EB`，系统推断紫 `#6D5BD0`，确认绿 `#168A5B`，待确认琥珀 `#A86509`，冲突／危险红 `#B4233C`，未知灰 `#7A8493`。
- 圆角 8–12px；正文桌面 14–16px、移动不小于 16px；数字使用表格数字。标题不做超大营销字号。
- 卡片不是默认容器；一个首屏不超过 3 个主视觉区。长说明折叠为证据详情，首屏优先显示结论、图形和边界。
- 不使用装饰性 AI 机器人、宇宙渐变、发光脑、奖杯、排名皇冠或“能力战斗力”意象。

### 8. 组件与交互状态

统一设计：全局导航、公共真实性条、私有同步条、数据模式徽标、来源政策徽标、运行时状态、版本选择器、筛选器、搜索、方向节点、能力节点、图表工具栏、等价表格、证据抽屉、多行输入、元数据表单、保存模式卡、分类建议器、关系行、证据条目、差距行、路线步骤、历史节点、设备／同步行、导出与删除对话框、错误摘要、空状态、局部失败、Toast／状态播报。

每个交互组件至少覆盖默认、悬停、焦点、按下、选中、禁用、加载、成功、待确认、警告、错误。危险操作不能只靠红色；删除对话框写明对象、影响、恢复性和取消入口，默认焦点放在取消。

筛选改变图表时在标题附近显示已生效条件和结果数，并以礼貌状态播报。没有匹配与没有数据源使用不同空状态。后台刷新不得让上一已核验内容突然消失。

### 9. 响应式

- **1440×1024**：紧凑侧栏 + 12 列主内容；图表与证据详情可并排；高密度但保留足够留白。
- **1024×768**：侧栏折叠；图表与详情上下排列；复杂矩阵可在组件内横向滚动并提供列表切换。
- **390×844**：单栏；底部导航不遮挡主要操作；证据抽屉转全屏；筛选进入底部抽屉；表格转语义行卡。
- **320×844**：全部 P0 页面和核心操作仍可完成。长版本号、URL、中英文混排可换行；页面不整体横向滚动。
- 移动软键盘出现时，工作台输入、错误、保存模式、隐私提示、提交与取消均可达；粘性操作栏不能覆盖内容或安全区。
- 支持 200% 文本放大、系统大字号、横竖屏和减少动效。

### 10. 无障碍

以 WCAG 2.2 AA 为设计目标，未经过正式审计前不得声称完全符合。

- 每页唯一 H1，标题层级连续；提供跳到主要内容。
- 全部核心流程可用键盘：方向、能力、筛选、图表替代表格、工作台、分类纠正、证据确认、路线编辑、历史查看、同步、导出、删除。
- 焦点环清晰且不被裁切；抽屉／对话框正确管理焦点，关闭后返回触发项，Escape 可取消非破坏操作。
- 自定义图形节点有名称、角色、状态和操作说明，并提供列表／表格替代。
- 加载、分类、保存、同步、重算、导出、删除、错误恢复使用礼貌 live region；只播报阶段变化，不逐字播报字符数。
- 错误摘要链接到字段；表单标签常驻，不以 placeholder 代替；必填、格式、上限和保存后果可感知。
- 状态、置信度、冲突、过期、来源政策和运行时不只依赖颜色。
- 触控目标至少 44×44 CSS px，相邻危险与普通操作留足间距。
- 图表包含简短结论、口径、文本摘要和等价数据表。

### 11. 演示数据标识

设计稿只允许三类数据身份：

1. `获批历史研究快照`：证据截止 2026-08-03，核心目的样本 10（中国 4／公开远程 6）与边界样本 2。
2. `演示数据 · 用户提供`：脱敏虚构材料，不代表真实用户、个人能力或已保存档案。
3. `目标态演示 · 当前未接通`：用于展示未来 live、账号、同步、持续来源和恢复状态，不代表运行时已实现。

当前来源事实必须单独显示：`研究清单已批准 · 运行时来源 0 · 招聘实例 0`。不伪造在线率、实时刷新、连接成功、用户数、薪资、市场份额、个人分数或模型准确率。

允许沿用的历史样本数字：React 9/10、TypeScript 8/10、工程质量 10/10、跨职能协作 10/10、测试／CI/CD 等 8/10、AI 直接要求 4/10 + 加分项 2/10；每处必须紧邻 `本次目的抽样样本内，不是市场份额`。
