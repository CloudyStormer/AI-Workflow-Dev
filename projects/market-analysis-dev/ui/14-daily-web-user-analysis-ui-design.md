## 1. 设计结论

本设计把已批准 Prompt 转为可直接实现的九页 Web 规格，不依赖外部生成图片。页面保持“职业方向总览 → 技术栈全景”为固定前两层，再进入市场日更证据、用户材料、结构化分析、市场对照、差距与路线。

视觉沿用项目既有灰白画布、白色内容面、紫色主操作、青绿色成功反馈和橙色风险提示，但移除旧稿中的假数据、旧字符上限和“即时 AI 结论”。本文件是布局、组件、状态和交互的权威增量说明；早期十张图片及 v1.0–v1.7 发布完整性资产仅作历史参考，不覆盖本轮真实度规则。

### 1.1 当前必须呈现的真实状态

| 项目 | 当前事实 | 默认界面 |
|---|---|---|
| 运行时来源/连接器 | 0 / 0 | 数据未就绪，不显示 0 分或假趋势 |
| 中国大陆有效招聘样本 | 0 | 不生成市场结论、排名或份额 |
| 信息源工作台服务闭环 | 未形成 | 输入页可说明目标流程，但保存/分析操作显示未就绪 |
| 用户输入记录 | 0 | 个人证据档案为空，不伪造简历或能力 |
| 业务数据库写入 | 0 | 不声称已保存、已同步或跨端恢复 |
| 2026-08-25 研究批次 | 4 条官方技术更新 + 4 条招聘用途样本 | 仅真实持久化并发布后才成为历史快照 |

目标态画面如用于设计说明，必须就近显示“目标态演示·当前未接通”；个人示例必须显示“演示数据·用户提供”。

## 2. 设计原则

1. **先方向、再能力、后证据**：前两层顺序固定，不用日更或 AI 功能抢占认知入口。
2. **真相就近**：每个指标、图表、分析和操作旁显示来源、快照、`as_of`、样本量与状态。
3. **证据先于结论**：没有目标、市场快照或已确认用户证据时，只展示补证据动作。
4. **公共与私有分域**：公共研究和用户材料在导航、背景、标签与导出中均不混写。
5. **失败保留现场**：刷新、保存、分类、分析、同步或删除失败时，不清空最近成功内容。
6. **少字但不省边界**：长解释收进“为什么这样判断”抽屉；关键真相和风险不可折叠隐藏。

## 4. 设计系统

### 4.1 颜色与语义

| Token | 值 | 用途 |
|---|---|---|
| `canvas` | `#F5F7FA` | 页面背景 |
| `surface` | `#FFFFFF` | 卡片、表格、抽屉 |
| `text-primary` | `#172033` | 标题、正文 |
| `text-secondary` | `#475467` | 辅助说明 |
| `border` | `#D0D7E2` | 分隔、输入边框 |
| `primary` | `#4338A8` | 主动作、选中态 |
| `primary-hover` | `#372E8F` | 主动作悬停 |
| `link` / `focus` | `#174EA6` / `#1D4ED8` | 链接、焦点环 |
| `success` | `#087F5B` | 已确认、真实成功 |
| `info` | `#1D4ED8` | 处理中、信息 |
| `warning` | `#8A4B08` | 过期、待确认、证据不足 |
| `danger` | `#B42336` | 失败、删除、冲突 |

状态同时使用图标、文字、边框样式与色彩。普通文字对比度至少 4.5:1，非文本控件和焦点至少 3:1。

### 4.2 字体、间距与控件

- 字体：`Inter, PingFang SC, Microsoft YaHei, system-ui, sans-serif`。
- 桌面 H1 28/36、H2 22/30、正文 16/24、辅助 14/20、数据 24/32。
- 移动正文不小于 16px，辅助不小于 14px；不使用 12px 用户文案。
- 8px 栅格；卡片圆角 12px；输入/按钮高度 44px，移动端主按钮 48px。
- 焦点环：2px `#1D4ED8` + 2px 外间距；错误不能用焦点环替代。
- 表格行高不小于 48px；长链接、版本号、哈希允许断行但保留完整复制值。

### 4.3 核心组件

| 组件 | 必备字段/状态 | 交互 |
|---|---|---|
| 全局真相条 | 状态、`as_of`、最近成功、样本、覆盖、缺失、规则版本 | 打开质量说明 |
| 证据卡 | 标题、来源、日期、观测时间、地区、层级、权利、事实类型 | 打开证据抽屉 |
| 图表卡 | 标题、单位、样本、来源、缺失、规则、`as_of` | 图/表切换、标记下钻 |
| 长文本输入 | 标签、1–100,000 Unicode 计数、草稿状态、帮助 | 粘贴、保存草稿、清空 |
| 敏感信息确认框 | 检测类别、风险、影响范围 | 返回编辑、继续、取消 |
| 双轴分类器 | 来源渠道、内容类型、建议依据、置信度 | 各轴独立确认或纠正 |
| 分析进度 | 已完成、进行中、失败项、恢复方式 | 离开后恢复、重试失败项 |
| 事实层标签 | 事实层中文名、来源、确认人、时间 | 查看原文与变更历史 |
| 互斥关系选择器 | 新增/印证/重复/冲突/证据不足/不适用 | 每候选只能选一项 |
| 版本差异 | 旧/新字段、依据、状态、变更人/时间 | 逐项接受或查看原版 |
| 删除确认框 | 删除对象、范围、不可恢复内容 | 输入确认、删除、取消 |
| Toast/页面消息 | 状态、对象、下一步 | 聚焦错误摘要；成功不抢焦点 |

## 5. 页面规格与线框

### 5.1 01 职业方向总览

```text
[职业方向总览]                       [查看技术栈]
[数据未就绪｜尚无可发布市场快照｜来源0｜样本不可用]
┌──────────────────────────────┐ ┌──────────────────────┐
│ 方向二维图                   │ │ 证据说明             │
│ Y 证据充分度                 │ │ 地区：—              │
│ │  无真实标记                │ │ 层级：—              │
│ └──────── X 机会信号         │ │ as_of：—             │
│ 暂不能比较八个方向           │ │ [查看来源与质量]     │
```

真实快照接通后的目标态才显示八个方向的点；X/Y 轴、单位、置信区间、样本和来源完整可见。默认不排序、不生成“最适合你”。

### 5.2 02 技术栈全景

```text
[技术栈全景] [方向筛选] [证据层筛选]
[真相条]
┌能力域────────┬核心基础┬工程实践┬进阶能力┬方向专项┬前瞻观察┐
│ 语言与运行时 │ 未就绪 │ 未就绪 │ 未就绪 │ 未就绪 │ 未就绪 │
│ UI与交互     │ 未就绪 │ ...                                      │
│ 工程化       │ ...  共八个能力域，不用“全部八域”聚合代替        │
└──────────────┴────────┴────────┴────────┴────────┴────────┘
[节点详情抽屉：证据、地区、层级、日期、样本、规则、未知项]
```

五层是语义层而非固定强行填满；没有真实 P2 项时显示“本快照暂无该层证据”。

### 5.3 03 市场证据与趋势

页签为“今日 / 历史日期 / 技术更新 / 招聘用途样本 / 修订记录”。

```text
[市场证据与趋势] [日期] [类型] [来源] [状态] [搜索]
[数据未就绪｜尚无已发布日快照]                       [刷新]
┌ 日更数量与来源覆盖 ────────────────┐ ┌ 快照列表 ────────┐
│ 无快照：不画折线、柱或 0           │ │ 尚无可显示记录   │
│ [查看等价表]                        │ │ [查看来源质量]   │
└─────────────────────────────────────┘ └──────────────────┘
```

“今日无新增”仅用于本次成功刷新且确实无新增；失败、未就绪和无新增不能共用空态。2026-08-25 的 4+4 只有真实发布后显示“历史研究快照”。

### 5.4 04 来源与质量

页面上半区为“来源政策 × 运行时状态”矩阵，下半区为来源表和质量说明。每行包含来源身份、政策、接入状态、内容类型、地区、最后成功、失败原因/错误码、新鲜度、缺失字段。研究批准和运行连接分别成列。

未配置连接器时写“运行时未接通”，不能显示绿色健康块。只有发生真实请求失败，才显示“刷新失败”及代码。

### 5.5 05 信息源工作台

```text
[信息源工作台]  草稿— / 保存状态：服务未就绪
①输入与保存 → ②元数据 → ③敏感信息确认 → ④双轴分类确认 → ⑤分析 → ⑥结果版本
┌─────────────────────────────────────────────┐
│ 材料正文                                    │
│ [1–100,000 Unicode 多行输入]                │
│ 0 / 100,000                                 │
└─────────────────────────────────────────────┘
[来源名称] [原链接] [地区] [层级] [日期未知可留空]
[保存草稿（未就绪）] [清空]
说明：网址不会自动访问；尚无真实保存和分析服务。
```

六步只出现一套步骤。保存成功后才进入分类；来源渠道和内容类型是两个独立选择器，用户确认后才进入分析。分析结果逐字段给原文位置、依据、置信度、规则/模型版本和失败项。

### 5.6 06 个人证据档案

左侧是材料/版本列表，主区按“用户自述、用户已确认、可外部核验、系统评估、模型推断、未知/冲突”分层。每条字段能回到原文片段；没有用户材料时不展示示例简历或能力图。

候选去重关系必须单选：新增、印证、重复、冲突、证据不足、不适用。确认或纠正生成新版本，不静默覆盖旧版本。

### 5.7 07 差距与成长路线

```text
[差距与成长路线]
┌────────────────────────────────────────────────────┐
│ 证据不足                                           │
│ 缺少：目标方向 / 可用市场快照 / 已确认用户证据     │
│ 当前不能生成差距分数、优先级或确定路线             │
│ [确认目标方向] [查看市场快照] [补充个人证据]       │
└────────────────────────────────────────────────────┘
```

三项齐全后，目标态卡片才包含目标能力、市场依据、用户证据、缺口、充分度、优先级依据、未知项；路线步骤包含证据产出、完成条件、依赖、投入、市场依据和复评时间，不承诺就业结果。

### 5.8 08 未来方向与历史

三轨时间线：公共研究快照、私有用户材料/确认、分析/差距/路线版本。轨道显著标来源身份，不把全部轨道统一写成用户数据。按日期、版本、来源和状态筛选；修订以新节点追加并用虚线关联被替代版本。

### 5.9 09 账号与数据权利

没有账号服务时显示“账号服务未就绪”，不用“登录失败”。页面提供保存范围、同步状态、最近成功、设备冲突、当前账号；原始材料和分析结果是两个独立导出动作，可同时执行。删除二次确认显示对象、版本、关联分析和失败恢复；不默认长期保存、公开或第三方传输。

## 6. 状态模型

### 6.1 公共研究状态

| 状态 | 画面 | 允许动作 |
|---|---|---|
| 数据未就绪 `not_ready` | 无快照、无图形标记、时间为“—” | 查看来源质量 |
| 刷新中 `refreshing` | 保留最近成功快照，显示进度与开始时间 | 返回、查看旧快照 |
| 实时可用 `live` | 显示真实刷新时间、覆盖、样本和规则 | 查看详情、导出 |
| 无新增 `no_new_items` | 查询成功，无新记录，保留旧快照 | 查看旧快照 |
| 部分可用 `degraded` | 成功域、失败域、影响范围并列 | 查看失败来源、重试 |
| 数据过期 `stale` | 最近成功、过期阈值、失败原因和错误码 | 使用旧快照、重试 |
| 刷新失败 `failed` | 真实请求失败；当前指针不推进 | 查看错误、重试 |

### 6.2 用户分析状态

| 状态 | 主反馈 | 恢复点 |
|---|---|---|
| 草稿 | 未提交，仅当前编辑 | 保存或退出 |
| 已保存 | 显示版本、哈希、保存时间 | 进入分类 |
| 分类中 | 分析来源渠道与内容类型 | 离开后恢复 |
| 待用户确认 | 两轴建议与依据 | 确认或纠正 |
| 分析中 | 展示分项进度，不伪造百分比 | 离开后恢复 |
| 部分完成 | 成功项与失败项分列 | 重试失败项 |
| 已完成 | 显示版本、依据、未知项 | 查看/导出/重新分析 |
| 证据不足 | 不生成确定差距或路线 | 补材料/快照/目标 |
| 失败 | 保留原文和上次成功版本 | 查看原因、重试 |

空白、网址-only、超长、敏感信息、重复提交、网络中断、跨端冲突、删除失败和无权限均使用页内错误摘要连接到具体字段；不得只显示红条。

## 7. 图表与数据契约

每张图由同一结构化数据同时生成视觉标记与完整等价表；图表状态不可用时，表也明确“未就绪”，不能填 0。

| 图形 | 结构化字段 | 视觉通道 | 等价表最小列 |
|---|---|---|---|
| 八方向二维坐标 | direction_id、x、y、confidence、snapshot | X/Y 坐标、置信描边 | ID、方向、X、Y、置信、来源 |
| 八域×五层矩阵 | domain、level、evidence_state | 行、列、形状、纹理 | 能力域、层、状态、证据数 |
| 日更数量/覆盖双轴图 | date、item_count、source_count、missing | 柱、线、缺失纹理 | 日期、记录、来源、缺失 |
| 来源政策×运行矩阵 | source、policy、runtime、freshness | 行列、图标、边框 | 来源、政策、运行、新鲜度 |
| 地区/层级分布 | region、level、sample_count | 分组条带 | 地区、层级、样本、用途 |
| 快照修订时间线 | snapshot_id、published_at、revision_of | 节点、时间、虚线关联 | 版本、时间、修订关系、状态 |
| 分析依赖图 | node_id、type、depends_on、state | 节点形状、真实拓扑边 | 节点、类型、依赖、状态 |
| 事实层堆叠 | truth_layer、count、unknown | 分段、纹理 | 事实层、数量、未知/冲突 |
| 个人证据覆盖矩阵 | evidence_id、domain、level、truth_layer | 单元标记、描边 | 证据、能力域、层、事实层 |
| 版本差异图 | field_id、old、new、relation | 左右轨、关系符号 | 字段、旧值、新值、关系 |

所有图显示单位、时间范围、规则版本、`as_of`、样本量、来源覆盖和缺失值；图例中的用户文案使用简体中文，内部键只出现在开发附注。

## 8. 关键流程

### 8.1 公共证据下钻

职业方向 → 技术栈 → 市场证据 → 日期快照 → 证据详情 → 返回原筛选。任何节点未就绪时停在可解释空态，不自动跳到假数据。

### 8.2 用户材料分析

粘贴材料 → 敏感信息确认 → 保存原始版本 → 双轴建议 → 人工确认/纠正 → 结构化分析 → 完成/部分完成/失败 → 结果版本。保存失败不进入分析，刷新后从真实服务恢复。

### 8.3 差距与路线

选择目标 → 绑定真实市场快照 → 选择已确认/可核验证据 → 检查三项条件 → 条件不足则补证据；条件齐全才生成差距和路线版本。

### 8.4 版本与删除

打开历史 → 新旧对照 → 重新分析 → 保留旧结果。删除原始材料或分析结果分别确认；失败保留现场，成功后返回列表并播报。

## 9. 响应式规格

| 视口 | 布局 |
|---|---|
| 1440 | 240px 左导航；内容最大 1180px；主图与详情 8:4；表格完整列 |
| 1024 | 72px 图标导航，悬停/聚焦显示中文名；图与表上下排列；抽屉宽 420px |
| 390 | 独立单列重排；底部四入口 +“更多”；筛选为全屏抽屉；固定操作不遮挡键盘 |
| 320 | 同内容继续重排；不缩放 390 画面；长标签换行；主操作占满宽度 |
| 200% | 有效 CSS 视口减半并回流；不横向滚动、不截字、不遮挡、不丢信息 |

移动软键盘出现时，长文本输入保留可见标签、字符计数和“保存草稿”；底部操作栏进入文档流。表格在移动端转换为按记录分组的键值卡，字段不删减。

## 10. 无障碍实现注释

- 提供“跳到主内容”；导航、筛选、图/表切换、表格、抽屉和弹窗均可仅用键盘完成。
- 弹窗打开后聚焦标题，焦点锁定；Esc 关闭并返回触发按钮。删除确认不可用 Esc 误提交。
- 状态变化用 `aria-live="polite"`；保存/删除失败用错误摘要和字段关联，避免频繁播报分析进度。
- 图表提供标题、摘要、完整数据表和下钻链接；装饰图标对辅助技术隐藏。
- 颜色以外再用文字、形状、纹理与图标表达状态；支持 `prefers-reduced-motion`。
- 本设计定义语义和视觉要求；真实 DOM、读屏、键盘、200% 与对比度仍须前端实现后由 QA 验证，不能由静态说明冒充已通过。
