## START OF DESIGN PROMPT

你是一名擅长复杂信息产品、数据可视化和无障碍设计的资深 UI/UX 设计师。请为 **Frontend Career Radar（前端职业成长雷达）** 设计一套桌面优先、响应式的 Web 数据大屏／数据看板体验。

这不是营销官网，也不是传统“后台模板换皮”。它是一个证据型职业成长产品：帮助前端开发者先看职业方向，再看技术栈全景；理解国内招聘、全球／远程、工程质量与 AI 增量信号；并允许用户主动粘贴文章、招聘／面试要求、简历或项目材料，在不夸大证据、不静默覆盖研究的前提下完成分类、摘要和对照。

请直接产出完整的高保真设计方案。若工具支持交互原型，请连接本文指定的主路径与关键状态；若不支持，请以带清晰注释的状态画板表达。不要输出代码，不选择 React、Vue、图表库、后端、数据库、云或部署方案。

### 1. 设计目标与硬性原则

#### 1.1 核心目标

1. 用户在 10 秒内看懂当前内容是有截止日期、样本量和覆盖缺口的研究快照，不是实时全市场统计。
2. 用户始终先完成“职业方向总览 → 技术栈全景”的认知顺序，再进入证据、地区、AI 或个人材料。
3. 用图形化结构取代大段文字，但所有关键图形必须可追溯、可解释，并有等价文本或数据表。
4. 让用户清楚区分：事实、来源观点、角色推断、未知；已批准研究、用户提供材料；用户自述、可核验证据、系统提取、模型推断。
5. 在高信息密度下保持极简、干净、有逻辑、安静可信；每个页面只突出一个主要判断问题。
6. 用户信息源输入应像严谨的“研究工作台”，而不是无边界的 AI 对话框。
7. 用户必须能一眼区分“服务进程健康”“快照数据就绪”“当前获批快照”“上一有效快照降级”“打包静态回退”和“没有可用数据”；健康绝不等于就绪，回退绝不等于实时。

#### 1.2 不可违反的产品边界

- 全局主导航前两项和核心流程前两层必须严格为：**01 职业方向总览 → 02 技术栈全景**。
- 不得把招聘证据、学习计划、个人评分、成长记录或“AI 热点”插到这两层之间。
- “9/10”“8/10”等数字只能写成“本次 10 个核心目的样本中的计数”，不得显示为市场份额、行业占比、全国排名或趋势。
- 中国样本只有 4 个，覆盖北京、上海、深圳；全球／远程样本 6 个；另有 2 个边界样本。不同集合不得静默相加。
- 全球、美国、远程与中国证据必须分区。远程必须显示国家／地区、时区、税务、工作许可或“未披露”限制，不得暗示全球任意地点可申请。
- 没有个人证据时，不生成雷达分数、能力百分比、缺口断言、“已掌握”或“已完成”。统一显示“未知／待补充”。
- 简历、自述、项目描述先标记为“用户提供／用户自述，待核验”，不得冒充已核验能力。
- AI 工具使用、AI 输出审核、AI 产品构建必须分为三类；P1-AI 不得在 P0 Web 基础和 P1 工程质量之前。
- 首版只处理用户主动粘贴的正文及可选元数据，不自动抓取 URL，不要求账号、文件上传或外部账号连接。
- F10 用户正文、原始 URL、简历、个人材料、备注、分类建议和对照结果只能留在当前浏览器标签页内存；不得进入只读研究服务的请求正文、查询参数、路径、请求头、Cookie、日志、错误栈、缓存、遥测、数据库、队列或第三方服务。
- 默认不长期保存输入正文或处理结果。不得设计未经授权的跨设备同步、持久个人档案、服务端分析或第三方模型传输；这类动作只能以“尚未授权／不可用”说明出现。
- 只读研究服务不得出现新增、编辑、删除、导入、上传或发布研究快照的可执行入口；页面中的“删除”只允许删除 F10 当前标签页内存中的用户输入与结果。
- 不复制或大段展示受版权保护的原文，只显示最小必要摘要和短事实片段。
- 不声称产品、页面或设计“完全符合 WCAG 2.2”；只可写“以 WCAG 2.2 AA 为设计目标，待正式审计”。

### 2. 信息架构与全局导航

#### 2.1 一级导航顺序

1. **职业方向总览**：8 个方向、方向证据强度、适用层级、限制与失效条件。
2. **技术栈全景**：P0、P1、P1-AI、P2、观察项及方向映射。
3. **招聘证据**：国内、全球／远程、边界样本和原始证据追溯。
4. **AI 增量**：工具使用、输出审核、产品构建三类信号。
5. **信息源工作台**：用户文本输入、双轴分类、摘要与研究对照。
6. **个人证据准备**：未知状态、待补证据、证据等级和隐私边界。
7. **快照与质量说明**：服务健康／就绪、当前版本、来源覆盖、降级／静态回退、错误与只读边界。

桌面端使用窄侧栏或紧凑顶部导航；首两项使用顺序编号和当前进度线强化固定层级。不要用层层嵌套的大型菜单。移动端使用顶部标题加底部导航：固定展示“方向”“技术栈”“信息源”，其余收进“更多”；仍需通过编号和页面标题明确 01 → 02 的顺序。

#### 2.2 全局固定信息

在每个页面顶部的紧凑“证据快照条”显示两组不得混淆的信息：

- **内容身份**：`获批研究快照 {version}`、`snapshot_id`、`内容 SHA256` 的短码和 `批准状态`；
- `证据截止：2026-08-03`
- `10 个核心目的样本：国内 4 / 公开远程 6`
- `另有 2 个边界样本`
- `不是市场份额`
- **运行身份**：服务 `健康／异常`、数据 `就绪／未就绪／降级／静态回退`、`本次观测时间 observed_at`、`最近成功加载`；必须明确 `observed_at 只是本次响应时间，不代表招聘市场刚刚更新`。

快照条默认一行，支持展开查看版本、来源覆盖、发布时间、证据截止日、最后成功加载、覆盖缺口与故障详情。健康和就绪使用两个独立、带文字和图标的状态，不合并成单一绿点。不得用遮挡内容的大型警告横幅反复打断用户。移动端压缩成“快照 {version} · {就绪状态} · 证据截止 2026-08-03”按钮，展开为底部抽屉。

#### 2.3 页面层级

每页统一采用：页面标题和一句结论 → 关键图形 → 解释／筛选 → 证据抽屉或详情。避免在首屏堆满卡片。页内最多一个主色 CTA；危险操作只在明确上下文中出现。

#### 2.4 全局数据真实性与服务状态契约

所有核心页面必须复用同一组状态组件，不能让各页面自行发明“在线／离线”文案：

| `data_mode`／状态 | 用户可见名称 | 必须显示 | 可继续操作 | 禁止表达 |
|---|---|---|---|---|
| `approved_research_snapshot` 且健康、就绪 | 当前获批快照 | 快照 ID、版本、批准状态、证据截止日、发布时间、内容 SHA256、`observed_at` | 浏览方向、能力、声明、证据和有界筛选 | “实时市场”“刚刚同步招聘数据” |
| 服务健康但未就绪 | 服务在线，快照未就绪 | 健康成功、就绪失败、失败原因、重试入口；无有效快照时不显示伪空图表 | 查看状态说明；若有独立静态回退则明确切换 | “暂无岗位”“0 条能力” |
| 当前重载失败但有上一有效快照 | 降级：正在使用上一有效快照 | 当前失败原因、旧快照版本、真实证据截止日、最近成功加载时间 | 继续只读浏览旧版，查看错误详情 | “当前版本”“已恢复”“实时” |
| 打包静态内容可用 | 静态回退 | `静态回退`、打包版本／SHA、证据截止日、服务是否不可用 | 继续浏览核心内容 | 把静态文件说成服务已就绪或实时连接 |
| 无任何有效快照 | 暂无可用研究快照 | 未就绪原因、可用版本提示（若有）、重试／返回说明 | 查看质量说明和重试 | 空白页面、伪造默认数据、伪空成功 |
| 查询局部失败 | 部分内容暂不可用 | 成功区域、失败区域、错误原因、重试范围、快照身份 | 已成功内容继续可读，只重试失败区域 | 清空整页、把局部错误冒充全局离线 |
| 查询无匹配 | 当前条件下 0 条 | 已生效筛选、快照身份、样本边界、重置筛选 | 修改／重置筛选 | “市场没有”“需求为零”“你不需要” |
| 指定版本不存在 | 未找到该快照版本 | 请求版本、可用版本、返回当前版本的明确操作 | 选择可用版本 | 静默替换成当前版本 |
| 快照哈希／引用无效 | 数据校验失败，未就绪 | 错误类别、受影响范围、恢复操作；不回显不可信内容 | 重试或查看静态回退（如真实存在） | 伪空集合、继续展示已判定无效的数据 |
| 来源链接失效 | 来源当前不可访问 | 最小证据摘要、最后核验日、访问限制 | 浏览摘要和返回原上下文 | 自动判定岗位关闭 |

状态优先级：**数据校验失败／无有效快照 > 降级 > 静态回退 > 局部失败 > 当前获批快照**。同时存在多个状态时，顶部只显示最高优先级结论，展开面板列出全部细节；不得用单一“系统正常”掩盖数据问题。

新鲜度只以已返回的业务时间和版本事实表达：证据截止日、发布时间、最近成功加载、当前观测时间、当前／上一有效／静态回退。没有获批阈值时不得自行发明“24 小时新鲜”“7 天过期”等数字；旧版降级必须直说“正在使用上一有效版本”。

### 3. 关键页面设计任务

#### 页面 01：职业方向总览（第一层，默认首页）

**用户问题：我有哪些方向可以考虑，各方向的证据边界是什么？**

布局：

- 首屏左侧为“方向轨道图／方向星系图”的二维布局，右侧为选中方向的摘要面板；不是能力雷达分数。
- 8 个方向必须完整出现：
  1. 产品型前端／应用工程
  2. 前端平台／设计系统／开发者体验
  3. AI 应用前端／AI 产品工程
  4. 数据可视化／实时交互
  5. 跨端／桌面／移动
  6. 全栈产品协作
  7. Web 质量工程（性能、可访问性、安全）
  8. UX Engineering／设计开发融合
- 二维轴建议：横轴“偏产品交付 ←→ 偏平台／系统”，纵轴“广度协作 ←→ 专项深度”。轴表示研究整理维度，不是客观排名；必须带说明。
- 节点大小映射“当前直接证据条数”，描边样式映射“置信度”，节点内使用方向图标和简称；禁止只靠颜色。
- 选择方向后，右侧显示：方向定义、用户价值、适用层级、主要能力域、证据信号、置信度、已知限制、失效条件。
- 主 CTA：`查看该方向的技术栈`，进入页面 02 并携带方向上下文。
- 次操作：`比较方向`，最多选择 3 个方向，使用行列对齐的比较表；不可用一个总分排序“最佳方向”。
- 未选中方向时显示全部方向概览，不自动推荐“最适合你”。

关键状态：默认、加载当前获批快照、上一有效快照降级、静态回退、未就绪、局部失败、悬停／键盘聚焦、已选择、最多 3 个比较、证据不足、无直接证据、筛选无匹配、图表替代表格。未就绪且无回退时不得用 8 个空节点冒充“无方向”。

#### 页面 02：技术栈全景（第二层）

**用户问题：选定方向后，能力应该按什么层次理解？**

布局：

- 顶部保留来源方向的面包屑：`01 职业方向总览 / {方向名} → 02 技术栈全景`。
- 核心用“分层能力地图”而非卡片瀑布：从左到右固定为 P0、P1、P1-AI、P2、观察项，P0/P1 视觉上先于 P1-AI。
- 每列使用可折叠能力组；能力项用小型节点，节点之间仅显示关键依赖线，避免复杂蜘蛛网。
- P0：Web 平台、JavaScript／TypeScript、一个主框架、Git／API／调试与协作。
- P1：测试、性能、可访问性、安全、构建与依赖、CI/CD、可观测性、设计系统、基础全栈协作。
- P1-AI：模型接口基础、AI 交互状态、评估与安全、AI 辅助研发审核责任。
- P2：数据可视化／实时、跨端、大规模前端、云与交付等方向专项。
- 观察项：WebGPU、WASM、本地 AI、WebNN、生成式 UI、MCP／代理协议。
- 能力节点显示：名称、优先级、适用方向数、适用层级、证据计数、事实类型；展开后显示可验证行为、直接证据、反证、未知、失效条件。
- 提供“当前方向 / 全部方向”切换和“初级 / 中级 / 高级 / Staff·负责人”层级筛选。
- 对 React、Vue、TypeScript 等明显标注：`职业市场能力内容，不是本产品实现技术选型`。
- 用户未提供个人证据时，个人对照区域只显示“未知／待补充证据”，不得把市场优先级渲染为个人水平。

关键状态：通用基线、指定方向、方向切换、层级切换、一项能力多方向复用、当前快照／降级旧版／静态回退、能力查询局部失败、非法筛选、版本不存在、直接证据不足、观察项、证据详情打开、未知个人状态、图表替代表格。

#### 页面 03：招聘证据与地区对照

**用户问题：这些结论来自哪些地区、层级和样本，哪些能够比较？**

布局：

- 顶部用三段式样本条明确集合：`中国一线 4`、`公开远程 6`、`边界样本 2`；三段之间有清楚分隔，不显示合并占比。
- 主图一：国内与全球／远程“要求类别 × 样本组”的并列点图或分组条形图。数值是岗位页计数 `n/N`，不是百分比。每个柱／点旁直接标 `n/N` 和“目的样本”。
- 主图二：远程约束矩阵，行是岗位，列是国家／地区、时区、工作许可、税务／合同、限制披露状态；用图标 + 文字，不以颜色唯一表达。
- 主图三：层级覆盖点阵，显示初级／中级／高级／Staff·负责人样本数；初级样本不足时用“样本不足”空心样式，不显示 0% 市场需求。
- 可切换到证据表格。表格列：来源、来源类型、岗位、发布时间或“未披露”、采集／最后核验日、地区、远程限制、层级、必须／优先／加分／职责、样本组、访问限制、状态。
- 点击任一图形标记或表格行打开右侧证据抽屉，保留直接链接、最小事实摘要、事实类型、置信度、限制与失效条件。
- 外链不可用显示“当前不可访问”，同时保留最后核验日；不得自动显示“岗位已关闭”。
- 筛选结果始终回显快照 ID／版本和全部有效条件；“条件下 0 条”与“数据未就绪”使用完全不同的空状态。

关键状态：全部样本、中国、全球／远程、边界样本、无样本地区、缺发布日期、外链失效、来源冲突、筛选无结果、表格替代视图。

#### 页面 04：AI 增量能力

**用户问题：AI 对前端增加了哪些职责，哪些只是加分项？**

布局：

- 顶部先显示基础护栏：`P0 Web 基础 → P1 工程质量 → P1-AI 增量`，AI 不得成为第一层或最大面积的营销模块。
- 主图使用三轨并列泳道：
  - AI 工具使用：任务拆解、上下文、生成、差异检查；
  - AI 输出审核：测试、事实核验、安全、回归、责任链；
  - AI 产品构建：流式状态、取消／重试、工具审批、来源、评估、可观测性、人机边界。
- 每条证据信号标记“硬要求 / 职责 / 加分项 / 角色推断”，岗位只写加分项时不得升级为硬要求。
- 使用小型分组条形图映射三类信号在“核心样本”和“边界样本”中的计数，两个样本组分开，直接显示 n/N。
- 设置“反证与限制”面板：AI 使用率不等于岗位替代率；生成速度不等于交付效率；特定公司信号不可泛化全部前端。
- 不使用机器人、霓虹脑、宇宙渐变等泛 AI 装饰。

关键状态：三类总览、单轨展开、核心／边界样本切换、加分项、证据不足、反证展开、替代表格。

#### 页面 05：信息源工作台（F10 交互核心）

**用户问题：我提供的信息是什么，它与获批研究有什么关系？**

把本页设计成清晰的四步工作流，而不是聊天界面：

`1 粘贴内容 → 2 确认分类 → 3 查看摘要 → 4 对照研究`

##### A. 输入区

- 一个足够大的多行文本框，标签：`粘贴文章、招聘／面试要求、简历、项目材料或其他正文`。
- 辅助说明：`1–100,000 个 Unicode 字符；只输入网址不会自动抓取；默认不长期保存。`
- 实时字符计数 `12,480 / 100,000`；接近上限时提示但不打断输入。
- 提供可选元数据折叠区：标题、原始网址、来源平台／发布方、作者、发布日期、采集日期、地区、岗位层级、用户备注。
- 日期“未披露”必须是显式选项，采集日不得替代发布日期。
- 提交前设置权利确认复选框：`我确认有权将此内容用于个人研究；提交不代表获得再发布权。`
- 主按钮：`分析并建议分类`；次按钮：`清空`。清空已有内容须二次确认。
- 固定隐私短提示：`建议先删除姓名、联系方式、证件、详细地址和雇主机密。当前设计默认仅在本次会话处理，不进入长期个人档案。`
- 在提交区旁固定显示隔离说明：`正文与个人材料只留在当前标签页内存，不发送到只读研究快照服务，也不进入 URL、请求头、Cookie、日志、缓存、遥测、数据库、队列或第三方服务。`

##### B. 输入校验状态

- **空白／仅空格**：不处理；错误与输入框通过文本和语义关联，文案 `请先粘贴可处理的正文。`
- **网址-only**：识别 URL 后显示 `当前不会自动访问或抓取网址，请同时粘贴正文。`；原 URL 保留在可选元数据。
- **超长**：超过 100,000 字符时不静默截断；显示实际字符数、超出量和“拆分后重试”建议，保留原输入。
- **敏感信息疑似存在**：提交后、处理前显示阻断确认层；列出只显示类别和大致位置的检测结果，不回显完整敏感值；操作为 `返回脱敏` 与 `仍在本次会话处理`。不得默认勾选确认。
- **无权利确认**：焦点移到复选框说明，不处理。

##### C. 双轴分类确认

分类建议必须同时呈现两个相互独立的字段：

1. 来源渠道：搜索引擎结果、公司／机构官方来源、招聘平台／ATS、媒体／长文平台、政府／标准／研究机构、社区／社交平台、用户简历／个人材料、其他、未知。
2. 内容类型：行业／技术文章、招聘职位、面试要求、面试经验、简历／个人证据、项目／案例、学习资料、其他、未知。

每个字段显示：首选建议、最多 2 个候选、置信度（高／中／低 + 数值仅作分类置信表达）、识别依据、缺失元数据。支持下拉或可搜索选择器人工纠正，纠正后显示“用户确认”图标与文字。多个分类同时成立时允许候选和“未知”，不得强迫伪确定。

按钮：`确认分类并生成摘要`、`返回修改`。键盘焦点顺序必须先来源渠道、后内容类型、再确认。

##### D. 处理中

用文本步骤器展示：`识别结构 → 生成最小摘要 → 提取信号 → 对照获批研究`。显示已完成、正在进行、尚未开始，不用无限循环动效作为唯一反馈。提供 `取消处理`；取消后保留输入并回到可编辑状态。处理状态用 `role="status"` 或等价可感知机制播报，避免频繁打断。

步骤器只描述当前浏览器中的交互和本地处理状态，不得画成“上传中”“已发送服务器”“云端分析”。若只读研究快照服务可用，浏览器可以读取获批快照作为对照基线，但界面必须明确：只有快照查询离开页面，用户正文和对照结果不回传。

##### E. 摘要结果

输出模块固定为：

- 最小必要摘要；
- 关键主张／要求；
- 技术与能力信号；
- 时间、地区、层级；
- 来源与访问限制；
- 待核验项。

每条内容标记为：来源事实、来源观点、系统提取、模型推断或未知。简历／个人材料顶部固定显示 `用户提供／用户自述，待核验`。不要展示能力评分，不要用“你已经掌握”。

##### F. 与获批研究对照

- 用“关系矩阵 + 详情列表”表达。每个关键关系只允许一个主状态：
  - 新增证据
  - 相互印证
  - 重复
  - 冲突
  - 证据不足
  - 不适用
- 关系卡／行必须显示：用户材料中的主张、对应研究结论、关系、理由、置信度、可能影响、双方来源边界。
- 冲突状态必须左右并列呈现“获批研究快照”与“用户提供材料”，不自动裁定一方为真，不合并成一个分数。
- 招聘／面试材料固定归入 `用户提供目的样本`，显示其自身 `n`，不得与既有 10 个核心样本静默相加。
- 页面固定双区标签：`获批研究快照` 与 `用户提供 · 本次会话`，任何时候都能辨认来源集合。
- 对照基线区同时显示快照版本、SHA 短码、证据截止日和数据模式。若研究服务未就绪但静态回退存在，明确显示 `使用静态回退基线`；若没有可用基线，则结果进入“部分成功：摘要已完成，对照未完成”，保留输入与摘要并只允许重试对照步骤。

##### G. 完成后操作

- `修改原文或元数据并重新处理`
- `重试失败步骤`
- `复制输入作为回退`
- `删除本次输入和结果`
- `返回浏览研究`

重新处理时，明确提示新结果将替代旧结果；旧结果显示“已被新结果替代”，不再参与对照。删除使用确认对话框，文案说明本次会话中的输入和结果将移除；删除后返回空状态并以非打断式状态消息确认。不要提供未授权的“永久保存”“同步到云端”或“发送给第三方”按钮。

##### H. 完整状态清单

必须分别绘制或在组件状态页中完整表达：

1. 初始空白；
2. 编辑中；
3. 仅空白校验失败；
4. 网址-only；
5. 接近字符上限；
6. 超长；
7. 权利确认缺失；
8. 敏感信息待确认；
9. 待确认分类；
10. 分类低置信／多个候选／未知；
11. 用户已纠正并确认分类；
12. 处理中；
13. 用户取消处理；
14. 处理成功；
15. 部分成功；
16. 重复；
17. 冲突；
18. 处理失败；
19. 可重试；
20. 修改后待重新处理；
21. 旧结果已替代；
22. 删除确认；
23. 已删除；
24. 处理能力暂不可用但原输入仍保留。

部分成功必须显示哪些步骤成功、哪些失败以及可执行的下一步；失败不得清空输入。

##### I. F10 与只读研究服务隔离状态

设计一个常驻但不喧宾夺主的“处理边界”详情面板，至少表达：

- `用户输入存放：当前标签页内存`
- `发送到研究快照服务：否`
- `持久化／日志／遥测：否`
- `第三方模型传输：未授权，不发生`
- `刷新或关闭标签页：输入与结果丢失`
- `研究对照基线：{快照版本 / 静态回退 / 暂不可用}`

如果客户端误把 F10 正文、文件或个人材料发送给只读研究服务，界面显示“请求被拒绝，正文未被服务处理”，保留浏览器内输入并提供返回修改；错误详情不得回显完整敏感正文。不要把这种拒绝设计成可绕过的“仍然上传”确认。

#### 页面 06：个人证据准备

**用户问题：系统还需要哪些证据，当前为什么不能判断我？**

布局：

- 顶部大号状态不是分数，而是 `个人判断状态：未知／待补充证据`。
- 使用“证据阶梯”展示：阅读／收藏 → 练习 → 独立项目 → 生产结果 → 同行审查。明确这是证据强度类型，不等同于一个人的固定等级。
- 待补清单分组：目标地区／层级、年限与主栈、项目及本人贡献、生产结果、测评、同行评价、时间与版本、公开／保存／删除授权。
- 用户自述、可核验证据、系统评估、模型推断使用独立标签与解释，不允许视觉上混成一个“可信度得分”。
- 可引导到信息源工作台粘贴脱敏材料，但明确当前会话处理和待核验边界。
- 不出现虚构的个人能力雷达图；未来若证据完整仍须独立产品审批才可定义评分。

关键状态：无证据、仅用户自述、已提供待核验、含公开限制、含保存限制、证据过期／版本不明、不可公开材料、信息源入口。

#### 页面 07：快照与质量说明

**用户问题：我现在看到的是哪一版研究，服务和内容是否真的可用，出现问题时还能信任什么？**

本页是只读真实性说明页，不是运维控制台，不提供重载、发布、上传、编辑或删除研究的后台权限。布局采用“当前结论 → 版本身份 → 健康／就绪 → 覆盖与来源 → 错误／降级详情 → 只读与隐私边界”。

##### A. 当前结论摘要

- 首屏只给一个准确结论：`当前获批快照可用`、`服务在线但快照未就绪`、`正在使用上一有效快照`、`正在使用静态回退` 或 `暂无可用研究快照`。
- 同时显示两个独立状态：`服务健康` 与 `数据就绪`；二者使用文字、图标和形状，禁止只用红绿灯。
- 显示数据模式：`approved_research_snapshot`、`degraded_previous_snapshot`、`static_fallback` 或 `unavailable`，并提供简体中文解释。

##### B. 版本身份卡

字段完整显示：`snapshot_id`、版本、批准状态、内容 SHA256（默认短码、可复制完整值）、证据截止日、发布时间、当前选择版本、本次 `observed_at`、最近成功加载时间。紧邻 `observed_at` 显示：`这是本次响应时间，不代表招聘市场刚刚更新。`

版本列表仅用于只读查看已存在版本。请求不存在版本时，显示请求值和可用版本，必须由用户明确选择；不得静默回到当前版本。

##### C. 样本与覆盖

- 使用分段数量条或小型表格显示核心目的样本 10、中国 4、公开远程 6、边界样本 2。
- 列出覆盖地区、岗位层级缺口、初级样本不足、远程样本偏差和目的抽样声明。
- 频次只能使用 `n/N`，不出现百分比、市场份额、总体排名或趋势推断。
- “来源覆盖”按可访问、当前不可访问、发布日期未披露、受登录／版权／robots／API 限制分类；这些状态描述证据可追溯性，不等于市场变化。

##### D. 加载校验与降级详情

用有顺序的检查列表展示：快照身份、内容哈希、方向—能力引用、声明—来源引用、事实来源、推断依据／置信度／失效条件、未知原因、目的样本分母和版本一致性。每项显示“通过／失败／未知 + 文字原因”，不展示无依据的综合健康分数。

降级时显示：失败的当前加载、仍在使用的上一有效版本、旧版真实证据截止日、最近成功时间和重试范围。静态回退时显示：打包版本、SHA、打包时间（若有）、服务状态和“静态内容不证明服务已接通”。

##### E. 错误与恢复

分别设计：加载中、服务异常、健康但未就绪、哈希失败、引用断裂、上一有效版本降级、静态回退、指定版本不存在、查询局部失败、来源链接失效、完全无可用快照。每个错误块必须回答：发生了什么、哪些内容仍可信、当前展示哪个版本、用户能做什么、哪些动作不可用。

允许的用户动作只有只读范围内的 `重试检查`、`只重试失败区域`、`查看错误详情`、`查看可用版本`、`查看静态回退`、`返回上一页`。不得设计研究写入、服务重启、强制刷新、重新发布或绕过校验按钮。

##### F. F10 与服务边界

固定显示：`研究快照服务只提供获批内容查询，不接收用户正文、文件、简历、个人材料、备注、分类、摘要或对照结果。` 用“允许读取”和“禁止发送”两列说明边界；禁止发送列覆盖请求正文、查询参数、路径、请求头、Cookie、日志、错误栈、缓存、遥测、数据库、队列和第三方服务。

关键状态：健康且就绪、健康但未就绪、异常且无回退、降级使用上一版、静态回退、加载中、局部失败、指定版本不存在、哈希失败、引用断裂、来源不可访问、无匹配（不是故障）、F10 内容被拒绝、320px 只读详情、等价文本表格。

#### 通用证据抽屉／详情页

所有页面复用同一证据详情组件，字段顺序固定为：

1. 结论与事实类型；
2. 来源名称和直接链接；
3. 发布日期或“未披露”；
4. 采集／最后核验日；
5. 地区、层级、样本组；
6. 必须／优先／加分／职责；
7. 置信度和依据；
8. 访问、版权、robots、API、登录和保存限制；
9. 反证、冲突、未知和失效条件。

抽屉关闭后焦点返回触发元素；移动端改为全屏详情页并提供明确返回。

| AI 三轨泳道 | 页面 04，拆分 AI 信号 | 工具使用、输出审核、产品构建、要求级别、证据来源 | 三条等宽轨道；标签区分硬要求／加分／职责 | 不推断替代率或保证提效 |
| 双轴分类面板 | 页面 05，确认用户来源 | 来源渠道、内容类型、各置信度、依据、确认状态 | 两个独立选择器／轴；候选 chips；用户确认标志 | 两轴不得混为单分类 |
| 研究关系矩阵 | 页面 05，对照研究 | 用户主张、研究结论、六类关系、理由、置信度 | 关系图标 + 文本；冲突双栏 | 不覆盖获批研究，不生成综合分数 |
| 证据阶梯 | 页面 06，解释个人证据等级 | 阅读、练习、独立项目、生产结果、同行审查 | 离散台阶 + 说明 | 活动不自动等于能力 |
| 健康／就绪双状态 | 全局快照条与页面 07，区分进程和数据可用性 | `health`、`readiness`、失败原因、最近检查时间 | 两个独立状态单元 + 图标 + 文字 | 健康不证明就绪；不能合并成一个绿点 |
| 快照版本时间轴 | 页面 07，查看当前／上一有效／静态打包版本 | `snapshot_id`、版本、批准状态、发布时间、证据截止日、内容 SHA、最近成功加载 | 离散版本节点；当前、上一有效、静态回退用形状和文字区分 | `observed_at` 不是市场更新时间；不存在版本不静默替换 |
| 快照完整性检查表 | 页面 07，解释未就绪原因 | 哈希、引用、事实来源、推断依据、未知原因、样本分母、版本一致性 | 顺序列表／表格，逐项通过／失败／未知 | 不生成综合“可信度分数”，失败数据不得继续展示 |
| 来源覆盖状态表 | 页面 07，说明证据可追溯性 | 来源类型、可访问状态、最后核验日、发布日期状态、版权／robots／API／登录限制 | 分组计数 + 等价明细表 | 来源失效不等于岗位关闭，覆盖不等于市场份额 |

#### 4.1 图形的非颜色编码

- 事实：实心圆 + `事实`
- 来源观点：引号形图标 + `来源观点`
- 角色推断：虚线菱形 + `角色推断`
- 未知：空心圆 + `未知`
- 用户提供：文档图标 + `用户提供`
- 用户确认：勾选印章 + `用户确认`
- 冲突：双向箭头 + `冲突`

图标旁始终保留文字。颜色只提供冗余提示，不承担唯一含义。

### 5. 演示数据与数据真实性标识

设计稿只能使用以下三类数据，并在页面显著标识来源身份：

1. **获批研究快照数据**：来自已批准 PRD 和市场调研，证据截止 2026-08-03。
2. **演示用用户输入**：为展示输入和对照状态而编写的脱敏虚构文本，统一标记 `演示数据 · 用户提供 · 本次会话`。
3. **演示用运行状态**：只用于展示健康／就绪、降级、静态回退和错误画板，统一标记 `演示状态 · 不代表服务已实现或已接通`；不得伪造真实服务 URL、刷新成功、在线率或故障时间。

允许在稿中直接使用的已批准快照数字：

- 核心目的样本：10；中国大陆一线城市：4；公开远程：6；边界样本：2。
- 核心样本内：React 9/10；TypeScript 8/10；工程质量要求 10/10；跨职能协作 10/10；测试／CI/CD 等工程信号 8/10；AI 直接要求 4/10，另有加分项 2/10。
- 中国覆盖只限北京、上海、深圳；初级核心样本仅 1 个；远程样本偏 Greenhouse 与中高级岗位。

以上数字旁必须出现 `本次目的抽样样本内`，不得添加 `%` 号、同比、市场排名或没有来源的新数字。

建议设计两条演示输入：

- 演示 A：一条脱敏招聘职位文本；来源渠道为“招聘平台／ATS”，内容类型为“招聘职位”，对研究同时产生“相互印证”和“新增证据”。
- 演示 B：一段脱敏简历自述；来源渠道为“用户简历／个人材料”，内容类型为“简历／个人证据”，结果固定显示“用户自述，待核验”，不得生成能力分数。

演示稿角落或画板标题统一加 `仅为设计演示，不代表实时数据、真实用户或已上线功能`。不要伪造实时刷新时间、在线人数、增长率、薪资、市场份额、个人水平或模型准确率。

页面 07 至少使用四套并列演示画板，且每套都带上述演示状态标识：

- 健康且就绪：获批快照 v1.0，证据截止 2026-08-03；`observed_at` 使用明显的占位标识，不写成市场更新时间。
- 健康但未就绪：哈希或引用检查失败，无有效快照时不显示 0 条市场内容。
- 降级：当前加载失败，使用上一有效快照；旧版本、截止日和失败原因同时显示。
- 静态回退：服务不可用但打包获批内容可读；明确静态内容不证明服务已接通。

### 6. 视觉方向与设计系统

#### 6.1 总体气质

- 关键词：极简、克制、专业、理性、清晰、证据感、数据密集但不压迫。
- 参考气质：研究仪表板、严谨编辑系统、现代数据产品；不要模仿证券交易终端的噪声，也不要做赛博朋克或企业管理后台套件。
- 大面积中性浅色背景，白色或极浅表面，低饱和强调色，细边框，极轻阴影或无阴影。
- 禁止大面积渐变、玻璃拟态、霓虹光、3D 图表、插画英雄区、厚重卡片墙、圆角泛滥、装饰性 KPI 数字。
- 圆角建议 8–12px；只有输入工作台的主容器可略大。卡片不是默认容器，优先用分区、留白和细分割线建立层级。

#### 6.2 建议色彩语义

- 页面背景：`#F6F8FA`
- 主表面：`#FFFFFF`
- 主文字：`#17212B`
- 次文字：`#667085`
- 边框：`#DDE3EA`
- 品牌／主操作：深青 `#0F766E`
- 信息／链接：蓝 `#2563EB`
- AI 增量：紫 `#6D5BD0`，只用于 AI 分类，不做大面积背景
- 成功／已确认：绿 `#168A5B`
- 警告／待确认：琥珀 `#A86509`
- 错误／冲突／删除：红 `#B4233C`
- 未知／不可用：灰 `#7A8493`

设计模型可微调色值以满足对比度，但不得改变语义。正文和关键控件以 WCAG 2.2 AA 对比度为目标；未审计前不宣称通过。

#### 6.3 字体与排版

- 使用适合中英文混排的现代无衬线字体；数字启用等宽或表格数字特性。
- 建议桌面正文 14–16px，移动正文不小于 16px；辅助文字不小于 12px且保证对比度。
- 页面标题 28–32px，区块标题 18–22px；不使用超大营销字号。
- 长摘要默认限制到 3–5 行，提供“展开全文”；不得通过小字号硬塞内容。

#### 6.4 间距与网格

- 桌面 12 列网格，内容最大宽度约 1440px；侧栏约 224–240px。
- 8px 基础间距；主要区块 24–32px；相关标签间距 8–12px。
- 数据表固定表头；只在表格／矩阵容器内允许横向滚动，不允许整页横向滚动。

#### 6.5 核心组件

设计并统一以下组件：全局导航、证据快照条、健康／就绪双状态、数据模式徽标、版本身份卡、只读版本选择器、最近成功加载信息、完整性检查表、局部错误面板、静态回退说明、F10 隔离边界面板、页面标题、筛选器、分段控件、搜索、标签／状态徽标、方向节点、能力节点、证据行、图表工具栏、数据表、证据抽屉、步骤器、多行输入、元数据表单、分类建议器、关系行、状态消息、空状态、错误状态、确认对话框、Toast／状态播报、分页／渐进加载、移动底部抽屉。

所有组件至少给出默认、悬停、聚焦、按下、选中、禁用、加载、成功、警告、错误状态；危险操作与普通操作不可仅靠颜色区分。

### 7. 交互规则

#### 7.1 导航与上下文

- 从方向进入技术栈后保留方向筛选和清楚的返回路径。
- 切换方向时不丢失研究截止日、抽样声明和证据范围。
- URL／页面标题概念上应可直达各模块，但不要设计需要登录才能访问的核心内容。
- 桌面证据详情使用右侧抽屉；移动使用全屏详情。关闭后焦点回到原触发项。

#### 7.2 筛选与图表

- 筛选改变图表时，在图表标题附近显示当前条件和结果数，并通过不打断的状态播报告知变化。
- “没有匹配数据”显示筛选空状态和重置按钮；“当前没有样本”显示证据不足／未知，二者文案不同。
- 图例项可聚焦并切换，但不可因为关闭图例就改变样本口径说明。
- Tooltip 只能补充信息，关键数值与标签不能只存在于 Tooltip。
- 请求条件非法时把错误关联到对应筛选字段，不自动回退为全量结果；请求版本不存在时要求用户明确选择可用版本。
- 后台刷新或重试不得让已经可读的上一有效快照瞬间消失。状态从当前版切换到降级／静态回退时，礼貌播报数据模式、正在展示的版本和失败范围。

#### 7.3 表单与危险操作

- 校验优先在字段离开焦点或提交时触发；长文本输入期间不要频繁弹错。
- 错误信息说明问题和下一步，保留用户输入。
- 重新处理前说明旧结果将被替代；删除和清空需要明确对象、后果和取消入口。
- 删除确认的默认焦点放在“取消”，不能用含糊的“确定”。
- 处理中允许取消；失败和部分成功允许重试，不得出现无说明的死循环。

### 8. 响应式要求

#### 8.1 大屏／桌面（≥ 1280px，重点画板 1440×1024）

- 使用紧凑侧栏 + 主内容；图表与详情可并排。
- 职业方向页采用 7/5 或 8/4 分栏；技术全景可横向展示五层。
- 信息源工作台可使用输入／流程主区和范围说明辅助区，但处理中和结果阶段以内容全宽为主。
- 快照与质量页首屏并排显示“当前结论”和“版本身份”，下方按健康／就绪、覆盖、完整性、错误与隐私边界展开；不做运维 KPI 墙。

#### 8.2 中等宽度（768–1279px，重点画板 1024×768）

- 侧栏折叠为图标栏或顶部导航；图表与详情上下排列。
- 五层能力地图允许容器内横向滚动，同时提供纵向列表切换。
- 筛选收进可见的“筛选”按钮，按钮显示已启用条件数。
- 健康／就绪双状态和版本身份上下排列，错误详情默认折叠但最高优先级结论始终可见。

#### 8.3 移动端（320–767px，重点画板 390×844，并验证 320px）

- 单栏布局，正文 16px；底部导航不遮挡内容、提交、取消或系统键盘。
- 多行输入在键盘弹出后仍能看见当前字段和主要操作；主要操作可使用安全区内粘性底栏，但不能覆盖错误说明。
- 方向图转为可排序的语义列表；技术全景转为按 P0 → P1 → P1-AI → P2 → 观察项的纵向折叠列表。
- 图表默认显示最关键视图，并提供数据表；矩阵使用卡片化行列表作为等价视图。
- 证据抽屉变为全屏页；对话框不超出视口；长链接可换行但不可破坏点击目标。
- 快照与质量页改为单栏语义列表；版本、截止日、最近成功加载、状态和恢复操作不得被横向表格隐藏。320px 下完整显示静态回退、未就绪和降级原因。
- F10“处理边界”面板在移动端放在提交按钮之前，并保持可展开；软键盘出现时隔离提示、错误和提交／取消均可到达。
- 横竖屏、200% 文本放大和系统大字号下不丢失核心操作。

### 9. 无障碍与包容性要求

以 WCAG 2.2 AA 为设计目标，最终是否符合需开发和正式审计验证。

- 页面具有唯一 H1，标题层级连续；主导航、主内容、筛选、图表、表格、表单和状态区具有清楚语义。
- 提供“跳到主要内容”；键盘焦点顺序与视觉／阅读顺序一致，焦点环至少 2px 且不被裁切。
- 所有功能可用键盘完成：方向选择、技术栈切换、证据抽屉、图例、筛选、表单、分类纠正、重试、重新处理、删除和关闭。
- 自定义图形节点若可交互，具有可读名称、角色、状态和操作说明；同时提供列表／表格替代。
- 图表具有简短结论、口径、数据表和文本摘要；视觉变化、置信度、冲突、错误和未知不只依赖颜色。
- 图标按钮提供可访问名称；链接文字说明目的，不使用单独的“查看详情”。
- 表单标签常驻，不用 placeholder 代替；必填、格式、字符上限和错误与字段关联。
- 动态处理状态使用礼貌级别的 live region 或等价机制；只播报阶段变化和完成／失败，不逐字播报计数。
- 服务健康、数据就绪、降级、静态回退、版本切换和局部失败均需可被辅助技术感知；播报必须包含当前展示的版本，不用“状态已变化”这类无上下文文案。
- 加载中使用可访问名称；无有效快照、条件下 0 条和来源不可访问具有不同标题、说明与恢复操作，读屏不能把它们都读作“暂无数据”。
- 阻断错误在提交后聚焦错误摘要，摘要链接到对应字段；敏感确认和删除对话框正确管理焦点并支持 Escape 取消。
- 触控目标至少 44×44 CSS px；相邻危险与普通操作保持足够间距。
- 支持系统减少动效；加载、成功或冲突不依赖闪烁、自动播放或大幅位移。
- 中英文混排、超长技术词、100,000 字符计数、长 URL、200% 放大和 320px 宽度下内容仍可访问。

### 10. 文案与语气

文案应简短、直接、诚实，不营销、不恐吓、不替用户下结论。

推荐：

- `本次 10 个核心目的样本中的 9 个提到 React；这不是市场份额。`
- `当前样本不足，无法判断该地区的总体需求。`
- `用户提供／用户自述，待核验。`
- `来源之间存在冲突，暂不合并结论。`
- `默认仅在本次会话处理，不进入长期个人档案。`
- `当前不会自动访问或抓取此网址。`
- `服务可以响应，但研究快照尚未就绪。`
- `当前加载失败，正在使用上一有效快照 v{version}；证据截止日为 {date}。`
- `当前使用静态回退内容；这不代表研究服务已经接通。`
- `本次观测时间只表示响应时刻，不代表招聘市场刚刚更新。`
- `摘要已完成，研究对照暂不可用；你的输入仍保留在当前标签页。`

禁止：

- `React 市占率 90%`
- `你最适合 AI 前端`
- `你的竞争力 87 分`
- `已掌握 TypeScript`（仅有简历自述时）
- `全球远程，任何地区均可申请`
- `AI 将淘汰传统前端`
- `已完全符合 WCAG 2.2`
- `永久安全保存`、`绝不泄露`等未经实现和验证的承诺
- `服务在线，所以数据最新`
- `实时招聘快照`（本版只有获批研究快照）
- `没有匹配结果，因此市场没有需求`
- `已上传并安全分析`（F10 正文不得上传）
