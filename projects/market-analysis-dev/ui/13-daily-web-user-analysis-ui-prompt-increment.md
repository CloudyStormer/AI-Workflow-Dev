## START OF COPYABLE DESIGN PROMPT

你是一名擅长证据型数据产品、复杂工作台、隐私体验和无障碍设计的资深 UI/UX 设计师。请为 **Frontend Career Radar（前端职业成长雷达）** 生成一套可直接评审、可供前端实现的高保真响应式 Web UI 图片或可交互原型。

这是对既有权威设计 Prompt 的增量升级。沿用原有极简、干净、克制、数据可追溯的视觉语言和组件体系，不重新发明品牌。所有用户可见导航、按钮、状态、表格、图表、错误、空态、提示和无障碍名称均使用完整简体中文；内部英文键只可放在开发标注或次级括号中，不得作为主文案裸露。

### 一、不可改变的产品真相

1. 固定认知顺序必须保持：**01 职业方向总览 → 02 技术栈全景**。日更证据、个人材料、差距和路线只能出现在这两层之后。
2. 当前真实运行状态是：信息源工作台尚未形成真实服务闭环；用户输入记录为 0；业务数据库写入为 0；运行时来源和连接器均为 0；中国大陆招聘有效样本为 0。不得把目标态、演示数据、研究清单或浏览器内存预览画成已经上线的实时能力。
3. 已有 2026-08-25 批次只包含 4 条官方技术更新和 4 条公开招聘用途样本。只有在它们被真实持久化并发布成不可变研究快照后，网页才可显示为该日期的历史记录；不得冒充今天数据、实时流或市场份额。
4. 招聘样本没有可核验发布时间时，字段显示“发布时间未知”，只显示真实 `observed_at` 与 `as_of`；禁止补造时间。
5. 用户粘贴的文章、岗位、面试、简历、经历或项目材料只是证据载体。简历自述不是已核验能力，用户招聘样本不是公开市场份额，模型推断不是事实。
6. HTTP 200、原文回显、前端本地缓存、JSON 可读取或一段模型摘要，都不等于“已保存”“分析完成”或“实时可用”。状态必须来自真实服务结果。

2. 技术栈全景

### 三、关键页面与必须画出的内容

#### 1. 职业方向总览

- 只从真实发布的研究快照读取 8 个职业方向；显示快照日期、地区、层级、样本量、来源覆盖和缺失情况。
- 方向图使用“机会信号 × 证据充分度”等可解释二维坐标，不用雷达多边形制造精确度幻觉。
- 当前无可用快照时显示“数据未就绪，暂不能比较方向”，不得显示 0 分、假排名或演示热度。
- 提供“查看证据”入口，进入市场证据页并保留方向筛选。

#### 2. 技术栈全景

- 按 8 类能力域展示真实证据覆盖与五层优先级；某层无真实项目时明确空态，不补齐假样本。
- 每个能力节点可展开其来源、地区、层级、时间、样本与规则版本。
- 区分“市场证据较多”“仅用户材料提及”“系统推断”“证据不足”，禁止只靠颜色区分。

#### 3. 市场证据与趋势

- 在前两层之后设置“日更证据”页签：今日、历史日期、技术更新、招聘用途样本、修订记录。
- 每条记录展示：领域、标题、来源、规范化链接、地区、层级、样本用途、发布时间（若可核验）、观测时间、`as_of`、权利状态、事实类型、快照版本。
- 2026-08-25 的 4 条技术更新与 4 条招聘用途样本只在真实发布后显示，并显著标“历史研究快照”；当天无新条目时显示“今日无新增”，不能把昨日记录改名为今日。
- 趋势图必须同时展示样本量、来源覆盖、缺失天数、规则版本、`as_of` 和等价数据表；标题使用“本雷达已接入来源样本趋势”，不得写“市场份额”。
- 点击趋势标记可下钻到该日快照和证据列表；返回后保留筛选、排序、滚动位置。

#### 4. 来源与质量

- 分开呈现“来源政策是否允许”和“运行时是否接通”两条轴，研究批准不能等同于连接器在线。
- 展示来源身份、权利策略、地区、内容类型、抓取/录入方式、最后成功时间、当前失败原因、错误码、新鲜度、覆盖缺口。
- 对 `not_ready`、`stale`、`degraded`、`failed` 显示可执行解释；无真实失败记录时不能画历史故障。
- 提供快照级质量说明：去重规则、修订数量、缺失字段、未知发布时间、冲突证据与不可用来源。

#### 5. 信息源工作台

把它设计为真实服务驱动的六步工作流，而不是大文本框加假 AI 结果：

1. **输入与保存**：支持文章、岗位、面试、简历、经历、项目证据；1–100,000 个 Unicode 字符；网址-only 只作为用户输入保存，不自动联网抓取。
2. **可选元数据**：标题、来源名称、原链接、作者/公司、地区、职业层级、发布时间、备注；未知可留空，不得强迫用户猜测。
3. **敏感信息确认**：检测到手机号、邮箱、地址、证件、薪资或公司机密时先解释风险，允许返回编辑、继续保存或取消；未经授权不向第三方传输。
4. **双轴分类确认**：系统建议“来源渠道 + 内容类型”，用户必须逐项确认或纠正后才能进入正式分析。
5. **结构化分析**：显示抽取依据、原文位置、置信度、规则/模型版本和不确定项；部分成功要逐项列出成功与失败。
6. **结果与版本**：摘要、证据映射、市场对照、差距、优先级、路线、历史版本、重新分析和删除。

来源渠道选项：搜索、招聘平台、公司招聘页、文章/媒体、社区、GitHub/官方文档、用户原创、其他、未知。
内容类型选项：文章、岗位、面试材料、简历、经历、项目证据、技术发布、其他、未知。

抽取字段至少覆盖：技能、工具、项目、职责、结果、量化指标、时间、职业层级、地区、证据链接、局限、冲突。每个字段都能回到原文片段或明确显示“无依据”。

#### 6. 个人证据档案

- 按“用户自述、用户已确认、可外部核验、系统评估、模型推断、未知/冲突”分层展示，层级不能混写。
- 同一材料的每次编辑产生新版本，保留原始内容哈希、保存时间、确认后的来源渠道和内容类型；历史版本只读可追溯。
- 去重时展示候选关系，并要求每条候选只选择一种互斥关系：新增、印证、重复、冲突、证据不足、不适用。
- 允许用户纠正分类或抽取，再生成新分析版本；旧结果不被静默覆盖。

#### 7. 差距与成长路线

- 只有“目标方向已确认 + 对应市场快照存在 + 用户具有已确认或可核验证据”三者齐全时，才显示差距和优先级。
- 任一输入缺失时进入“证据不足”态，只提示补充证据或确认目标，不生成确定路线、分数或优先级。
- 差距卡展示：目标能力、市场要求依据、用户现有证据、缺口、证据充分度、优先级依据、未知项。
- 路线步骤展示：目标能力、预期证据产出、完成条件、依赖、预计投入、市场依据、复评时间；不承诺就业结果。
- 新快照或新证据到来时生成新分析版本，并提供新旧对照，不覆盖旧路线。

#### 8. 未来方向与历史

- 使用时间线关联：研究快照、用户原始材料版本、分类确认、分析版本、差距版本、路线版本和用户纠正。
- 公共研究轨与私有个人轨视觉分区，默认不把用户内容混入公共研究。
- 支持按日期、版本、来源和状态筛选；可打开任一历史版本及其当时依据。

#### 9. 账号与数据权利

- 展示数据保存范围、同步状态、最后成功同步、设备冲突和当前账号身份；没有真实账号服务时显示“账号服务未就绪”。
- 删除必须二次确认，说明删除对象、影响范围、是否包含原始版本和分析结果；失败时保留现场并给出重试入口。
- 导出原始材料与分析结果为两个独立动作，可同时执行；导出内容带版本、时间和事实层级说明。
- 不设计未经授权的长期保存、公开分享、第三方模型传输或跨账号可见性。

### 四、状态模型与反馈

公共研究快照必须覆盖并分别画出：

- **数据未就绪（`not_ready`）**：没有可用发布快照，不能推导为 0。
- **刷新中（`refreshing`）**：保留最近成功快照，可取消重复触发；重复刷新幂等。
- **实时可用（`live`）**：仅真实服务和真实新鲜度满足规则时使用。
- **无新增（`no_new_items`）**：本次查询成功但没有新记录，继续保留旧快照。
- **部分可用（`degraded`）**：显示成功域、失败域、影响范围与当前仍可用的最近成功数据。
- **数据过期（`stale`）**：显示最近成功时间、过期阈值、当前失败原因与错误码。
- **刷新失败（`failed`）**：只有真实请求执行失败时使用；失败不清空、不推进当前快照指针。

用户分析必须覆盖并分别画出：草稿、已保存、分类中、待用户确认、分析中、部分完成、已完成、证据不足、失败。所有异步状态都提供明确反馈、离开页面后的恢复说明和屏幕阅读器播报；刷新页面后必须从服务端恢复真实状态，而不是重新伪造进度。

同时覆盖：空白输入、网址-only、超长输入、敏感信息确认、保存失败、分类失败、用户取消、部分抽取、重复提交、重新分析、删除失败、网络中断、跨端冲突、已删除、无权限。每个状态都有下一步动作，不能只给红色错误条。

### 五、数据映射与图表约束

为每张图建立“结构化数据 → 视觉标记 → 图例 → 完整等价表”四段映射。至少画出以下语义图形，不用同一种柱形图换标题冒充多类图表：

- 8 个职业方向二维解释坐标图；
- 8 能力域 × 五层优先级矩阵；
- 日更证据数量与来源覆盖双轴时间图；
- 来源政策 × 运行时状态矩阵；
- 样本地区/层级分布图；
- 日快照与修订时间线；
- 原始材料 → 分类 → 抽取 → 证据 → 差距 → 路线依赖图；
- 事实层级堆叠与未知/冲突分布；
- 个人证据覆盖矩阵；
- 新旧分析版本差异图。

每张图必须标单位、样本量、来源覆盖、缺失值、时间范围、规则版本和 `as_of`。完整等价表逐记录包含所有视觉标记对应的 ID、值、状态和来源，键盘和读屏用户可获得同等信息。无数据、数据未就绪和查询成功为空是三种不同画面：未就绪不画 0，成功为空不画旧柱或假标记。

### 六、视觉方向

- 延续既有极简、干净、专业、冷静的证据型数据产品风格；高信息密度但低噪声，避免营销渐变、霓虹科技风、巨型装饰数字和卡片墙。
- 每页只突出一个主问题；以层级、留白、对齐和就近真相条组织信息，减少大段说明文字。
- 公共研究与私有个人内容使用稳定的布局分域；事实、推断、未知、冲突同时使用文字、图标和形状，不只依赖颜色。
- 所有目标态和示例数据就近标“目标态演示·当前未接通”或“演示数据·用户提供”；不得让标签只出现在远处页脚。

### 七、响应式与移动端

输出或原型至少覆盖 1440、1024、390、320 四种逻辑视口，并提供真正的 200% 浏览器缩放回流证据。

- 1440：完整左侧导航、全局上下文栏、主图/表、证据详情并排。
- 1024：导航折叠但保留中文无障碍名；图表与等价表上下排列，不裁切字段。
- 390/320：为每个宽度独立重排，禁止整体缩放桌面图；正文不小于 16px，辅助文字不小于 14px，触控目标不小于 44×44px。
- 移动端软键盘弹出时，输入、分类确认和底部操作栏不能互相遮挡；粘贴 100,000 字符时仍可退出、保存草稿和查看字符计数。
- 200%：有效 CSS 视口减半后完整回流，无横向滚动、文字截断、控件遮挡或信息丢失。

### 八、无障碍

- 所有功能可仅用键盘完成；跳到主内容、焦点顺序、焦点可见、返回焦点、弹窗焦点锁定与 Esc 关闭明确可见。
- 状态更新使用适合的 `aria-live` 语义；长分析进度不过度播报，错误与完成结果可被读屏理解。
- 图表提供标题、摘要、数据表和下钻链接；图标有简体中文名称，装饰图标从辅助技术隐藏。
- 正常正文和小字对比度至少 4.5:1，大字至少 3:1；焦点和非文本控件至少 3:1。
- 不以颜色作为唯一状态编码；加载动画支持减少动态效果偏好。
- 表单标签、错误、帮助说明和字符计数建立可解析关联；敏感信息确认、删除确认和分类确认均有清晰标题与后果说明。

### 九、关键交互原型

请至少使以下流程可点击并支持键盘：

1. 职业方向 → 技术栈 → 市场证据 → 指定日期快照 → 证据详情 → 返回原筛选。
2. 粘贴材料 → 敏感信息确认 → 保存原始版本 → 双轴分类建议 → 人工确认/纠正 → 分析 → 部分成功/重试。
3. 个人证据 → 选择目标方向 → 市场快照对照 → 证据不足补充 → 差距 → 路线 → 生成新版本。
4. 历史版本 → 新旧对照 → 重新分析 → 保留旧结果。
5. 删除原始材料/分析结果 → 二次确认 → 成功或失败恢复。
6. 公共刷新 → 刷新中 → 无新增/部分可用/过期/失败 → 保留最近成功快照。

### 十、演示数据标识与禁止事项

- 演示数据必须与真实数据逐项分区并就近标识，禁止用“live”“实时”“已接入”“已保存”“分析完成”描述未接通能力。
- 不把 4 条招聘用途样本画成中国市场结论；中国大陆有效招聘样本仍为 0。
- 不自动访问 URL，不绕过登录、robots、版权、API 或来源政策。
- 不把用户自述变成能力评分，不生成未经证据支持的优先级或路线，不承诺求职结果。
- 不向第三方发送隐私材料，不默认公开，不跨账号展示，不设计未经授权的永久保留。
- 不输出前端代码、后端、数据库、模型、技术选型、连接器、服务、部署或生产发布方案。

### 十一、输出清单

1. 增量设计说明：与既有设计系统的继承关系、信息架构、页面映射、状态模型、数据契约、隐私与真相边界。
