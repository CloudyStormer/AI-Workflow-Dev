## 1. 产品定位与阻断裁决

超级无敌帅超超总只通过项目网页查看结果。产品信息架构前两层保持：**职业方向总览 → 技术栈全景**；日更证据、用户资料、差距与路线位于其后，不能改变该顺序。

本增量有两个阻断目标：

1. **真实日更页面化：** 技术更新和招聘证据经校验、去重、持久化与版本化发布后，自动进入项目网页；Markdown／JSON 只是输入和审计材料，不是用户入口。
2. **真实分析闭环：** 用户提交文案后不能只原样回显。系统必须保留原文版本，完成结构化提取、去重归类、技能／项目证据映射、置信度与依据、市场对照、差距优先级、学习路线和下一步建议；失败或证据不足时保持未知。

在两个目标真实实现并联调前，页面只能显示 `not_ready`、预览或受控降级，不能称分析完成。

## 2. 网页入口与信息层级

### 2.1 职业方向总览与技术栈全景

- 两层均从真实已发布研究快照读取，显示 `as_of`、最近成功、来源覆盖、样本量与缺口。
- 技术栈变化只表达“本雷达已接入来源样本中的变化”，不得称市场份额或完整行业趋势。
- 没有中国大陆招聘样本时，中国区域显示 `not_ready` 和缺口；不能用北美样本代替。

### 2.2 日更证据入口

- 在第二层之后提供“今日证据／近期变化”入口，展示技术趋势、招聘技能证据、技术栈变化和覆盖状态。
- 2026-08-25 批次发布后，网页能看到 4 条技术更新和 4 条招聘样本；到后续日期若无新成功批次，只能作为历史／上次成功快照展示，不能继续标“今日”。
- 每条内容至少显示：证据域、标题、来源、canonical URL、地区、岗位层级（招聘）、样本量、`published_at`（有则显示）、`observed_at`、`as_of`、状态、权利／访问限制、事实或评估类型。
- 技术更新、招聘事实、用户输入、系统评估和模型推断分别存储、筛选和展示，不能混成一个事实列表。

### 2.3 `/source-workbench`

- 接受用户主动粘贴的文章、招聘／面试要求、简历、经历和项目材料；不自动抓取仅粘贴的 URL。
- 提交后显示真实后端状态：保存中、已保存、分析中、待确认、已完成、部分完成、失败；刷新页面后从服务端恢复，不允许浏览器内假保存。
- 用户可查看原文、每个历史版本、来源渠道／内容类型、分析版本、使用的市场快照版本、证据映射、差距和路线。
- 用户可纠正分类、确认或拒绝证据候选、重新分析；新分析生成新版本，不静默覆盖旧分析。

## 3. 用户输入分析生命周期

```text
提交原文
  → 原文最小校验与版本持久化
  → 来源渠道／内容类型建议
  → 用户确认或纠正
  → 结构化提取
  → 内容内及历史去重／归类
  → 技能、项目、岗位与个人证据映射
  → 与指定真实市场／技术快照对照
  → 差距与优先级分析
  → 学习路线／下一步建议
  → 用户确认、回看、重分析或删除
```

### 3.1 原文与版本

- 每次提交先生成不可混淆的原文版本，记录提交时间、用户确认的来源、内容类型和原文哈希。
- 编辑原文生成新版本；旧版本及其分析结果保留，用户能查看“当时原文 + 当时市场快照 + 当时分析规则”。
- 原文是“用户提供的事实证据载体”，不表示其中每句话已被外部核验，也不表示用户已掌握所提技能。

### 3.2 双轴分类与结构化提取

- 来源渠道至少包括：搜索引擎、招聘平台、公司招聘页、文章／媒体、社区、GitHub／技术文档、用户原创、其他／未知。
- 内容类型至少包括：文章／报告、职位描述、面试要求、简历、经历、项目证据、技术发布、其他／未知。
- 提取对象至少包括：技能、工具／框架、项目、职责、成果、指标、时间、岗位层级、地区、证据链接、限制和冲突。
- 每项输出保留原文定位、提取依据、置信度、分析规则版本；不确定项进入待确认，不自动升级为个人事实。

### 3.3 去重、映射与事实分层

- 相同原文或同一材料的重复提交合并为关联版本，不重复增加证据计数；不同版本保留差异。
- 招聘或文章材料进入“用户提供的目的样本”，不得静默并入公共招聘样本或市场比例。
- 技能和项目证据映射必须区分：原文事实、用户自述、用户确认事实、可核验证据、系统评估、模型推断、未知／冲突。
- 系统评估和模型推断必须显示依据、置信度、规则／模型版本与可推翻条件，不能写成“已掌握”“已完成”或外部市场事实。

### 3.4 市场对照、差距与路线

- 对照必须绑定一个真实已发布的技术／招聘快照，显示地区、层级、样本量、来源覆盖、缺失来源和 `as_of`。
- 差距由“用户确认目标 + 快照中的能力要求 + 用户确认／可核验证据”组成；任一关键输入缺失时保持未知。
- 优先级同时说明市场证据强度、目标相关性、能力依赖、个人证据缺口和不确定性，不输出伪精确综合分数。
- 路线每一步包含目标能力、建议证据产物、完成判定、依赖、投入区间、市场依据和复评条件；用户可确认、调整、暂停或删除。
- 新市场快照或新用户证据不会静默改写旧路线；系统生成新分析版本并说明变化原因。

## 4. 日更证据生命周期与历史

```text
人工真实批次或后续合规采集
  → 来源／权利／时间／字段校验
  → 技术与招聘分域规范化
  → 稳定 identity、去重和 revision
  → 持久化证据与运行记录
  → 发布不可变研究快照
  → current pointer 指向最新成功快照
  → 项目网页查询、历史回看和用户分析引用
```

- 新批次只追加事件、revision 和快照；旧事件、旧快照及引用它们的用户分析版本必须保留。
- 招聘 identity 不得只依赖标题；应结合 canonical URL、公司／岗位标识、地区和观测状态。岗位下架走状态变化，不删除历史。
- 失败批次不移动 current pointer、不清空页面、不生成“当前趋势”；可以显示带日期的上次成功快照。
- 2026-08-25 的 4 个招聘样本只能证明当日仍可访问，因页面未提供发布日期，不能伪造 `published_at`。

## 5. 真相与分析状态

### 5.1 公共日更状态

| 状态 | 条件 | 网页行为 |
|---|---|---|
| `not_ready` | 真实导入／来源、持久化、发布或查询链未完成 | 说明缺失环节；当前应为此态。 |
| `refreshing` | 新批次正在校验或发布 | 保留上次成功快照，不提前显示未发布结果。 |
| `live` | 当前成功快照满足新鲜度和质量门 | 显示日更证据、覆盖、最近成功和 `as_of`。 |
| `no_new_items` | 真实运行成功但无新增 | 明确无新增，不复制旧数据凑数。 |
| `degraded` | 部分来源失败但剩余结果可用 | 显示失败来源、缺口和剩余真实数据。 |
| `stale` | 只有超过新鲜度阈值的上次快照 | 标旧日期，不称当前。 |
| `failed` | 全部必要来源或发布链失败 | 保留上次成功，显示失败；不发布新快照。 |

### 5.2 用户分析状态

| 状态 | 含义 |
|---|---|
| `draft` | 原文尚未提交 |
| `saved` | 原文版本已持久化，尚未分析 |
| `classifying` / `awaiting_confirmation` | 正在分类或等待用户纠正 |
| `analyzing` | 正在提取、映射和对照 |
| `partial` | 部分步骤成功，失败项和已成功项均可见 |
| `completed` | 指定输入、快照和规则版本下的分析完成 |
| `uncertain` | 证据不足或冲突，结论保持未知 |
| `failed` | 分析失败；原文和上次成功分析不丢失，可幂等重试 |

页面打开、HTTP 200、原文回显、前端生成摘要或 JSON 可读，均不能成为 `live` 或 `completed`。
