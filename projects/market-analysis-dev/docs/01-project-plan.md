## 1. 管理结论

Frontend Career Radar 应先验证一条最短且可审查的价值链：**把已批准、带来源边界的市场证据，转成用户能够在浏览器中理解的职业方向和技术栈内容**。第一阶段优先形成可浏览 Web 内容；后端服务、持续采集、真实个人数据接入和正式部署全部后置。

本计划不把“今天优先看到 Web 内容”解释为跳过审批门。若希望在 2026-08-04 看到浏览器预览，项目计划、PRD、UI 提示词、UI 设计、架构和首批任务拆解必须依次及时通过；这些门可以压缩等待时间，但不能省略。今天的 Web 预览是**加速目标**，不是在上游审批耗时未知时作出的无条件工期承诺。

当前真实基线：

- 项目已完成治理初始化，但没有业务代码、运行入口、构建命令、测试命令或部署结果。
- 市场调研 v1.0 已获批准，证据截止日为 2026-08-03。
- 招聘核心样本为 10 个目的抽样岗位页：中国大陆一线城市 4 个、公开远程 6 个；另有 2 个 AI Native／全栈边界样本。
- 样本可用于识别能力组合，不能估算市场份额、岗位总量、薪资中位数或框架总体占比。
- `docs/00-intake.md` 当前不存在；本计划只使用 README、项目级 Skill、已批准市场调研和已登记审批，不补造用户访谈或个人能力事实。

## 2. 项目目标

### 2.1 产品方向目标

建立一个面向 AI 互联网时代前端开发者的证据型职业成长产品，使用户能够：

1. 先理解可选择的职业方向，再理解相应技术栈全景；
2. 区分国内招聘证据、全球／远程对照、工程质量要求和 AI 增量能力；
3. 看见结论的来源、日期、地区、岗位层级、样本量、置信度和已知限制；
4. 在提供个人证据后，将市场要求与自身事实进行对照；
5. 持续记录学习与成果，但不把学习活动、模型推断或任意评分冒充真实能力。

### 2.2 当前阶段目标

- 先交付可浏览的 Web 内容切片，用已批准的冻结研究快照验证信息价值和阅读顺序。
- 通过浏览器切片收集对“职业方向总览 → 技术栈全景”两层结构的反馈。
- 把服务端采集、数据库、账号、真实个人成长记录和生产部署从首个切片中剥离，防止基础设施遮蔽内容验证。
- 保持整个阶段可追溯：每个结论都能回到来源、样本边界或明确标注的角色推断。

### 2.3 成功口径

当前 MVP 被认为有效，需要同时满足：

- 用户可以在浏览器中打开并完整浏览核心内容；“可浏览”不等于已经生产部署。
- 前两层严格为“职业方向总览 → 技术栈全景”。
- 国内招聘与全球／远程对照分开呈现，不把美国或全球趋势写成中国市场事实。
- 页面显著展示证据截止日、目的抽样性质、核心样本量和主要覆盖缺口。
- AI 工具使用、AI 输出审核和 AI 产品构建三类信号不混写。
- 没有个人证据时只显示“未知／待补充”，不生成个人能力分数或缺口结论。
- 受版权、robots、API、登录或条款限制的来源不成为首个 Web 切片的运行依赖。

## 3. 范围

### 3.1 MVP 范围

1. **浏览器优先的只读内容体验**
   - 以已批准市场调研 v1.0 为冻结内容快照；首版不依赖后端服务和在线采集。
   - 支持从职业方向进入技术栈全景，并能回看证据说明和未知项。

2. **第一层：职业方向总览**
   - 覆盖产品型前端／应用工程、平台与设计系统、AI 应用、数据可视化／实时交互、跨端、全栈协作、Web 质量工程等研究方向。
   - 每个方向保留证据信号、适用层级、置信度和失效条件。

3. **第二层：技术栈全景**
   - 按 P0、P1、P1-AI、P2、观察项组织市场能力，而不是按热点榜单排序。
   - React、Vue、TypeScript 等只作为研究内容，不在本计划中选择本项目自身的实现技术栈。

4. **证据与限制**
   - 显示来源链接、发布日期或采集日期、地区、层级、样本量、来源类型和访问限制。
   - 显示“事实／来源观点／角色推断／未知”及置信度，不隐藏反证。
   - 明示 10 个核心岗位是目的抽样，不是市场份额或完整总体。

5. **国内、全球／远程和 AI 增量对照**
   - 中国样本与全球／美国趋势分区，不相互代替。
   - 远程岗位保留国家、时区、税务或工作许可限制。
   - AI 增量与 Web 基础、工程质量并列，不能用 AI 热度覆盖 P0 基础。

6. **个人证据的空状态和录入边界**
   - 只定义待补证据类型和“未知”状态，不在 MVP 中接入真实账号或批量导入隐私数据。
   - 用户自述、可核验证据、系统评估和模型推断必须分层。

7. **基本质量约束**
   - 核心内容可通过键盘顺序访问，具备清晰标题层级、焦点可见性、非颜色唯一编码和必要文本替代。
   - 以 WCAG 2.2 作为设计与 QA 的参考基线，但在未完成正式审计前不得声称“完全合规”。

### 3.2 明确非目标

- 不在 MVP 中建设实时全网招聘聚合器、爬虫、定时任务或职位下架监控。
- 不绕过 LinkedIn、BOSS、猎聘等平台的登录、验证码、robots、付费或反爬限制。
- 不复制、长期保存或再发布受版权保护的完整职位正文。
- 不把当前样本计算成市场份额、薪资结论、岗位替代率或用户竞争力分数。
- 不在用户未提供证据时判断其已掌握、未掌握、已学习或未学习某项能力。
- 不在本阶段接入简历、GitHub、学习平台、公司内部成果、真实账号或其他隐私数据。
- 不在首个 Web 切片建设后端 API、数据库、数据管道、模型服务或生产监控。
- 不在本阶段选择前端框架、后端语言、数据库、云平台、图表库或部署平台。
- 不执行生产部署、公开发布、域名配置、付费采购或对外通知。
- 本计划不代替 PRD、UI/UX、架构、任务拆解、代码、测试报告或发布方案。

## 4. 交付策略：Web 内容先行

### 4.1 第一条交付纵切

首个可浏览切片只回答三个问题：

1. 用户可以考虑哪些前端职业方向？
2. 每个方向对应怎样的技术栈与能力层级？
3. 这些判断基于什么证据，哪些仍未知？

该切片使用仓库内冻结内容或等价静态数据，不要求后端存在。可以在开发环境、静态预览或其他经后续架构批准的非生产方式打开；具体实现形式由架构师决定。

### 4.2 后置能力

只有浏览器切片获认可后，才规划以下独立阶段：

- 合法稳定的数据源清单与来源级使用许可复核；
- 招聘快照、去重、标准化、过期和趋势序列；
- 个人成长证据的账号、授权、保存、删除和审计；
- 市场基线与个人证据的匹配或推荐逻辑；
- 后端服务、数据库、任务调度、可观测性和成本控制；
- 生产部署、域名、发布、监控和回滚。

## 7. 依赖与前置条件

### 7.1 已具备

- 市场调研 v1.0 已通过，文件哈希与审批登记一致。
- 项目身份、治理外壳、固定角色池和单根仓边界已建立。
- “职业方向总览 → 技术栈全景”前两层顺序已由项目级规则锁定。

### 7.2 关键依赖

- **人工审核依赖**：每个上游产物必须明确通过，今天的加速目标依赖审核响应时间。
- **产品依赖**：MVP 用户、使用场景、功能边界和详细验收标准由 PRD 冻结。
- **设计依赖**：数据密度、阅读顺序、响应式、空状态和可访问性由 UI/UX 两站交付。
- **架构依赖**：项目实现技术、预览方式、目录和验证命令由架构师定义。
- **内容依赖**：首版只使用获批调研快照；任何新增市场结论必须回到有来源的调研更新。
- **个人证据依赖**：没有用户授权事实时，只能提供通用市场基线。
- **数据权利依赖**：后续数据服务必须逐来源完成版权、条款、robots、API、登录和保存边界复核。

## 9. 项目级验收口径

### 9.1 项目计划 v1.0 验收

- 已绑定获批市场调研的版本、SHA 和审批 ID。
- 已定义目标、MVP、非目标、里程碑、依赖、风险、角色入场和停止门。
- 已将 Web 内容优先、后端服务和正式部署后置写入范围和关键路径。
- 已保留目的抽样、国内／全球边界、AI 增量、可访问性及数据权利约束。
- 已明确个人事实缺失和待补证据，不对用户作能力推断。
- 没有代写 PRD、UI/UX、架构、技术选型、代码或发布方案。

### 9.2 首个可浏览 Web 切片的项目级退出条件

详细 AC 由后续 PRD 定义，但不得低于以下底线：

1. 使用真实验证命令在声明的浏览器范围内打开；记录命令、结果和限制。
2. 前两层顺序正确，核心路径无断链，静态内容在无后端时仍可阅读。
3. 明示数据截止日 2026-08-03、10 个核心目的样本及主要覆盖缺口。
4. 国内、全球／远程、AI 增量、工程质量和可访问性信息不混淆。
5. 核心结论具有来源或明确推断标签；受限来源不成为运行依赖。
6. 无个人证据时不显示能力分数、缺口断言或“已完成”记录。
7. 完成键盘、焦点、标题结构、文本替代、对比度等后续 QA 确定的基础检查。
8. 不包含未经批准的后端、真实账号、隐私数据、自动抓取或生产发布。

## 10. 待超级无敌帅超超总补充的个人能力证据

在获得以下输入前，项目只能展示通用市场基线：

1. 主要目标：求职、晋升、转型、团队培养或长期趋势观察；
2. 目标地区、行业、公司类型、岗位层级和目标时间窗口；
3. 从业年限、当前主技术栈及自述熟练度；
4. 可核验的项目、工作成果、生产指标、代码／文档、测评或同行评价；
5. 每项证据的时间、技术版本、本人贡献、公开限制和可否长期保存；
6. 每周可投入时间、偏好学习方式和希望优先补强的方向；
7. 成功标准：面试、Offer、晋升、项目质量、学习连续性或其他；
8. 对简历、仓库、外部账号、薪资、隐私、数据保留、删除和 AI 评估的授权边界。

证据等级建议后续由产品经理定义，但必须区分：阅读／收藏、练习、独立项目、生产结果、同行审查。课程完成或 AI 生成代码不能自动升级为“已掌握”。
