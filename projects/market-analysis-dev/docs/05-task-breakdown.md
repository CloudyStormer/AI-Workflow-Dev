## 1. 管理结论

首批实施按“**先形成完整简体中文的浏览器内容，再补浏览器内信息源工作台**”拆成两段，后端服务、真实来源接入、用户数据持久化和生产部署继续后置：

1. **内容纵切**：先完成可运行工程、职业方向总览、技术栈全景、招聘证据、AI 增量和个人证据准备。所有导航、操作、状态反馈、图表标签、错误、空状态、无障碍文案和移动端必须提供完整简体中文版。
2. **本地交互纵切**：内容纵切稳定后，再实现 F10 信息源工作台；只允许当前标签页内存与 Web Worker，不自动抓取网址、不保存用户正文、不访问第三方模型或后端。
3. **质量纵切**：每个功能都必须具备来源边界、等价文本／表格、键盘路径、窄屏适配和真实验证证据；没有执行的检查不得写成通过。

本拆解列出有序待办，但超级无敌帅超超总若明确“通过”，只授权唯一首个下游工作项 `CFR-FE-001`，对应唯一角色为固定 `06 前端工程师`。本轮项目经理不会在审核前发送开发路由，也不会一次启动多个开发角色或多个开发工作项。

## 3. 本批范围与完成定义

### 3.1 内容纵切完成定义

完成 `CFR-FE-001` 至 `CFR-FE-007` 后，才可称为“首个完整可浏览内容切片”，且必须同时满足：

- 默认进入 `/directions`，固定顺序为“01 职业方向总览 → 02 技术栈全景”；
- 六个路由均可在无后端、无外链网络和无账号时打开；
- 页面显示证据截止日 2026-08-03、10 个核心目的样本及主要覆盖缺口；
- 中国、全球／远程、AI 增量、事实／推断／未知边界不混写；
- 图表均有文字摘要与等价表格，Tooltip 不承载唯一信息；
- 完整覆盖简体中文导航、操作、状态、图表、错误、空状态、无障碍播报和移动端；
- 不把视觉基线图片中的文案、日期、数字或状态冒充运行数据；
- 通过已声明的 lint、单元／组件测试、构建和关键 E2E 验证。

`CFR-FE-001` 只交付第一条可见纵切，不代表整个内容纵切已经完成。

### 3.2 本地交互纵切完成定义

完成 `CFR-FE-008` 至 `CFR-FE-010` 后，F10 才可称为“本地交互候选”：

- 接受 1–100,000 个 Unicode 字符，空白、100,001、URL-only 和恶意 HTML 有明确处理；
- 来源渠道与内容类型双轴分类可由用户确认或纠正；
- 摘要、信号和研究关系保持“用户提供”身份，不覆盖获批研究；
- 招聘输入保持独立目的样本，不并入核心 10 个样本；
- 用户正文不进入 URL、Storage、Cache、日志、遥测、第三方模型或后端；
- 取消、重试、部分成功、替代和删除状态真实可达，删除后旧结果不再参与对照；
- 24 个工作台状态、键盘、辅助技术与移动键盘场景有验证证据。

### 3.3 明确排除

- 后端 API、数据库、账号、跨设备同步、文件上传和个人档案；
- 真实招聘源、自动采集、URL 抓取、受限 API、登录或反爬绕过；
- 云端模型、第三方分析 SDK、远程字体／脚本、PWA 与 Service Worker；
- Docker、CI/CD、域名、公开发布、生产部署、监控和付费资源；
- 市场份额、薪资预测、岗位替代率、个人竞争力分数和“已掌握”推断。
