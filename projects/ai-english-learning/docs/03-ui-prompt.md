## 3. 可直接用于设计生成的完整提示词

你是一名资深教育产品 UI/UX 设计师。请为 AI English Learning 的 Web/H5 单词页设计“句中行内字母槽填空”交互。

本次只调整单词页的填空模式。保持现有学习产品的现代极简、温和鼓励、清爽高级感，不改背单词模式、聊天、首页、个人中心、导航、学习进度或其他产品逻辑。

设计的核心不是新增一个花哨控件，而是让英文句子中的缺词位置本身成为唯一答案入口。用户看到的字母槽、系统提示字母和自己输入的字母必须始终是同一份答案。

### 3.1 目标

1. 移除句子下方独立答案输入框。
2. 将真实输入焦点与句中整组字母槽绑定。
3. 让用户直观看懂答案长度、提示位置、已输入内容、当前编辑位置和剩余数量。
4. 支持连续输入、定位修改、退格、完整答案粘贴、剩余字母粘贴、提交、错误修正和下一题。
5. 在手机软键盘、桌面键盘、键盘导航和辅助技术下均可独立完成。
6. 保持当前页面视觉语言，不把练习改造成键盘游戏或验证码输入。

### 3.2 主要用户与场景

- 通勤中的手机用户：单手点击句中槽位，软键盘出现后完成输入、修改和提交。
- 桌面学习用户：连续打字、方向键定位、退格、粘贴、Enter 提交并进入下一题。
- 初学者：需要明确区分系统提示、自己输入和仍未填写的槽位。
- 使用读屏或键盘的用户：整组槽位只进入一次 Tab 顺序，并能听懂题目上下文、答案进度和结果。
- 容易拼错的用户：错误后保留答案，在原位置直接修正，而不是重新输入整词。

### 3.3 信息层级

一级信息：

1. 英文句子和句中答案槽
2. 当前输入位置
3. 检查答案 / 下一题主操作

二级信息：

1. 中文句意
2. 剩余字母数量
3. 正确、错误或未完成反馈

三级信息：

1. 再提示一些
2. 换一组字母
3. 答后同义词、搭配和使用场景扩展

不要让“共 N 个字母”“随机显示 N 个”“提示 1/3”等元数据压过句子和作答。可将其压缩为一行辅助说明或按需 Tooltip。

## 5. 行内字母槽组件

### 5.1 语义模型

- 视觉上可显示多个字母槽，但交互和辅助技术语义上必须是一个有名称的文本输入。
- 整组输入仅占一个 Tab 停靠点，不能让每个字母槽成为独立输入框。
- 槽组放在原句的缺词位置，前后文本保持自然阅读顺序。
- 点击任一可编辑槽后，焦点进入该答案输入，并把编辑位置定位到对应槽位。
- 系统提示槽和固定分隔符不可编辑，但可以被读屏说明。

### 5.2 槽位类型

每个答案位置只能属于以下一种类型：

1. 空字母槽：等待用户输入。
2. 用户字母槽：显示用户键入或粘贴的字母。
3. 系统提示槽：显示固定提示字母，不可被输入覆盖。
4. 固定分隔符：连字符、撇号或空格，原样显示且不计入可编辑字母数量。
5. 当前编辑槽：在空槽或用户槽基础上增加明确焦点指示。

视觉和语义都不能把系统提示误认为用户已经作答。

### 5.3 基本示例

目标词 apple：

- 初始：_____
- 输入 a：a____
- 继续输入：ap___ → app__ → appl_ → apple

目标词 apple，系统提示第 4、5 位 le：

- 初始：___le
- 输入 a：a__le
- 继续输入：ap_le → apple

含分隔符的目标：

- well-known：____-_____
- don't：___'_
- ice cream：___ _____

分隔符固定显示，输入、退格、粘贴和校验只在字母槽推进。

## 6. 输入、编辑与粘贴

### 6.1 连续输入

- 初始编辑位置为第一个未填写、非提示的字母槽。
- 用户键入英文字母后，填入当前可编辑槽，并移动到下一个未填写、非提示槽。
- 自动跳过系统提示槽和固定分隔符。
- 字母不区分大小写；界面使用与目标词一致的统一显示规则。
- 数字、表情、标点和其他非答案字符不得进入字母槽。
- 被拒绝字符使用不打断输入的文字或读屏提示，不弹出阻塞式对话框。

### 6.2 定位修改

- 点击任一用户字母槽可把编辑位置定位到该槽。
- 桌面端支持左右方向键在可编辑字母槽之间移动，并自动跨过提示槽和分隔符。
- 在已有用户字母的槽位键入新字母时，替换当前字母并保持其他槽位不变。
- 当前编辑槽必须同时使用焦点环、加粗下划线或光标形态表达，不能只靠颜色。

### 6.3 退格

- 当前槽有用户字母时，Backspace 删除该字母并保留焦点。
- 当前槽为空时，Backspace 移到前一个可编辑用户槽并删除该字母。
- 退格自动跨过系统提示槽和固定分隔符。
- 退格绝不删除、移动或覆盖系统提示字母。
- 错误答案状态下退格或重新输入后，整体恢复为“修改中”，但此前输入不得被清空。

### 6.4 粘贴

支持两种明确场景：

1. 粘贴完整答案：
   - 当粘贴内容的字母数量和分隔符结构可与整组槽位对齐时，按目标位置合并。
   - 系统提示位置必须与粘贴内容兼容；兼容时保留提示身份并填充其他槽。
2. 粘贴剩余字母：
   - 从当前编辑位置开始，只向未填写、非提示槽依次填入。
   - 自动跨过提示槽和固定分隔符。

粘贴后：

- 已有用户字母默认保留，除非用户明确定位到该槽执行替换。
- 超出可用槽位的字符不应造成布局错位。
- 非答案字符被过滤时给出简短状态提示。
- 不得因粘贴重新随机提示、清空输入或重复插入分隔符。

## 7. 提示字母与用户输入合并

- 同一题内初始随机提示必须稳定，任何普通输入、退格、聚焦或提交都不得重排。
- “再提示一些”只增加可用提示，不删除、移动或覆盖任何用户字母。
- “换一组字母”可以改变仍为空槽中的提示位置，但必须保留全部用户输入及其槽位。
- 若新提示候选与用户已填写位置冲突，用户字母优先；系统改选兼容空槽。
- 没有更多兼容提示时禁用按钮，并显示“当前答案已无更多可用提示”。
- 提示字母与用户字母必须通过颜色之外的第二种方式区分，例如提示字母顶部小点、提示标签或不同字重。
- 切换到下一题后才清空输入，并为新题生成新的稳定提示。

## 8. 提交与反馈状态

### 8.1 未完成提交

- 用户点击“检查答案”或按 Enter 时，如果仍有空字母槽，不判定错误。
- 显示“还差 N 个字母”，将编辑位置移到第一个未填写槽。
- 保留全部用户输入和系统提示。
- 未完成状态使用中性提醒，不使用错误红色或抖动。

### 8.2 完整但错误

- 保留用户输入、提示字母和当前题目。
- 不自动跳题，不清空答案，不用正确答案覆盖用户输入。
- 文案使用“再检查一下拼写，你可以直接修改后重试”，避免打击性表达。
- 整组槽位显示错误边界、错误图标和文字反馈；不得只依赖红色。
- 除非产品另行提供逐字母判定能力，不在本设计中擅自标出具体哪一位错误，也不提前泄露正确字母。
- 用户定位、退格或输入后进入“修改中”，可再次提交。

### 8.3 正确

- 显示明确成功图标、文字和非颜色反馈。
- 保持完整答案可见。
- 主按钮从“检查答案”切换为“下一题”。
- 第一次 Enter 提交答案；正确状态下再次 Enter 才进入下一题。
- 下一题清空上一题用户输入、反馈和编辑位置，并生成新题稳定提示。
- 答后可展示同义词、常见搭配和场景扩展。

### 8.4 主动结束本题

- 若已有“结束本题 / 查看答案”能力，应使用次级、低强调操作。
- 用户主动结束后才展示正确答案和原因。
- 本提示词不新增该业务能力；只有现有产品范围提供时才设计对应状态。

## 9. 同义词兼容

- 正确性以可接受答案集合判定，不只绑定一个字符串。
- 只有字母数量、固定分隔符和当前提示字母均与本题槽位兼容的候选，才能在当前槽组判为正确。
- 不兼容同义词不得作为可输入候选，也不能造成“语义正确但槽位永远无法容纳”的死路。
- 不兼容同义词只在答后扩展中展示。
- UI 不在作答前泄露完整可接受答案列表。
- 如果输入语义可接受但与当前槽位不兼容，产品层应避免把它作为本题可接受答案；UI 不自行发明额外判定规则。

延续现有设计系统：

- 深紫文字：#25075F

- 次文字：#776C69
- 成功色：#15836F
- 错误色：#B54C59
- 深色模式强调文字：#DDB4FF

### 10.1 字母槽

- 字体：ui-monospace、SFMono-Regular、Menlo、Monaco、Consolas、等宽回退。
- 桌面字母：24–28px；移动端：20–24px。
- 单槽视觉宽度：最小 0.72em；可点击槽的实际命中区域不小于 32px 宽。
- 整组输入命中高度至少 44px。
- 空槽底线：2px，rgba(119,108,105,0.42)。
- 用户字母：#17131B，字重 750。
- 系统提示：#4C0C91，字重 850，并增加非颜色标识。
- 当前编辑槽：3px 品牌紫底线或 2px 焦点框，附稳定光标。
- 整组聚焦：0 0 0 4px rgba(99,33,164,0.12)。
- 正确：#15836F + 对勾图标 + 文字。
- 错误：#B54C59 + 警示图标 + 文字。
- 分隔符无底线，使用正文颜色显示。

### 10.2 布局与动效

- 字母槽必须看起来属于句子，不得落回句子下方形成第二输入区。
- 长单词允许随句子自然换行；不要在整页产生水平滚动。
- 仅当一个连续单词组在当前行完全无法容纳时，整组换行，不将字母槽拆成难以理解的无序片段。
- 状态切换 160–180ms，使用轻微颜色、边界或透明度过渡。
- 错误反馈最多一次轻微位移，不连续抖动。
- prefers-reduced-motion 下取消呼吸、抖动和非必要过渡。

## 11. 移动端软键盘

- 点击句中槽组或可编辑槽必须调起英文文本键盘。
- 关闭自动更正、自动大写和拼写替换，避免系统静默改写答案。
- Enter 键语义为“检查”；正确后变为“下一题”。
- 软键盘出现后，当前句子、编辑槽、状态反馈和主按钮必须仍可见或可通过最小滚动到达。
- 焦点变化时将当前槽滚动到安全可视区域，但不要让页面反复跳动。
- 主按钮可在键盘上方保持可达，但不得遮挡句子、反馈或提示按钮。
- iOS Safari 与 Android Chrome 均需覆盖。

## 12. 响应式

### 12.1 手机：320–767px

- 单列卡片，左右安全边距至少 16px。
- 句子字号 21–24px，槽位随文本自然换行。
- 页面级不得出现横向滚动。
- 模式切换、槽组和主按钮触控目标至少 44px 高。
- 提示操作位于主按钮后，避免与键盘操作竞争。
- 320px 宽度、最长目标词和带分隔符答案必须单独出状态稿。

### 12.2 平板：768–1200px

- 主卡片居中，句子与槽组仍在同一阅读块。
- 主按钮可与反馈同区布局，但不与答案槽争夺横向空间。
- 横竖屏都不得恢复独立答案框。

### 12.3 桌面：大于 1200px

- 主卡片建议最大宽度 720px。
- 字母槽直接嵌入句子，桌面键盘路径是主要交互。
- 目标词相关 Examples 侧栏在填空状态继续隐藏。

## 13. 无障碍

### 13.1 名称与描述

- 整组答案使用一个 textbox 语义。
- 可访问名称示例：“补全句子中的英文单词”。
- 描述包含：
  - 完整句子上下文
  - 可编辑英文字母总数
  - 已输入数量
  - 剩余数量
  - 系统提示的位置与字母
  - 固定分隔符结构
  - 当前正确、错误、未完成或修改中状态

### 13.2 键盘

- Tab：一次进入整组答案。
- 左右方向键：在可编辑槽间移动。
- 字母键：输入或替换。
- Backspace：删除当前或前一个可编辑用户字母。
- Command/Ctrl + V：粘贴完整答案或剩余字母。
- Enter：检查答案；正确状态下再次 Enter 进入下一题。
- 焦点顺序：返回 → 模式切换 → 答案槽组 → 主按钮 → 提示操作。

### 13.3 状态播报

- 使用礼貌 live region 播报提示变化、剩余字母数、过滤字符、错误、正确和切题结果。
- 不逐键播报整句，避免读屏噪声；按必要节奏播报“已输入 N 个，还差 M 个”。
- 提示位置使用从 1 开始的自然语言，例如“第 4 位提示 L”。
- 正确、错误、提示和当前焦点均需图标、形态或文字辅助，不能只靠颜色。
- 焦点对比度、正文对比度和状态边界满足 WCAG 2.2 AA。

4. 连续输入中，提示与输入稳定合并。
5. 点击中间槽定位修改。
6. 退格跨过提示和分隔符。
7. 粘贴完整答案。

9. 未填完整提交。
10. 完整但错误。
11. 错误后修改中。
12. 正确，主按钮变为下一题。
13. 再提示一些。

## 17. 提示词验收标准

- [ ] 句中槽位是唯一答案入口，句子下方没有独立输入框。
- [ ] 系统提示和用户输入稳定合并，不移动、不删除、不覆盖。
- [ ] 支持连续输入、点击定位、方向键、退格和替换。
- [ ] 支持粘贴完整答案与剩余字母，并正确跨过提示和分隔符。
- [ ] 未完成提交提示剩余数量且不判错。
- [ ] 错误后保留答案，允许原位修改重交。
- [ ] 正确后明确切换为下一题操作。
- [ ] 1 字母、2 字母、连字符、撇号和空格答案有明确状态。
- [ ] 可接受同义词必须与当前槽位兼容，不兼容同义词只在答后展示。
- [ ] 移动软键盘不会遮挡当前作答、反馈和主操作。
- [ ] 键盘可独立完成聚焦、输入、定位、退格、粘贴、提交和下一题。
- [ ] 整组槽位作为一个有名称的答案输入被辅助技术识别。
- [ ] 状态表达不只依赖颜色，并满足 WCAG 2.2 AA。
- [ ] 浅色、深色、320px、390px、平板和桌面规则完整。
- [ ] 保持现有页面视觉语言和受影响前端冻结事实。
- [ ] 未生成任何设计稿、原型、图片或实现代码。

## 18. 审核选项

请超级无敌帅超超总只审核本提示词：

- 通过
- 修改：请说明需要调整的交互、视觉或边界状态
- 打回

在收到明确“通过”前，UI/UX 必须停止，不得进入设计生成阶段；收到“通过”后只自动进入唯一下一站 UI 设计生成，并在该站独立交付后再次停在审核门。
