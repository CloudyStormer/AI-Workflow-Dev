## 3. 可直接用于设计生成的完整提示词

你是一名资深教育产品 UI/UX 设计师。请为 AI English Learning 的 Web/H5 单词页设计“句中行内字母槽填空 + 主动查看答案”交互。

本次只调整单词页填空模式中的“查看答案”状态，并完整继承 v1.1 行内字母槽规范。保持用户提供 `ui/` 的现代极简、温和鼓励、清爽高级感，不改背单词模式、聊天、首页、个人中心、导航、学习进度或其他产品逻辑。

设计的核心不是新增一个答案区域，而是让英文句子中的缺词位置始终成为唯一答案入口与唯一答案展示位置。用户看到的字母槽、系统提示、自己输入和确认揭晓后的标准答案必须是同一组行内槽位的不同状态。

### 3.1 目标

1. 移除句子下方独立答案输入框。
2. 将真实输入焦点与句中整组字母槽绑定。
3. 让用户直观看懂答案长度、提示位置、已输入内容、当前编辑位置和剩余数量。
4. 支持连续输入、定位修改、退格、完整答案粘贴、剩余字母粘贴、提交、错误修正和下一题。
5. 在手机软键盘、桌面键盘、键盘导航和辅助技术下均可独立完成。
6. 保持当前页面视觉语言，不把练习改造成键盘游戏或验证码输入。
7. 在未答、部分作答、提交未完成和答错状态提供低强调“查看答案”；独立答对后不再提供。
8. 首次触发必须确认并说明计分影响；取消或退出不能改变答案、记录、进度或焦点上下文。
9. 确认后在原行内槽直接显示完整标准答案，进入只读“正确答案，已查看”，并提供“下一题”和“重新作答本题”。
10. 清楚表达查看答案及查看后重试答对均不计独立答对、正确率分子或熟练度收益。

### 3.2 主要用户与场景

- 通勤中的手机用户：单手点击句中槽位，软键盘出现后完成输入、修改和提交。
- 桌面学习用户：连续打字、方向键定位、退格、粘贴、Enter 提交并进入下一题。
- 初学者：需要明确区分系统提示、自己输入和仍未填写的槽位。
- 使用读屏或键盘的用户：整组槽位只进入一次 Tab 顺序，并能听懂题目上下文、答案进度和结果。
- 容易拼错的用户：错误后保留答案，在原位置直接修正，而不是重新输入整词。

### 3.3 信息层级

一级信息：

1. 英文句子和句中答案槽
2. 当前输入位置
3. 当前结果和“检查答案 / 下一题”主操作

二级信息：

1. 中文句意
2. 剩余字母数量
3. 正确、错误或未完成反馈
4. 揭晓后的“重新作答本题”

三级信息：

1. 再提示一些
2. 换一组字母
3. 查看答案（仅未答、部分作答、未完成或答错时）
4. 答后同义词、搭配和使用场景扩展

不要让“查看答案”、计分说明、“共 N 个字母”“提示 1/3”等信息压过句子和作答。查看答案必须可发现但保持低强调；计分后果在确认层和揭晓结果中用短文案表达，不在默认作答界面堆成长说明。

## 5. 行内字母槽组件

### 5.1 语义模型

- 视觉上可显示多个字母槽，但交互和辅助技术语义上必须是一个有名称的文本输入。
- 整组输入仅占一个 Tab 停靠点，不能让每个字母槽成为独立输入框。
- 槽组放在原句的缺词位置，前后文本保持自然阅读顺序。
- 点击任一可编辑槽后，焦点进入该答案输入，并把编辑位置定位到对应槽位。
- 系统提示槽和固定分隔符不可编辑，但可以被读屏说明。

### 5.2 槽位类型

每个答案位置只能属于以下一种类型：

1. 空字母槽：等待用户输入。
2. 用户字母槽：显示用户键入或粘贴的字母。
3. 系统提示槽：显示固定提示字母，不可被输入覆盖。
4. 固定分隔符：连字符、撇号或空格，原样显示且不计入可编辑字母数量。
5. 当前编辑槽：在空槽或用户槽基础上增加明确焦点指示。

视觉和语义都不能把系统提示误认为用户已经作答。

### 5.3 基本示例

目标词 apple：

- 初始：_____
- 输入 a：a____
- 继续输入：ap___ → app__ → appl_ → apple

目标词 apple，系统提示第 4、5 位 le：

- 初始：___le
- 输入 a：a__le
- 继续输入：ap_le → apple

含分隔符的目标：

- well-known：____-_____
- don't：___'_
- ice cream：___ _____

分隔符固定显示，输入、退格、粘贴和校验只在字母槽推进。

## 6. 输入、编辑与粘贴

### 6.1 连续输入

- 初始编辑位置为第一个未填写、非提示的字母槽。
- 用户键入英文字母后，填入当前可编辑槽，并移动到下一个未填写、非提示槽。
- 自动跳过系统提示槽和固定分隔符。
- 字母不区分大小写；界面使用与目标词一致的统一显示规则。
- 数字、表情、标点和其他非答案字符不得进入字母槽。
- 被拒绝字符使用不打断输入的文字或读屏提示，不弹出阻塞式对话框。

### 6.2 定位修改

- 点击任一用户字母槽可把编辑位置定位到该槽。
- 桌面端支持左右方向键在可编辑字母槽之间移动，并自动跨过提示槽和分隔符。
- 在已有用户字母的槽位键入新字母时，替换当前字母并保持其他槽位不变。
- 当前编辑槽必须同时使用焦点环、加粗下划线或光标形态表达，不能只靠颜色。

### 6.3 退格

- 当前槽有用户字母时，Backspace 删除该字母并保留焦点。
- 当前槽为空时，Backspace 移到前一个可编辑用户槽并删除该字母。
- 退格自动跨过系统提示槽和固定分隔符。
- 退格绝不删除、移动或覆盖系统提示字母。
- 错误答案状态下退格或重新输入后，整体恢复为“修改中”，但此前输入不得被清空。

### 6.4 粘贴

支持两种明确场景：

1. 粘贴完整答案：
   - 当粘贴内容的字母数量和分隔符结构可与整组槽位对齐时，按目标位置合并。
   - 系统提示位置必须与粘贴内容兼容；兼容时保留提示身份并填充其他槽。
2. 粘贴剩余字母：
   - 从当前编辑位置开始，只向未填写、非提示槽依次填入。
   - 自动跨过提示槽和固定分隔符。

粘贴后：

- 已有用户字母默认保留，除非用户明确定位到该槽执行替换。
- 超出可用槽位的字符不应造成布局错位。
- 非答案字符被过滤时给出简短状态提示。
- 不得因粘贴重新随机提示、清空输入或重复插入分隔符。

## 7. 提示字母与用户输入合并

- 同一题内初始随机提示必须稳定，任何普通输入、退格、聚焦或提交都不得重排。
- “再提示一些”只增加可用提示，不删除、移动或覆盖任何用户字母。
- “换一组字母”可以改变仍为空槽中的提示位置，但必须保留全部用户输入及其槽位。
- 若新提示候选与用户已填写位置冲突，用户字母优先；系统改选兼容空槽。
- 没有更多兼容提示时禁用按钮，并显示“当前答案已无更多可用提示”。
- 提示字母与用户字母必须通过颜色之外的第二种方式区分，例如提示字母顶部小点、提示标签或不同字重。
- 切换到下一题后才清空输入，并为新题生成新的稳定提示。

## 8. 提交与反馈状态

### 8.1 未完成提交

- 用户点击“检查答案”或按 Enter 时，如果仍有空字母槽，不判定错误。
- 显示“还差 N 个字母”，将编辑位置移到第一个未填写槽。
- 保留全部用户输入和系统提示。
- 未完成状态使用中性提醒，不使用错误红色或抖动。

### 8.2 完整但错误

- 保留用户输入、提示字母和当前题目。
- 不自动跳题，不清空答案，不用正确答案覆盖用户输入。
- 文案使用“再检查一下拼写，你可以直接修改后重试”，避免打击性表达。
- 整组槽位显示错误边界、错误图标和文字反馈；不得只依赖红色。
- 除非产品另行提供逐字母判定能力，不在本设计中擅自标出具体哪一位错误，也不提前泄露正确字母。
- 用户定位、退格或输入后进入“修改中”，可再次提交。

### 8.3 正确

- 显示明确成功图标、文字和非颜色反馈。
- 保持完整答案可见。
- 主按钮从“检查答案”切换为“下一题”。
- 第一次 Enter 提交答案；正确状态下再次 Enter 才进入下一题。
- 下一题清空上一题用户输入、反馈和编辑位置，并生成新题稳定提示。
- 答后可展示同义词、常见搭配和场景扩展。

### 8.4 主动结束本题

“查看答案”是 PRD v1.2 已批准的 P0 次要操作。它主动结束当前独立作答，不是额外提示，也不是“检查答案”的失败兜底。

#### 8.4.1 可用状态矩阵

| 当前状态 | “查看答案” | 确认后的可见结果 | 结果语义 |
|---|---|---|---|
| 未作答 | 可用 | 原槽直接显示完整标准答案并只读 | `revealed` |
| 部分作答 | 可用 | 保存部分输入快照，原槽显示标准答案 | `revealed` |
| 提交未完成 | 可用 | 保留“不判错”，保存输入快照后揭晓 | `revealed` |
| 完整但答错 | 可用 | 保存错误答案与提交结果，原槽显示标准答案 | `revealed` |
| 揭晓前独立答对 | 不显示或不可触发 | 保持正确答案与“下一题” | `independent-correct` |
| 已查看 | 不再显示 | 保持同一只读结果 | `revealed` |
| 查看后重试答对 | 不再显示 | 显示辅助练习答对与下一步 | `correct-after-reveal` |

- 不要求先答错、等待倒计时或耗尽提示；连续答错、双击、长按和全局 Enter 均不得隐式触发。
- 纯背单词模式不显示“查看答案”。
- 同一题已揭晓后重复点击、重复确认或恢复页面必须幂等，只保留一次揭晓与结算语义。

#### 8.4.2 操作层级与首次确认

- 默认作答时，“检查答案”继续是品牌紫主按钮；“再提示一些”“换一组字母”为普通次级按钮；“查看答案”位于次级操作之后，使用安静的文字按钮或低强调描边按钮。
- “查看答案”虽低强调，但文字必须直接可见，不能只藏在省略号、长按、Tooltip 或手势中；触控目标至少 44×44px。
- 首次触发打开确认层，不立即揭晓。推荐文案：
  - 标题：`查看正确答案？`
  - 说明：`查看后，本题不会计为独立答对，也不会提高正确率或熟练度。`
  - 继续作答：`继续作答`
  - 确认揭晓：`查看答案`
- 默认焦点放在较安全的“继续作答”；确认按钮不得默认获得焦点，也不得用“确定”等含糊文案。
- 点击“继续作答”、按 `Esc`、关闭确认层、切换模式或离开本题均视为取消：不揭晓、不写查看记录、不推进题量、不改变连续答对、输入、提示、错误反馈或复习记录。
- 取消后焦点返回原“查看答案”触发器；若用户离开页面则按正常导航处理，不强制抢回焦点。
- 对话框使用明确标题、说明和 `dialog` / `alertdialog` 等价语义，正确管理焦点；不得让读屏焦点落到背景作答控件。

#### 8.4.3 确认揭晓与原槽只读状态

- 明确确认后，用本题标准目标词完整替换现有句中行内槽的可见内容。不得新增句下答案框、答案卡、侧栏或跳转页面。
- 其他可接受同义词仍只放在答后扩展；揭晓不改变当前槽位长度，也不改用另一候选词。
- 揭晓前的空白、部分输入、未完成或错误输入作为结果快照保存，但不得与标准答案在槽内叠加、划掉或逐位对照，避免视觉噪声与答案混乱。
- 槽组进入真正只读状态：不接受输入、粘贴、退格、方向键编辑或点击定位；不显示文本光标和当前编辑槽。
- 只读槽使用品牌紫或中性信息色边界、眼睛／锁定图标和文字徽标 `正确答案 · 已查看`。不得复用独立答对的纯成功绿色与庆祝动效。
- 揭晓状态必须同时依靠文字、图标和形态表达，不能只把字母变色。
- 分隔符、大小写和字母逐字符显示继续遵守目标词结构；1～2 字母短词也必须完整显示。

#### 8.4.4 揭晓后的反馈与操作

- 揭晓后结果摘要紧邻句子，推荐主文案：`已查看答案。本题不计为独立答对，也不会提高正确率或熟练度。`
- 可补一行短说明：`进入下一题后，本题记为已复习 / 未独立答对。`
- 主按钮立即变为 `下一题`；次按钮为 `重新作答本题`。
- “提示”和“检查答案”在揭晓后不可用：应从操作区移除或保持明确禁用并说明原因，不得仍可聚焦或响应快捷键。
- 不显示积分、烟花、连对增长、熟练度上涨或“回答正确”庆祝；揭晓会中断连续答对，但不需要用惩罚性红色或打击性语言。
- 仅确认揭晓不推进今日题量；用户选择“下一题”后才结算并进入新题。

#### 8.4.5 重新作答本题

- 选择“重新作答本题”后，清空可编辑字母，恢复本题最初的稳定提示集合；不得重新随机提示、增加提示或降低难度。
- 槽组恢复可编辑，提示和检查答案重新可用；焦点回到第一个未填写、非提示槽。
- 页面保留一个安静的上下文标签 `已查看答案后的辅助练习`，防止用户误以为独立作答资格已恢复。
- 查看后重试答错，继续允许原位修改；查看后重试答对显示：`辅助练习答对了。本题仍不计为独立答对或正确率分子。`
- `correct-after-reveal` 可以使用成功图标表达练习完成，但必须同时保留“查看后答对／不计独立答对”文字，不得替换为普通 `independent-correct` 状态。
- 查看后重试不提高熟练度、不回填正确率分子、不恢复连对；“下一题”仍是结算和推进动作。

#### 8.4.6 计分、进度与复习语义的界面表达

- 默认作答界面不堆叠完整统计规则；确认层只说明最重要后果，揭晓结果再说明“已复习 / 未独立答对”。
- 任何题目结果徽标至少区分：`独立答对`、`已查看答案`、`查看后答对`。三者不可只使用深浅不同的绿色。
- 正确率分子只计 `independent-correct`。`revealed` 在用户进入下一题后计入分母但不计分子；`correct-after-reveal` 不回填分子。
- 查看答案与查看后答对均不增加单词熟练度、不延长复习间隔；该词的后续复习不晚于答错基线。
- 单独确认查看答案不新增连续学习天数；若整个学习会话满足既有完成条件，仍可计学习日，但本题不产生答对收益。
- 这些统计变化只在已有进度／结果位置提供短反馈，不新增复杂统计卡、积分条或惩罚提示。

#### 8.4.7 刷新、离题与幂等边界

- 确认前刷新、切换模式、离开题目或取消确认：恢复原作答状态，不产生查看记录。
- 确认后刷新、离开再返回或切换模式后返回：保持 `revealed` 或 `correct-after-reveal`，不得回退为未查看、重新获得独立答对资格或生成新提示。
- 同一题重复触发只更新一次状态播报，不重复推进进度、写入多次揭晓或改变统计。
- 进入下一题时，重置上一题输入、查看状态、确认层、反馈和焦点，并为新题建立自己的稳定提示。
- 本期不做查看答案历史页、跨设备同步、答案收藏、自动揭晓或复习算法重构。

## 9. 同义词兼容

- 正确性以可接受答案集合判定，不只绑定一个字符串。
- 只有字母数量、固定分隔符和当前提示字母均与本题槽位兼容的候选，才能在当前槽组判为正确。
- 不兼容同义词不得作为可输入候选，也不能造成“语义正确但槽位永远无法容纳”的死路。
- 不兼容同义词只在答后扩展中展示。
- UI 不在作答前泄露完整可接受答案列表。
- 如果输入语义可接受但与当前槽位不兼容，产品层应避免把它作为本题可接受答案；UI 不自行发明额外判定规则。

## 10. 视觉规范

延续现有设计系统：

- 页面暖米色：#EAD3AB
- 主卡片：#FFFDF8
- 句子区浅暖色：#F8EDDB
- 青绿色背景：#20D4C4
- 品牌紫：#4C0C91
- 深紫文字：#25075F
- 主文字：#17131B
- 次文字：#776C69
- 成功色：#15836F
- 错误色：#B54C59
- 深色模式强调文字：#DDB4FF

### 10.1 字母槽

- 字体：ui-monospace、SFMono-Regular、Menlo、Monaco、Consolas、等宽回退。
- 桌面字母：24–28px；移动端：20–24px。
- 单槽视觉宽度：最小 0.72em；可点击槽的实际命中区域不小于 32px 宽。
- 整组输入命中高度至少 44px。
- 空槽底线：2px，rgba(119,108,105,0.42)。
- 用户字母：#17131B，字重 750。
- 系统提示：#4C0C91，字重 850，并增加非颜色标识。
- 当前编辑槽：3px 品牌紫底线或 2px 焦点框，附稳定光标。
- 整组聚焦：0 0 0 4px rgba(99,33,164,0.12)。
- 正确：#15836F + 对勾图标 + 文字。
- 错误：#B54C59 + 警示图标 + 文字。
- 分隔符无底线，使用正文颜色显示。

### 10.2 布局与动效

- 字母槽必须看起来属于句子，不得落回句子下方形成第二输入区。
- 长单词允许随句子自然换行；不要在整页产生水平滚动。
- 仅当一个连续单词组在当前行完全无法容纳时，整组换行，不将字母槽拆成难以理解的无序片段。
- 状态切换 160–180ms，使用轻微颜色、边界或透明度过渡。
- 错误反馈最多一次轻微位移，不连续抖动。
- prefers-reduced-motion 下取消呼吸、抖动和非必要过渡。

### 10.3 “查看答案”状态

- 默认“查看答案”使用低强调文字按钮或 1px 品牌紫描边，不与主按钮争夺视觉重量；hover、active、focus-visible 和 disabled 状态必须完整。
- 确认层沿用白色内容面板、12–16px 圆角、轻阴影和清晰分区；不使用危险红色大面积警告，因为查看答案不是破坏性系统操作，但必须用琥珀信息图标提醒学习后果。
- 桌面确认框建议宽 360–440px；移动端宽度为视口减 32px或使用安全区底部确认层。标题、说明与按钮间距分别不少于 12px、20px。
- `revealed` 槽组使用品牌紫／深紫 + 眼睛或锁定图标 + `正确答案 · 已查看`；不得与普通正确状态完全同形同色。
- `correct-after-reveal` 使用成功图标 + `辅助练习答对` + `不计独立答对`，不使用彩纸、积分增长或连胜动效。
- 揭晓转场仅允许 160–180ms 的边界／透明度变化；不得逐字翻牌、模糊后显现或制造答案竞猜动效。减少动态效果时直接切换。

## 11. 移动端软键盘

- 点击句中槽组或可编辑槽必须调起英文文本键盘。
- 关闭自动更正、自动大写和拼写替换，避免系统静默改写答案。
- Enter 键语义为“检查”；正确后变为“下一题”。
- 软键盘出现后，当前句子、编辑槽、状态反馈和主按钮必须仍可见或可通过最小滚动到达。
- 焦点变化时将当前槽滚动到安全可视区域，但不要让页面反复跳动。
- 主按钮可在键盘上方保持可达，但不得遮挡句子、反馈或提示按钮。
- 软键盘打开时，“查看答案”仍须通过最小滚动到达；不能因为键盘存在而只剩手势或溢出菜单入口。
- 首次触发确认层时，不得清空输入或写入查看记录。确认层必须位于可视区域，按钮不被键盘或系统安全区遮挡。
- 用户明确确认后收起软键盘，移除输入光标，将句中完整答案、结果摘要、“下一题”和“重新作答本题”滚动到同一可操作上下文。
- 用户取消确认后，恢复原作答上下文；若键盘因焦点切换收起，可将焦点返回答案槽并允许用户继续输入，但不得强制页面跳动。
- iOS Safari 与 Android Chrome 均需覆盖。

## 12. 响应式

### 12.1 手机：320–767px

- 单列卡片，左右安全边距至少 16px。
- 句子字号 21–24px，槽位随文本自然换行。
- 页面级不得出现横向滚动。
- 模式切换、槽组和主按钮触控目标至少 44px 高。
- 提示操作位于主按钮后，避免与键盘操作竞争。
- “查看答案”位于提示操作之后并单独占可触控行；揭晓后操作区只保留全宽“下一题”和低强调“重新作答本题”。
- 确认层按钮在 320px 下纵向排列，默认先显示“继续作答”，再显示“查看答案”；不得出现文字截断。
- 320px 宽度、最长目标词和带分隔符答案必须单独出状态稿。

### 12.2 平板：768–1200px

- 主卡片居中，句子与槽组仍在同一阅读块。
- 主按钮可与反馈同区布局，但不与答案槽争夺横向空间。
- 横竖屏都不得恢复独立答案框。
- 查看答案确认层保持在当前卡片上下文；揭晓结果、下一题与重新作答不得因横竖屏切换丢失。

### 12.3 桌面：大于 1200px

- 主卡片建议最大宽度 720px。
- 字母槽直接嵌入句子，桌面键盘路径是主要交互。
- 目标词相关 Examples 侧栏在填空状态继续隐藏。
- “查看答案”保持为次级操作；确认层打开时背景不可操作，关闭后焦点必须回到触发器或结果摘要。

## 13. 无障碍

### 13.1 名称与描述

- 整组答案使用一个 textbox 语义。
- 可访问名称示例：“补全句子中的英文单词”。
- 描述包含：
  - 完整句子上下文
  - 可编辑英文字母总数
  - 已输入数量
  - 剩余数量
  - 系统提示的位置与字母
  - 固定分隔符结构
  - 当前正确、错误、未完成或修改中状态

- 揭晓前，标准答案不得出现在可访问名称、隐藏描述、状态消息、按钮名称、可复制隐藏文本或仅视觉隐藏的 DOM 内容中。
- 确认层只说明后果，不提前读出答案。
- 揭晓后，槽组改为只读答案输出语义；可访问名称至少表达 `正确答案，已查看`，并按字符正确读出字母、空格、连字符和撇号。
- 查看后重试时描述必须包含 `已查看答案后的辅助练习`，避免辅助技术用户误解为重新获得独立答对资格。

### 13.2 键盘

- Tab：一次进入整组答案。
- 左右方向键：在可编辑槽间移动。
- 字母键：输入或替换。
- Backspace：删除当前或前一个可编辑用户字母。
- Command/Ctrl + V：粘贴完整答案或剩余字母。
- Enter：检查答案；正确状态下再次 Enter 进入下一题。
- Tab 顺序：返回 → 模式切换 → 答案槽组 → 主按钮 → 提示操作 → 查看答案。
- “查看答案”使用 Enter 或空格触发；不得绑定全局 Enter、双击或长按。
- 确认层打开后焦点留在层内，初始落在“继续作答”；Esc 取消。只有焦点明确位于“查看答案”确认按钮时，Enter / 空格才揭晓。
- 取消后焦点返回“查看答案”；确认后焦点移至结果摘要，随后顺序到“下一题”和“重新作答本题”。
- 揭晓后的只读槽不再接受编辑快捷键；重新作答后焦点回到首个可编辑槽。

### 13.3 状态播报

- 使用礼貌 live region 播报提示变化、剩余字母数、过滤字符、错误、正确和切题结果。
- 不逐键播报整句，避免读屏噪声；按必要节奏播报“已输入 N 个，还差 M 个”。
- 提示位置使用从 1 开始的自然语言，例如“第 4 位提示 L”。
- 正确、错误、提示和当前焦点均需图标、形态或文字辅助，不能只靠颜色。
- 打开确认层时播报“查看答案确认；查看后不计独立答对”；取消时简短播报“已取消，答案未查看”。
- 揭晓后一次性播报“正确答案、已查看”、逐字符答案、结果语义和下一步；不得在用户确认前把完整答案写入 live region。
- 查看后重试答对时播报“辅助练习答对，不计独立答对、正确率分子或熟练度收益”。
- 重复触发已揭晓状态只播报一次现有状态，不重复播报结算或制造多条 Toast。
- 焦点对比度、正文对比度和状态边界满足 WCAG 2.2 AA。

### 13.4 答案防泄露

- 揭晓前不得在页面可见文案、Tooltip、title、aria-label、aria-description、live region、复制内容、隐藏答案框、图片 alt、data 属性或浏览器自动填充建议中暴露完整标准答案。
- 填空模式继续隐藏包含目标词的 Examples 侧栏；“查看答案”确认层也不显示目标词预览。
- 长按、hover、聚焦、复制句子或读屏浏览只能获得题目上下文、槽位长度、提示位置和用户已输入内容，不能获得未确认的标准答案。
- 防泄露是交互暴露边界，不是安全加密承诺；不得在 UI 文案中宣称客户端答案绝对不可获取。

## 15. 非目标与禁止事项

- 不改变已批准 PRD v1.2 的产品逻辑、20 条 `AC-RA` 或 v1.1 继续有效的行内槽规则。
- 不改变随机提示算法的业务规则，只定义其可见与可交互行为。
- 不改背单词、聊天、首页、个人中心或全局信息架构。
- 不新增排行榜、积分、徽章、复杂动效或游戏化装饰。
- 不做倒计时自动揭晓、连续答错自动揭晓、看答案奖励、查看后恢复独立答对资格、答案历史页、跨设备同步或复习算法重构。
- 不把“查看答案”设计成额外提示、长按手势、句下答案框、答案卡、侧栏或独立页面。
- 不在确认前通过可见或辅助技术内容泄露标准答案。
- 不指定前端框架或实现库。
- 不输出实现代码。
- 不先生成设计稿、原型或图片。
- 不修改用户提供的 `ui/` 权威视觉母版。
- 不允许固定 06 在提示词及必要 UI 状态未完成后续审核和重新授权前恢复实现。

## 17. 提示词验收标准

- [ ] 句中槽位是唯一答案入口，句子下方没有独立输入框。
- [ ] 系统提示和用户输入稳定合并，不移动、不删除、不覆盖。
- [ ] 支持连续输入、点击定位、方向键、退格和替换。
- [ ] 支持粘贴完整答案与剩余字母，并正确跨过提示和分隔符。
- [ ] 未完成提交提示剩余数量且不判错。
- [ ] 错误后保留答案，允许原位修改重交。
- [ ] 正确后明确切换为下一题操作。
- [ ] 1 字母、2 字母、连字符、撇号和空格答案有明确状态。
- [ ] 可接受同义词必须与当前槽位兼容，不兼容同义词只在答后展示。
- [ ] 移动软键盘不会遮挡当前作答、反馈和主操作。
- [ ] 键盘可独立完成聚焦、输入、定位、退格、粘贴、提交和下一题。
- [ ] 整组槽位作为一个有名称的答案输入被辅助技术识别。
- [ ] 状态表达不只依赖颜色，并满足 WCAG 2.2 AA。
- [ ] 浅色、深色、320px、390px、平板和桌面规则完整。
- [ ] 保持用户提供 `ui/` 视觉母版和受影响前端冻结事实。
- [ ] 未生成任何设计稿、原型、图片或实现代码。

### 17.1 “查看答案”v1.2 专项验收

- [ ] 未答、部分作答、提交未完成和答错状态均可主动查看答案，无需先答错或等待。
- [ ] 揭晓前独立答对时不再显示或触发“查看答案”，结果保持 `independent-correct`。
- [ ] “查看答案”低强调但可发现，不藏在手势、Tooltip 或溢出菜单中。
- [ ] 首次触发只打开确认层，明确说明不计独立答对、正确率分子或熟练度收益。
- [ ] “继续作答”为默认焦点；取消、Esc、关闭、切换模式或离题均不揭晓、不写记录、不改变原状态。
- [ ] 只有焦点明确位于确认按钮时 Enter／空格才揭晓；全局 Enter、双击和长按不会触发。
- [ ] 确认后只在现有句中行内字母槽显示完整标准答案，不新增句下答案框、答案卡或页面跳转。
- [ ] 揭晓前输入快照被保留用于结果记录，但不与正确答案在槽内混排。
- [ ] 揭晓后的槽组真正只读，不接受输入、粘贴、退格、定位或编辑快捷键。
- [ ] `正确答案 · 已查看`使用文字、图标和形态表达，不复用独立答对的纯成功状态。
- [ ] 揭晓后提示和检查答案不可用，主操作为“下一题”，次操作为“重新作答本题”。
- [ ] 揭晓结果明确说明“已复习 / 未独立答对”，不显示积分、连对增长或熟练度上涨。
- [ ] 重新作答恢复本题最初稳定提示，不重随机、不恢复独立答对资格。
- [ ] 查看后重试答对显示 `correct-after-reveal` 与辅助练习反馈，不计正确率分子或熟练度收益。
- [ ] 同一题重复触发、重复确认、刷新或离开再返回保持幂等，不重复结算或回退为未查看。
- [ ] 进入下一题才推进今日题量，并重置上一题查看状态、确认层、输入和焦点。
- [ ] 移动端确认后软键盘收起，正确答案、结果、下一题和重新作答仍在当前任务流内可访问。
- [ ] 键盘焦点顺序、确认层焦点管理、Esc 取消、结果焦点和返回焦点均已定义。
- [ ] 屏幕阅读器可获知确认后果、完整答案、已查看状态和下一步；所有状态均非颜色唯一表达。
- [ ] 揭晓前的可见、隐藏、复制和辅助技术内容均不泄露完整答案；短词与固定分隔符揭晓正确。
