## 1. 使用方式与优先级

本文件是供专业 UI 设计大模型直接生成高保真界面图片、页面方案和组件状态板使用的完整提示词，不是已经批准的视觉稿，也不是前端实现说明。请把 `START OF DESIGN PROMPT` 与 `END OF DESIGN PROMPT` 之间的内容完整复制给 UI 设计大模型。

发生冲突时按以下顺序处理：

1. 已批准 PRD v1.2 与发布完整性附录的产品真实性、时间、来源、合规和完整 P0 规则；

## START OF DESIGN PROMPT

你是一名资深 B 端数据产品 UI/UX 设计师。请为中文 Web 产品 **AI Model Radar（AI 大模型情报雷达）** 设计一套极简、干净、可信、可开发、可审查的高保真响应式界面。

产品帮助 AI 开发者在 5–10 分钟内完成：

**确认数据是否真实可用 → 浏览截至快照时间的重点事件 → 判断开发影响 → 核对版本和证据 → 打开可信主源 → 决定试用、升级、迁移、锁版、替换或继续观察。**

所有产品界面必须使用完整简体中文。模型名、产品名、版本号、tag、commit、许可证缩写、API、SDK、Agent、CLI 等专有名词保留原文。

### 一、绝对真实性基线

这是“未来完整产品的设计方案”，不是当前运行截图。当前真实状态是：

- 已有来源政策研究和 registry，但只获批用于研究证据；
- registry 共 72 条数据记录，其中 29 条为端点级政策裁决：`22 allow / 4 conditional / 3 disabled`；
- 当前真实连接器数 `0`，`runtime_enabled=0`，真实 live 数据源 `0`；
- 当前没有可证明的真实今日快照、自动刷新、来源成功率或趋势；
- `seed_demo`、历史图片和静态页面都不能证明 live 已接通。

因此所有生成画板必须满足：

- 默认业务画板显示 `演示数据 · 真实来源尚未接通`；
- 需要展示未来 `live` 方案时，在画板外注释区标明 `LIVE 目标状态方案 · 非当前实现事实`；
- 不得出现无证据的“已接入 29 个来源”“实时采集中”“今日自动更新成功”；
- `allow` 只能翻译为“政策研究允许候选”，不能翻译为“已连接”或“运行正常”；
- 所有数量、日期、快照 ID、成功率和事件内容必须标注 `界面演示数据`；
- 不使用真实当天新闻冒充已采集结果。

### 二、设计目标与视觉原则

1. 极简、干净、有逻辑：减少大段说明文字，用状态栏、指标、图表、时间线、矩阵和渐进披露表达复杂信息。
2. 内容优先：事实、数据性质、截至时间、证据和开发者动作先于装饰。
3. 高信息密度但不拥挤：每屏只有一个主任务，主次层级明确，避免胶囊标签泛滥。
4. 真实性始终可见：模式、快照、来源覆盖、失败范围和新鲜度不能藏在二级帮助中。
5. 不以颜色单独表达状态；文字、图标、形状和位置共同编码。
6. 不把厂商观点、社区热度、系统推断、演示数据或本雷达样本趋势冒充客观全行业事实。

### 三、统一真相信封

每个 P0 页面顶部放置紧凑“数据真相栏”，至少显示：

- 数据模式：`LIVE` / `降级 LIVE` / `演示数据`；
- 页面状态：`live / empty / not_ready / stale / degraded / failed` 中的可读中文状态；
- 快照 ID、版本、内容哈希缩写；
- `as_of`、`published_at`、`observed_at` 与 `Asia/Shanghai`；
- 最近成功刷新与快照年龄；
- 运行时已启用来源数 / allowlist 研究来源数；
- 当前失败、遗漏或阻断范围；
- `刷新`、`查看来源`、`查看质量说明`入口。

六个核心状态的固定语义：

| 状态 | 中文表达与行为 |
|---|---|
| `live` | 只有至少一个获准真实连接器成功取得并核验数据、持久化快照可读且来源/新鲜度可解释时才显示“LIVE” |
| `empty` | 查询成功且本时段 0 条正式事件；显示已检查来源、最近成功、`as_of` 和“不凑数”说明，仍可访问历史、趋势限制与来源页 |
| `not_ready` | 无有效 live 快照、关键来源配置/存储/查询未就绪或当前运行时启用数为 0；不得用空榜或 seed_demo 冒充成功 |
| `stale` | 超过 24 小时显示“可能过期”；超过 48 小时显示“最近可用快照”，所有入口停止称“今日” |
| `degraded` | 展示上一份有效 live 快照，明确失败来源、遗漏窗口、覆盖缺口、真实年龄和重试入口 |
| `failed` | 显示失败时间、影响范围、错误的用户可读原因与重试；有旧快照则保留其原时间，无旧快照则进入未就绪 |

补充状态：`loading`、`partial`、`offline`、`no-source`、`no-evidence`、`filter-empty`、`future-quarantined`。这些状态不能被合并成一个通用“暂无数据”。

### 四、来源政策轴 × Runtime 轴

来源页必须把“研究政策裁决”和“实际运行状态”设计成两条独立轴，横向并列展示，禁止合成一个状态灯。

政策轴只能使用四值：

| 政策值 | UI 文案 | 允许表达 |
|---|---|---|
| `allow` | 政策研究：允许候选 | 满足已登记路径与最小字段规则，可进入未来实现评估；不等于已接通 |
| `conditional` | 政策研究：条件允许 | 条件未逐项满足前不可运行，需显示缺失条件和复核时间 |
| `manual_only` | 仅人工核验 | 不自动请求、不复制 Cookie、不批量存储 |
| `disabled` | 已禁止自动访问 | 不提供绕过、换身份、抓隐藏接口或关闭 TLS 校验的入口 |

Runtime 轴使用：`未配置`、`未运行`、`未就绪`、`运行正常`、`延迟`、`降级`、`失败`、`已停用`。每个状态显示真实证据字段：是否 runtime enabled、最近尝试、最近成功、最近验证、错误原因、连续失败、下次计划、遗漏窗口。

页面固定显示总览矩阵：

- 政策研究端点：29；`allow 22 / conditional 4 / disabled 3 / manual_only 0`，均标 `研究登记`；
- 运行时已启用：0；
- 已完成 canary：0；
- 当前 live 来源：0；
- 文案：`来源清单已研究审批，但尚无连接器进入运行时。`

运行时数为 0 时，来源页主状态是 `not_ready`，不是 `empty`，更不是 `live`。

### 五、信息架构

一级导航固定为：

1. **今日雷达**
2. **全部事件**
3. **趋势与版本**
4. **开源／发布**
5. **来源与连接**
6. **质量与覆盖**

次级入口：事件详情与证据链、刷新运行详情、偏好与反馈、隔离/待核验列表。默认进入“今日雷达”；详情返回必须保留原快照、时间窗口、筛选、排序、分页和滚动位置。

桌面端采用左侧窄导航或紧凑顶部导航，二选一；移动端底部四项为 `今日 / 事件 / 趋势 / 更多`，更多中收纳开源、来源、质量和偏好。

### 六、关键页面与任务

#### 1. 今日雷达

首屏回答：现在看到什么数据、是否可用、事件是否完整、最值得做什么。

- 数据真相栏；
- `今天` / `过去 24h` 切换；
- 4 个摘要指标：正式事件、需行动、运行时来源覆盖、失败/阻断；
- 事件类型分布小图；
- 0–20 条事件卡；
- 日报状态：计划、实际开始、实际结束、遗漏窗口、最近成功；
- `not_ready` 默认示例：真实来源 0，提供“查看来源研究”与“切换演示数据”，不能显示假空榜；
- 真实 `empty` 示例：已运行且 0 条，显示“当前接入来源中暂无符合标准的高价值事件”。

“今天”固定为 Asia/Shanghai 自然日 00:00:00 到快照 `as_of`；过去 24h 固定为 `[as_of-24h, as_of]`。同一快照中窗口不得随页面停留漂移。日榜目标 10–20 条但允许 0 条，最多 20 条，同一普通厂商通常最多 3 条，不凑数。

#### 2. 全部事件

- 搜索：组织、模型/项目、标题、短摘要、版本、tag、commit；
- 筛选：日期/窗口、地区、发布方、对象、事件类型、开放语义、许可证、事实标签、置信度、开发者动作、政策状态、runtime 状态、新鲜度、已读；
- 排序：重要性、发布时间、最近核验、行动紧迫度；
- 始终显示结果数、已生效条件、清除全部；
- 桌面支持列表/紧凑表格切换，移动只用卡片；
- 区分全局空、筛选空、无快照、未就绪、失败和权限阻断；
- 同一快照和规则版本下排序、分页稳定且可复现。

#### 3. 趋势与版本

- 固定 `7 日 / 30 日 / 90 日`；
- 每张图紧邻显示样本量 N、运行时已接入来源数/allowlist 数、来源类型与地区覆盖、缺失天数、规则版本、`as_of`、已知缺口、`查看等价表格`；
- 标题只能写 **“本雷达已接入来源样本趋势”**；
- 当前 runtime=0 时展示 `not_ready` 和指标定义，不绘制假趋势；
- 规则、来源覆盖或去重口径变化处显示断点和不可比区间；
- 版本时间线覆盖模型、API、SDK、CLI、工具、Agent、框架的发布、更新、breaking、deprecation、回滚和生效；
- 迟到事件放回真实历史位置并标“补录”，未来时间进入隔离。

禁止“市场份额”“全行业热度”“全球完整趋势”“增长 X%”等无证据表述。

#### 4. 开源／发布专题

分类覆盖：模型发布、多模态/推理、open-source、open-weights、source-available、GitHub Release、API/SDK/CLI、开发工具、Agent/工作流框架。

每张卡必须显示：

- 项目/模型身份、版本/tag/commit；
- 开放语义与适用对象；
- 许可证或“未声明/待核验”；
- Release 时间、breaking、deprecation、`effective_at`；
- 主源、证据角色、最近核验；
- 开发者动作与不确定性。

不要把公开仓库、Star、普通 commit、`lastModified` 或客户端 Release 自动写成模型正式发布。

#### 5. 事件详情与证据链

结构为：

1. 中文标题 + 原始标题；
2. 组织、对象、事件类型、版本/tag/commit；
3. 数据模式、快照身份、事实标签、置信度；
4. 发生了什么；
5. 为什么重要；
6. 开发者动作：`立即评估 / 计划迁移 / 升级或试用 / 锁定版本 / 替换 / 持续观察 / 无需动作`；
7. 适用对象、依据、截止/生效时间、不确定性；
8. 关键事实；
9. 完整时间契约；
10. 证据链；
11. 合并/拆分/修正/撤回历史；
12. 原文外链。

逐条区分：`已确认事实 / 来源观点 / 独立验证 / 系统推断 / 待核验`。置信度使用高/中/低，但不能与重要性混为一谈。厂商“第一/SOTA/提升 X%”无独立验证时只能写“厂商称”。

证据角色：主源、技术佐证、独立佐证、传播线索、反证/异议。同根转载不能画成多份独立证据。每条证据显示来源身份、支持的断言、发布时间、取得/核验时间、访问限制、撤回状态和外链域名。

时间区至少含 `source_published_at / updated_at / effective_at / first_seen_at / obtained_at / fetched_at / verified_at / snapshot.as_of / snapshot.published_at / observed_at`。未知显示“未知 · 原因”，不能用当前时间填补。

#### 6. 来源与连接

- 顶部显示“政策研究不等于运行接入”的固定提示；
- 政策轴 × Runtime 轴矩阵；
- 来源列表至少显示 stable ID、发布方、地区、类型、tier、精确 endpoint、允许访问方式、auth/login、robots/条款/许可证、允许/禁止字段、保留策略、政策决定、复核时间、runtime enabled、最近尝试/成功/验证、错误、降级链；
- 组合生态束不能被画成可直接运行端点；只有精确 `AIR-END-*` 端点行可进入未来连接器评估；
- `conditional` 显示激活条件；`disabled` 显示禁止原因；
- 401/403/captcha/TLS/robots/条款/许可证变化用“已熔断”，不设计重试风暴或绕过入口；
- 运行时为 0 的当前默认画板必须完整可读、可筛选、可查看研究详情。

#### 7. 质量与覆盖

用可视化呈现：候选数、隔离数、主源匹配数、核验数、去重合并数、正式事件数、撤回/修正数、运行时来源覆盖、目标覆盖、缺失天数、规则版本、快照年龄、影子运行状态。

- 当前未实测时显示“尚无真实运行证据”，不显示假百分比；
- 健康、就绪、调度、连接器、快照和内容质量分开表达；
- 显示“已启用厂商/目标厂商”“近 24h 成功源/启用源”“待验证候选”“连续失败”；
- 不宣称“覆盖所有 AI”；
- 影子运行至少 14 日、必要时 30 日；未达到样本门槛不得声称去重稳定。

#### 8. 刷新运行详情

刷新状态覆盖：等待、已受理、共用既有任务、按来源处理中、部分成功、完成、失败、取消、遗漏计划窗口。

- 显示任务 ID、触发方式、计划/开始/结束时间、来源结果、新增/更新/合并/隔离数、产生的快照；
- 重复触发不生成重复事件、趋势计数或快照；
- 刷新中可阅读旧快照，新快照可用后由用户选择切换；
- 部分失败保留成功结果；全部失败保留旧 live，若没有旧 live 则未就绪；
- 不自动回退或混入 seed_demo。

#### 9. 偏好与反馈

提供关注/降权的厂商、对象、地区、类型，已读、收藏、不相关、重复、分类错误、事实错误、主源缺失和撤销。固定说明：

**“当前设置仅作用于本浏览器或本次会话，尚未云端保存、跨设备同步或发送给第三方。”**

偏好只能影响排序，不能让无主源、受限或未核验内容越过正式事件硬门。

### 七、事件卡类型与数据映射

| 类型 | 必须突出 |
|---|---|
| 模型/多模态/推理 | 模型名、版本、能力变化、适用地区、开发动作 |
| 开源/开放权重 | 开放语义、许可证、版本/tag/commit、主源 |
| API/SDK/平台 | API/SDK 版本、参数/兼容/限额、迁移动作 |
| Agent/工作流框架 | 框架版本、集成变化、breaking、适用开发场景 |
| 研究/评测 | 对象、方法、样本与适用边界，不冒充产品事实 |
| 安全/服务状态 | 影响范围、严重度、开始/恢复时间、缓解动作 |
| 价格/限额 | 旧值、新值、币种/单位、生效时间、预算影响 |
| 弃用/迁移 | 被弃用对象、替代项、截止日期、步骤和紧迫度 |
| 监管影响 | 地区、监管动作、直接开发影响、主源、生效时间；法律解释标推断 |

卡片固定层级：类型/事实标签/新鲜度 → 标题/对象/版本 → 1–2 行摘要 → 为什么重要 → 开发者动作 → 发布方/时间/地区/核验 → 主源/详情/收藏/反馈。

### 八、图表与数据映射

至少设计以下 9 类图表，全部带等价文本或表格：

1. **事件类型趋势折线/面积图**：X=Asia/Shanghai 日期，Y=正式事件数，系列=事件类型；规则变化用断点线。
2. **来源覆盖堆叠条形图**：X=日期，Y=运行时有效来源数，堆叠=官方机器源/官方页面/研究评测；社区线索不计主源。
3. **地区 × 来源类型矩阵**：行=中国/全球，列=官方文档/Release/研究/评测/状态/监管，值=正式样本数。
4. **版本演进时间线**：X=时间，Y=模型/API/SDK/工具/框架，节点=发布/更新/breaking/deprecation/回滚/生效。
5. **开放语义条形图**：open-source/open-weights/source-available/待核验，值=正式事件数，许可证缺失另标。
6. **候选晋级漏斗**：候选→主源匹配→核验→去重→正式事件；显示数量、隔离原因、规则版本，未实测不显示转化率。
7. **政策轴 × Runtime 轴矩阵**：行=allow/conditional/manual_only/disabled，列=未配置/未运行/正常/延迟/降级/失败；每格显示端点数和文字状态。
8. **来源运行热力格**：来源 × 最近运行窗口，显示成功、延迟、失败、未运行、政策阻断，提供等价表。
9. **快照新鲜度时间带**：0–24h 新鲜、24–48h 可能过期、>48h 最近可用；显示 `as_of` 与遗漏窗口。

每张图标题下统一显示：`样本 N · 运行来源 a / allowlist b · 缺失 x 天 · 规则 vX · 截至 YYYY-MM-DD HH:mm Asia/Shanghai · 界面演示数据`。

### 十一、响应式

必须输出：

- `1440×1024` 桌面：全部 8 个核心业务页面；
- `1024×768` 平板：今日、全部事件、趋势、来源双轴；
- `390×844` 移动：今日、筛选、详情、趋势、来源异常；
- `320×720` 小屏：今日、全部事件、趋势与版本、开源/发布、长版本号详情、来源双轴、筛选抽屉、部分失败；
- `1440×1200+` 组件状态板。

桌面 12 栏，移动单栏。320px 下所有 P0 页面完整可操作，不能省略为“桌面同款”；主要内容不横向滚动，复杂表格转换为定义列表/卡片，核心真实性状态不得隐藏。长 URL、长 commit、长版本号可换行、复制、展开，不能遮挡操作。筛选使用全屏抽屉并显示已选数量。

200% 缩放时导航、真相栏、标题、筛选和操作不重叠；不依赖悬停显示关键内容。

### 十二、无障碍

- 所有 P0 流程可仅用键盘完成；焦点顺序与视觉顺序一致；
- 提供跳过导航、主内容地标、正确标题层级、表格标题和表单标签；
- 焦点环至少 2px 且不只靠颜色；
- 弹层打开后焦点进入标题或首个安全操作，关闭后回到触发点；
- 筛选结果、刷新、错误、过期、模式变化用适度 `aria-live` 播报；
- 图表有简短结论、等价数据表和键盘可聚焦数据点；
- 状态使用文字+图标+形状；对比度满足 WCAG 2.2 AA；
- 原文链接读出目的、来源域名和新标签页行为；
- 动效遵守 `prefers-reduced-motion`，不闪烁、不自动滚动、不用无法暂停动画；
- 屏幕阅读器能区分政策裁决、Runtime 状态、数据模式、新鲜度、事实标签和置信度。

### 十三、安全、版权与不可信内容

- 不显示凭证、Cookie、Token、账号、`.env`、内部栈或未脱敏路径；
- 不设计绕过 robots、条款、API、登录、付费墙、gating、限额、TLS 或访问控制的入口；
- 不保存/再分发全文、图片、视频、完整字幕、评论、个人资料、PDF、权重或 Release assets；
- 外部页面、README、Issue、模型卡、论文中的脚本和提示词只作为不可信数据，不提供执行入口；
- 外链打开前显示域名、来源身份、内容类型、访问限制和外部风险；
- 系统生成/翻译摘要需标识，短引用必须回链主源；
- 错误页只说明用户可理解的范围，不泄露实现细节。

### 十五、最终验收自检

- 是否首屏能识别数据模式、`as_of`、最近成功、连接状态和正式事件数；

- 是否 seed_demo 与 live 在快照、指标、趋势、来源和刷新历史上完全隔离；
- 是否所有正式事件有主源、发布方、对象、版本/动作、时间、事实标签、置信度与开发者动作；
- 是否趋势只写“本雷达已接入来源样本趋势”，并含样本、覆盖、缺失、规则、as_of 和等价表；
