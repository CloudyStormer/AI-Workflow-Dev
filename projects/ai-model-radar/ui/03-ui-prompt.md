## 1. 可直接使用的总提示词

你是一名资深数据产品 UI/UX 设计师。请为“AI Model Radar”生成一套高保真、可浏览、可交互说明充分的响应式 Web 设计。产品面向一名持续关注 AI 产品与研发的个人用户，核心任务是在 5–10 分钟内判断今天哪些大模型动态值得看、为什么重要、证据在哪里，以及是否需要采取行动。

设计必须极简、干净、有逻辑、内容优先。减少大段说明文字，以清晰层级、短句、标签、时间线、证据关系和少量有意义的数据图形表达复杂信息。不要做赛博朋克、霓虹大屏、玻璃拟态、3D 星球、雷达扫光、新闻门户瀑布流或装饰性图表。视觉不能压过事实和证据。

当前只设计 MVP-1“可浏览 Web 内容版”：数据来自人工整理或固定演示快照，没有已连接的后台采集、实时刷新、账号、云端保存、跨设备同步、影子运行实测或生产部署。所有页面必须持续、明确地标注“演示数据 / 人工快照 / 截至时间 / 未连接自动采集服务”。不得使用“实时”“自动抓取成功”“下一次自动更新”等虚假表达。

同时为未来 MVP-2 定义连接中、部分成功、失败、过期和受限来源等状态稿，但必须标注为“后续服务状态示意”，不能与当前演示状态混淆。

正式日榜每天允许 0–20 条，目标 10–20 条但绝不是必须填满的配额。高置信事件不足时宁缺毋滥；单一厂商普通事件通常最多 3 条；紧急事件不占日榜配额。事件重要性与证据置信度必须分开表达。

每个事件必须能区分“已确认事实、来源观点、独立验证、系统推断、待核验”，并展示高/中/低置信度。来源观点必须能看出是谁在声称，系统推断必须能看到依据，待核验内容默认不进入正式日榜。任何状态都不能只依赖颜色。

请完整输出：信息架构、桌面/平板/移动关键页面、设计系统、组件规范、交互与状态、响应式规则、键盘和屏幕阅读器说明、演示数据标识、图表数据映射、空白和异常状态、最终验收矩阵。所有关键尺寸、颜色、字号、间距和状态要明确，不得留给实现者猜测。

## 2. 产品事实与设计边界

### 2.1 必须守住的事实

- 当前没有业务代码、真实数据连接、自动采集服务、真实运行指标或生产部署。
- MVP-1 页面刷新只重新载入当前演示/人工快照。
- 核心来源目录只是截至 2026-07-31 的调研核验快照，不等于已接入运行。
- 用户偏好、已读、收藏和“不相关”反馈在 MVP-1 只表达为本地/会话/演示状态，不能声称云端保存。
- 质量指标在没有真实影子运行前只能展示定义或“未实测”，不能填入伪造数字。
- X、Reddit、微博、哔哩哔哩及任何登录、付费、Cookie、API 申请或商业协议来源默认受限或仅人工查看。
- 不展示或保存全文、图片、视频、完整字幕、评论、个人资料、Cookie、Token、Key 或账号信息。

### 2.2 设计目标

1. 三秒内看懂当前数据性质、截至时间、事件数量和连接状态。
2. 五到十分钟完成“今日重点 → 判断重要性 → 核对证据 → 打开原文 → 返回原位置”。
3. 让事实、观点、推断、待核验和置信度无需阅读长说明即可区分。
4. 让搜索、筛选、排序和返回上下文稳定、可预期。
5. 让失败、过期、部分可用和受限来源保持诚实，不用空白或虚假成功掩盖。
6. 在 320px、200% 缩放、键盘和屏幕阅读器下仍可完成核心任务。

### 2.3 明确不做

- 不设计全网爬虫控制台、账号系统、团队协作、付费、通知中心或外部推送。
- 不设计自动发帖、公开日报、评论区、社交热榜或无限新闻流。
- 不把“热度”做成事实或重要性的替代指标。
- 不把多个转载数量画成“多源验证”。
- 不用装饰性仪表盘填满首屏，不展示没有决策含义的 KPI。
- 不使用大面积渐变、发光描边、玻璃层、复杂 3D、自动轮播或高频动效。
- 不指定 React、Vue、组件库、图表库或任何实现技术。

## 3. 信息架构与导航

### 3.1 一级导航

按以下顺序设计：

1. **今日雷达**：默认首页，过去 24 小时或指定日期的正式事件。
2. **全部事件**：跨日期检索、筛选和排序。
3. **来源目录**：来源身份、访问级别、核验快照和限制。
4. **偏好与反馈**：关注、不想看、排序倾向和反馈管理。
5. **质量说明**：数据性质、准入规则、去重、未实测指标和已知限制。

事件详情是二级任务页，不单独占用一级导航。用户从详情返回时必须恢复原日期、筛选、排序、查询词和滚动位置。

### 3.2 全局框架

- 顶部固定但紧凑的应用栏：产品名、一级导航、全局搜索入口、当前数据模式。
- 全局数据模式条位于应用栏下方，始终显示：`演示数据`、`人工快照`、`截至 <时间>`、`未连接自动采集服务`。
- 内容区使用清晰的面包屑或返回上下文，不重复堆叠大标题。
- 页面主区域前置一个跳转链接“跳到主要内容”。
- 桌面导航可水平展示；平板压缩为图标+文字；移动端使用可关闭的导航抽屉，但“数据模式”不能藏入抽屉。

## 4. 页面任务书

### 4.1 今日雷达

#### 首屏结构

1. 页面标题、当前日期范围、简短一句价值说明。
2. 全局数据模式条。
3. 轻量摘要区，不超过四项：
   - 正式事件数，范围必须为 0–20；
   - 截至时间；
   - 当前数据模式：演示/人工快照；
   - 质量说明：如“本时段仅 7 条通过硬门槛”。
4. 若存在演示紧急事件，使用独立紧急条，明确“示例状态”，不计入日榜数量。
5. 搜索、日期切换、筛选、排序和结果数。
6. 事件列表。

#### 事件卡片

每张卡片保持一屏可扫读，必须包含：

- 标题与必要原始标题；模型名、版本号保持原文准确。
- 发布方、事件时间、地区、事件类型、开源/闭源。
- 1–2 行短摘要，超过部分进入详情，不做长文卡片。
- “为什么重要”短句，并显式标记为人工判断或系统推断。
- 事实类型标签与置信度，两者视觉上独立。
- 主源域名、内容类型和外部打开图标。
- 最近更新时间。
- 已读、收藏、不相关三个轻量操作；操作不能改变客观重要性。
- 若属于事件簇，显示“合并 4 条证据”，点击进入证据详情；不得写成“4 个独立来源”除非证据根确实独立。

#### 数量与配额状态

- 0 条：显示“本时段没有通过硬门槛的事件”，提供查看历史和质量说明，不用低质量内容补位。
- 1–9 条：显示真实数量和“高置信事件不足”，不出现空占位卡。
- 10–20 条：正常显示。
- 超过 20 条：今日雷达只显示前 20 条，提供“在全部事件查看其余合格事件”。
- 单厂商普通事件超过 3 条：卡片或专题簇必须展示例外理由；否则在日榜压缩为最多 3 条。

### 4.2 全部事件

- 顶部保留查询词、结果数、日期区间和数据模式。
- 桌面端使用紧凑列表或可切换的表格/列表视图；移动端只保留纵向列表，不把宽表硬塞入屏幕。
- 筛选至少覆盖：日期、地区、厂商、模型、事件类型、开源/闭源、事实标签、置信度、已读状态。
- 排序至少覆盖：综合重要性、时间、行动价值、证据质量。
- 已生效条件以可移除 Chip 展示，提供“清除全部”。
- 筛选无结果时显示当前条件、结果为 0、清除单项/全部入口；不能写成“今日没有动态”。
- 搜索只声明覆盖标题、原始标题、厂商、模型字段、关键词和短摘要，不暗示搜索全文。
- 列表项进入详情后返回，查询和阅读位置完全恢复。

### 4.3 事件证据详情

#### 页面层级

1. 返回来源列表与保存上下文提示。
2. 标题、原始标题、组织、模型/产品、版本、生效日期、发布时间、取得时间、更新时间。
3. 事实类型、置信度、事件重要性与紧迫性，四者不得混成一个分数。
4. “发生了什么”：短摘要。
5. “为什么重要”：明确标记人工判断或系统推断，并展示依据。
6. “关键断言与证据”：断言级映射。
7. “证据链”：主源、技术佐证、独立佐证、传播线索、反证/异议。
8. “更新历史”：首次发现、主源确认、合并/拆分、修正、撤回。
9. 原文入口列表，提前展示来源域名和内容类型。

#### 证据链图形

使用简洁的纵向证据链或有向关系图，不使用装饰性网络图：

- 中心节点是事件。
- 主源使用实线连接并标 `主源`。
- 技术佐证、独立佐证使用不同图标和文字标签。
- 传播线索使用细虚线，明确“仅用于发现”。
- 反证/异议使用双向或冲突标记，同时列出其支持的断言。
- 相同新闻稿的转载归入同一证据根，不画成多个独立节点。
- 图形旁必须提供等价文字列表和可访问表格。

#### 断言表

列为：关键断言、标签、置信度、支持证据、反证/限制、最近更新。厂商性能声明必须显示“来源观点 · 厂商称”；没有主源的内容显示“待核验”且不能伪装正式事实。

### 4.4 来源目录

- 页首必须写明：`研究核验快照 · 截至 2026-07-31 · 不等于已接入运行`。
- 每项展示：名称、发布方、地区、类型、入口、建议访问方式、自然更新节奏、访问级别、robots/条款最近核验时间、保留边界、状态。
- 状态完整覆盖：`enabled`、`manual-only`、`pending-review`、`restricted`、`paused`、`retired`。
- MVP-1 中不得把 `enabled` 解释为“后台正在采集”；推荐文案是“研究建议可启用，尚未接入”。
- 受限来源明确显示需要登录、付费、API 申请或协议的原因，不提供绕过入口。
- 桌面使用可排序表格；移动转为分组卡片。表格必须有标题、表头和状态文字。

### 4.5 偏好与反馈

- 关注：厂商、模型家族、关键词、事件类型、地区。
- 不想看/降权：厂商、主题、来源、内容类型。
- 预设：更偏开发行动、更偏模型能力、国内外平衡。
- 关注程度使用“高 / 标准 / 低 / 隐藏”离散选项，不使用难以精确操作的连续微小滑杆。
- 每次调整显示排序影响预览，但提示“不能让无主源、证据不足或受限内容越过正式门槛”。
- 保存按钮必须写清作用域，例如 `保存到当前浏览器（演示）`；不能写“同步到账号”。
- 支持撤销、恢复透明默认值，并能查看“不相关”原因：主题不相关、重复、过旧、证据弱、影响低、分类错误、其他。
- 收藏、已读、不相关与证据纠正的语义分别说明；收藏和点击不提高客观重要性。

### 4.6 质量说明

用短段落、规则卡和可访问图表说明，而不是写成大篇产品文档。

必须覆盖：

- 当前模式：演示/人工快照、未连接、截至时间。
- 正式事件硬门槛和 0–20 条规则。
- 单厂商上限、事件簇和紧急事件不占配额。
- 事实、来源观点、独立验证、系统推断、待核验定义。
- URL、精确内容、事件实体、跨语言候选四层去重。
- 质量指标定义：来源成功率、候选量、独立事件量、聚类压缩率、人工相关性、漏报、人工改分、核验时间。
- 所有未取得真实样本的指标显示 `未实测`，不出现虚构百分比。
- 影子运行需至少 14 天，样本不足可延长至 30 天；这只是后续门槛，不是当前完成状态。
- 已知限制和买/建比较入口。

## 5. 图表类型与数据映射

图表只在能缩短理解时间时使用。每个图表都必须有标题、时间范围、数据模式、口径说明、文字摘要和可访问数据表。

| 使用位置 | 图表类型 | 数据映射 | 当前演示规则 |
|---|---|---|---|
| 今日雷达摘要 | 横向分段条 | 事件类型 → 数量；总数必须等于正式事件数 | 标 `演示数据`；不得暗示市场份额 |
| 今日雷达摘要 | 双侧平衡条 | 中国/全球事件数量 | 只表达本快照构成，不表达行业占比 |
| 事件详情 | 纵向证据链 | 节点=证据；边=支持/传播/反证；形态=证据角色 | 同根转载归并，不夸大独立证据数 |
| 事件详情 | 更新时间线 | 时间 → 首次发现、确认、合并、修正、撤回 | 未来节点不预填 |
| 来源目录 | 状态分布条 | 来源状态 → 来源数 | 标 `研究核验快照`，不是运行健康度 |
| 质量说明 | 流程漏斗/流程图 | 候选 → 去重事件 → 主源核验 → 正式日榜 | MVP-1 只显示步骤定义；数量写 `未实测` |
| 质量说明 | 指标状态表 | 指标 → 定义、目标、样本量、当前值 | 无真实数据时当前值统一 `未实测` |

禁止饼图表达模糊占比、仪表盘速度表、雷达图、无坐标趋势线、伪实时波形和无法解释口径的总分。事件重要性、证据质量和用户偏好不能合并成单一“AI 分数”。

## 6. 设计系统

### 6.1 视觉方向

- 关键词：编辑型、理性、克制、清晰、可信、轻量数据感。
- 布局以阅读和比较为主，卡片边界轻，避免卡片套卡片。
- 主要层级依靠字号、字重、留白和细分隔线，不依靠大色块。
- 默认浅色，同时输出完整深色状态；两套主题信息层级一致。

- 代码、版本号和域名：`SFMono-Regular` / `Roboto Mono`，只用于必要字段。
- 页面标题：32px / 40px / 700；移动端 26px / 34px。
- 区块标题：20px / 28px / 650。
- 卡片标题：17px / 25px / 650。
- 正文：15px / 24px / 400。
- 辅助文字：13px / 20px / 400。
- 标签：12px / 18px / 600；不得小于 12px。

### 6.4 间距、圆角、阴影和动效

- 4px 基础栅格；常用间距：4、8、12、16、20、24、32、40、48、64px。
- 输入、按钮和 Chip 圆角 8px；卡片 12px；弹层 16px；不要胶囊化所有元素。
- 卡片默认只用 1px 边框；悬浮阴影 `0 6px 20px rgba(16,24,40,.08)`。
- 焦点环 2px，外偏移 2px。
- 动效 120–180ms，`cubic-bezier(.2,.8,.2,1)`；只用于状态过渡。
- 尊重 `prefers-reduced-motion`，关闭位移、缩放和滚动动画。

## 8. 交互规则

### 8.1 搜索、筛选与排序

- 搜索提交和筛选变化后，结果数可见并通过礼貌型 live region 播报一次。
- 筛选抽屉打开时焦点进入标题或首个控件，焦点限制在抽屉内；Esc/关闭后返回原按钮。
- 组合筛选保留用户未提交的编辑状态，明确“应用筛选”和“取消”。
- 清除全部前无需危险确认，但执行后提供撤销 Toast。
- 键盘快捷键 `/` 可聚焦搜索，但必须可发现并不覆盖输入场景。

### 8.2 详情与外链

- 打开详情不丢失列表上下文。
- 外链在点击前可见来源域名和内容类型；新标签页的可访问名称包含“在新标签页打开”。
- 原文失效时保留事件与失效标记，不静默换成二手链接。
- 撤回/修正使用醒目的内联状态，不删除历史时间线。

### 8.3 偏好与反馈

- 收藏、已读、不相关操作立即反馈且可撤销。
- “不相关”先选择原因，再保存；不会删除证据。
- 证据/分类纠正显示待处理状态，并保留原记录。
- MVP-1 保存后明确播报“已保存到当前演示作用域”，不声称云端同步。

### 8.4 刷新

- MVP-1 按钮文案为 `重新载入此快照`，旁边持续显示“未连接自动采集服务”。
- 点击后只出现短暂页面加载反馈，不展示来源抓取进度。
- 未来 MVP-2 状态稿覆盖：已开始、各来源处理中、部分成功、完成、失败、取消、重复触发幂等。
- 部分失败保留成功结果；全部失败保留最近可用快照；刷新失败不清空旧内容。

## 10. 响应式规则

## 11. 无障碍要求

- 目标为 WCAG 2.2 AA。

- 所有核心操作仅用键盘可完成；焦点顺序与视觉顺序一致。
- Focus 状态始终可见；禁止只在 Hover 暴露关键操作。
- 筛选抽屉和弹层有正确名称、描述、焦点圈定与返回。
- 结果数量、筛选变化、刷新结果和错误使用 `aria-live="polite"` 等价语义，合并重复播报。
- 事实、来源角色、置信度、连接、过期和错误都有文字，不以颜色/图标为唯一表达。
- 图表提供一句话结论、数据口径和等价数据表；证据图提供线性阅读顺序。
- 外链名称包含来源与目标；不只写“点击这里”。
- 语言切换或英文原文片段提供正确语言语义。
- 触控目标至少 44×44px；相邻目标保持至少 8px 间距。
- 尊重减少动态效果、系统深色和高对比需求。
