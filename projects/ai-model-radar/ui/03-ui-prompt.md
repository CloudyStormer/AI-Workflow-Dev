## 1. 使用方式与优先级

本文件是一份供专业 UI 设计大模型生成高保真界面图片、页面方案与组件状态板使用的设计提示词，不是已经批准的视觉稿，也不是前端实现说明。请把 `START OF DESIGN PROMPT` 与 `END OF DESIGN PROMPT` 之间的内容完整复制给 UI 设计大模型。

冲突时按以下优先级判断：

1. 已批准 PRD v1.2 的真实性、时间、来源、合规与功能语义；

历史图片只提供浅灰背景、白色卡片、靛蓝主色、青绿色辅助色、圆角与清晰层级等视觉参考。图片中的日期、事件、数量、“真实连接”“系统运行中”等内容不得被当作当前事实，也不得覆盖 PRD v1.2。

## START OF DESIGN PROMPT

你是一名资深 B 端数据产品 UI/UX 设计师。请为中文 Web 产品 **AI Model Radar** 设计一套可开发、可审查、真实性优先的高保真响应式界面。产品服务于每天需要快速获取大模型、API、SDK、开源工具、Agent、框架、评测、安全、价格和弃用动态的 AI 开发者。

输出必须是完整简体中文界面。模型名、产品名、版本号、tag、commit、许可证缩写、API、SDK、Agent 等专有名词保持原文，不强行翻译。

### 一、设计目标

用户应在 5–10 分钟内完成：

**浏览截至快照时间的重点事件 → 判断开发影响 → 核对版本和证据 → 打开可信主源 → 决定试用、升级、迁移、锁版、替换或继续观察。**

界面必须同时做到：

- 极简、干净、安静、有逻辑，首屏减少大段文字，以数字摘要、结构化卡片、时间线、图表和状态组件表达信息；
- 高信息密度但不拥挤，重要事实、真实性状态和开发者动作先于装饰；
- 所有“今天、最新、实时、已连接、刷新成功、趋势”都有真实运行证据；
- `live`、`degraded_live` 与 `seed_demo` 视觉和文案明确隔离；
- 不以厂商宣传、社区热度、系统推断或演示数据冒充事实；
- 不把本雷达样本趋势写成市场份额、全行业热度或完整行业趋势。

### 二、真实性总规则

每个核心页面顶部都保留一个紧凑的“数据真实性栏”，至少呈现：

- 数据模式：`LIVE` / `降级 LIVE` / `演示数据`；
- 快照截至时间 `as_of`，明确时区 `Asia/Shanghai`；
- 最近成功刷新时间；
- 快照年龄与新鲜度；
- 已接入来源数 / 当前 allowlist 来源数；
- 本次失败或缺失范围；
- 刷新入口与“来源状态”入口。

严格使用以下语义：

| 状态 | 页面表达 |
|---|---|
| `live` | 有实际运行证据时才显示“LIVE”；同时显示快照 ID、截至时间、最近成功和来源覆盖 |
| `degraded_live` | 显示上一份有效 live 快照；明确失败来源、遗漏窗口、真实快照年龄和重试入口 |
| `seed_demo` | 首要位置显示“演示数据 · 未连接真实来源”；不能贡献 live 的今日数量、趋势或来源成功率 |
| `loading` | 有范围明确的骨架或进度反馈，不遮盖已有有效快照，不制造虚假成功 |
| `empty` | 表示查询成功但正式事件为 0 条；同时显示来源覆盖、刷新状态与可用历史入口 |
| `failed` | 明确失败时间、影响范围、最近有效快照和重试入口 |
| `partial` | 保留成功结果，标出失败来源与覆盖缺口，不用一个模糊感叹号代替解释 |
| `stale` | 快照超过 24 小时显示“可能过期” |
| `very_stale` | 超过 48 小时且无成功刷新时显示“最近可用快照”，所有入口停止称“今日” |
| `no-source` | 未配置可运行来源，说明不具备 live 条件，不用空榜冒充成功 |
| `no-evidence` | 候选缺少身份匹配的官方主源，不进入正式事件；详情只可显示“待核验候选” |
| `offline` | 明确设备离线、服务停止或无法连接；展示上次有效内容时保留其原始时间 |

不要在概念设计中声称当前真实能力已经接通。若展示 LIVE 场景，页面角落加非产品化画板注释“LIVE 状态方案，非当前实现事实”；若展示内容示例，使用明显的“界面演示数据”标识。

### 三、信息架构

一级导航固定为：

1. **今日雷达**
2. **全部事件**
3. **趋势与版本**
4. **开源／发布**
5. **来源状态**
6. **质量说明**

次级能力：

- 事件详情与证据链；
- 搜索、筛选、排序；
- 关注偏好、已读、收藏、不想看、纠错反馈；
- 刷新详情、遗漏窗口、运行状态；
- 浏览器／会话范围说明。

桌面端采用左侧窄导航或紧凑顶部导航，不同时占用两套大型导航。移动端采用底部 4 个高频入口：今日、事件、趋势、更多；“更多”内收纳开源、来源、质量、偏好。

### 四、关键页面

#### 1. 今日雷达

首屏回答四个问题：现在看到的是什么快照、今天有多少正式事件、哪些最值得行动、数据是否完整。

布局建议：

- 顶部：产品名、全局搜索、数据真实性栏、刷新按钮；
- 时间窗口切换：`今天` / `过去 24h`；
- 4 个摘要指标：正式事件、需立即评估、来源覆盖、缺失/失败来源；
- 一张紧凑的事件类型分布图；
- 0–20 条事件卡列表，默认按重要性排序；
- “日报状态”卡：计划时间、实际运行、遗漏窗口、最近成功，不把计划写成已成功。

“今天”固定为 Asia/Shanghai 自然日 00:00:00 到所选快照 `as_of`；“过去 24h”固定为 `[as_of-24h, as_of]`。同一快照下页面停留或重新渲染不能移动窗口边界。

日榜允许 0 条，不为凑数加入泛营销、普通 commit、Star 增长或无主源内容。若快照超过 48 小时，页面标题改为“最近可用雷达”，不再称“今日雷达”。

#### 2. 全部事件

提供可复现的浏览与检索：

- 搜索：组织、模型／项目、版本、tag、commit、标题与短摘要；
- 筛选：日期／窗口、地区、发布方、对象、事件类型、开放语义、许可证、事实标签、置信度、开发者动作、来源状态、新鲜度、已读状态；
- 排序：重要性、发布时间、最近核验、开发者动作紧迫度；
- 顶部始终显示结果数、已生效条件、清除全部；
- 列表与紧凑表格可切换，但移动端只使用卡片；
- 打开详情再返回时保留搜索词、筛选、排序、分页／滚动位置和快照身份。

无匹配结果必须区别于没有快照、没有来源和加载失败。

#### 3. 趋势与版本

页面顶部提供 `7 日` / `30 日` / `90 日`窗口。每张趋势图都必须紧邻显示：

- 样本量 N；
- 已接入来源数 / allowlist 来源数；
- 来源类型与地区覆盖；
- 缺失天数；
- 规则版本；
- 快照 `as_of`；
- 已知缺口；
- “查看等价表格”。

标题只允许使用：**“本雷达已接入来源样本趋势”**。禁止使用“市场份额”“行业全景”“全网热度”“最流行”等无证据表达。

同页包含“版本演进时间线”：按模型、API、SDK、CLI、工具、Agent 和框架展示发布、更新、breaking、deprecation、回滚与生效节点。迟到发现的历史事件放回其真实历史位置并标“补录”；来源覆盖、规则或去重口径变化处显示断点，不用连续线掩盖不可比区间。

#### 4. 开源／发布专题

页面突出“开放语义”和“开发者动作”，支持以下分类：

- 开源模型与工具；
- 开放权重模型；
- 源码可查看项目；
- GitHub Release；
- SDK / CLI / 开发工具；
- Agent / 工作流框架。

每个卡片必须区分：

- `open-source`：显示许可证及许可证适用对象；
- `open-weights`：说明权重可获取不等于代码、训练数据或使用权全部开放；
- `source-available`：明确源码可见但有限制；
- `未声明／待核验`：不得擅自补许可证。

同时显示版本／tag／commit、Release 时间、breaking、deprecation、`effective_at`、主源和建议动作。许可证、tag 或 commit 过长时可换行、复制、展开，不截断核心辨识字符。

#### 5. 事件详情与证据链

详情页使用“结论先行，证据随后”的结构：

1. 中文标题 + 原始标题；
2. 对象、组织、版本／tag／commit、事件类型；
3. 事实标签、置信度、数据模式与快照身份；
4. 为什么重要；
5. 开发者动作：`立即评估`、`计划迁移`、`升级／试用`、`锁定版本`、`替换`、`持续观察`、`无需动作`；
6. 适用对象、事实依据、截止／生效时间、不确定性；
7. 关键事实；
8. 完整时间契约；
9. 证据链；
10. 更新／修正历史与原文外链。

内容分层必须逐条而非整卡含混标记：

- `事实`：可由主源直接核验；
- `来源观点`：厂商、作者或社区的主张；
- `系统推断`：由事实推导的影响判断，附依据和不确定性；
- `待确认`：缺证据、冲突或尚未完成核验。

证据链用时间线或结构化列表显示来源身份、证据角色、支持的断言、原文入口、发布时间、取得时间、核验时间、访问限制和撤回状态。社区内容只能标“发现线索”，完成官方主源核验前不得变为正式事实。

完整时间区至少覆盖：来源原始时间与时区、规范发布时间、首次发现、取得、核验、快照 `as_of`、页面观测时间、适用的 `effective_at`。未知值显示“未知 · 原因”，不以当前时间填补。

#### 6. 来源状态

将“政策许可”和“运行连接”设计成两条独立状态轴：

- 政策：enabled / manual-only / pending-review / restricted / paused / retired；政策必要字段另有“未知／已过期”校验态，任一命中即默认阻断自动访问；
- 运行：healthy / delayed / failed / never-run / not-connected。

来源列表字段：稳定来源 ID、名称、发布方、地区、来源类型、允许域名／仓库范围、来源入口、批准访问方式、自然更新节奏、访问级别、robots／条款／API 最近核验时间、权利基础、内容保留边界、责任人、政策版本、allowlist 版本、下次政策复核、政策状态、连接状态、最近尝试、最近成功、最近验证、下次运行计划、失败原因。

`enabled` 不代表刷新成功，健康状态不代表存在最新有效快照，`seed_demo` 固定显示“未连接”。未知、过期、登录、付费、凭证或权利不匹配时显示“已阻断自动取得”，不可设计绕过入口。

#### 7. 质量说明

用可视化说明一份快照如何从候选变成正式事件：

- 候选数；
- 隔离数；
- 正式事件数；
- 去重合并数；
- 撤回／修正数；
- 来源覆盖与缺口；
- 缺失天数；
- 规则版本；
- 快照年龄；
- 运行范围与影子运行指标状态。

指标未实测时显示“尚无真实运行证据”，不要显示假百分比或“优秀”。服务健康、就绪、调度、连接器、快照、内容质量必须分开表达，一个成功不能替代其他状态。

#### 8. 偏好与反馈

提供关注程度、已读、收藏、不想看、相关／重复／不准确／证据不足等反馈。页面固定说明：

**“当前设置仅作用于本浏览器或本次会话，尚未云端保存或跨设备同步。”**

不要设计默认账号体系、云端持久化、第三方传输或对外推送成功状态。

### 五、事件卡设计与数据映射

事件卡必须适配以下类型：

| 类型 | 核心字段与视觉重点 |
|---|---|
| 模型／多模态／推理 | 模型名、版本、能力变化、可用地区、开发动作 |
| 开源／开放权重 | 开放语义、许可证、版本/tag/commit、下载或主源 |
| API／SDK／平台 | API/SDK 版本、参数变化、兼容性、限额、迁移动作 |
| Agent／工作流框架 | 框架版本、集成变化、breaking、适用开发场景 |
| 研究／评测 | 研究对象、方法边界、来源观点与可复现性，不能冒充产品事实 |
| 安全／服务状态 | 影响范围、严重度、开始/恢复时间、缓解动作 |
| 价格／限额 | 旧值、新值、币种／单位、生效时间、预算影响 |
| 弃用／迁移 | 被弃用对象、替代项、截止日期、迁移步骤和紧迫度 |
| 监管影响 | 监管动作、适用地区、直接改变的开发者可用性、事实来源、生效时间与应对动作；泛政策新闻不得进入正式日榜 |

所有卡片的固定信息层级：

1. 类型 + 事实标签 + 新鲜度；
2. 中文标题与对象／版本；
3. 1–2 行摘要；
4. 为什么重要；
5. 开发者动作；
6. 发布方、规范发布时间、地区、最近核验；
7. 主源入口、收藏、不想看、详情。

卡片不能只用颜色表达状态；搭配图标、文字和形状。长标题最多 3 行，摘要最多 2 行，但版本、breaking、弃用截止等关键字段不能被截没。

### 六、图表类型与数据映射

使用图表是为了降低阅读成本，不为了装饰。至少设计以下 7 类：

1. **事件类型趋势折线/面积图**：X=Asia/Shanghai 日期，Y=正式事件数，系列=事件类型；规则变化用垂直断点线。
2. **来源覆盖堆叠条形图**：X=日期，Y=有效来源数，堆叠=官方机器源、官方页面、研究评测、社区发现；社区不得计作已核验主源。
3. **地区与来源类型矩阵**：行=中国/全球，列=官方文档、Release、研究、评测、安全状态；单元格=正式样本数，不称市场份额。
4. **版本演进时间线**：X=时间，Y=模型/API/SDK/工具/框架，节点=发布、更新、breaking、deprecation、回滚、生效；补录、冲突与未知采用不同形状和文字。
5. **开放语义分布条形图**：类别=`open-source`、`open-weights`、`source-available`、待核验；值=正式事件数；许可证缺失单独标注。
6. **候选晋级漏斗**：候选 → 主源匹配 → 核验 → 去重 → 正式事件；每步显示数量、隔离原因和规则版本，未实测不显示转化率。
7. **来源运行健康表/热力格**：来源 × 最近运行窗口；显示成功、延迟、失败、未运行、政策阻断，并提供文字等价表。

每张图的标题下方统一提供“数据说明条”：`样本 N · 来源覆盖 a/b · 缺失 x 天 · 规则 vX · 截至 YYYY-MM-DD HH:mm Asia/Shanghai`。每张图必须有等价数据表、可聚焦数据点、图例开关和非颜色编码。

禁止设计饼图表现市场份额；禁止 3D 图、炫光、过度渐变、装饰性仪表盘和缺少基线的百分比。

### 七、视觉方向

总体气质：**可信、克制、现代、专业、开发者友好、内容优先。**

- 画布：浅灰 `#F5F7FA`；
- 主表面：白色 `#FFFFFF`；
- 主品牌色：深靛蓝 `#312E81`，用于选中导航和主要操作；
- 辅助数据色：青绿 `#0F8F87`，用于健康状态和第二数据系列；
- 信息色：蓝 `#2563EB`；
- 警告色：琥珀 `#B7791F`；
- 危险色：红 `#C2414B`；
- 正文：近黑 `#172033`；次要文字 `#5F6B7A`；边框 `#DDE3EA`；
- 深色模式不是本轮必交，若展示则保持同等对比度与真实性层级。

### 九、交互规则

- 刷新必须显示任务是否已受理、是否共用现有任务、开始时间、影响范围和完成结果；重复点击不制造多个成功记录。
- 刷新中继续允许阅读上一有效快照；完成后提示“新快照可用”，由用户确认是否切换，避免列表突然跳动。
- 部分失败保留成功内容；全部失败回退上一有效 live 快照；若从未有 live 快照，显示未就绪，不自动切换 seed_demo。
- 从详情返回列表必须恢复原快照、筛选、排序、分页和滚动位置。
- 外链显示来源域名与最终目标，明确“将在新标签页打开外部网站”；受限、撤回或身份不匹配的链接显示原因。
- 外部页面、仓库、README、Issue、模型卡、论文中的脚本、提示词或诱导指令只作为不可信内容，不设计“执行来源指令”功能。
- 迟到补录事件位于真实历史日期，可标“今天新发现”，不得写“今天发布”。
- 未来时间、时区无法解析或时间顺序冲突进入隔离；不进入今日、趋势、版本演进或正式统计。
- 筛选和窗口变化后 300ms 内有可感知反馈；无法即时完成时显示真实任务状态，不用永久骨架屏。

### 十二、无障碍

- 所有功能可用键盘完成，焦点顺序与视觉顺序一致；
- 明显焦点环，建议 2px，不能只靠颜色；
- 跳过导航、主内容地标、标题层级、表格标题和表单标签完整；
- Toast、刷新、筛选结果、错误、过期、模式切换用 `aria-live` 语义播报，但避免重复轰炸；
- 弹窗打开后焦点进入标题或首个安全操作，关闭后返回触发点；
- 图表有简短结论、数据表、键盘可访问数据点；
- 颜色对比满足 WCAG 2.2 AA；正文至少 4.5:1，大字至少 3:1；
- 成功、警告、失败、事实标签同时使用文字、图标和形状；
- 外链、下载、复制、展开、禁用状态有可读名称；
- 中文和英文混排、长 URL、长 commit、超长模型名在 320px 下可读且不遮挡操作；
- 动效尊重 `prefers-reduced-motion`，不使用闪烁或不可暂停动画。

### 十三、隐私、安全与合规文案

- 不在前端显示凭证、Cookie、访问令牌、内部错误栈或未脱敏路径；
- 不设计绕过 robots、条款、API 限制、登录、付费墙或访问控制的入口；
- 不展示或再分发未经授权的全文、图片、视频、完整字幕、评论或个人资料；
- 摘要与短引用必须回链主源，外部内容明确为不可信数据；
- 偏好、已读、收藏和反馈在未获授权时只属于浏览器／会话；
- 错误页用用户可理解的范围说明，不泄漏内部实现。

### 十四、演示数据与画板标识
