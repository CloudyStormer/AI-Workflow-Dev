## 1. 使用方式与优先级

本文件是一个可直接交给专业 UI 设计大模型的完整 UI/UX Prompt 增量。它不是已经批准的视觉稿，不是前端代码，也不证明真实新闻服务已经接通。

请将 `START OF DESIGN PROMPT` 与 `END OF DESIGN PROMPT` 之间的内容完整复制给 UI 设计大模型。冲突时按以下优先级处理：

1. 已批准 `docs/02-prd-ai-developer-news-increment.md` v1.0；
2. 已批准 `docs/02-prd.md` v1.2 与发布完整性附录中不冲突的真实性、证据与合规规则；
3. 本 Prompt 的信息架构、页面、状态、视觉、响应式与无障碍要求；
4. 既有 Prompt 与历史视觉资产中不冲突的设计语言；
5. 设计模型的默认发挥。

当前真实事实必须贯穿全部设计：

- 当前 `/today` 是验收不合格的静态/示例页面，不能称真实可用；
- `runtime_enabled=false`、真实连接器 `0`、真实 live 快照 `0`；
- 来源研究清单不等于已接入，HTTP 200、路由可打开、seed、mock、静态 JSON 都不等于 `live`；
- 既有前端、架构和任务拆解处于冻结/协调状态；
- 本轮不采集新闻、不连接服务、不部署，也不开放收藏、账号或其他写入能力。

## START OF DESIGN PROMPT

你是一名资深中文新闻产品与 B 端数据产品 UI/UX 设计师。请为 **AI Model Radar（AI 开发圈新闻雷达）** 输出一套极简、干净、可信、可开发、可审查的高保真响应式 Web UI 设计。

这是一个供单一核心用户每天长期使用的真实 AI 开发新闻产品。用户需要用 5–10 分钟回答：

**今天国内外 AI 开发领域发生了什么 → 哪些变化需要行动 → 原始证据在哪里 → 数据截至何时 → 来源或刷新是否失败。**

所有用户可见界面、导航、筛选、状态、图表、空态、错误和无障碍文案必须使用完整简体中文。模型名、产品名、API、SDK、Agent、CLI、tag、commit、许可证等专有名词保留原文。

### 一、最高优先级设计原则

1. **极简、干净、有逻辑。** 减少大段解释，优先使用短标题、摘要数字、紧凑事件卡、时间线、矩阵、分层详情和渐进披露。
2. **新闻阅读优先。** 首屏首先展示今天是否有真实合格新闻、最重要的 3–5 条、为什么重要和开发者动作，不做装饰性治理大屏。
3. **真实性始终可见。** 数据模式、`as_of`、最近成功、来源覆盖、失败范围、快照年龄必须就近可见，不能藏进帮助弹窗。
4. **一手证据优先。** 每条正式事件必须能回到发布方官方来源；媒体、社群和搜索结果只能作为发现线索。
5. **不凑数。** 每日正式事件允许 `0–20` 条；没有合格事件时显示真实空态，不补旧卡、随机卡或营销内容。
6. **不把演示画成实时。** 当前真实运行来源、连接器和 live 快照均为 0。当前态设计默认展示 `not_ready`，任何目标态数据必须显著标注 `目标态演示 · 非当前运行事实`。
7. **状态不只靠颜色。** 颜色、文字、图标、形状和位置共同编码；所有图表有等价表格或结构化文本。

### 二、产品定位与内容范围

正式事件必须对 AI 开发者有明确行动价值，覆盖：

- 模型、API、SDK、价格、额度、上下文、弃用与下线；
- AI 编程、Agent、工作流、开发者平台、插件和 CLI；
- 官方 GitHub Release、模型卡、开源项目版本、许可证和兼容性；
- 框架、推理、训练、数据、评测、观测、GPU 与基础设施中的开发决策变化；
- 重要论文、项目主页和可复现工程实践；
- 会改变开发、部署或合规行动的安全通告、服务状态和政策。

普通 commit 活跃、Star 变化、无主源转载、泛营销、与 AI 开发无关的企业新闻不得进入正式日榜。公开仓库或模型更新时间本身不等于正式发布。

### 三、全局信息架构

一级导航固定为：

1. **今日雷达**
2. **全部事件**
3. **趋势与版本**
4. **开源与发布**
5. **来源与质量**

二级/上下文入口：

- 事件详情与证据链；
- 刷新运行详情；
- 隔离与待核验说明（只读）；
- 搜索、筛选、排序；
- 数据口径与质量说明。

不要出现收藏、稍后读、账号、登录、通知、反馈写入、删除、发布或来源启用入口。当前 P0 是纯阅读与只读诊断产品。

桌面使用左侧窄导航；移动端底部 4 项为 `今日 / 事件 / 趋势 / 更多`，“更多”收纳开源、来源与质量。详情返回必须恢复原快照、时间窗口、搜索、筛选、排序、分页和滚动位置。

### 四、全局数据真相栏

每个 P0 页面顶部都放一条紧凑、不可关闭的数据真相栏，固定显示：

- 当前页面状态的完整中文名称；
- 数据模式：`真实服务` / `受控旧快照` / `目标态演示`；
- 快照 `as_of` 与 `Asia/Shanghai`；
- `last_success_at`，没有则写“尚无成功记录”；
- 快照年龄与 24/48 小时阈值；
- 近 24 小时成功来源数 / 已启用来源数；
- 国内/国际覆盖是否可用；
- 当前失败来源数、遗漏窗口或未就绪原因；
- `刷新状态`、`来源详情`入口。

当前默认真相栏必须写：

**“数据未就绪｜真实来源尚未接通｜连接器 0｜真实快照 0｜尚无成功记录”**

不得把来源研究数量、allowlist 数量、静态内容数或页面加载成功映射成运行覆盖。

### 五、统一真相态

| 内部状态 | 用户可见中文与视觉行为 |
|---|---|
| `live` | 只有真实服务、合规来源、持久化快照和新鲜度证据同时成立时显示“真实数据 · 已更新”；同时展示 `as_of`、最近成功、覆盖分母和证据入口。 |
| `empty` | 真实查询成功且本窗口没有合格新闻；显示“暂无符合标准的事件”、检查过的来源范围、`as_of` 和“不凑数”；不得回填旧卡。 |
| `not_ready` | 依赖、运行许可、连接器、持久化或查询尚未就绪；当前产品默认态。显示缺失条件，不画 0 条成功空榜，不显示假新闻。 |
| `stale` | 只有超过 24 小时的已核验快照；显示旧日期、年龄、失败原因和最近成功。超过 48 小时页面不得称“今日”或“最新”。 |
| `degraded` | 部分来源失败，但剩余真实快照仍安全可读；保留成功内容并明确失败来源、覆盖缺口和遗漏窗口。 |
| `failed` | 所有必要来源或关键依赖失败，不能安全生成当前结果；若有旧快照只读展示并保留原日期，没有则进入未就绪。 |

补充交互状态：首次加载、保留旧快照的后台刷新、刷新排队、刷新进行中、部分成功、新快照可用、无新增、取消、超时、离线、筛选空、无主源、未来时间隔离、补录、证据冲突、撤回与修正。

严格区别：

- `empty` 是“成功查询后为 0”；
- `not_ready` 是“无法完成可信查询”；
- `filter-empty` 是“当前筛选无匹配”；
- `failed` 是“真实请求执行后失败”；
- `stale` 是“有已核验旧快照，但不够新”。

### 六、核心页面

#### 1. 今日雷达

页面目标：30 秒内看懂今天是否有真实数据、最值得关注什么、是否需要行动。

页面结构从上到下：

1. 数据真相栏；
2. `今天` / `过去 24 小时`窗口切换；
3. 每日摘要区：一句总览、3 个关键变化、1 个风险/缺口；
4. 小型摘要指标：正式事件、需行动、近 24 小时成功来源/启用来源、失败来源；
5. 小时级增量时间带：展示每个小时真实新增、无新增、部分失败或遗漏；
6. 0–20 条事件卡，默认按行动价值和重要性排序；
7. 每日摘要运行卡：计划 `08:30`、实际开始、实际完成、`last_success_at`、遗漏窗口、结果快照；
8. 刷新运行入口与来源缺口入口。

当前态必须设计一张 `not_ready` 画板：不显示任何示例新闻，显示未就绪原因和“查看来源准备情况”。另设计目标态 `live`、真实 `empty`、`degraded`、`stale` 与 `failed` 状态；所有目标态数据显著标注 `目标态演示 · 非当前运行事实`。

“今天”固定为 `Asia/Shanghai 00:00:00–snapshot.as_of`；“过去 24 小时”固定为 `[as_of-24h, as_of]`。同一快照下窗口不能随页面停留漂移。

#### 2. 全部事件

顶部使用一行紧凑搜索与筛选摘要，避免用大段说明占首屏。

搜索范围：中文标题、原始标题、发布方、模型/项目、摘要、版本、tag、commit。

筛选项：

- 时间：今天、过去 24 小时、7/30/90 日、自定义；
- 地区：国内、国际、跨区域/待核验、全部；
- 内容域、发布方、涉及产品/仓库；
- 来源类型、来源政策、运行状态；
- 事实标签、可信度、开发者动作；
- 版本、许可证、breaking、deprecation；
- 新鲜度、补录、撤回/修正。

排序：重要性、发布时间、最近核验、行动紧迫度。始终显示结果数、已生效条件、清除全部和当前快照。桌面支持卡片/紧凑表格切换；移动只用卡片。

分别设计：全局真空、筛选空、未就绪、陈旧、部分失败与失败；不能用同一“暂无数据”占位。

#### 3. 趋势与版本

固定窗口：`7 日 / 30 日 / 90 日`。页面只能描述 **“本雷达已接入来源样本趋势”**，禁止“市场份额”“全网热度”“全球全量趋势”。

每张图紧邻显示：

- 样本量 N；
- 运行时已启用来源数 / 研究目标来源数；
- 国内/国际和来源类型覆盖；
- 缺失天数；
- 规则版本与去重口径；
- `as_of` 和最近成功；
- 已知缺口；
- `查看等价表格`。

同页设计版本演进时间线：模型、API、SDK、CLI、Agent、框架、工具、开源项目的发布、更新、breaking、deprecation、回滚和生效节点。补录放回原始历史位置并标注“今天发现”，未来时间进入隔离。

当前运行样本为 0 时显示 `not_ready` 和指标定义，不画假折线、不输出百分比。

#### 4. 开源与发布

页面只展示有官方 Release、模型卡、正式发布说明或等价一手证据的事件。

卡片固定字段：项目/模型、发布方、版本/tag/commit、开放语义、许可证、Release 时间、breaking、deprecation、`effective_at`、主源、最近核验、开发者动作。

开放语义严格区分：

- `open-source`：源码与许可证满足相应开放定义；
- `open-weights`：权重可获取，不代表代码、数据或商用权全部开放；
- `source-available`：源码可见但存在限制；
- `未声明/待核验`：不推断许可证和兼容性。

GitHub Star、普通 commit、下载量和仓库公开不能单独成为“正式发布”证据。

#### 5. 来源与质量

页面分成“来源覆盖”“运行状态”“质量说明”三个可切换区，但共享同一真相栏。

来源政策轴只显示：`政策允许候选 / 条件未满足 / 仅人工核验 / 禁止自动访问`；运行轴只显示：`未配置 / 未运行 / 未就绪 / 正常 / 延迟 / 降级 / 失败 / 停用`。两轴必须横向并列，禁止合成一盏绿灯。

来源行至少显示：稳定 ID、发布方、国内/国际、来源类型、精确入口、政策状态、运行状态、最近尝试、最近成功、最近核验、连续失败、错误/阻断原因、遗漏窗口与下次计划。

质量区展示从候选到正式事件的只读漏斗：候选 → 一手源匹配 → 核验 → 去重 → 正式事件；同时展示隔离、撤回/修正、来源覆盖、缺失天数、规则版本和快照年龄。未实测时写“尚无真实运行证据”，不画假转化率。

国内/国际覆盖用“成功来源/启用来源”和“启用发布方/目标发布方”双分母展示；分母为 0 时显示不可计算。

#### 6. 事件详情与证据链

信息结构：

1. 中文标题、原始标题；
2. 发布方、对象、地区、内容域；
3. 版本/tag/commit、许可证、breaking/deprecation/effective date；
4. 数据模式、快照身份、事实标签、可信度；
5. 发生了什么；
6. 为什么重要；
7. 开发者动作与适用对象；
8. 关键事实与不确定性；
9. 完整时间契约；
10. 证据链、去重关系、修正/撤回历史；
11. 打开原始来源。

事实标签逐条使用：`已确认事实 / 发布方观点 / 独立验证 / 系统推断 / 待核验`。发布方“第一、SOTA、提升 X%”没有独立证据时只能写“发布方称”。

证据角色：主源、技术佐证、独立佐证、传播线索、反证/异议。每条证据显示支持的断言、来源身份、原文域名、发布时间、取得时间、核验时间、访问限制和撤回状态。同根转载不能画成多个独立证据。

时间表至少含：`source_published_at`、`updated_at`、`effective_at`、`observed_at`、`fetched_at`、`verified_at`、`snapshot.as_of`、`last_success_at`。未知写“未声明/未知 · 原因”，不能填当前时间。

#### 7. 刷新运行详情

刷新是一次可追溯请求，不是成功承诺。状态包括：已受理、共用既有任务、按来源处理中、部分成功、成功且无新增、成功有新快照、失败、取消、遗漏计划窗口。

显示：任务 ID、触发方式、计划/开始/结束时间、逐来源结果、新增/更新/合并/隔离数、产生的快照、失败原因与覆盖缺口。

刷新过程中继续阅读旧快照；新快照成功持久化后提示“新快照可用”，由用户切换。重复触发共用任务，不制造重复事件、趋势计数或快照。全部失败时不更新 `as_of`，不生成新新闻。

### 七、事件卡与新闻密度

卡片层级固定为：

1. 内容域 + 事实标签 + 新鲜度；
2. 中文标题，最多 2 行；
3. 原始标题或对象/版本，最多 1 行；
4. 中文短摘要，最多 2 行；
5. 为什么重要，1 行；
6. 开发者动作，1 个主动作标签；
7. 发布方、来源、地区、发布时间、观测/核验时间；
8. `查看证据`、`打开原文`。

不要在卡片上堆满胶囊。只把事实标签、真相态、breaking/deprecation 和主动作做成标签，其余使用清晰排版和分隔。

每种事件重点：

| 类型 | 视觉重点 |
|---|---|
| 模型/API/SDK | 版本、能力/限制、价格/额度、生效时间、迁移动作 |
| AI 编程/Agent | 工具版本、工作流变化、兼容性、适用开发场景 |
| 开源发布 | tag/commit、许可证、开放语义、breaking |
| 框架/推理/基础设施 | 性能或兼容变化的适用边界，不把发布方结论写成独立事实 |
| 论文/实践 | 方法、样本、复现入口、适用范围 |
| 安全/状态/政策 | 影响范围、开始/恢复/生效时间、缓解动作、地区 |
| 价格/弃用 | 旧值、新值、单位、截止日、替代项和紧迫度 |

### 八、图表类型与数据映射

至少设计以下 10 类图表，全部使用同一结构化数据生成可视图与等价表：

1. **小时级增量时间带**：X=北京时间小时，标记=新增/无新增/部分失败/遗漏；值=合格事件数和来源结果。
2. **事件类型趋势图**：X=日期，Y=正式事件数，系列=内容域；规则变化处断线。
3. **国内/国际覆盖分组条**：分组=国内/国际/跨区域，值=成功来源/启用来源与启用发布方/目标发布方。
4. **版本演进时间线**：X=时间，Y=模型/API/SDK/Agent/框架/开源；节点=发布/更新/breaking/deprecation/回滚/生效。
5. **开放语义分布条**：open-source/open-weights/source-available/待核验；许可证缺失单列。
6. **候选晋级漏斗**：候选→一手源匹配→核验→去重→正式事件；显示隔离原因，不在样本不足时显示转化率。
7. **政策轴 × 运行轴矩阵**：政策四态 × 运行八态；每格展示端点数和文字状态。
8. **来源运行热力格**：来源 × 最近 24 小时；成功/延迟/失败/未运行/政策阻断使用文字或图形双编码。
9. **快照新鲜度时间带**：0–24h 新鲜、24–48h 陈旧、>48h 最近可用，标出 `as_of`、最近成功与遗漏窗口。
10. **证据链关系图**：规范事件连接主源、技术佐证、独立佐证、传播线索、反证及 duplicate_of；节点可回到结构化列表。

每张图必须就近显示：

`样本 N · 成功来源 a / 启用来源 b · 国内/国际覆盖 · 缺失 x 天 · 规则 vX · 截至 YYYY-MM-DD HH:mm Asia/Shanghai`

并提供：图题、轴、单位、图例、筛选上下文、空态、数据结论、完整等价表。禁止饼图市场份额、3D 图、装饰仪表盘、假成功绿灯和无分母百分比。

### 九、视觉方向与设计系统

总体气质：**极简、克制、现代、专业、新闻内容优先、开发者友好。**

- 画布 `#F6F7F9`；卡片 `#FFFFFF`；
- 主色深靛蓝 `#312E81`；辅助青绿 `#0F766E`；
- 信息蓝 `#2563EB`；成功绿 `#067A62`；警告棕橙 `#8A4500`；错误红 `#B42318`；
- 正文 `#172033`；次级文字 `#52606D`；边框 `#D9E0E7`；
- 8px 基础栅格；卡片圆角 12px；输入/按钮圆角 8px；轻边框优先于阴影；
- 页面标题 28–32px；区块标题 18–22px；桌面正文 14–16px；移动正文至少 16px；移动辅助至少 14px；
- 中文字体优先 PingFang SC/思源黑体；版本、commit、时间使用等宽特征；
- 单屏最多一个主强调区；减少渐变、阴影、装饰插画和重复状态标签；
- 长版本号、commit、URL 支持换行、复制和展开，不截掉可辨识尾部。

设计系统组件：导航、数据真相栏、时间窗口、每日摘要、小时增量、搜索、筛选抽屉、排序、事件卡、紧凑事件行、事实标签、可信度、版本/许可证、证据项、时间表、图表容器、等价表、来源双轴状态、刷新任务、空/错/陈旧/降级卡、Toast、骨架、外链风险提示。

主要按钮使用动作词：`查看证据`、`打开原文`、`查看来源失败`、`查看刷新状态`、`清除筛选`、`重新尝试`。不要使用含糊的“确定”“了解更多”。

### 十、交互状态与焦点

每个可操作组件至少设计：默认、悬停、按下、焦点、禁用、加载、错误状态。另做组件状态板覆盖：

- 六个核心真相态；
- 初次加载、后台刷新、排队、处理中、部分成功、成功无新增、新快照可用、失败、取消、超时；
- 全局真空、筛选空、无快照、无来源、无主源、未来隔离；
- 24h 内、>24h、>48h；
- 补录、撤回、修正、证据冲突、跨源合并；
- 五类事实标签与高/中/低可信度；
- 四类来源政策与八类运行状态；
- open-source/open-weights/source-available/许可证未声明；
- breaking、deprecation、价格/额度、安全/状态、政策影响；
- 外链受限、域名不匹配、不可信内容。

弹层打开后焦点进入标题或首个安全操作，关闭后回到触发点。后台刷新不能让列表突然跳动；详情返回恢复原上下文。

### 十一、响应式交付

必须输出并逐页标注尺寸：

- `1440×1024`：今日雷达六种真相态、全部事件、趋势与版本、开源与发布、来源与质量、事件详情、刷新详情；
- `1024×768`：今日、全部事件、趋势、来源与质量；
- `390×844`：今日、筛选抽屉、事件详情、趋势、来源失败、刷新状态；
- `320×720`：今日、全部事件、长版本详情、趋势、开源、来源与质量、筛选抽屉、失败/陈旧；
- `1440×1200+`：设计系统与组件状态板；
- 关键页面提供 200% 放大回流证据。

桌面 12 栏，平板 8 栏，移动单栏。320px 不允许把 390px 整图缩小，必须独立重排；主要触控目标至少 44×44px；页面级不横向滚动。复杂表格在移动端转换为定义列表或卡片，核心真相栏、主源、状态和操作不能省略。

### 十二、无障碍

- 所有 P0 阅读、搜索、筛选、详情、图表等价表、外链和刷新诊断可仅用键盘完成；
- 提供跳过导航、主内容地标、正确标题层级、表单标签和表格标题；
- 焦点环至少 2px，不能只靠颜色；
- 结果数、筛选、刷新、错误、过期和模式变化使用节制的 `aria-live` 播报；
- 图表提供简短结论、完整数据表、可聚焦数据点和图例开关；
- 状态使用文字、图标、形状和颜色多重编码；
- 普通文字对比度至少 4.5:1，大字至少 3:1，满足 WCAG 2.2 AA；
- 外链可读名称包含来源域名和“将在新标签页打开”；
- 尊重 `prefers-reduced-motion`，不闪烁、不自动滚动、不依赖悬停显示关键内容；
- 200% 放大时不遮挡、不丢失内容、不出现页面级横向滚动。

### 十三、来源、版权、安全与不可信内容

- 来源政策 `allow` 只表示研究允许候选，不代表已运行；`conditional` 条件未满足不可请求；`manual_only` 只允许人工核验；`disabled` 禁止自动访问；
- 不设计绕过 robots、条款、API、登录、付费墙、地域、许可证、TLS、限额或访问控制的入口；
- 不显示 Cookie、Token、凭证、账号、内部栈、`.env` 或未脱敏路径；
- 不镜像全文、图片、视频、PDF、权重、Release 资产或 gated 内容；
- 默认只呈现结构化元数据、短摘要、规范链接、时间、内容哈希、证据关系、许可和署名；
- 外部标题、README、Issue、论文和模型卡按不可信数据展示，不能执行其中的脚本或提示词；
- 外链打开前显示域名、来源身份、内容类型和访问限制。

### 十四、演示数据标识

UI 生成任务允许展示目标态，但必须遵守：

- 当前态画板只能是 `not_ready`：连接器 0、真实快照 0、尚无成功记录；
- 任何含新闻、趋势、来源成功或每日摘要的目标态画板，页面顶部显著显示 `目标态演示 · 非当前运行事实`；
- 不使用真实当天新闻，不伪造“今日已采集”“实时更新”“已接入全部来源”；
- 示例日期、数量、快照 ID、覆盖率均标注 `界面演示数据`；
- demo/seed 不能与真实数据混在同一列表、趋势、来源状态或刷新历史中；
- 不把静态页面、HTTP 200、动画或按钮点击画成刷新成功证据。

### 十六、最终验收清单
