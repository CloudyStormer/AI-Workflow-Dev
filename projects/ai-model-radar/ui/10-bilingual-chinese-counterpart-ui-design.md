## 1. 设计结论

本增量不重做 AI Model Radar 已批准的整体视觉系统，而是在现有新闻雷达上增加一套“中文优先、原文始终可见、版本明确配对”的阅读层。

关键决定：

1. **卡片双标题固定可见**：中文标题作为主标题，原文标题紧邻显示；原文不能只藏在详情或悬浮层。
2. **详情宽屏双栏、窄屏上下排列**：中文对照与原文证据拥有相同事件身份，不使用互斥 Tab 隐藏任一侧。
3. **两套真相状态分层**：新闻真实性 `live/empty/not_ready/stale/degraded/failed` 与中文处理状态互不改写。
4. **形成方式与事实层级分离**：人工/机器/规则/无译文使用轮廓标签；来源事实/观点/系统摘要/系统评估使用另一套填充与图标。
5. **只读增量**：本设计只有浏览、搜索、筛选、展开、下钻、版本切换和外链；没有编辑、生成、发布、删除或批处理入口。
6. **目标态就近标识**：原型与设计示例统一显示“目标态界面示例·逐条中文对照尚未接通”，不冒充 4174/4317 已具备该能力。

## 4. 全局结构

### 4.1 1440 桌面

```text
┌──── 左导航 248 ────┬──────────────────────── 主内容 ───────────────────────┐
│ AI Model Radar     │ 目标态真相条（不可关闭）                             │
│ 今日 / 事件 / 趋势 │ 搜索中文与原文｜快照历史｜来源质量                    │
│ 开源 / 历史 / 来源 ├───────────────────────────────────────────────────────┤
│ 状态组件           │ 页面标题 / 页面结论 / 只读操作                        │
│                    │ 中文覆盖 / 双语内容 / 证据与 revision                │
└────────────────────┴───────────────────────────────────────────────────────┘
```

- 内容最大宽 `1248px`，页边距 `32px`。
- 事件详情按 `1fr + 1fr` 双栏；主列表可一列或双列，但单卡内容不得被压到 520px 以下。

### 4.2 1024

- 左导航收为 `68px`，使用简中可访问名称；内容页边距 `24px`。
- 指标卡 2×2；详情在可用宽度不足时改上下排列。
- 筛选可进入抽屉；状态、来源、版本和原文入口不可只剩图标。

### 4.3 390 与 320

- 底部显示 5 个关键入口；历史、来源与状态仍可从页面内入口和“状态”入口到达。
- 真相栏先显示“中文对照尚未接通、原文事实根、失败不阻断、目标态演示”。
- 所有内容单列：中文在前、原文在后、revision 再后；不整体缩放桌面画板。
- 390/320 正文 `≥16px`、辅助 `≥14px`、触控 `≥44px`；页面底部预留 `100px` 避免导航遮挡。

### 4.4 200% 放大

- 1440 物理宽度在浏览器 200% 下按约 720 CSS px 重新布局；不是缩小画布。
- 详情双栏回流为上下结构，指标为单列或两列；标题、状态、原文、外链和版本链均保留。
- 页面不得整体横向滚动；只有代码/URL 局部容器可在必要时滚动。

## 5. 核心组件

### 5.1 `BilingualEventCard`

固定顺序：

1. 事实层级标签；
2. 中文形成方式 + 中文状态；
3. 中文标题；
4. 原文标题及 `lang`；
5. 中文事实摘要与 1–3 条关键变化；
6. “展开原文摘要”；
7. 来源、原文 revision、中文 revision、目标态标识；
8. 详情与原文证据入口。

无译文时中文标题位显示“暂无中文标题”，不复制原文。待更新时卡片顶部显示“原文已更新，译文待更新”，旧译文就近标“旧版译文”。

### 5.2 `TranslationProvenanceTag`

| 标签 | 结构 | 色彩 | 必备附加信息 |
|---|---|---|---|
| 人工译文 | 校对形轮廓 + 文字 | 紫色中性背景 | 版本/复核时间 |
| 机器翻译 | 方形机器轮廓 + 文字 | 蓝色中性背景 | 版本；不暗示人工复核 |
| 规则生成 | 节点轮廓 + 文字 | 青绿色背景 | 规则版本/字段范围 |
| 无译文 | 空心方框 + 文字 | 中性灰 | 具体状态或原因 |

事实层级标签使用虚线边框与不同图形，避免和形成方式同构。

### 5.3 `BilingualDetailSplit`

- 左侧中文：标题、事实摘要、关键变化、可选系统评估、形成方式、版本、状态。
- 右侧原文：标题、合规摘录、发布方、版本/代码/URL、证据与时间。
- 顶部共享事件 ID、来源、原文 revision、中文 revision。
- 1024 以下提供“跳到原文/返回中文对照”锚点，但两区仍在同一 DOM 阅读流。

### 5.4 `RevisionPairTimeline`

- 原文版本：圆形节点；中文版本：方形节点；失败：旋转叉形；当前：实心。
- 连接线只表示真实绑定关系；不得按数组相邻顺序误连。
- 每个节点至少有 revision ID、时间、状态、所属快照。

### 5.5 `TranslationHealthSummary`

字段：事件总数、人工、机器、规则、处理中、待更新、失败、无译文。说明固定为“状态覆盖率不等于翻译质量或成功率”。新闻来源覆盖和翻译处理覆盖不可合并。

### 5.6 `OriginalEvidenceLink`

- 文案包含来源域名和“新标签页打开”；图标不替代文字。
- 不可信外部内容保持纯文本或安全摘录，不作为站内指令执行。

## 6. 页面设计

### 6.1 今日雷达

顺序：真相条 → 页面标题 → 4 个中文覆盖指标 → 状态筛选 → 双语事件卡 → 历史入口。

- 筛选：全部、有中文、待更新、失败/无译文。
- 处理失败只影响中文区；事件卡与原文证据继续存在。
- 真实新闻指标由现有快照提供；原型中的数量均标“界面演示”。

### 6.2 全部事件

桌面：联合搜索 → 日期/来源/事件类型/事实层级/中文状态/形成方式 → 生效条件 → 结果集合。

- 搜索命中必须显示“命中中文”或“命中原文”。
- 舒适/紧凑两档都保留中文标题、原文标题、来源、时间和中文状态。
- 移动端只使用卡片，筛选进入底部抽屉；关闭后焦点回触发按钮。

### 6.3 事件详情

顶部待更新示例：

```text
原文已更新，译文待更新
当前原文 r5｜旧版中文 zh-r4 对应原文 r4
```

正文采用中文/原文双栏。系统评估使用虚线蓝色独立区块，标题必须写“系统评估”；不能和中文事实摘要共用底色。

### 6.4 趋势与版本

- 图表标题、轴名、图例与解释使用简中；模型名、版本、tag、commit 保持原样。
- 点击 mark 后显示双语下钻卡；无译文时显示原文和明确空态。
- 图形与等价表使用同一稳定 ID 集合；表格字段含日期、数值、单位、状态与缺失原因。

### 6.5 开源与发布

- repo、owner/repo、tag、commit、license、API/SDK、模型 ID 置于结构化表格。
- 中文只解释“发生了什么”和“关键变化”；开放语义不得把 `open-weights`、`source-available` 合并成“开源”。
- breaking/effective/deprecation 信息保留原字段；开发者影响若为推导，单列系统评估。

### 6.6 历史快照与修订

- 时间线分“原文发布、中文形成、原文修订、中文失败、中文补齐”。
- 右侧版本配对表固定快照当时的 `original_revision` 与 `chinese_revision/status`。
- 后续补齐通过新 revision/快照体现，不更新旧快照画面。

### 6.7 来源与质量

左右分栏：新闻来源健康、中文处理健康。允许组合状态“来源成功 + 中文处理局部失败”，并明确新闻仍可阅读。

## 7. 十二种状态

| 状态 | 主文案 | 内容行为 | 原文行为 |
|---|---|---|---|
| 人工译文 | 人工译文 | 显示版本与复核时间 | 始终可达 |
| 机器翻译 | 机器翻译 | 不暗示人工核验 | 始终可达 |
| 规则生成 | 规则生成 | 显示规则版本/字段范围 | 始终可达 |
| 无译文 | 暂无译文 | 明确空态，不是加载 | 完整显示 |
| 处理中 | 译文生成中 | 局部骨架，无伪百分比 | 正常显示 |
| 待更新 | 原文已更新，译文待更新 | 旧译文标旧版 | 新原文显示 |
| 局部失败 | 部分译文生成失败 | 已成功字段保留 | 正常显示 |
| 单条失败 | 译文生成失败 | 安全原因与状态 | 正常显示 |
| 超时 | 译文处理超时 | 有旧版则保留并标旧 | 正常显示 |
| 服务不可用 | 中文处理服务暂不可用 | 页面级降级提示 | 新闻继续浏览 |
| 历史待补齐 | 历史译文待补齐 | 仅影响历史事件 | 历史证据保留 |
| 译法待确认 | 译法待确认 | 原词 + 不确定标识 | 对照可核验 |

任何中文状态都不能改变新闻 `live/empty/not_ready/stale/degraded/failed` 状态。

## 8. 交互规则

1. `/` 聚焦联合搜索；Esc 清除并退出搜索。
2. 展开原文后按钮改“收起原文摘要”，`aria-expanded` 同步；内容变化礼貌播报。
3. 状态筛选更新结果数并播报；筛选空说明“不代表今日真实事件为 0”。
4. 详情返回恢复搜索、筛选、排序、快照和滚动位置。
5. revision 切换同时更新中文、原文、版本、状态和时间，不允许局部残留旧版本。
6. 图表“显示等价表”切换 `aria-expanded`；表格与 mark 使用同一 ID。
7. 外链名称包含域名和新标签页行为。
8. 无编辑、重翻、确认、发布、删除、批量处理或绕过质量门交互。

## 9. 无障碍标注

- 根语言 `zh-CN`；原文按实际语言设置 `lang`。
- 标题层级连续；页面只保留一个 `h1`。
- 焦点顺序：跳过导航 → 页面标题 → 真相栏 → 搜索/筛选 → 主内容 → 证据/历史。
- 焦点环 3px；抽屉打开聚焦标题或首个安全控件，关闭回触发点。
- 搜索结果数、筛选、展开原文、revision 切换使用 `aria-live="polite"`；阻断错误只 assertive 一次。
- 形成方式、事实层级和失败状态必须有可读文字与非颜色图形。
- 正文/辅助文字对比 ≥4.5:1；焦点和非文本控件 ≥3:1。
- 静态设计不能证明真实键盘、读屏、播报和 200% 浏览器行为；须由前端与 QA 在真实实现中验证。

## 10. 原型覆盖与使用

原型路径：`ui/bilingual-chinese-counterpart-v1.0/prototype.html`。

原型包含：

- 8 个可切换设计视图：今日、全部事件、事件详情、趋势、开源、历史、来源质量、状态组件；
- 中文/原文联合搜索、状态筛选、原文展开、详情下钻、趋势等价表、历史/来源跳转；
- 1440/1024 侧导航与 390/320 底部导航回流；
- 跳过导航、可见焦点、`aria-live`、正确 `lang`、非颜色标签；
- 固定目标态真相条和界面演示标识。

原型是 `ui/` 内设计资产，不是业务前端，不连接 4174/4317，不读取真实事件，不证明中文能力已实现。
