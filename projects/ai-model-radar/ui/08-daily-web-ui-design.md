## 1. 设计结论

本设计把 AI Model Radar 固定为“真实快照优先的只读 AI 开发新闻产品”。用户进入任何页面，先确认数据模式、日期、快照和新鲜度，再阅读事件、证据与修订；刷新只是受控请求，不暗示一定成功。

当前真实事实仍是：`/today` 未接入真实批次，运行时连接器 0、live 快照 0、业务数据写入 0。因此当前默认画面只允许 `not_ready`；本文中的新闻、正数覆盖、成功快照和趋势均属于 **目标态演示 · 非当前运行事实**。设计说明不是网页实现、数据接入或服务完成证明。

本轮不生成外部图片。线框、组件、状态、响应式和无障碍均在本文给出，前端可直接据此实现；历史 9 张图片和 `release-completeness-v1/` 只提供视觉语言参考。

## 2. 体验原则

1. **真相先于内容**：每个 P0 页面先出现不可关闭的真相栏。
2. **日期不可漂移**：今日、过去 24 小时、历史日期分别绑定明确快照。
3. **失败保旧**：刷新失败不清空、不移动 current pointer、不更新 `as_of`。
4. **历史只追加**：快照与 revision 均不可变，修订用关系链表达。
5. **状态一义**：未就绪、真实空、无新增、过期、降级、失败分别设计。
6. **内容优先**：减少解释段落；用短摘要、时间线、证据关系和等价表表达。
7. **只读边界**：不出现收藏、编辑、删除、发布、启用来源或数据库管理。

## 5. 全局组件规范

### 5.1 全局真相栏 `TruthBar`

固定字段顺序：状态中文名 → 数据模式 → 快照日期/ID → `as_of` → 最近成功 → 来源成功/应运行 → 失败来源 → 新鲜度 → 详情入口。

当前态文案固定为：

> 数据未就绪｜当前页面尚未接入真实已发布快照｜连接器 0｜live 快照 0｜尚无成功记录

- 高度：桌面自适应最小 64px；移动不设固定高度，按 2–4 行回流。
- `not_ready` 不显示 0% 覆盖、绿色灯或虚构时间。
- 目标态页面左上必须出现“目标态演示 · 非当前运行事实”。

### 5.2 控件

| 组件 | 默认 | 焦点/键盘 | 加载/禁用 | 错误/反馈 |
|---|---|---|---|---|
| 搜索框 | 40px，高度内含清除 | 3px 外焦点环；`/` 聚焦 | 搜索中保留输入 | 结果数由 `aria-live=polite` 播报 |
| 日期/快照选择器 | 日期 + 快照 ID 两段 | 方向键移动，Enter 选择 | 未就绪时仅可查看口径 | 未来日期隔离并说明原因 |
| 刷新按钮 | 次级描边按钮 | Enter/Space 触发一次 | 运行中、冷却中禁用重复提交 | Toast + 运行详情链接 |
| 筛选抽屉 | 已生效数量可见 | 开启聚焦标题，关闭回触发点 | 数据加载中保留条件 | 筛选空提供清除条件 |
| 外链 | 来源域名 + 外链图标 | 可聚焦，名称含“新标签页打开” | 不可用时保留来源文字 | 风险来源先提示 |
| 复制按钮 | 复制 ID/URL | Enter/Space | 无内容禁用 | 成功 Toast，不抢焦点 |

### 5.3 内容组件

- `EventCard`：标题、发布方、地区、分类、发布状态、时间三元组、事实标签、开发者影响、主源域名。
- `SnapshotCard`：自然日、snapshot ID、事件数、覆盖、失败数、`as_of`、current-at-that-time。
- `RevisionTimeline`：新增=实心圆、修订=方形、撤回=叉形、恢复=菱形；每个节点含时间与快照。
- `EvidenceItem`：主源/佐证/传播线索/反证/重复，显示独立性和时间。
- `StatusPanel`：状态标题、一句话原因、影响范围、可执行下一步、诊断入口。
- `ChartFrame`：图题、口径、图例、可视图、结论、完整等价表开关。

## 6. P0 页面设计与线框

### 6.1 今日雷达 `/today`

```text
┌ 真相栏：数据未就绪 / 模式 / 快照 / 覆盖 / 刷新详情 ┐
├ 今日雷达                         [日期] [刷新]       ┤
│ 今天｜过去24小时      一句话真实摘要                │
├──────────────────────────────────────────────────────┤
│ not_ready：未接入真实快照                           │
│ [缺失链路：持久化] → [质量门] → [发布]              │
│ [查看来源与质量] [查看数据口径]                     │
├──────────────────────────────────────────────────────┤
│ 历史日期入口 / 最近刷新请求（若真实存在）            │
└──────────────────────────────────────────────────────┘
```

目标 `live` 画板在真相栏上方显著标“目标态演示”。内容顺序：真相栏 → 4 个指标 → 一句话摘要 → 事件卡列表 → 来源缺口 → 历史入口。指标只允许正式事件、预发布、需行动、来源成功/应运行；数字都链接到对应集合。

### 6.2 历史快照 `/history`

```text
┌ 真相栏 ┐
├ 历史快照      [日历/列表] [日期范围]                ┤
│ 日期列表 4栏  │ 当日快照链 8栏                     │
│ 08-25  1快照  │ snap-001 → snap-002(current-at-time)│
│ 08-24  无快照 │ 新增 / 修订 / 撤回 / 合并          │
│               │ [查看相邻差异] [打开快照详情]       │
└──────────────────────────────────────────────────────┘
```

- “无成功快照”使用空心虚线节点，不等于 0 事件。
- 补录同时显示事实发生日与发现日；未来时间进入隔离区。

### 6.3 快照详情 `/snapshots/:snapshotId`

两栏布局：左 8 栏为事件集合与差异，右 4 栏为不可变元数据。固定显示 snapshot ID、自然日、`as_of`、发布时间、内容哈希、规则版本、来源覆盖、失败来源、前一快照、refresh run。无编辑、删除或设为 current 操作。

### 6.4 事件详情 `/events/:eventId`

```text
┌ 标题 + 原始标题 + 发布状态 + 修订状态               ┐
├ 发生了什么 ─ 为什么重要 ─ 开发者动作                ┤
├ 事实区 8栏                         时间契约 4栏       ┤
├ 证据关系图 8栏                     来源清单 4栏       ┤
├ Revision 时间线 / 出现于哪些快照                    ┤
└ 原文链接（域名 + 新标签页提示）                     ┘
```

事实、发布方观点、角色评估、待核验四区不得混写；置信度与重要性分别显示。撤回保留旧版本入口和原因。

### 6.5 全部事件 `/events`

桌面：搜索与紧凑筛选行 → 生效条件 → 结果数 → 表格/卡片切换 → 事件集合。移动只用卡片，筛选进入全屏抽屉。全局无快照、未就绪、筛选空、真实空、过期、降级、失败各有独立面板。

### 6.6 刷新运行详情 `/refresh/:runId`

主区使用九阶段时间线：受理 → 校验 → 取得/导入 → 规范化 → 去重/revision → 持久化 → 质量门 → 发布 → pointer 更新。右栏显示请求 ID、幂等键、触发方式、时间、来源分母、成功/失败/跳过、新增/修订/撤回/合并/隔离、生成快照或“未发布新快照”。

刷新失败时页面底部固定提供“继续阅读上次成功快照”（有旧快照）或“查看未就绪原因”（无旧快照）。不提供绕过质量门。

### 6.7 来源与质量 `/sources`

顶部短句：“来源政策允许不等于运行已接通”。主体分三层：

1. 来源政策 × 运行状态矩阵；
2. 来源行：身份、地区、类型、入口、政策、应运行、最近尝试/成功、连续失败、错误、遗漏窗口；
3. 质量门：输入 → 权利/字段/时间 → 主源 → identity → 去重/revision → 发布快照。

当前态只显示连接器 0、live 快照 0 和“尚无真实运行记录”，不画成功率。

### 6.8 趋势与版本、开源与发布

- 趋势标题固定“本雷达已接入来源样本趋势”；提供 7/30/90 日、样本 N、覆盖、缺失日、规则版本、`as_of` 和等价表。
- `runtime=0` 时不画线，只显示指标定义和未就绪原因。
- 开源卡固定字段：身份、版本/tag/commit、开放语义、许可证、发布时间、生效/弃用、主源、证据角色、开发者动作。

## 7. 真相状态矩阵

| 状态 | 图标/形状 | 主文案 | 内容区 | 主动作 |
|---|---|---|---|---|
| `not_ready` | 空心断链圆 | 数据未就绪 | 不显示事件或 0% | 查看缺失链路 |
| `refreshing` | 分段进度环 | 正在刷新 | 保留旧快照；无旧快照显示骨架 | 查看运行详情 |
| `live` | 实心勾方块 | 今日真实数据已发布 | 当日真实事件 | 查看新增 |
| `no_new_items` | 横线圆 | 本次刷新无新增 | 保留当前快照 | 查看历史 |
| `empty` | 带勾空框 | 本日无符合标准的事件 | 无柱、无旧事件 | 查看检查范围 |
| `degraded` | 缺口六边形 | 部分来源失败 | 成功内容 + 失败范围 | 查看失败来源 |
| `stale` | 沙漏方框 | 当前仅有过期快照 | 真实旧日期 + 错误原因 | 查看最近成功 |
| `failed` | 叉形八边形 | 本次刷新失败 | 保旧或无旧快照分支 | 查看错误详情 |

补充状态：首次加载、离线、排队、同日复用、冷却、校验失败、质量门失败、发布失败、筛选空、无主源、证据冲突、未来时间隔离、补录、修订、撤回。

## 8. 图表与等价表契约

所有图形与表格读取同一个结构化集合；视觉 mark 与表格记录以稳定 ID 双向对应。

| 图形 | 视觉结构 | 必备字段 | 空/未就绪行为 |
|---|---|---|---|
| 刷新生命周期 | 九节点时间线 | stage_id、时间、状态、原因 | 未运行显示定义，不画成功节点 |
| 快照追加链 | 有向节点链 | snapshot_id、previous、current、状态 | 失败 run 不生成节点 |
| 日期×快照矩阵 | 行列矩阵 | 日期、快照、事件数、覆盖、失败 | 无快照=虚线；真实0=带勾空框 |
| Revision 时间线 | 多形状节点 | revision_id、类型、时间、快照 | 无修订显示“仅初版” |
| 相邻快照差异 | 分类条 + 数字 | 新增、修订、撤回、合并、无变化 | 不可比时不画差值 |
| 来源运行结果 | 分组条 | 来源、应运行、成功/失败/跳过 | 未就绪不算成功率 |
| 新鲜度带 | 时间带 | as_of、最近成功、当前、阈值 | 无成功记录不画时间带 |
| 事件—证据关系 | 中心辐射关系 | event_id、evidence_id、角色、独立性 | 无主源进入阻断态 |

等价表逐项含 ID、字段、值、单位、状态、来源、缺失原因；图例、筛选和结论也必须可用键盘访问。

## 9. 响应式规则

### 1440×1024

- 12 栏；主内容 8 栏 + 上下文 4 栏。
- 今日八态、历史、快照、事件、全部事件、刷新、来源质量均有完整桌面布局。

### 1024×768

- 8 栏；导航 64px；详情元数据移到主内容下方。
- 今日、历史、事件详情、刷新详情必须完整，表格允许横向容器滚动但页面不得横向滚动。

### 390×844 与 320×720

- 两个宽度分别重排，不整体缩放。
- TruthBar 变为状态标题 + 关键四字段 + “展开全部”。
- 事件卡一列；时间三元组改定义列表；长 URL 断行。
- 390 正文 ≥16px、辅助 ≥14px；320 同标准；触控 ≥44px。
- 底部导航不遮挡内容，页面尾部预留 88px 安全区。

### 200% 浏览器缩放

- 1440 的有效 CSS 视口按 720px 回流为单/双列；不做画布缩放。
- 标题、正文、间距和控件随浏览器缩放；内容、真相栏、错误原因和等价表入口均保留。
- 无文字裁切、组件互撞或页面级横向滚动。

## 10. 键盘与辅助技术

1. 跳过导航 → 页面标题 → 真相栏详情 → 全局控件 → 主内容 → 侧栏。
2. 搜索、日期、筛选、事件、图表等价表、刷新和外链全部可键盘完成。
3. 抽屉/弹窗打开聚焦标题或首个安全控件；关闭后回触发点；Esc 可关闭非阻断浮层。
4. 刷新受理、状态变化、新快照、结果数、错误与陈旧使用节制的 `aria-live=polite`；阻断错误使用 `assertive` 一次。
5. 后台刷新不抢焦点、不自动滚动、不突然重排已读列表；新快照以可操作通知提示切换。
6. 图表有标题、摘要、完整数据表和非颜色图例；外链名称含域名和“新标签页打开”。
7. 正文对比度 ≥4.5:1，大字/非文本控件 ≥3:1；焦点环 3px 且与相邻颜色 ≥3:1。

## 11. 可实现交互流程

### 流程 A：今日 → 事件证据 → 返回

打开今日 → 读取真相栏 → 打开事件 → 查看事实/证据/revision → 打开原文 → 返回后恢复快照、位置与筛选。

### 流程 B：刷新失败保旧

触发刷新 → 按钮进入已受理/禁重复 → 查看运行详情 → 质量门失败 → 不生成快照、不移动 pointer → 继续阅读旧快照并保留旧日期。

### 流程 C：历史快照对比

打开历史 → 选择日期 → 选择两个相邻快照 → 查看新增/修订/撤回/合并 → 下钻事件 → 返回对比上下文。

### 流程 D：来源失败诊断

从 TruthBar 打开来源质量 → 查看政策轴与运行轴 → 展开失败来源 → 查看错误码、最近尝试和遗漏窗口 → 返回原页面。

## 12. 演示与真实数据标识

- 当前态画面：只允许 `not_ready`，不含新闻卡、成功覆盖、成功趋势或最近成功。
- 目标态画面：顶部固定“目标态演示 · 非当前运行事实”。
- 2026-08-25 的 6 条核验输入：只可标“已核验输入，尚未接入网页与业务库”。
- 示例 snapshot ID、时间、覆盖和数量：逐项标“界面演示数据”。
- Demo/seed 不进入真实快照列表、趋势、刷新历史或 current pointer。

## 13. 前端交付标注

实现时每个页面应有：路由、页面标题、TruthBar、加载/空/错误边界、可恢复返回上下文、结构化图表数据和等价表。本文不指定框架或图表库；不得用静态图片代替可访问图表，也不得用前端硬编码将 `not_ready` 伪装成 `live`。

静态设计无法证明真实键盘行为、`focus-visible`、`aria-live`、浏览器 200% 回流或数据双向等价；这些必须由前端实现与 QA 在真实浏览器验证。
