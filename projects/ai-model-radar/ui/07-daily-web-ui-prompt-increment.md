## START OF DESIGN PROMPT

你是一名资深中文新闻产品与数据产品 UI/UX 设计师。请为 **AI Model Radar（AI 开发圈新闻雷达）** 设计一套极简、干净、可信、可追溯、可开发的响应式 Web UI 增量，把“已核验批次如何成为真实网页快照”表达清楚。

核心体验是：

**打开 `/today` → 一眼确认今天是否真的有已发布快照 → 阅读真实事件 → 查看原始证据与修订 → 回看历史 → 理解刷新、失败与保旧状态。**

全部导航、操作、状态、筛选、图表、错误、空态和无障碍文案使用完整简体中文。模型名、API、SDK、tag、commit、canonical URL、snapshot ID 等专有字段可保留原文，但必须有中文字段名与解释。

### 一、不可妥协的设计原则

1. **真实优先。** 页面只把来自真实持久化且已发布不可变快照的内容称为今日或历史新闻。
2. **默认去 Demo。** 真实模式中 Demo、seed、mock、硬编码卡片数量必须为 0；不得在接口失败时静默回退 Demo。
3. **日期不漂移。** “今日”按 `Asia/Shanghai` 自然日与快照日期判断。往日批次只进入历史，不沿用为今日。
4. **失败保旧。** 新批次失败时保留上次成功快照及原日期，不清空列表、不移动 current pointer、不伪造 `as_of`。
5. **历史只追加。** 新成功批次创建新快照；修订、撤回和补录创建新 revision 或审计记录，不静默覆盖旧事实。
6. **少文字、多结构。** 用紧凑真相栏、状态卡、时间线、差异标记、证据关系和短摘要替代大段说明。
7. **状态含义唯一。** `empty`、`not_ready`、`no_new_items`、`stale`、`degraded`、`failed` 不得共用同一个“暂无数据”画面。
8. **状态不只靠颜色。** 同时使用中文文字、图标、形状、边框和位置；每张图表提供完整等价表格。

### 二、全局信息架构

沿用 AI 开发圈新闻产品的五个一级导航：

1. **今日雷达**：默认入口 `/today`；
2. **全部事件**：真实已发布事件的跨日期查询；
3. **趋势与版本**：只展示已接入来源样本趋势；
4. **开源与发布**：有一手发布证据的版本事件；
5. **来源与质量**：来源覆盖、运行状态、质量门与刷新记录。

本增量新增或强化的上下文入口：

- **历史快照**：按日期、快照和当时覆盖回看；
- **事件详情**：事实、证据、时间、revision 与撤回链；
- **刷新运行详情**：请求、来源结果、质量门、发布结果；
- **快照详情**：snapshot ID、日期、`as_of`、`published_at`、事件集合、覆盖和失败情况；
- **数据口径**：当前模式、日期规则、失败保旧、历史不可变说明。

不要设计账号、收藏、稍后读、编辑、删除、发布、来源启用、数据库管理或其他写操作。本阶段是单用户只读新闻与诊断体验；唯一主动动作是受控的“刷新请求”，其 UI 只能表达请求与状态，不能承诺成功。

### 三、全局真相栏

每个 P0 页面顶部放不可关闭的紧凑真相栏，显示：

- 页面状态中文名；
- 数据模式：`真实服务` / `上次成功快照` / `目标态演示`；
- 快照日期与 `snapshot_id`；
- `as_of`、`published_at`、最近成功时间，均标 `Asia/Shanghai`；
- 快照年龄与是否超过新鲜度阈值；
- 成功来源数 / 应运行来源数、失败来源数；
- 是否正在刷新、触发方式和请求时间；
- `查看刷新详情`、`查看来源与质量`入口。

当前真实画板必须显示：

**“数据未就绪｜当前页面仍为 Demo，尚未接入真实已发布快照｜连接器 0｜live 快照 0｜尚无成功记录”**

当前画板不得显示示例新闻、0 条成功空榜、成功覆盖率、绿色运行灯或虚构最近成功时间。

### 四、真相状态与页面行为

| 内部状态 | 用户可见中文 | 页面行为 |
|---|---|---|
| `not_ready` | 数据未就绪 | 导入、持久化、发布或真实查询链任一未完成。解释缺失环节，不显示 Demo 或成功空态。当前默认态。 |
| `refreshing` | 正在刷新 | 保留上次成功快照；显示受理时间、触发方式、阶段与“继续阅读上次快照”。无上次快照时只显示刷新状态骨架，不造新闻。 |
| `live` | 今日真实数据已发布 | 仅在当日真实运行通过质量门并发布快照后成立；显示今日事件、自上次查看新增、`as_of`、最近成功和覆盖。 |
| `no_new_items` | 本次刷新无新增 | 刷新真实成功但新增合格事件为 0；保留当前成功快照与历史入口，不复制旧闻为新增。 |
| `empty` | 本日无符合标准的事件 | 当日真实查询和来源检查成功且最终事件为 0；显示检查范围、`as_of` 和“不凑数”。不得与未就绪混用。 |
| `degraded` | 部分来源失败 | 剩余真实结果通过质量门；显示可读内容、失败来源、覆盖缺口、遗漏窗口与上次成功。 |
| `stale` | 当前仅有过期快照 | 只有上一成功快照且超过阈值；显著显示真实旧日期、快照年龄和失败原因，不称今日或最新。 |
| `failed` | 本次刷新失败 | 必要环节或全部来源失败，未发布新快照；current pointer 不变。若有旧快照继续只读展示并标日期，无旧快照则引导查看失败详情。 |

补充状态：首次加载、离线、请求排队、同日请求复用、冷却中、输入校验失败、规范化失败、质量门失败、发布失败、部分成功但未过质量门、新快照可用、筛选空、无主源、证据冲突、未来时间隔离、补录、修订、撤回。

必须遵守：

- `empty` = 真实查询成功且本日确实为 0；
- `filter-empty` = 当前筛选无匹配，可清除筛选；
- `not_ready` = 无法完成可信查询，不能推导为 0；
- `no_new_items` = 本次刷新没有新增，但可能仍有当前快照内容；
- `failed` = 真实请求执行失败；
- `stale` = 有已核验旧快照，但新鲜度不合格。

### 五、核心页面设计

#### 1. `/today` 今日雷达

从上到下：

1. 全局真相栏；
2. `今天` 与 `过去 24 小时`窗口及固定快照上下文；
3. 刷新状态条：自动首次互动触发 / 手动触发 / 同日复用 / 冷却；
4. 一句真实摘要与“自上次查看新增 N 条”；
5. 指标：本日正式事件、预发布、需行动、成功来源 / 应运行来源、失败来源；
6. 事件列表；
7. 上次成功与历史日期入口；
8. 来源缺口、运行详情与数据口径。

事件卡至少显示：中文标题、发布方、分类、国内/国际、发布状态（预发布/稳定/GA 等）、`published_at`、`observed_at`、事实/评估边界、开发者影响、canonical 原文域名与“新标签页打开”。

分别设计：当前 `not_ready`、`refreshing`（有/无旧快照）、目标 `live`、`no_new_items`、真实 `empty`、`degraded`、`stale`、`failed`（有/无旧快照）。

目标态如使用 2026-08-25 的 6 条核验事实，只能放在“2026-08-25 历史快照”或明确的设计演示画板，并标：

**“目标态演示 · 基于 2026-08-25 已核验输入 · 尚未接入网页与业务库”**

#### 2. 历史快照

提供日历/日期列表与快照列表两种视角：

- 每日显示成功快照数量、事件数、最后发布时间、来源覆盖、失败数和状态；
- 日期详情显示当日所有不可变快照、current-at-that-time 标记和 refresh run；
- 可对比相邻快照的新增、修订、撤回、合并与无变化；
- “今天发现的补录”回到事实发生日，并显示发现日；
- 未来时间数据进入隔离，不进入今日、历史统计或趋势。

旧快照只能查看，不能编辑或删除。页面必须让用户清楚“现在的 current pointer”和“当时的快照”不是同一概念。

#### 3. 事件详情与 revision 链

页面包含：

- 中文标题与原始标题；
- 稳定 event identity；
- 发布方、分类、地区、发布状态；
- canonical URL 与来源类型；
- 版本/tag/commit；
- `published_at`、时间精度、`observed_at`、首次取得、核验时间、`as_of`；
- 已确认事实、发布方观点、角色评估、待核验内容分区；
- 开发者影响与建议动作；
- 多来源证据关系；
- revision 时间线：初版、更新、修正、撤回、恢复；
- “出现于哪些快照”列表。

同一事件跨来源归并为一个事件和多证据，不重复计数。版本或正式发布状态不同不得误合并。撤回状态显示原因、时间和旧版本入口，不静默消失。

#### 4. 全部事件

搜索中文/原始标题、发布方、产品、版本、tag、commit 与摘要。筛选：日期、快照、国内/国际、分类、发布状态、事实标签、revision 状态、新鲜度、来源、预发布、撤回/修正。排序：重要性、发布时间、首次观测、最近修订。

固定显示当前查询所属快照/日期、结果数、生效筛选与清除全部。详情返回恢复搜索、筛选、排序、分页和滚动位置。分别设计全局真空、筛选空、未就绪、陈旧、部分失败和失败。

#### 5. 刷新运行详情

刷新请求状态按时间线展示：

`已受理 → 输入/来源校验 → 取得/导入 → 规范化 → 去重与 revision → 持久化候选/证据 → 质量门 → 发布快照 → current pointer 更新`

每次运行显示：

- refresh request ID、触发方式（当日首次互动/手动）、幂等键；
- 请求、开始、结束时间；
- 同日是否复用既有任务、冷却剩余时间；
- 来源分母、成功、失败、跳过与原因；
- 新增、修订、撤回、合并、隔离数量；
- 质量门结果；
- 生成的 snapshot ID；若未生成明确写“未发布新快照”；
- current pointer 是否改变；
- 上次成功快照与继续阅读入口。

刷新按钮的状态：可用、焦点、已受理、排队、运行中、同日复用、冷却、成功有新增、成功无新增、部分失败、失败、离线。运行中禁止制造重复请求；失败不更新 `as_of`。

#### 6. 来源与质量

来源行显示政策状态与运行状态两条独立轴，不合成绿灯。每行包含：来源名称、地区、来源类型、精确入口、政策状态、是否应运行、最近尝试、最近成功、连续失败、错误原因、遗漏窗口。

质量区展示：输入记录 → 字段/权利/时间校验 → canonical 主源 → 稳定 identity → 去重/revision → 质量门 → 已发布快照。每一段显示数量与可下钻证据；未运行时只显示定义和“尚无真实运行记录”，不显示假转化率。

#### 7. 快照详情

显示 snapshot ID、自然日、`as_of`、`published_at`、来源覆盖、失败来源、规则版本、事件集合、内容哈希、前一快照、由哪个 refresh run 产生。明确“已发布快照不可修改”。新快照以关系链连接前一快照，不使用覆盖动画暗示旧数据消失。

### 六、刷新交互与反馈文案

当日首次互动只触发一次幂等 request；同日重复进入复用状态。手动刷新是显式次级按钮，显示冷却与进行中状态。关键文案：

- “已受理今日首次刷新请求”；
- “正在刷新，继续显示 8 月 25 日的上次成功快照”；
- “同日刷新任务已存在，已显示其当前进度”；
- “刷新成功，本次无新增”；
- “部分来源失败，已发布通过质量门的结果”；
- “刷新失败，未发布新快照；仍显示上次成功内容”；
- “尚无成功快照，查看未就绪原因”；
- “发现新快照，切换查看”——仅在持久化和发布成功后出现。

不要使用“实时更新”“已同步全部来源”“抓取完成”等无法由状态证明的文案。

### 七、视觉方向与组件系统

总体气质：**极简、清爽、新闻内容优先、可信数据产品、低噪声。**

- 浅灰画布、白色卡片、深靛蓝主色与克制青绿辅助色；
- 正文深灰，成功/警告/错误必须达到 WCAG 2.2 AA 对比度；
- 8px 栅格，卡片圆角 12px，轻边框优于重阴影；
- 桌面标题 28–32px、正文 14–16px；移动正文至少 16px、辅助文字至少 14px；
- 单屏只保留一个主强调区，避免胶囊洪水、渐变、装饰仪表盘和长篇解释；
- snapshot ID、commit、URL 可换行、复制和展开，不裁掉辨识尾部。

组件至少包括：全局真相栏、日期/快照选择器、刷新按钮与进度、事件卡、快照卡、revision 时间线、证据项、来源双轴状态、筛选抽屉、状态提示、Toast、加载骨架、错误详情、外链提示、图表容器和等价表。

每个可操作组件设计默认、悬停、按下、焦点、禁用、加载、成功和错误状态。

### 八、数据可视化与字段映射

至少设计以下 8 类语义图形，并由同一结构化数据同时生成可视图与完整等价表：

1. **刷新生命周期时间线**：X=时间；节点=受理、校验、导入/取得、去重、持久化、质量门、发布；状态=未开始/进行中/成功/失败/跳过。
2. **快照追加链**：节点=snapshot ID；边=前一快照；标记=current、历史、失败未发布；失败 run 不能生成快照节点。
3. **日期 × 快照矩阵**：行=日期，列=快照；值=事件数、来源覆盖、失败数；无成功快照与真实 0 事件使用不同形状。
4. **事件 revision 时间线**：节点=revision；类型=新增/修订/撤回/恢复；显示观测时间、发布时间和出现快照。
5. **相邻快照差异条**：新增、修订、撤回、合并、无变化；每个数量可下钻到事件 ID。
6. **来源运行结果分组条**：成功/失败/跳过/未运行，分母为应运行来源；`not_ready` 时不画 0 成功率。
7. **快照新鲜度带**：标出 `as_of`、最近成功、当前时间、阈值与遗漏窗口；过期仍保留真实旧日期。
8. **事件—证据关系图**：事件 identity 连接主源、佐证、传播线索、反证与 duplicate；同根转载不计独立证据。

每张图就近显示：图题、时间范围、单位、样本量、来源分母、规则版本、`as_of`、缺失/失败说明、图例、结论与“查看完整数据表”。等价表必须逐项包含所有可视 mark 的 ID、字段、值和状态，做到双向一致。禁止饼图市场份额、3D 图、无分母百分比、假成功绿灯和装饰性随机柱。

### 十、键盘、读屏与无障碍

- 今日、日期切换、历史、搜索筛选、详情、刷新请求、失败诊断、图表等价表和外链可仅用键盘完成；
