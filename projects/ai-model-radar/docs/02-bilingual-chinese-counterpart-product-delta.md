## 1. 产品裁决

超级无敌帅超超总要求：每条真实、有用的 AI 开发信息，在保留原文的同时，额外提供一份可追溯的中文对照。

本增量补充现有 AI 开发圈新闻、真实日更网页和本地真实服务范围；冲突时以本文件为准。当前 `4174/4317` 的真实采集、持久化、快照、来源与相关性过滤继续运行，本轮不修改代码、数据库、服务或生产环境。

核心原则：

1. **原文是事实根。** 中文对照是附加解释层，不能覆盖、删除或静默改写原始标题、原始摘要、原文链接、时间、版本和证据。
2. **逐条覆盖。** 每个正式事件及其当前修订必须有可见的中文对照状态：已有中文对照、原文已是中文、译文待生成、译文失败或译文待更新；不允许静默缺失。
3. **真实优先。** 事件是否真实、有用仍由现有主源、准入、相关性和证据规则决定；翻译不能把候选变成正式事件，也不能增加原文没有的事实。
4. **失败不阻断新闻。** 中文生成失败、超时或暂不可用时，真实原文事件照常发布并可打开，只明确显示“中文对照暂不可用”。
5. **版本可追溯。** 原文修订与中文对照修订分别只追加；用户能知道中文内容对应哪一版原文、何时生成、用什么方式形成。

## 2. P0 覆盖范围

“每条信息”在本轮指进入正式事件库、快照或历史记录的事件级信息，不把来源运行日志、健康指标和纯统计数字误当成需要逐字翻译的新闻。

| 页面／对象 | P0 中文对照要求 | 不改变的原始信息 |
| --- | --- | --- |
| 今日雷达 `/today` | 每张事件卡提供中文标题、中文事实摘要、1–3 条中文关键变化；可识别中文形成方式和状态 | 原始标题、发布方、模型／产品／仓库名、版本、发布时间、原文链接 |
| 全部事件 `/events` | 与今日使用同一逐条契约；搜索同时匹配中文标题、原始标题、中文摘要和公开版本字段 | 事件身份、筛选结果、快照与修订关系 |
| 事件详情 `/events/:eventId` | 并列提供原始标题／原始摘要片段与中文标题／中文摘要／中文关键变化；中文“开发者影响”必须单列为系统评估 | 原文、证据、事实／观点／推断标签、完整时间与 revision 链 |
| 趋势与版本 `/trends` | 聚合标签、分类和说明为简体中文；下钻到具体事件、版本或变更时应用完整逐条中文对照 | 数值、日期、模型名、版本号、样本量、规则版本和 `as_of` |
| 开源与发布 `/open-source` | 每条 Release／模型卡／工具发布提供中文标题、中文摘要和关键变化；明确开放语义与许可证是否已声明 | 仓库、tag、commit、许可证标识、版本、breaking／deprecation／effective date、原文链接 |
| 历史快照与旧事件 | 每条可访问事件至少显示中文对照状态；已有对照按版本读取，未回填项显示“无译文／待回填” | 历史快照不可变、旧事件不删除、不被当天数据覆盖 |

### 2.1 每条事件的中文内容

每个事件修订的中文对照包含：

- `中文标题`：忠实表达原始标题，不加入夸张、结论或未证实判断；
- `中文事实摘要`：用 1–3 句说明谁发布／更新了什么、版本或生效时间、已核验的关键事实；
- `中文关键变化`：1–3 条，逐条可回到结构化事实或证据；没有足够依据时明确“原文未说明”；
- `开发者影响`：可选的系统评估，必须与译文分区并标“系统评估”，不能冒充原文观点；
- `中文形成方式与状态`：始终可见，不能藏在仅管理员可见区域。

## 3. 原文与中文对照关系

1. 原始标题与中文标题均可访问；详情页不得只显示中文而隐藏原始标题。
2. 原始摘要片段只在现有版权、最小化与来源规则允许时保存和展示；不允许保存时保留原始标题、规范 URL 和必要事实字段，不为凑对照复制全文。
3. 中文标题、摘要和关键变化必须绑定一个明确的事件修订；原文发生变化后，旧中文内容不得冒充新修订的当前译文。
4. 中文内容不得反向改写发布方、版本、时间、许可证、事实／观点边界或事件准入结论。
5. 中文原文无需重复“翻译”。此时显示“原文已是中文，无需译文”，并仍保留形成状态和原文身份。

## 4. 中文内容来源与真实性标签

每份中文对照必须使用以下用户可见标签之一，并保留对应依据：

| 标签 | 产品语义 | 允许行为 | 禁止行为 |
| --- | --- | --- | --- |
| 人工译文 | 经明确人工翻译或复核 | 可标翻译／复核时间和版本 | 不得把未经人工处理的内容标成人工译文 |
| 机器翻译 | 由自动翻译能力生成，尚未或已经人工复核均需另行说明 | 显示机器翻译、置信度或不确定项 | 不得冒充发布方原文或人工译文 |
| 规则生成 | 依据已核验结构化字段生成中文表述，例如版本、日期和动作模板 | 显示规则版本和输入事实范围 | 不得生成结构化字段之外的新事实或主观结论 |
| 无译文 | 翻译未生成、失败、待更新，或原文已是中文无需另译 | 显示具体原因；原文事件继续可用 | 不得用空字符串、旧译文或静态占位伪装已完成 |

“发布方观点”“系统摘要”“系统评估”仍按既有事实分层单独标识；它们与“人工／机器／规则”的形成方式是两个不同维度，不能合并成一个模糊标签。

## 5. 保真与内容安全规则

以下内容默认原样保留，不做意译或本地化改写：

- 发布方、模型、产品、仓库、组织、API、SDK、Agent、框架名称；
- 版本号、tag、commit SHA、CVE、许可证标识、模型 ID、端点与文件名；
- 代码、命令、配置键、参数、错误码、URL、域名和路径；
- 日期、时间、时区、价格、额度、单位、百分比和上下文长度。

允许在专有名词后增加中文解释，但解释必须与原词并存。例如“deprecated（已弃用）”不能替换掉公开的 `deprecated` 状态。无法确定译法时保留原词并标“不确定”，不得猜译。

中文摘要不得：

- 将营销措辞改写成已证实能力；
- 将论文、厂商或作者观点写成系统事实；
- 将 commit、模型更新时间或媒体转述写成正式发布；
- 执行或复述来源中的提示注入、脚本指令或敏感操作；
- 引入原文和结构化证据中不存在的比较、排名、性能或行动建议。

## 6. 生命周期、持久化与重复刷新

产品顺序约束如下：

`采集原始材料 → 规范化与主源核验 → 形成事件修订 → 生成／复核中文对照 → 持久化中文对照修订 → 发布快照／后续补充快照 → 页面只读展示`

具体规则：

1. 中文生成只能在事件通过规范化、相关性和证据核验后发生；不得在采集阶段把未经核验的译文直接写成正式事件。
2. 中文对照必须服务端持久化并版本化；浏览器读取层不得临时、隐式翻译，也不得刷新后丢失。
3. 每个中文对照至少可追溯：事件 ID、原文修订号／指纹、中文修订号、形成方式、状态、形成时间、规则／能力版本、复核状态和失败原因。
4. 相同原文修订、相同中文策略版本的重复刷新必须复用既有结果，不产生重复译文或覆盖历史记录。
5. 原文修订后，旧中文对照保留在历史链；新对照完成前标“译文待更新”，不得把旧译文当成当前版本。
6. PublishedSnapshot 保持不可变。新增或修正中文对照通过新的追加修订／快照体现，不能原地改写往日快照。
7. 翻译失败批次不得清空事件、删除原文、回退 Demo 或替换最近成功新闻快照。

## 7. 失败、超时与历史回填

| 场景 | 产品行为 |
| --- | --- |
| 首次翻译失败／超时 | 发布真实原文事件；显示“中文对照暂不可用”及安全原因；可重试但不无限循环。 |
| 部分字段成功 | 只展示已完成字段并标“中文对照不完整”；缺失字段不能由前端猜填。 |
| 原文已修订、译文未更新 | 显示新原文和“译文待更新”；旧译文仅在历史版本中可见。 |
| 重复刷新 | 相同输入幂等复用；状态和时间不伪装成新译文。 |
| 翻译服务不可用 | 新闻采集、核验、持久化和原文浏览继续；来源真相与翻译真相分别显示。 |
| 旧历史事件 | 当前快照和最近事件优先回填；所有可访问历史事件必须至少有明确中文状态，不能静默遗漏。 |
| 无法安全翻译 | 保留原文、专有名词和链接，标“无译文／需人工复核”；不输出低可信猜测。 |

历史回填不能覆盖旧快照，也不能改变事件原始发布时间、首次观测时间或当时证据。回填时间与对应原文版本必须单独记录。

## 8. 简体中文、移动端与无障碍

1. 中文对照状态、形成方式、失败原因、待更新提示和复核状态全部使用简体中文。
2. 320px、390px、200% 放大下，原始标题、中文标题、来源标签、原文入口和译文状态均可访问；不能通过移动端隐藏原文或来源标签换取空间。
3. 键盘可在中文内容、原始内容、形成方式、证据与原文入口之间顺序导航，焦点连续可见。
4. 读屏必须能区分“原始标题”“中文标题”“机器翻译／人工译文／规则生成／无译文”“系统评估”和“原文链接”。
5. 原始语言内容使用正确语言语义；代码、版本、URL 和中英混排不能被错误逐字朗读成中文句子。
6. 状态不能只靠颜色；使用中文文字和非颜色标识表达。

## 9. MVP、优先级与不做项

### 9.1 P0

- 今日、全部事件、详情、趋势下钻、开源／发布和历史事件使用统一的逐条中文对照契约；
- 当前快照内每个事件有中文内容或明确“无译文／待更新”状态，覆盖率 100%；
- 原文与中文对照版本化持久化、可追溯、刷新后不丢失；
- 中文失败不阻断真实新闻，原文、证据、快照和历史不受损；
- 完成简体中文、移动端、键盘、读屏和 200% 放大验收。

### 9.2 P1

- 对历史事件分批补齐可用中文对照；
- 人工复核和纠错工作流；
- 用户术语偏好或个人词汇表。后两项涉及写入或个人偏好时必须另行明确数据权利范围。

### 9.3 明确不做

- 不伪造来源、中文事实、主源身份或人工复核；
- 不删除、覆盖或隐藏原文，不镜像受限全文；
- 不使用静态 Demo、硬编码译文或浏览器内临时翻译冒充已持久化能力；
- 不因翻译失败阻断真实新闻、清空页面或把 `live` 改成假成功；
- 不把“中文生成成功”当作事件真实、相关或有用的证明；
- 不指定翻译供应商、模型、技术栈、数据库结构或部署方案；
- 不在本轮修改 UI 设计、前端、后端、数据库、运行服务或生产部署。
