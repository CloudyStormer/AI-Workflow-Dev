## 1. 产品裁决

超级无敌帅超超总只通过项目网页查看 AI 开发圈新闻，不以 Markdown、JSON 或仓库文件作为日常入口。当前 `/today` 的 Demo 验收不合格，必须被真实服务读取的已发布快照替换；在替换完成前，页面只能显示 `not_ready` 或显式 Demo，绝不能称真实日更已完成。

P0 是一个最小真实纵切：

1. 把 `output/daily/2026-08-25.json` 作为**一次性导入输入**，校验字段、主源、时间、事实标签与内容指纹；导入不等于直接让前端读取文件。
2. 对事件规范化和去重后持久化；为每条事件建立稳定 identity、revision 与证据关系。
3. 发布不可变 `PublishedSnapshot`，再由 `/today`、事件详情和质量／运行记录页面读取真实服务结果。
4. 页面显示真实日期、`published_at`、`observed_at`、`as_of`、canonical URL、来源、状态与开发者影响；预发布不得写成稳定版。
5. 保留所有历史事件、历史 revision、历史快照和往日批次；新的成功快照只移动 current pointer，不覆盖旧记录。
6. 失败批次不得清空页面或替换上次成功快照；没有当天成功快照时必须显示无新增、陈旧、失败或未就绪的真实状态。

## 2. 页面入口与信息规则

### 2.1 `/today`（唯一默认入口）

- 默认按 Asia/Shanghai 自然日展示当前成功快照中的当日合格事件，并突出“自上次查看新增”。
- 2026-08-25 批次成功发布后，可在 2026-08-25 历史日期和事件详情中看到 6 条事实；到 2026-08-26 时，若尚无 8 月 26 日成功批次，不能把这 6 条继续标成“今日”。
- 页面顶部必须显示：页面状态、快照日期、`as_of`、最近成功时间、当前覆盖、失败来源数和是否正在刷新。
- 每条卡片至少显示：中文标题、发布方、类别、地区、发布状态（预发布／稳定／GA 等）、发布时间、观测时间、事实／评估边界、开发者影响与 canonical 原文入口。
- 分类至少覆盖：模型／API、SDK、开源、开发工具、安全／服务状态；国内／国际可筛选。

### 2.2 事件详情与历史

- 详情可查看原始标题（有则展示）、canonical URL、来源类型、版本／tag／commit、发布时间精度、`observed_at`、首次取得、核验状态、事实摘要、角色评估和 revision 链。
- 同一事件后续更新写入新 revision；撤回写状态与原因；都不得静默改写旧版本。
- 用户可以切换日期或进入历史快照，查看当时的事件集合、覆盖和失败情况。

### 2.3 来源与质量／运行记录

- 展示每次 refresh request 的触发方式、开始／结束、成功／无新增／部分失败／完全失败、来源分母、成功数、失败数和发布的 snapshot ID。
- Demo、人工输入批次、live 自动批次必须显式区分；任何真实页面不得静默回退 Demo。

## 3. 数据生命周期与不可覆盖契约

```text
人工核验 JSON 或后续合规采集
  → 输入校验（字段、主源、时间、权利、事实标签）
  → 规范化与稳定 identity
  → 跨来源去重／事件 revision
  → 持久化候选、证据、运行记录
  → 质量门
  → 发布不可变 PublishedSnapshot
  → current pointer 指向最新成功快照
  → 网页查询与历史回看
```

稳定 identity 优先采用发布方事件 ID、canonical URL、版本／tag／commit 与发布方组合；不能仅用中文标题。相同 identity 的修订保留 revision 链和各自 `observed_at`／`as_of`。不同版本或不同正式发布状态不得误合并。

`PublishedSnapshot` 发布后不可修改。新批次成功只新建快照并更新 current pointer；旧快照、事件和证据继续可查。校验失败、部分失败或完全失败的运行不更新 current pointer，不删除或覆盖上一成功快照。

## 4. 每日首次互动触发

- Asia/Shanghai 每个自然日内，超级无敌帅超超总首次进入本项目验收，或首次在固定 00 的 AIWorkFlow/Radar 交流中触发一次幂等 refresh request。
- 同日重复进入复用同一 refresh 状态和结果，不无限重复取得；用户可使用明确的手动刷新，但必须显示冷却／进行中／已复用，并与自动触发共享幂等与质量门。
- refresh 完成且有新增时，新事实追加进入新快照；无新增时记录成功无新增，不复制事件。
- 固定 00 每个自然日首次相关交流应主动报告：是否已触发、当前状态、最近成功与新增条数。真实运行未完成前必须报告 `not_ready`，不能声称已自动更新。
- 这不是 24 小时后台生产任务，不授权生产定时器、云资源、账号、付费来源或部署。后台调度另行定义。

## 5. 真相状态

| 状态 | 成立条件 | 页面行为 |
|---|---|---|
| `not_ready` | 数据库、导入、发布或真实查询链任一未完成 | 不展示 Demo 充数；说明缺失环节。当前应为此状态。 |
| `refreshing` | 当日幂等 refresh 已受理且未结束 | 保留上次成功快照，显示进度和触发时间。 |
| `live` | 当日真实运行成功并发布满足新鲜度的快照 | 展示今日与自上次查看新增，显示 `as_of` 和最近成功。 |
| `no_new_items` | 当日真实运行成功但新增合格事件为 0 | 明确“本次无新增”，不复制旧闻或 Demo。 |
| `degraded` | 部分来源失败，但剩余结果通过质量门 | 显示失败来源、覆盖缺口和真实成功数据。 |
| `stale` | 只有上一成功快照且已超过产品新鲜度阈值 | 显示旧日期与原因，不称今日或最新。 |
| `failed` | 必要环节或全部来源失败，不能发布新快照 | 保留并标识上次成功快照；current pointer 不变。 |

页面 HTTP 200、静态 JSON 可读、Demo 卡片存在或导入命令返回成功，均不足以成为 `live`。
