## 2. `live`、空榜与 `seed_demo` 边界

- 正式发布默认产品模式是 `live`。`live` 只有在至少一个获准真实连接器成功取得并核验数据、当前版本化快照可读、来源和新鲜度可解释时才可标记就绪。
- `seed_demo` 仅用于演示、测试和故障隔离；必须在全局、页面和数据记录上持续标记为演示。它不能被合并到真实趋势、真实来源覆盖或日报，也不能作为 P0 功能完成证据。
- `live` 当日可以真实为 0 条：前提是当日刷新确实运行、启用来源范围和最近成功时间可见，并明确“当前接入来源中暂无符合标准的高价值事件”。不得为了凑数加入旧闻或噪声。
- 全部来源刷新失败时，上一有效快照可以受控读取，但必须标记降级、真实 `as_of`、失败范围和重试状态；超过 v1.2 新鲜度红线时不得称“今日”。
- 任一 P0 页面或筛选入口若处于 `disabled`、无数据契约、无真实后端或仅静态占位，该能力即未完成；不能因为主页 HTTP 200 而通过发布门。

## 3. 数据持久化与前后端联调

- 候选、正式事件、来源状态、刷新运行、去重关系、核验证据、版本化快照和质量结果必须跨服务重启保留；浏览器内存或构建时 JSON 不能作为 `live` 的唯一事实来源。
- 前端必须从真实业务服务读取今日、全部事件、趋势、专题、详情、来源和刷新结果。前端静态数据只能在明确 `seed_demo` 中使用；生产 `live` 路径的隐形静态回退为 0。
- 同一刷新请求重试不得重复生成事件、重复增加趋势计数或改变已确认事件身份。迟到旧事件、未来时间隔离、修订、撤回和合并都需保留审计历史。
- 健康表示进程可响应；就绪表示 `live` 的关键来源配置、存储、当前快照与查询能力可用。健康成功而未就绪时，产品不能声称情报可用。

## 4. 统一完成门

AI Model Radar 只有同时满足以下条件才可称为全功能完成：

1. v1.2 所有 P0 业务 AC 与本附录 AC 通过，未关闭 P0／P1 缺陷为 0；
2. 使用真实获准来源和真实持久化完成前后端联调，Mock、演示数据、禁用入口和空后端不能替代；
3. 加载、真实空榜、部分来源失败、全部失败、过期、未就绪、离线、恢复与不可信内容状态可验收；
4. 简体中文覆盖导航、操作、筛选、图表、来源、状态、错误、空榜、移动端和无障碍文案；
5. 320px 移动端、键盘、屏幕阅读器和 200% 放大可完成全部 P0 路径，状态不只依赖颜色；
6. 单元、契约、集成、端到端与回归测试通过，且能观测健康、就绪、来源质量、刷新、新鲜度和错误；
7. 权限、凭证、外链、不可信正文、版权／robots／API／登录边界通过安全检查；
8. 真实数据备份恢复和应用版本回滚完成演练，回滚不丢失或重复正式事件。

## 5. Given-When-Then 验收标准

- **AC-AMR-REL-01 真实今日**：Given `live` 模式，When 打开今日雷达，Then 所有正式事件来自获准真实来源并符合 v1.2 时间契约；预置静态事件数量为 0。
- **AC-AMR-REL-02 零事件真实性**：Given 当日没有合格事件，When 今日榜为 0 条，Then 显示已检查来源、最近成功、`as_of` 和真实空榜原因，不用旧闻凑数。
- **AC-AMR-REL-03 P0 入口**：Given 正式发布候选，When 遍历今日、全部、趋势、开源专题、详情、搜索筛选、来源和刷新，Then入口可用率为 100%，`disabled` 或占位入口数量为 0。
- **AC-AMR-REL-04 主源证据**：Given 任一正式事件，When 打开详情，Then 至少有一条可访问的官方主源或明确的待核验隔离状态；无主源却进入正式事件数量为 0。
- **AC-AMR-REL-05 开源语义**：Given 事件涉及开源发布，When 查看专题，Then 明确区分三种开放类型，显示许可证／未声明、版本／tag／commit 和开发者动作。
- **AC-AMR-REL-06 趋势口径**：Given 查看 7／30／90 日趋势，When 读取图表和等价表格，Then 样本量、来源覆盖、缺失天数、规则版本与 `as_of` 完整，市场份额表述数量为 0。
- **AC-AMR-REL-07 刷新幂等**：Given 同一刷新被重复触发或网络重试，When 任务完成，Then 正式事件、版本和趋势计数不重复，运行结果可追溯。
- **AC-AMR-REL-08 来源故障**：Given 单个来源失败，When 查询雷达，Then 其他来源继续、失败来源与最近成功可见；全部失败时不生成“当前”快照。
- **AC-AMR-REL-09 重启持久化**：Given 已形成正式事件和快照，When 服务重启，Then 身份、证据、合并、来源状态和历史版本保持一致，不回退到种子数据。
- **AC-AMR-REL-10 模式隔离**：Given `seed_demo` 与 `live` 都可访问，When 审计查询和趋势，Then 两种数据不混合且演示标识持续可见，`seed_demo` 不贡献真实完成率。
- **AC-AMR-REL-11 健康就绪**：Given 进程可响应但存储、当前快照或关键查询不可用，When 检查状态，Then 健康与就绪分离，界面不以 HTTP 200 声称全功能完成。
- **AC-AMR-REL-12 不可信内容**：Given 来源正文含脚本、提示注入或危险外链，When 取得和展示，Then 内容按不可信数据处理，不执行指令、不泄露凭证并安全打开原文。
- **AC-AMR-REL-13 简体中文**：Given 选择简体中文，When 遍历全部 P0 路径，Then导航、状态、筛选、图表、来源、错误、空榜和移动端文案覆盖率为 100%。
- **AC-AMR-REL-14 移动与无障碍**：Given 320px、键盘、屏幕阅读器或 200% 放大，When 完成浏览、筛选、详情、来源和刷新，Then 核心内容与操作可达且图表有等价文本／表格。
- **AC-AMR-REL-15 备份回滚**：Given 备份恢复或版本回滚，When 核对正式事件，Then 已承诺恢复点内数据完整、审计关系不变且事件不重复。
- **AC-AMR-REL-16 完成门**：Given 准备声明全功能完成，When 审查真实来源、联调、持久化、异常、测试、安全和恢复证据，Then 全部通过且未关闭 P0／P1 为 0；Mock、演示替代、禁用入口、空后端和仅 HTTP 200 证据数量均为 0。
