## 1. 产品定位

### 1.1 一句话定位

AI Model Radar 是面向超级无敌帅超超总的个人大模型动态雷达：把国内外分散的模型、API、开源、研究、评测、安全、服务状态与监管更新，合并为少量可追溯、可解释、能辅助行动的事件。

### 1.2 核心问题

当前已验证的问题是：信息入口分散、同一事件反复传播、国内外动态需要来回切换、厂商宣传与独立事实容易混写，而且“热度高”不等于“值得采取行动”。产品必须优先解决“更快判断今天什么值得看、为什么值得看、原始证据在哪里”，不是追求抓取更多页面。

### 1.3 价值主张

1. **少而重要：** 每日正式摘要最多 20 个独立事件；不足时宁缺毋滥。
2. **事件而非文章：** 同一发布的官方新闻、changelog、GitHub、媒体和社区传播合并为一个事件。
3. **证据可回看：** 每个正式事件都有主源、时间、发布方、证据角色、事实标签与置信度。
4. **面向行动：** 明确“为什么重要”和“可能影响什么”，但把系统判断标为推断，不伪装成事实。
5. **中外同屏：** 在质量不下降的前提下同时覆盖中国与全球的重要模型生态。

## 2. 目标、成功定义与产品原则

### 2.1 当前版本目标

1. 先交付一套可浏览、可理解、可审核的 Web 内容体验，让用户在没有后端服务时也能验证信息架构、内容密度和决策价值。
2. 使用明确标记的人工整理/演示快照展示日榜、事件详情、证据链、来源状态、偏好和质量说明；不得伪装成实时数据。
3. 为后续影子运行定义正式事件门槛、去重、排序、反馈和质量测量语义。
4. 保留从可浏览内容版进入合规采集、后台调度和 14–30 天影子运行的清晰路径，但这些后续能力必须重新获批。

### 2.2 当前版本成功定义

- 用户能在一个入口完成“看今日重点 → 判断重要性 → 核对证据 → 打开原文 → 调整偏好”的闭环。
- 所有展示内容都能区分人工/演示快照与真实接入数据；未接通的刷新、来源和统计不得显示为已运行。
- 所有正式事件至少有一个可直接打开的主源，并明确事实、来源观点、系统推断或待核验状态。
- 产品不会为了凑满 10 条而纳入低质量内容，也不会因为社交热度高而绕过证据门槛。

### 2.3 产品原则

- 官方源优先，社区源只做发现线索。
- 证据质量高于更新速度，行动价值高于传播热度。
- 事实、来源观点、系统推断、待核验必须分开。
- 没有真实连接就明确显示“演示/人工快照/未接通”。
- 内容最小化：短自写摘要 + 必要元数据 + 原文回链，不做全文搬运。
- 用户偏好可以影响排序，但不能降低事实、合规和主源硬门槛。

## 3. 用户与核心场景

### 3.1 已验证用户

当前唯一已验证用户是超级无敌帅超超总本人。尚无外部访谈、多人协作、商业化或付费意愿证据，因此 MVP 不推定存在团队用户、企业客户或公众读者。

### 3.2 用户画像

| 维度 | 描述 |
|---|---|
| 身份 | 持续关注 AI 产品与研发的大模型用户/决策者 |
| 主要任务 | 快速掌握模型与 API 变化，判断是否需要试用、迁移、关注风险或继续研究 |
| 主要痛点 | 来源分散、重复阅读、宣传与事实混杂、国内外信息割裂、低价值内容过多 |
| 风险偏好 | 希望信息新，但不能以违规访问、不可追溯或虚假实时为代价 |
| 当前未知 | 厂商权重、明确“不想看”类别、每日最佳阅读时段、提醒阈值、可接受误报/漏报 |

### 3.3 P0 使用场景

1. **晨间浏览：** 在 5–10 分钟内看完过去 24 小时最值得关注的事件。
2. **发布核验：** 看到“新模型发布”后，快速区分厂商事实、厂商性能声明和独立验证。
3. **开发决策：** 发现 API、价格、模型 ID、上下文、弃用或 SDK 变化，判断是否需要行动。
4. **中外对照：** 同时查看国内与海外动态，不因单一地区内容密集而淹没另一地区。
5. **原文追溯：** 从摘要进入主源、技术佐证、独立佐证或反证，不停留在二手标题。
6. **偏好校准：** 标记关注、忽略或不相关，逐步校准未来排序。

### 3.4 P1 使用场景

- 查看官方服务事故、严重安全公告、明确下线/价格生效或监管紧急事项。
- 查看来源健康、条款复核和影子运行质量，判断产品是否值得继续自建。
- 对照现有 RSS、Newsletter 或聚合服务，评估买/建组合。

## 4. MVP 交付顺序

### 4.1 MVP-1：可浏览 Web 内容版（当前最高优先级）

MVP-1 是当前首先定义和交付的产品里程碑：以人工整理或固定演示快照验证 Web 内容体验，不依赖后端服务或正式部署。

必须包含：

- 今日雷达、事件列表与事件详情。
- 主源、佐证、反证、时间、事实标签与置信度。
- 搜索、筛选、排序、偏好设置和反馈状态。
- 来源目录、数据说明、空白/过期/失败/部分可用状态。
- 明确的“演示数据/人工快照/截至时间”标识。
- 响应式、键盘和辅助技术可用性。

MVP-1 不得声称：实时刷新已接通、自动采集已运行、后台任务稳定、影子运行已完成、生产部署已完成或质量指标已有实测结果。

### 4.2 MVP-2：验证服务版（后置，需另行批准）

在 MVP-1 的内容和交互获批、架构与来源边界获批后，才允许进入：

- A–D 级合规来源的增量取得和来源状态记录。
- 候选事件抽取、跨来源聚类、排序、人工复核和失败降级。
- 定时与按需刷新、最小持久化、审计记录和质量统计。
- 连续 14–30 天影子运行及买/建比较。

### 4.3 正式服务与部署（明确后置）

生产环境、公开访问、多用户、外部通知、账号系统、付费来源、受限平台 API、正式域名和持续运维均不属于当前 PRD 的执行授权。即使后续产品产物通过，也必须继续经过 UI/UX、架构、任务拆解、开发、审查、测试和具体发布授权。

## 5. 信息架构

信息架构只描述内容层级和任务顺序，不规定视觉样式。

1. **今日雷达**：过去 24 小时/指定日期的高价值事件和重要状态。
2. **全部事件**：按时间、类型、地区、厂商、证据状态和置信度浏览。
3. **事件详情**：摘要、为什么重要、关键事实、影响判断、证据链、更新历史和原文。
4. **来源目录**：来源身份、地区、类型、访问级别、当前启用/待核验/受限状态和最近核验时间。
5. **偏好与反馈**：关注/不想看、厂商/地区/类型权重、已读/收藏/不相关反馈。
6. **质量说明**：数据截至时间、演示/真实连接状态、候选/正式事件数量、去重说明、已知限制和影子运行指标。

默认进入“今日雷达”；事件详情必须可以返回原列表且保留筛选上下文。

## 7. 详细产品需求

### 7.1 今日雷达

**目标：** 让用户在有限时间内先看到最高行动价值事件，而不是无限新闻流。

**内容规则：**

- 默认展示过去 24 小时的正式事件；支持切换自然日或最近 7 天。
- 正式日榜为 0–20 条，目标 10–20 条但不是硬配额；不足时显示“本时段高置信事件不足”，不得补入低质量事件。
- 每条至少展示：标题、短摘要、发布方、事件时间、地区、事件类型、事实标签、置信度、为什么重要、主源入口和更新时间。
- 同一厂商通常不超过 3 条/日；同一重大主题的多个更新优先合并为专题事件簇。超出上限必须有明确高影响理由。
- 紧急事件不占日榜配额，但在日榜中只保留一个事件总结，避免重复提醒。
- MVP-1 页面必须在首要位置说明“演示/人工快照”及截至时间，不显示虚假的自动更新时间。

### 7.2 事件卡片与事件详情

**事件卡片：** 用于快速判断“是否值得打开”，不承载全部证据。

**事件详情必须包含：**

1. 中文可读标题与原始标题；模型名、版本号和专有名词不得被错误翻译。
2. 一段短摘要，说明发生了什么；系统生成或翻译内容必须标识。
3. “为什么重要/可能影响”单独呈现并标为系统推断或人工判断。
4. 关键字段：组织、模型/产品、事件类型、版本/生效日期、地区、发布时间、取得时间、最近更新时间。
5. 证据链：主源、技术佐证、独立佐证、传播线索、反证/异议；同根转载不得伪装成多条独立证据。
6. 每条关键断言对应的事实标签与置信度。
7. 更新历史：首次发现、主源确认、内容更新、合并/拆分、撤回或修正。
8. 原文入口；打开前能看见来源域名和内容类型。

### 7.3 事实标签与置信度

| 标签 | 定义 | 是否进入正式日榜 |
|---|---|---|
| 已确认事实 | 官方主源确认发布/变更，日期和对象可复核 | 是 |
| 来源观点 | 厂商、作者或媒体自己的性能/影响判断 | 可进入，但必须明确“谁声称” |
| 独立验证 | 方法与适用范围可查看的第三方评测/复核 | 是 |
| 系统推断 | 基于已列事实形成的影响或行动判断 | 可展示，必须列依据 |
| 待核验 | 社区/媒体单源、无主源或证据冲突 | 默认不进入正式日榜，只进入待核验区 |

置信度为高/中/低三档。高置信不等于事件重要；重要性与证据质量必须分别表达。厂商“领先、第一、SOTA、提升 X%”若无独立验证，只能写成“厂商称”。

### 7.4 搜索、筛选与排序

- 搜索范围包括事件标题、原始标题、厂商、模型、关键词和短摘要；不得默认搜索未获授权保存的全文。
- 筛选至少包括：日期、地区（中国/全球）、厂商、模型、事件类型、开源/闭源、事实标签、置信度和已读状态。
- 默认排序为综合重要性；还可按时间、行动价值和证据质量排序。
- 筛选后的结果数为 0 时，必须显示当前筛选条件和清除入口，不得误报为“今日没有动态”。
- 用户从详情返回时，日期、筛选、排序和阅读位置保持不变。

### 7.5 关注偏好与“不想看”

**可配置项：**

- 关注厂商、模型家族、关键词、事件类型和地区。
- 降权或隐藏厂商、主题、来源与内容类型。
- 对 API/价格/弃用、开源、研究评测、安全状态、监管和公司事件分别设置关注程度。
- 选择“更偏开发行动”“更偏模型能力”“国内外平衡”等预设，仅作为初始排序偏好。

**规则：**

- 偏好影响排序和个性化解释，但不能让无主源、证据不足或受限来源内容越过正式事件门槛。
- “不相关”反馈不得删除历史证据，只降低未来相似事件权重并保留可撤销状态。
- MVP-1 必须说明设置仅用于当前演示/浏览器或会话体验；未获得持久化、账号或跨设备授权前，不得声称已云端保存。
- 用户尚未提供完整偏好证据时使用透明默认值，不得声称系统已经学会用户兴趣。

### 7.6 已读、收藏和反馈

- **已读：** 表示用户打开或明确标记，不代表认同内容。
- **收藏：** 表示后续想回看，不提高事件客观重要性。
- **不相关：** 记录原因（主题不相关、重复、过旧、证据弱、影响低、分类错误或其他），用于后续排序评估。
- **证据/分类纠正：** 用户可指出重复合并错误、事实标签错误、翻译错误或主源缺失；修正前保留原记录和纠正状态。
- MVP-1 的反馈必须明确为演示/本地状态；只有后续服务获批后才能形成持久质量闭环。

### 7.7 来源目录

每个来源至少展示：名称、发布方、地区、来源类型、入口、建议访问方式、自然更新节奏、访问级别、robots/条款最近核验时间、内容保留边界和当前状态。

来源状态包括：

- `enabled`：已获准且当前可用。
- `manual-only`：只能人工发现或核验。
- `pending-review`：访问/条款/接口仍待确认。
- `restricted`：需登录、付费、API 申请或协议，默认关闭。
- `paused`：入口异常、条款变化、删除要求或质量问题导致停用。
- `retired`：已正式移除，保留审计说明。

MVP-1 只展示调研截至 2026-07-31 的核验快照；不得把研究建议清单显示为已接入运行来源。

### 7.8 刷新、数据新鲜度与连接状态

**MVP-1：**

- 页面刷新只重新加载当前演示/人工快照。
- 显示快照截至时间、制作者/数据性质和“未连接自动采集服务”。
- 不显示抓取成功率、下一次自动刷新或“实时”字样，除非存在真实证据。

**MVP-2 获批后：**

- 按需刷新必须反馈：已开始、各来源处理中、部分成功、完成、失败和取消。
- 同一刷新任务重复触发不得重复产生事件或重复统计。
- 部分来源失败时保留成功结果，并显示失败来源数、最近成功时间和重试入口。
- 数据快照超过 24 小时显示“可能过期”；超过 48 小时且没有成功刷新时不得继续标为“今日”。
- 刷新失败不清空上一版可用内容，除非内容已撤回或存在安全风险。

### 7.9 紧急事件

只有以下官方或高置信信号可进入紧急候选：重大持续服务中断、严重安全公告、明确模型下线/价格生效、强监管紧急通知。

- 社区热帖、媒体独家传闻、普通新模型发布和融资新闻默认不触发紧急提醒。
- 紧急状态必须显示确认来源、开始时间、当前状态和最近更新时间。
- 未确认信号只能显示为“待核验”，不得使用确定性告警文案。
- 外部推送、短信、邮件或消息通知不在当前范围内。

## 8. 事件准入、去重与排序规则

### 8.1 正式事件硬门槛

正式事件必须同时满足：

1. 属于模型、关键模型平台/API、开源、重要研究/评测、安全/服务状态、监管或重大且直接相关的公司事件。
2. 至少一个可直接打开的主源；只有搜索摘要、截图或无原文内容时不得进入正式日榜。
3. 发布方、事件时间、关键动作和对象可识别。
4. 内容取得方式与保存范围符合当前已知访问、条款和版权边界。
5. 事实标签、置信度和为什么重要均已填写；未知必须明确写未知。

### 8.2 事件类型

MVP 事件类型至少包括：`model-release`、`api-change`、`price-change`、`deprecation`、`open-source`、`research`、`evaluation`、`security-incident`、`service-incident`、`funding-ma`、`regulation`。

泛应用教程、纯营销活动、普通融资、没有模型/平台直接影响的产业新闻默认不进入大模型正式日榜；扩大为泛 AI 行业雷达必须经过产品变更审核。

### 8.3 四层去重

1. URL 规范化：处理跟踪参数、重定向、canonical 和镜像。
2. 精确内容：规范标题、版本、日期、空白和语言后比对。
3. 事件实体：组织 + 模型/产品 + 事件类型 + 版本/生效日期 + 关键动作。
4. 跨语言候选：语义相似只用于提出合并候选，最终必须以实体、版本、日期和动作确认。

错误合并必须支持拆分并保留修正记录；不同模型版本、价格调整、重大 Bug、回滚或后续安全事件不能仅因标题相似而强行合并。

### 8.4 重要性评分

产品排序沿用已批准调研的七个维度：影响 25%、新颖性 18%、行动价值 18%、证据质量 16%、影响范围 10%、紧迫性 8%、多样性价值 5%，再扣除重复、未核验、营销、付费墙和过时惩罚。

- 正式日榜建议分数门槛为 65/100；分数只是排序辅助，不能替代硬门槛。
- 单一厂商自述、社区热度和转载数量不能直接提高证据质量。
- 用户偏好可调整行动价值和排序，不得修改原始证据质量。
- 评分调整、人工改分和原因必须可回看；MVP-1 的分数为演示规则，不得称为已训练模型结果。

## 9. 核心用户流程

### 9.1 浏览与核验

```text
进入今日雷达
  → 查看数据性质与截至时间
  → 浏览 0–20 条正式事件
  → 按厂商/类型/地区/置信度筛选
  → 打开事件详情
  → 区分事实、来源观点和系统推断
  → 查看主源/佐证/反证
  → 打开原文或返回原列表位置
```

### 9.2 偏好与反馈

```text
打开偏好
  → 选择关注与不想看
  → 预览排序影响
  → 保存当前作用域
  → 在事件上标记已读/收藏/不相关
  → 可撤销或查看反馈原因
```

### 9.3 后续按需刷新（MVP-2）

```text
触发刷新
  → 显示任务开始和来源进度
  → 合法来源取得候选
  → 去重、聚类、核验和排序
  → 成功：产生新快照并说明新增/更新/合并数
  → 部分成功：保留成功结果并列出失败来源
  → 失败：保留上一快照，提供原因和重试
```

## 10. 页面与数据状态

| 状态 | 产品行为 |
|---|---|
| 首次进入/无快照 | 解释当前无内容、数据性质和下一步，不展示空白假榜单 |
| 演示快照 | 明确“演示/人工整理”和截至时间，所有交互不声称后台持久化 |
| 今日无高置信事件 | 显示 0 条并说明不凑数，仍可查看历史和来源状态 |
| 筛选无结果 | 显示当前筛选条件和清除入口，不等同于全局无内容 |
| 数据过期 | 超过 24 小时提示可能过期；超过 48 小时不再称“今日” |
| 加载中 | 保留任务上下文，禁止闪现旧数据为新数据 |
| 部分可用 | 展示成功内容和失败来源范围，不把部分结果说成完整 |
| 全部失败 | 保留最近一次可用快照、失败时间和重试入口 |
| 原文失效 | 保留事件与失效标记，优先寻找同一主源的新地址；不静默替换为二手来源 |
| 证据冲突 | 并列显示冲突和各自来源，状态降为待核验或相应降低置信度 |
| 内容撤回/修正 | 明确标记撤回或已修正，并保留更新时间与原因 |
| 来源受限 | 不提供规避入口；显示需授权/人工核验及当前关闭状态 |

## 11. 响应式、键盘与无障碍要求

- 支持 320px 到 2560px 宽度；移动端仍能完成浏览、筛选、打开详情、查看证据和返回原位置。
- 所有核心操作可通过键盘完成，焦点顺序与内容顺序一致；弹层/抽屉关闭后焦点返回触发点。
- 搜索、筛选、标签、置信度、来源角色、数据连接和错误状态均有可访问名称，不以颜色作为唯一表达。
- 动态结果数量、筛选变化、刷新结果和错误通过可感知状态播报，但不得反复打断阅读。
- 原文链接必须说明目的和来源域名；外部打开行为可预期。
- 长标题、长模型名、中英文混排、URL、版本号和时间在 320px 下不得遮挡关键状态或操作。
- 页面缩放至 200% 时核心内容和操作仍可用；不要求横向滚动才能阅读主要事件内容。
- 内容顺序应先给结论与数据性质，再给筛选和事件，再给补充说明；辅助技术用户不应先穿过大量导航才能到达今日事件。

## 12. 合规、版权、隐私与安全边界

1. robots 是访问规则，不等于版权或合同授权；启用来源前需同时核验 robots、服务条款、API 条款、速率、资格和保留/删除义务。
2. X、Reddit、微博、哔哩哔哩及任何需登录、Cookie、付费、开发者申请或商业协议的来源默认关闭；只能经正式 API/授权或人工查看。
3. 禁止模拟登录、共享凭证、使用浏览器登录态、绕过反爬/付费墙/访问控制。
4. 默认只保存规范化 URL、标题、发布方、时间、事件字段、短自写摘要、证据角色、置信度和必要指纹；不保存全文、图片、视频、完整字幕、评论或个人资料。
5. 不复制媒体/Newsletter 正文，不热链受限媒体，不去除水印；必要引用保持最短并标明出处。
6. 任何 API Key、Token、Cookie、账号、`.env` 或秘密都不能进入界面演示、文档、Git 或事件记录。
7. 若未来面向中国境内公众提供生成摘要，必须重新评估生成合成内容标识、备案、内容治理和服务责任；当前内部验证不等于已满足公开服务要求。
8. 用户偏好与反馈属于个人使用数据；未获授权前不上传第三方、不跨设备同步、不用于外部模型训练。

## 13. 产品指标与影子运行门槛

### 13.1 MVP-1 内容体验指标

- 首屏能够识别数据性质、截至时间、今日事件数和第一条事件。
- 100% 展示事件具有主源链接、发布方、事件时间、事实标签和置信度。
- 演示数据、人工快照、未接通状态和未实测指标误标为真实/实时的数量为 0。
- 用户可以在不打开二手来源的情况下完成主源核验。

### 13.2 MVP-2 影子运行质量门槛

这些门槛只有在服务阶段获批并取得真实数据后才可测量；当前文档不声称已经达标。

1. 连续运行至少 14 个日历日；样本或事件量不足以判断时延长至 30 日。
2. 100% 已启用来源有访问模式、robots/条款核验时间、保留边界和停用责任记录；未经批准的受限来源启用数为 0。
3. 100% 正式事件有主源、发布方、事件时间、取得时间、事实标签和置信度。
4. 正式日榜每日不超过 20 条；不足 10 条时明确显示不足，凑数事件为 0。
5. 人工标注集优先覆盖全部候选；候选超过 500 条时至少标注 300 条并覆盖同事件/非同事件、跨语言和版本相近样本。
6. 去重 precision 目标不低于 95%，recall 目标不低于 85%；未达标不得宣称“自动去重稳定”。
7. 正式事件人工相关性通过率目标不低于 80%；厂商自述被误写为独立事实、高影响断言无证据或受限来源违规取得均为阻断问题。
8. 重复事件泄漏率目标不高于 5%；高影响事件漏报必须逐条复盘，不以低价值补量掩盖漏报。
9. 来源成功率、候选量、独立事件量、聚类压缩率、人工改分率、平均核验时间、实际阅读/收藏/不相关反馈均须如实报告。
10. 若 30 日平均每天不足 6 个独立高分事件，必须重新选择降低数量目标、扩大范围或停止，不能静默把产品改成泛 AI 新闻站。

## 14. 验收标准（Given-When-Then）

### 14.1 可浏览内容与真实性

- **AC-01**：Given 用户首次进入 MVP-1，When 页面完成加载，Then 能立即看到数据性质、截至时间、今日正式事件数和当前是否连接真实服务。
- **AC-02**：Given 当前只有人工/演示数据，When 用户浏览任何页面，Then 系统不显示“实时”“自动抓取成功”或虚假的下一次更新时间。
- **AC-03**：Given 今日有 7 个通过硬门槛的事件，When 生成日榜，Then 只展示 7 个并说明高置信事件不足，不补入低分候选。
- **AC-04**：Given 今日有超过 20 个合格事件，When 生成正式日榜，Then 日榜最多展示 20 个，其余可在全部事件中查看。
- **AC-05**：Given 同一厂商有超过 3 个普通合格事件，When 生成日榜，Then 默认最多保留 3 个；例外必须说明重大影响理由或合并为事件簇。
- **AC-06**：Given 用户进入事件详情后返回，When 返回原列表，Then 日期、筛选、排序和阅读位置保持不变。

### 14.2 事件、证据和事实安全

- **AC-07**：Given 一个事件进入正式日榜，When 检查字段，Then 主源、发布方、事件时间、取得/更新时间、事件类型、事实标签、置信度和为什么重要均存在。
- **AC-08**：Given 厂商声称某模型“第一/SOTA/提升 X%”但没有独立评测，When 展示该断言，Then 明确写成“厂商称”并标为来源观点。
- **AC-09**：Given 系统输出影响判断，When 用户查看详情，Then 该内容标为系统推断并列出所依据事实。
- **AC-10**：Given 只有社区帖子或媒体单源且找不到主源，When 处理候选，Then 状态为待核验且默认不进入正式日榜。
- **AC-11**：Given 两个媒体转载同一新闻稿，When 展示证据链，Then 不把它们计为两个独立佐证。
- **AC-12**：Given 官方发布后出现独立评测反证，When 更新事件，Then 主叙事和反证并列展示，并更新置信度或状态。
- **AC-13**：Given 原文被撤回或更正，When 用户再次查看，Then 事件明确标记撤回/更正及时间，不静默保留旧结论。

### 14.3 去重、排序与范围

- **AC-14**：Given 中英文页面描述同一组织、模型版本、动作和日期，When 形成事件，Then 合并为一个事件并保留多条证据。
- **AC-15**：Given 同一厂商同日发布两个不同模型版本，When 标题高度相似，Then 系统不得仅凭语义相似强制合并。
- **AC-16**：Given 事件分数低于 65 或未通过主源硬门槛，When 生成日榜，Then 不进入正式日榜。
- **AC-17**：Given 用户提高某厂商权重，When 重新排序，Then 可以提高其行动价值排序，但不能让无主源或受限内容进入正式日榜。
- **AC-18**：Given 普通应用教程、营销活动或无模型直接影响的产业新闻，When 分类，Then 默认排除；扩展为泛 AI 范围必须走产品变更审核。

### 14.4 搜索、筛选、偏好与反馈

- **AC-19**：Given 用户组合地区、厂商、事件类型和置信度筛选，When 结果更新，Then 页面显示结果数和已生效条件。
- **AC-20**：Given 筛选后无结果，When 页面显示空状态，Then 明确是当前条件无结果并提供清除入口，不误报全局无内容。
- **AC-21**：Given 用户搜索模型名或版本号，When 命中事件，Then 可从标题、原始标题、厂商、模型字段或短摘要找到结果，而不依赖未授权全文。
- **AC-22**：Given 用户标记“不相关”，When 保存反馈，Then 记录原因、允许撤销、影响未来排序但不删除历史证据。
- **AC-23**：Given 用户收藏事件，When 事件被收藏，Then 收藏不改变该事件的客观重要性或证据质量。
- **AC-24**：Given MVP-1 尚无账号或持久化服务，When 用户修改偏好或反馈，Then 明确当前作用域，不声称已云端或跨设备保存。

### 14.5 来源、刷新与异常状态

- **AC-25**：Given 来源来自 X、Reddit、微博、哔哩哔哩或需登录/付费/API 申请的平台，When 未获得独立授权，Then 状态为受限或人工查看，自动启用为 0。
- **AC-26**：Given 用户查看 MVP-1 来源目录，When 看到核心来源，Then 页面说明这是截至 2026-07-31 的研究核验快照，不把它称为已接入运行源。
- **AC-27**：Given MVP-1 用户点击页面刷新，When 当前没有采集服务，Then 只重载当前快照并继续显示未接通状态。
- **AC-28**：Given MVP-2 某些来源刷新失败，When 其他来源成功，Then 保留成功结果并说明失败范围、最近成功时间和重试入口。
- **AC-29**：Given 全部来源刷新失败，When 用户查看页面，Then 最近可用快照仍可阅读，并显示失败时间；旧数据不伪装成新数据。
- **AC-30**：Given 快照超过 24 小时，When 用户浏览，Then 显示可能过期；超过 48 小时且无成功刷新时不再称为“今日”。
- **AC-31**：Given 用户重复触发同一刷新，When 任务仍在运行或已经完成，Then 不重复产生事件、统计或后台任务。

### 14.6 响应式与无障碍

- **AC-32**：Given 320px 宽度，When 用户浏览、筛选、打开详情和查看证据，Then 关键状态和操作可完成且主要内容不要求横向滚动。
- **AC-33**：Given 用户仅使用键盘，When 完成今日雷达到事件原文的流程，Then 所有核心操作可达，焦点顺序连续，关闭临时层后焦点返回触发点。
- **AC-34**：Given 屏幕阅读器用户查看事件，When 读取标签和置信度，Then 能获知文字状态、来源角色和连接状态，不只依赖颜色或图标。
- **AC-35**：Given 筛选结果或刷新状态动态变化，When 状态更新，Then 辅助技术获得适度播报且不会重复打断正在阅读的事件。
- **AC-36**：Given 页面缩放到 200%，When 用户操作核心流程，Then 内容和操作仍可用，长模型名与中英文混排不遮挡关键状态。

### 14.7 合规、版权和影子运行

- **AC-37**：Given 任一来源准备自动启用，When 检查来源注册，Then 访问方式、robots/条款核验、保留边界、资格和停用责任均有记录。
- **AC-38**：Given 内容来自媒体、Newsletter 或视频，When 生成事件，Then 默认只保留最小元数据、短自写摘要和原文链接，不保存全文、图片、完整字幕或评论。
- **AC-39**：Given 页面或文档可能包含凭证，When 执行交付检查，Then API Key、Token、Cookie、账号、`.env` 和秘密出现数量为 0。
- **AC-40**：Given 尚未完成真实影子运行，When 展示质量指标，Then 显示定义或“未实测”，不得填写推测数字。
- **AC-41**：Given 影子运行达到至少 14 日，When 申请宣布去重稳定，Then 去重 precision 不低于 95%、recall 不低于 85%，并公开样本量与范围；否则只能报告未达标。
- **AC-42**：Given 30 日平均每日独立高分事件少于 6 个，When 形成产品结论，Then 必须提出降低数量、扩大范围或停止三类决策，不得静默补入低质量内容。

## 15. 非功能需求

### 15.1 性能与反馈

- 在常见桌面和移动网络条件下，MVP-1 首个可读内容目标为 2.5 秒内；未达成时不得用永久骨架屏掩盖。
- 搜索、筛选、排序和偏好预览应在用户操作后 300 毫秒内产生可感知反馈；需要后台任务时先显示已受理状态。
- 外部原文不可用不应阻塞整个事件详情或列表。

### 15.2 兼容性

- 支持当前主流桌面 Chrome、Edge、Safari 的最近两个主要版本。
- 支持 iOS Safari 与 Android Chrome 的近两个主要版本。
- 支持 320px–2560px 宽度和 200% 页面缩放。

### 15.3 安全与可靠性

- 外部内容均视为不可信数据；页面不得执行来源中的脚本或指令。
- 原文链接、重定向和来源域名必须可识别，避免把不明地址伪装成官方源。
- 服务阶段需保留来源停用、事件撤回、失败降级和上一快照恢复能力；具体方案由架构角色定义。

## 16. 明确不做项

- 不做全网爬虫、无限新闻流或必须凑满 10–20 条的内容工厂。
- 不在 MVP-1 接入真实后台采集、调度、数据库、账号、跨设备同步或正式部署。
- 不在本 PRD 指定技术栈、API、数据库表、模型供应商、爬虫框架或云平台。
- 不使用浏览器 Cookie、共享账号、模拟登录或绕过 robots、条款、反爬、付费墙和访问控制。
- 不把 X、Reddit、微博、哔哩哔哩设为 MVP 刚性依赖。
- 不保存或再分发全文、图片、视频、完整字幕、评论、个人资料或付费 Newsletter。
- 不做外部推送、自动发帖、邮件订阅、公开日报、团队协作、商业化或公众服务。
- 不把厂商宣传、社区热度、单一榜单或系统推断展示为未经限定的客观事实。
- 不自动采购付费 API、Newsletter 或聚合服务，不申请账号或扩大权限。
- 不生成 UI 提示词、设计稿、架构、代码、后端服务或部署产物。

## 17. 依赖、风险与待确认项

### 17.1 依赖

- UI/UX 必须在本 PRD 通过后，由固定 `04 UI/UX设计师` 先交提示词再交设计，两次分别审核。
- 真实来源接入、数据结构、摘要、去重、调度、成本、安全和回滚必须由架构阶段定义。
- 影子运行指标需要后续 QA/数据能力及真实样本，当前不能伪造。
- 任何付费、登录、受限来源、生产发布和对外发送需要独立授权。

### 17.2 主要风险

| 风险 | 产品影响 | 产品级应对 |
|---|---|---|
| 用户偏好证据不足 | 信息正确但不实用 | 使用透明默认值，尽快收集关注/不想看和反馈，不声称已个性化 |
| 高价值事件产量不足 | 不能稳定达到 10–20 | 不凑数；按 30 日门槛重新决定数量、范围或停止 |
| 厂商/英语内容偏置 | 单一生态占榜 | 厂商上限、地区/类型多样性和来源贡献审计 |
| 去重误合并/漏合并 | 关键事件丢失或重复 | 版本/日期/动作硬约束、人工修正和标注集验证 |
| 摘要幻觉/事实混写 | 错误决策 | 强制标签、主源、反证、断言依据和阻断门槛 |
| 来源条款变化 | 数据中断或合规风险 | 来源状态、定期复核和默认停用，不绕过限制 |
| 内容版被误认作实时产品 | 用户信任受损 | 全局展示数据性质与截至时间，未接通功能明确禁用/说明 |

### 17.3 待超级无敌帅超超总后续补充但不阻塞本 PRD 审核

1. 最关注的厂商/模型家族和明确“不想看”内容。
2. 每日最佳阅读时间，以及是否需要 P0 紧急提醒。
3. “更偏开发行动、模型能力、国内动态或全球动态”的默认优先级。
4. 是否接受事件不足时显示少于 10 条；本 PRD 默认接受且禁止凑数。
5. MVP-1 内容体验验证后，是否继续投入 MVP-2 合规采集与影子运行。
