## 1. 产品定位

### 1.1 一句话定位

AI Model Radar 是面向超级无敌帅超超总的个人大模型动态雷达：把国内外分散的模型、API、开源、研究、评测、安全、服务状态与监管更新，合并为少量可追溯、可解释、能辅助行动的事件。

### 1.2 核心问题

当前已验证的问题是：信息入口分散、同一事件反复传播、国内外动态需要来回切换、厂商宣传与独立事实容易混写，而且“热度高”不等于“值得采取行动”。产品必须优先解决“更快判断今天什么值得看、为什么值得看、原始证据在哪里”，不是追求抓取更多页面。

### 1.3 价值主张

1. **少而重要：** 每日正式摘要最多 20 个独立事件；不足时宁缺毋滥。
2. **事件而非文章：** 同一发布的官方新闻、changelog、GitHub、媒体和社区传播合并为一个事件。
3. **证据可回看：** 每个正式事件都有主源、时间、发布方、证据角色、事实标签与置信度。
4. **面向行动：** 明确“为什么重要”和“可能影响什么”，但把系统判断标为推断，不伪装成事实。
5. **中外同屏：** 在质量不下降的前提下同时覆盖中国与全球的重要模型生态。

## 2. 目标、成功定义与产品原则

### 2.1 当前版本目标

1. 把“每天看到截至当前的最新 AI 开发动态与趋势”升级为当前产品目标，而不是继续停留在静态种子演示。
2. 覆盖模型／多模态／推理版本、开源模型与工具、API／SDK／开发平台、Agent／工作流框架、价格／限额／弃用、研究评测、安全和服务状态等具有开发行动价值的变化。
3. 以合规来源注册、连接器、调度、增量取得、规范化、去重、候选核验、正式事件和版本化快照形成真实后端闭环；前端不得自行抓取或猜测连接状态。
4. 让用户在今日雷达、全部事件、趋势与版本演进、开源／发布专题、事件详情、来源状态和质量说明之间完成“发现 → 核验 → 决定行动”的闭环。
5. 每个“今天、最新、趋势、已连接、刷新成功”均由可追溯时间、来源覆盖、规则版本和运行证据支撑；不能用页面打开时间或静态示例制造假实时。
6. 保留 `seed_demo` 作为独立演示／测试模式和上一快照作为失败降级，但二者不得混入 `live` 数据或支撑“真实今日”结论。

### 2.2 当前版本成功定义

- 用户每天能在一个入口完成“看截至当前的重点 → 判断开发影响 → 核对版本和证据 → 打开主源 → 采取或记录行动”的闭环。
- 今日榜每日为 0–20 条通过硬门的独立事件；不足不凑数，同一发布跨站传播不重复计数。
- 所有正式事件至少有一个可直接打开的主源，并具有发布方、版本／动作、完整时间语义、事实标签、证据置信度和开发者动作。
- 所有页面都能区分 `live`、`degraded_live` 与 `seed_demo`；静态前端、过期快照、来源失败和本地服务未持续运行不得伪装成“截至当前”。
- 7／30／90 日趋势只描述本雷达已接入来源样本，并显示样本量、来源覆盖、缺失天数、规则版本和 `as_of`，不称市场份额或全行业趋势。

### 2.3 产品原则

- 官方源优先，社区源只做发现线索。
- 证据质量高于更新速度，行动价值高于传播热度。
- 事实、来源观点、系统推断、待核验必须分开。
- 没有真实连接就明确显示“演示/人工快照/未接通”。
- “所有 AI”用版本化来源覆盖清单和缺口表达，不作不可验收的绝对覆盖承诺。
- `live` 与 `seed_demo` 数据、指标和状态完全隔离，任何一种模式都不能借用另一种模式的时间或运行结果。
- 内容最小化：短自写摘要 + 必要元数据 + 原文回链，不做全文搬运。
- 用户偏好可以影响排序，但不能降低事实、合规和主源硬门槛。

## 3. 用户与核心场景

### 3.1 已验证用户

当前唯一已验证用户是超级无敌帅超超总本人。尚无外部访谈、多人协作、商业化或付费意愿证据，因此 MVP 不推定存在团队用户、企业客户或公众读者。

### 3.2 用户画像

| 维度 | 描述 |
|---|---|
| 身份 | 持续关注 AI 产品与研发的大模型用户/决策者 |
| 主要任务 | 快速掌握模型与 API 变化，判断是否需要试用、迁移、关注风险或继续研究 |
| 主要痛点 | 来源分散、重复阅读、宣传与事实混杂、国内外信息割裂、低价值内容过多 |
| 风险偏好 | 希望信息新，但不能以违规访问、不可追溯或虚假实时为代价 |
| 当前未知 | 厂商权重、明确“不想看”类别、每日最佳阅读时段、提醒阈值、可接受误报/漏报 |

### 3.3 P0 使用场景

1. **晨间浏览：** 在 5–10 分钟内看完过去 24 小时最值得关注的事件。
2. **发布核验：** 看到“新模型发布”后，快速区分厂商事实、厂商性能声明和独立验证。
3. **开发决策：** 发现 API、价格、模型 ID、上下文、弃用或 SDK 变化，判断是否需要行动。
4. **中外对照：** 同时查看国内与海外动态，不因单一地区内容密集而淹没另一地区。
5. **原文追溯：** 从摘要进入主源、技术佐证、独立佐证或反证，不停留在二手标题。
6. **偏好校准：** 标记关注、忽略或不相关，逐步校准未来排序。

### 3.4 P1 使用场景

- 查看官方服务事故、严重安全公告、明确下线/价格生效或监管紧急事项。
- 查看来源健康、条款复核和影子运行质量，判断产品是否值得继续自建。
- 对照现有 RSS、Newsletter 或聚合服务，评估买/建组合。

## 4. MVP 交付顺序

### 4.1 已有静态内容纵切（保留但不代表当前目标完成）

`artifact-radar-frontend-001 / AMR-FE-001` 已形成简体中文静态演示首屏并停在 `frontend-delivery-review`。它只证明页面壳和真实性提示可以浏览，不证明完整 P0 页面、真实后端、连接器、自动刷新或今日情报已经可用；本次产品变更不批准、不否决、不修改该产物。

### 4.2 `seed_demo` 兼容模式（v1.1 未批准增量被取代）

v1.1 定义的版本化种子快照仍可作为无网络演示、契约测试、错误恢复验证和前端开发夹具，但不再是当前产品终态。该模式必须固定显示 `data_mode=seed_demo` 与 `connection_state=not_connected`，不得贡献真实来源成功率、今日事件数或趋势指标。

### 4.3 Live Daily Intelligence MVP（v1.2 当前产品增量）

当前 MVP 要形成可验收的真实每日 AI 开发情报闭环：

- 通过已批准 allowlist 中的合规官方主源、GitHub Releases、论文／项目主页和独立评测入口取得增量观察；社区只用于发现候选。
- 把观察规范化为包含版本、动作、完整时间语义与证据角色的候选，完成同发布跨站去重、主源核验、事实安全检查和候选到正式事件的晋级。
- 发布不可静默覆盖的版本化快照，向前端提供今日雷达、全部事件、趋势／版本演进、开源／发布专题、详情证据、来源状态、刷新结果和质量覆盖。
- 默认机器可读官方源每 1–2 小时检查一次，研究／评测每日 1–2 次，并在 Asia/Shanghai 08:30 生成日报；这是可配置产品基线，不是当前已经运行的事实。
- 手动刷新与定时刷新共用同一来源政策、去重、核验和发布门；重复触发幂等，任何失败都不清空上一份有效快照。
- 连续 14–30 天影子运行后才能声称来源覆盖、去重、新鲜度和日更质量达到已批准门槛。

### 4.4 持续运行与正式部署（仍需后续授权）

本地服务只有在设备、服务和调度持续运行时才能保证按时采集与 08:30 日报；关机、休眠、服务停止或无外部调度时必须显示中断和最近成功时间，不得承诺无条件每日更新。生产环境、公开访问、多用户、外部通知、账号系统、付费来源、受限平台 API、正式域名和持续运维仍不属于本 PRD 的执行授权，必须继续经过 UI/UX、架构、任务拆解、开发、审查、测试和具体发布授权。

## 5. 信息架构

信息架构只描述内容层级和任务顺序，不规定视觉样式。

1. **今日雷达**：默认 Asia/Shanghai 自然日，可切换过去 24 小时；展示 0–20 条高价值正式事件和日报状态。
2. **全部事件**：按时间、类型、地区、厂商、项目、证据状态和置信度检索、筛选与排序。
3. **趋势与版本演进**：以 7／30／90 日窗口查看本雷达已接入来源样本趋势和模型／工具版本时间线。
4. **开源／发布专题**：集中查看开源模型、权重、GitHub Release、SDK、CLI、开发工具、Agent／工作流框架及其许可证和开发动作。
5. **事件详情**：摘要、版本与生效时间、为什么重要、开发者动作、关键事实、证据链、更新历史和原文。
6. **来源与连接状态**：来源身份、覆盖范围、访问级别、allowlist、连接状态、最近成功、最近验证、失败和限制。
7. **偏好与反馈**：关注/不想看、厂商/地区/类型权重、已读/收藏/不相关反馈。
8. **质量与覆盖说明**：快照时间、模式、来源覆盖与缺口、候选/正式事件数量、去重、缺失天数、规则版本和影子运行指标。

默认进入“今日雷达”；事件详情必须可以返回原列表且保留筛选上下文。

## 7. 详细产品需求

### 7.1 今日雷达

**目标：** 让用户在有限时间内先看到最高行动价值事件，而不是无限新闻流。

**内容规则：**

- 默认“今天”是 Asia/Shanghai 从 00:00:00 到当前已发布快照 `snapshot.as_of` 的自然日；用户可切换“过去 24h”，该窗口固定为 `[snapshot.as_of - 24h, snapshot.as_of]`，不能随页面停留时间漂移。
- “最新”只表示当前最新成功发布的 live 快照及其 `snapshot.as_of`，不是页面打开时间、接口响应时间或单个来源刚被访问的时间。
- 正式日榜为 0–20 条，目标 10–20 条但不是硬配额；不足时显示“本时段高置信事件不足”，不得补入低质量事件。
- 每条至少展示：标题、短摘要、发布方、规范事件时间、来源原始时间／时区、地区、事件类型、版本、事实标签、置信度、为什么重要、开发者动作、主源入口和最近核验时间。
- 同一厂商通常不超过 3 条/日；同一重大主题的多个更新优先合并为专题事件簇。超出上限必须有明确高影响理由。
- 紧急事件不占日榜配额，但在日榜中只保留一个事件总结，避免重复提醒。
- 迟到发现的旧发布按原始发布时间进入历史窗口，并标“补录”；可以在“新发现”提示中出现，但不得改写为今天发布。
- 规范化后晚于取得／核验时间的未来发布时间进入隔离区，不进入今日、趋势、版本演进或正式事件统计。
- `snapshot.as_of` 距 `observed_at` 超过 24 小时标“可能过期”；超过 48 小时且没有成功刷新时改称“最近可用快照”，页面不得继续称“今日雷达”。
- `seed_demo` 页面必须在首要位置说明“演示／人工快照”和未连接状态；`live` 页面必须显示最近成功刷新、来源覆盖与失败范围。

### 7.2 事件卡片与事件详情

**事件卡片：** 用于快速判断“是否值得打开”，不承载全部证据。

**事件详情必须包含：**

1. 中文可读标题与原始标题；模型名、版本号和专有名词不得被错误翻译。
2. 一段短摘要，说明发生了什么；系统生成或翻译内容必须标识。
3. “为什么重要/可能影响”单独呈现并标为系统推断或人工判断。
4. 关键字段：组织、模型／产品／项目、事件类型、版本／tag／commit、breaking／deprecation、地区、来源原始发布时间与时区、规范发布时间、更新时间、生效时间、首次发现、取得、抓取、核验和快照时间。
5. 证据链：主源、技术佐证、独立佐证、传播线索、反证/异议；同根转载不得伪装成多条独立证据。
6. 每条关键断言对应的事实标签与置信度。
7. 更新历史：首次发现、主源确认、内容更新、合并/拆分、撤回或修正。
8. 原文入口；打开前能看见来源域名、内容类型、是否官方主源和访问限制。
9. 开发者动作：`立即评估`、`计划迁移`、`升级／试用`、`锁定版本`、`替换`、`持续观察`或`无需动作`，并列出依据、截止／生效时间和不确定性。

### 7.3 事实标签与置信度

| 标签 | 定义 | 是否进入正式日榜 |
|---|---|---|
| 已确认事实 | 官方主源确认发布/变更，日期和对象可复核 | 是 |
| 来源观点 | 厂商、作者或媒体自己的性能/影响判断 | 可进入，但必须明确“谁声称” |
| 独立验证 | 方法与适用范围可查看的第三方评测/复核 | 是 |
| 系统推断 | 基于已列事实形成的影响或行动判断 | 可展示，必须列依据 |
| 待核验 | 社区/媒体单源、无主源或证据冲突 | 默认不进入正式日榜，只进入待核验区 |

置信度为高/中/低三档。高置信不等于事件重要；重要性与证据质量必须分别表达。厂商“领先、第一、SOTA、提升 X%”若无独立验证，只能写成“厂商称”。

### 7.4 搜索、筛选与排序

- 搜索范围包括事件标题、原始标题、厂商、模型、关键词和短摘要；不得默认搜索未获授权保存的全文。
- 筛选至少包括：自然日／过去 24h、7／30／90 日、地区（中国／全球）、发布方、模型／项目、事件类型、开放语义、许可证、事实标签、置信度、开发者动作、来源状态、新鲜度和已读状态。
- 默认排序为综合重要性；还可按时间、行动价值和证据质量排序。
- 筛选后的结果数为 0 时，必须显示当前筛选条件和清除入口，不得误报为“今日没有动态”。
- 用户从详情返回时，日期、筛选、排序和阅读位置保持不变。

### 7.5 关注偏好与“不想看”

**可配置项：**

- 关注厂商、模型家族、关键词、事件类型和地区。
- 降权或隐藏厂商、主题、来源与内容类型。
- 对 API/价格/弃用、开源、研究评测、安全状态、监管和公司事件分别设置关注程度。
- 选择“更偏开发行动”“更偏模型能力”“国内外平衡”等预设，仅作为初始排序偏好。

**规则：**

- 偏好影响排序和个性化解释，但不能让无主源、证据不足或受限来源内容越过正式事件门槛。
- “不相关”反馈不得删除历史证据，只降低未来相似事件权重并保留可撤销状态。
- 在偏好持久化另行获批前，`seed_demo` 与 live 页面都必须说明设置仅作用于当前浏览器或会话；不得声称已云端或跨设备保存。
- 用户尚未提供完整偏好证据时使用透明默认值，不得声称系统已经学会用户兴趣。

### 7.6 已读、收藏和反馈

- **已读：** 表示用户打开或明确标记，不代表认同内容。
- **收藏：** 表示后续想回看，不提高事件客观重要性。
- **不相关：** 记录原因（主题不相关、重复、过旧、证据弱、影响低、分类错误或其他），用于后续排序评估。
- **证据/分类纠正：** 用户可指出重复合并错误、事实标签错误、翻译错误或主源缺失；修正前保留原记录和纠正状态。
- 当前反馈只允许是浏览器／会话状态；是否写入本地后端、如何留存和是否跨设备均需后续独立批准，不能因 live 情报接入而默认获得。

### 7.7 来源目录

每个来源至少展示：稳定来源 ID、名称、发布方、地区、来源类型、允许域名／仓库范围、入口、批准访问方式、自然更新节奏、访问级别、robots／条款／API 最近核验时间、权利基础、内容保留边界、责任人、政策版本、下次复核、连接状态、最近尝试、最近成功和最近验证。

来源必须先进入版本化 allowlist 才能运行；市场调研中的“建议来源”不是已启用来源。allowlist 的每个版本必须能回答新增／移除／暂停了什么及原因，未知或过期的必要政策字段默认拒绝自动访问。

来源状态包括：

- `enabled`：已获准且当前可用。
- `manual-only`：只能人工发现或核验。
- `pending-review`：访问/条款/接口仍待确认。
- `restricted`：需登录、付费、API 申请或协议，默认关闭。
- `paused`：入口异常、条款变化、删除要求或质量问题导致停用。
- `retired`：已正式移除，保留审计说明。

来源政策状态与运行连接状态是两条独立轴：`enabled` 不等于最近刷新成功，`paused/restricted` 也不能被运行端绕过。`seed_demo` 固定显示未连接；live 页面只显示有实际运行证据的连接状态。

### 7.8 刷新、数据新鲜度与连接状态

**`seed_demo`：**

- 页面刷新只重新加载当前演示/人工快照。
- 显示快照截至时间、制作者/数据性质和“未连接自动采集服务”。
- 不显示抓取成功率、下一次自动刷新或“实时”字样，除非存在真实证据。

**Live Daily MVP：**

- 默认调度基线为：机器可读官方源每 1–2 小时、研究／评测每日 1–2 次、Asia/Shanghai 08:30 生成过去 24 小时日报；每项可配置并显示实际启用值、上次运行和下次计划。
- 本地服务没有持续运行时，调度状态必须是“未持续运行／已中断”，并显示遗漏窗口；不能保证每日按时更新。
- 按需刷新必须反馈：已开始、各来源处理中、部分成功、完成、失败和取消。
- 同一刷新任务重复触发不得重复产生事件或重复统计。
- 部分来源失败时保留成功结果，并显示失败来源数、最近成功时间和重试入口。
- 数据快照超过 24 小时显示“可能过期”；超过 48 小时且没有成功刷新时不得继续标为“今日”。
- 刷新失败不清空上一版可用内容，除非内容已撤回或存在安全风险。

### 7.9 紧急事件

只有以下官方或高置信信号可进入紧急候选：重大持续服务中断、严重安全公告、明确模型下线/价格生效、强监管紧急通知。

- 社区热帖、媒体独家传闻、普通新模型发布和融资新闻默认不触发紧急提醒。
- 紧急状态必须显示确认来源、开始时间、当前状态和最近更新时间。
- 未确认信号只能显示为“待核验”，不得使用确定性告警文案。
- 外部推送、短信、邮件或消息通知不在当前范围内。

### 7.10 时间契约

| 字段 | 产品含义 | 禁止替代 |
|---|---|---|
| `source_published_at` | 主源声明的原始发布时间，保留原值、时区和规范化值 | 不能用抓取时间代替 |
| `updated_at` | 主源内容或该事件事实最近更新的时间 | 不能伪装首次发布 |
| `effective_at` | 价格、限额、弃用、下线、规则等实际生效时间 | 未声明时保持未知 |
| `first_seen_at` | 本雷达首次发现该候选的时间 | 不能决定事件属于哪一天 |
| `obtained_at` | 本雷达合法获得该观察的时间 | 不能冒充主源发布时间 |
| `fetched_at` | 某次连接器请求完成的时间 | 不能冒充已核验或已发布 |
| `verified_at` | 主源、对象、版本和关键动作完成核验的时间 | 未核验候选不得填写成功值 |
| `snapshot.as_of` | 当前快照纳入观察的事实截止点 | 不能用响应时间覆盖 |
| `snapshot.published_at` | 该不可变快照正式可查询的时间 | 不能说明内容本身刚发布 |
| `observed_at` | 客户端本次收到状态／响应的观测时间 | 不能制造“刚刚更新” |

时间字段统一保留来源时区和规范化时区。任何未来时间、无法解析的时区或时间顺序冲突都进入隔离并展示原因；不得靠截断、改成当前时间或静默删除来通过校验。

### 7.11 趋势与版本演进

- 固定提供 7／30／90 日窗口；窗口锚定所选快照 `as_of`，相同快照与规则版本下结果可复算。
- 每个趋势必须显示样本量、已接入来源数／allowlist 来源数、来源类型与地区覆盖、缺失天数、规则版本、快照 `as_of` 和已知缺口。
- 趋势只能称“本雷达已接入来源样本趋势”，不得称市场份额、全行业热度或完整 AI 趋势。
- 版本演进按模型／API／SDK／工具／框架展示发布、更新、breaking、deprecation、回滚和生效节点；迟到补录保持原历史位置。
- 来源覆盖、规则或去重方式变化时必须标注断点，不把不可比区间连成确定趋势。

### 7.12 开源／开放权重／源码可用语义

- `open-source`：许可证允许的源码开放项目；必须显示许可证及适用对象。
- `open-weights`：模型权重可获取，但代码、训练数据或使用权可能不同；不得简称“完全开源”。
- `source-available`：源码可查看但许可证不满足开放源码定义或带有限制；必须显著说明限制。
- 许可证未在主源明确声明时显示“未声明／待核验”，不得根据仓库公开、模型卡措辞或社区说法猜测。
- 新版事件至少包含项目／模型身份、版本或 tag；有 commit 时保留 commit，另列 breaking、deprecation、`effective_at` 和开发者动作。只有普通 commit、Star 增长或无 Release 语义的噪声默认不进入正式日榜。

### 7.13 开发者行动价值

正式事件必须至少回答一个可操作问题：是否需要试用新模型、升级 SDK／工具、迁移模型 ID、调整 API 参数／限额／预算、锁定或替换版本、处理安全／服务风险、关注 breaking／deprecation 截止时间，或明确说明当前无需动作。行动建议属于人工判断或系统推断，必须引用事实依据，不能替代官方升级说明。

## 8. 事件准入、去重与排序规则

### 8.1 正式事件硬门槛

正式事件必须同时满足：

1. 属于模型／多模态／推理版本，开源模型、权重或 GitHub Release，API／SDK／CLI／开发工具，Agent／工作流框架，模型平台价格／限额／弃用，具有直接开发影响的研究／评测，重大安全／服务状态，或直接改变开发者可用性的监管动作。
2. 至少一个可直接打开的主源；只有搜索摘要、截图或无原文内容时不得进入正式日榜。
3. 发布方、对象、版本或动作、`source_published_at` 和适用的 `effective_at` 可识别；未知字段有明确原因而非被当前时间替代。
4. 内容取得方式与保存范围符合当前已知访问、条款和版权边界。
5. 事实／厂商观点／系统推断／待核验标签、证据置信度、为什么重要和开发者动作均已填写；未知必须明确写未知。
6. 已通过未来时间、外部不可信内容、主源身份和重复事件检查；任何一项阻断失败只能留在候选／隔离区。

### 8.2 事件类型

Live Daily MVP 事件类型至少包括：`model-release`、`multimodal-release`、`reasoning-release`、`open-source-release`、`open-weights-release`、`github-release`、`api-change`、`sdk-change`、`developer-tool-release`、`agent-framework-change`、`workflow-framework-change`、`platform-change`、`price-change`、`limit-change`、`deprecation`、`research-impact`、`evaluation-impact`、`security-incident`、`service-incident`、`regulation-impact`。

泛应用教程、纯营销活动、普通融资与并购、仅有 Star／热搜增长、没有开发行动价值的产业新闻默认不进入正式日榜；扩大为泛 AI 行业雷达必须经过产品变更审核。

### 8.3 四层去重

1. URL 规范化：处理跟踪参数、重定向、canonical 和镜像。
2. 精确内容：规范标题、版本／tag／commit、日期、空白和语言后比对。
3. 事件实体：组织 + 模型／产品／项目 + 事件类型 + 版本／tag／commit + 发布／生效日期 + 关键动作。
4. 跨语言候选：语义相似只用于提出合并候选，最终必须以实体、版本、日期和动作确认。

同一发布被官网、GitHub、文档和社区跨站传播时合并为一个事件并保留多条证据；错误合并必须支持拆分并保留修正记录。不同版本／tag／commit、价格调整、breaking、deprecation、生效日期、重大 Bug、回滚或后续安全事件不能仅因标题相似而强行合并。

### 8.4 重要性评分

产品排序沿用已批准调研的七个维度：影响 25%、新颖性 18%、行动价值 18%、证据质量 16%、影响范围 10%、紧迫性 8%、多样性价值 5%，再扣除重复、未核验、营销、付费墙和过时惩罚。

- 正式日榜建议分数门槛为 65/100；分数只是排序辅助，不能替代硬门槛。
- 单一厂商自述、社区热度和转载数量不能直接提高证据质量。
- 用户偏好可调整行动价值和排序，不得修改原始证据质量。
- 评分调整、人工改分和原因必须可回看；`seed_demo` 的分数只用于演示，live 分数也不得在没有训练与验证证据时称为已训练模型结果。

## 9. 核心用户流程

### 9.1 浏览与核验

```text
进入今日雷达
  → 查看数据性质与截至时间
  → 浏览 0–20 条正式事件
  → 按厂商/类型/地区/置信度筛选
  → 打开事件详情
  → 区分事实、来源观点和系统推断
  → 查看主源/佐证/反证
  → 打开原文或返回原列表位置
```

### 9.2 偏好与反馈

```text
打开偏好
  → 选择关注与不想看
  → 预览排序影响
  → 保存当前作用域
  → 在事件上标记已读/收藏/不相关
  → 可撤销或查看反馈原因
```

### 9.3 Live Daily 刷新与发布

```text
触发刷新
  → 显示任务开始和来源进度
  → 合法来源取得候选
  → 去重、聚类、核验和排序
  → 成功：产生新快照并说明新增/更新/合并数
  → 部分成功：保留成功结果并列出失败来源
  → 失败：保留上一快照，提供原因和重试
```

### 9.4 趋势与版本核验

```text
进入趋势与版本演进
  → 选择 7／30／90 日窗口
  → 先查看样本量、来源覆盖、缺失天数、规则版本和 as_of
  → 查看本雷达已接入来源样本趋势
  → 下钻模型／API／SDK／工具／框架版本节点
  → 打开事件详情与主源
```

### 9.5 开源／发布专题

```text
进入开源／发布专题
  → 按 open-source／open-weights／source-available 筛选
  → 查看许可证或“未声明”
  → 核对版本／tag／commit、breaking、deprecation 与生效时间
  → 阅读开发者动作
  → 打开官方仓库 Release、模型卡或项目主页
```

## 10. 页面与数据状态

| 状态 | 产品行为 |
|---|---|
| 首次进入/无快照 | 解释当前无内容、数据性质和下一步，不展示空白假榜单 |
| `seed_demo` | 明确“演示／人工整理”、未连接和截至时间；不参与 live 事件数、趋势或来源成功率 |
| `live` | 显示快照版本、`as_of`、`published_at`、最近成功、来源覆盖和失败范围 |
| `degraded_live` | 继续展示上一份有效 live 快照，并显示失败、遗漏窗口和真实新鲜度 |
| 今日无高置信事件 | 显示 0 条并说明不凑数，仍可查看历史和来源状态 |
| 筛选无结果 | 显示当前筛选条件和清除入口，不等同于全局无内容 |
| 数据过期 | 超过 24 小时提示可能过期；超过 48 小时不再称“今日” |
| 迟到补录 | 按原始发布时间进入历史，显示首次发现时间和“补录”，不冒充今日发布 |
| 未来时间／时间冲突 | 隔离候选并显示原因，不进入今日、趋势、版本演进或正式统计 |
| 加载中 | 保留任务上下文，禁止闪现旧数据为新数据 |
| 部分可用 | 展示成功内容和失败来源范围，不把部分结果说成完整 |
| 全部失败 | 保留最近一次可用快照、失败时间和重试入口 |
| 日报未生成／延迟 | 显示计划时间、实际运行、遗漏原因和手动刷新入口，不用旧日报冒充当日新报 |
| 来源覆盖变化 | 显示 allowlist／规则版本和趋势断点，不把不可比窗口连续呈现 |
| 原文失效 | 保留事件与失效标记，优先寻找同一主源的新地址；不静默替换为二手来源 |
| 证据冲突 | 并列显示冲突和各自来源，状态降为待核验或相应降低置信度 |
| 内容撤回/修正 | 明确标记撤回或已修正，并保留更新时间与原因 |
| 来源受限 | 不提供规避入口；显示需授权/人工核验及当前关闭状态 |

## 11. 响应式、键盘与无障碍要求

- 支持 320px 到 2560px 宽度；移动端仍能完成今日／过去 24h 切换、搜索筛选、趋势窗口切换、开源分类、刷新、打开详情、查看证据和返回原位置。
- 所有核心操作可通过键盘完成，焦点顺序与内容顺序一致；弹层/抽屉关闭后焦点返回触发点。
- 搜索、筛选、标签、置信度、来源角色、数据连接和错误状态均有可访问名称，不以颜色作为唯一表达。
- 动态结果数量、筛选变化、刷新结果和错误通过可感知状态播报，但不得反复打断阅读。
- 原文链接必须说明目的和来源域名；外部打开行为可预期。
- 长标题、长模型名、中英文混排、URL、版本号和时间在 320px 下不得遮挡关键状态或操作。
- 页面缩放至 200% 时核心内容和操作仍可用；不要求横向滚动才能阅读主要事件内容。
- 内容顺序应先给结论与数据性质，再给筛选和事件，再给补充说明；辅助技术用户不应先穿过大量导航才能到达今日事件。

## 12. 合规、版权、隐私与安全边界

1. robots 是访问规则，不等于版权或合同授权；启用来源前需同时核验 robots、服务条款、API 条款、速率、资格和保留/删除义务。
2. X、Reddit、微博、哔哩哔哩及任何需登录、Cookie、付费、开发者申请或商业协议的来源默认关闭；只能经正式 API/授权或人工查看。
3. 禁止模拟登录、共享凭证、使用浏览器登录态、绕过反爬/付费墙/访问控制。
4. 默认只保存规范化 URL、标题、发布方、时间、事件字段、短自写摘要、证据角色、置信度和必要指纹；不保存全文、图片、视频、完整字幕、评论或个人资料。
5. 不复制媒体/Newsletter 正文，不热链受限媒体，不去除水印；必要引用保持最短并标明出处。
6. 任何 API Key、Token、Cookie、账号、`.env` 或秘密都不能进入界面演示、文档、Git 或事件记录。
7. 若未来面向中国境内公众提供生成摘要，必须重新评估生成合成内容标识、备案、内容治理和服务责任；当前内部验证不等于已满足公开服务要求。
8. 用户偏好与反馈属于个人使用数据；未获授权前不上传第三方、不跨设备同步、不用于外部模型训练。
9. 外部页面、仓库内容、README、Issue、模型卡与论文均视为不可信输入；其中的指令、提示词或脚本不得被执行，也不得改变来源政策、事实标签或产品规则。
10. 正式事件只能引用 allowlist 内核验通过的主源；重定向后的最终域名、仓库组织、发布身份和外链目标必须可识别，未知或不一致时进入隔离。

## 13. 产品指标与影子运行门槛

### 13.1 内容体验与真实性指标

- 首屏能够识别数据性质、截至时间、今日事件数和第一条事件。
- 100% 正式事件具有主源链接、发布方、完整时间契约、事实标签、置信度和开发者动作。
- 演示数据、人工快照、未接通状态和未实测指标误标为真实/实时的数量为 0。
- 用户可以在不打开二手来源的情况下完成主源核验。
- 7／30／90 日趋势 100% 显示样本量、来源覆盖、缺失天数、规则版本和 `as_of`；“市场份额／全行业完整趋势”误称次数为 0。
- `seed_demo` 对 live 今日事件数、来源成功率、趋势和刷新成功指标的贡献为 0。

### 13.2 Live Daily 影子运行质量门槛

这些门槛只有在服务阶段获批并取得真实数据后才可测量；当前文档不声称已经达标。

1. 连续运行至少 14 个日历日；样本或事件量不足以判断时延长至 30 日。
2. 100% 已启用来源有访问模式、robots/条款核验时间、保留边界和停用责任记录；未经批准的受限来源启用数为 0。
3. 100% 正式事件有主源、发布方、事件时间、取得时间、事实标签和置信度。
4. 正式日榜每日不超过 20 条；不足 10 条时明确显示不足，凑数事件为 0。
5. 人工标注集优先覆盖全部候选；候选超过 500 条时至少标注 300 条并覆盖同事件/非同事件、跨语言和版本相近样本。
6. 去重 precision 目标不低于 95%，recall 目标不低于 85%；未达标不得宣称“自动去重稳定”。
7. 正式事件人工相关性通过率目标不低于 80%；厂商自述被误写为独立事实、高影响断言无证据或受限来源违规取得均为阻断问题。
8. 重复事件泄漏率目标不高于 5%；高影响事件漏报必须逐条复盘，不以低价值补量掩盖漏报。
9. 来源成功率、调度成功／延迟／遗漏、候选量、隔离量、独立事件量、聚类压缩率、人工改分率、平均核验时间、快照年龄、日报生成状态和实际阅读／收藏／不相关反馈均须如实报告。
10. 若 30 日平均每天不足 6 个独立高分事件，必须重新选择降低数量目标、扩大范围或停止，不能静默把产品改成泛 AI 新闻站。

## 14. 验收标准（Given-When-Then）

### 14.1 内容体验与真实性

- **AC-01**：Given 用户首次进入产品，When 页面完成加载，Then 能立即识别 `data_mode`、`snapshot.as_of`、今日正式事件数、最近成功刷新和当前连接状态。
- **AC-02**：Given 当前只有 `seed_demo` 或人工快照，When 用户浏览任一页面，Then 不显示“实时”“今日已更新”“自动采集成功”或虚假的下一次运行时间。
- **AC-03**：Given 今日只有 7 个通过硬门槛的事件，When 生成日榜，Then 只展示 7 个并说明高置信事件不足，不补入低分候选。
- **AC-04**：Given 今日有超过 20 个合格事件，When 生成正式日榜，Then 日榜最多展示 20 个，其余可在全部事件中查看。
- **AC-05**：Given 同一发布方有超过 3 个普通合格事件，When 生成日榜，Then 默认最多保留 3 个；例外必须说明重大影响理由或合并为事件簇。
- **AC-06**：Given 用户进入详情后返回，When 返回原列表，Then 日期／窗口、筛选、排序和阅读位置保持不变。

### 14.2 事件、证据与事实安全

- **AC-07**：Given 一个事件进入正式日榜，When 检查字段，Then 主源、发布方、对象、版本／动作、完整时间契约、事件类型、事实标签、置信度、为什么重要和开发者动作均存在或明确标未知及原因。
- **AC-08**：Given 厂商声称某模型“第一／SOTA／提升 X%”但没有独立评测，When 展示该断言，Then 明确写成“厂商称”并标为来源观点。
- **AC-09**：Given 系统输出影响判断或行动建议，When 用户查看详情，Then 该内容标为系统推断并列出所依据事实与不确定性。
- **AC-10**：Given 只有社区帖子或媒体单源且找不到主源，When 处理候选，Then 状态为待核验且不进入正式日榜。
- **AC-11**：Given 两个媒体转载同一新闻稿，When 展示证据链，Then 不把它们计为两个独立佐证。
- **AC-12**：Given 官方发布后出现独立评测反证，When 更新事件，Then 主叙事和反证并列展示，并更新置信度或状态。
- **AC-13**：Given 原文被撤回或更正，When 用户再次查看，Then 事件明确标记撤回／更正及时间，不静默保留旧结论。

### 14.3 去重、排序与范围

- **AC-14**：Given 中英文页面描述同一组织、对象、版本、动作和日期，When 形成事件，Then 合并为一个事件并保留多条证据。
- **AC-15**：Given 同一发布方同日发布两个不同版本／tag／commit，When 标题高度相似，Then 不得仅凭语义相似强制合并。
- **AC-16**：Given 事件分数低于 65 或未通过主源硬门槛，When 生成日榜，Then 不进入正式日榜。
- **AC-17**：Given 用户提高某发布方权重，When 重新排序，Then 可以提高其行动价值排序，但不能让无主源、受限或未核验内容越过硬门。
- **AC-18**：Given 普通教程、纯营销、普通融资或无开发影响的产业新闻，When 分类，Then 默认排除；扩大为泛 AI 行业雷达须走产品变更审核。

### 14.4 搜索、筛选、偏好与反馈

- **AC-19**：Given 用户组合地区、发布方、事件类型、开放语义、许可证、事实标签、置信度、新鲜度和开发者动作筛选，When 结果更新，Then 显示结果数和全部已生效条件。
- **AC-20**：Given 筛选后无结果，When 页面显示空状态，Then 明确是当前条件下 0 条并提供清除入口，不误报全局无内容。
- **AC-21**：Given 用户搜索模型、项目、版本或 tag，When 命中事件，Then 可从结构化字段、标题或短摘要找到结果，而不依赖未授权全文。
- **AC-22**：Given 用户标记“不相关”，When 保存当前会话反馈，Then 记录原因、允许撤销、影响当前作用域排序但不删除历史证据。
- **AC-23**：Given 用户收藏事件，When 收藏状态变化，Then 不改变该事件的客观重要性、事实标签或证据质量。
- **AC-24**：Given 尚无获批的账号和反馈持久化范围，When 用户修改偏好或反馈，Then 明确当前浏览器／会话作用域，不声称已云端或跨设备保存。

### 14.5 来源、刷新与异常

- **AC-25**：Given 来源来自 X、Reddit、微博、哔哩哔哩或需登录／付费／API 申请的平台，When 未获得独立授权，Then 状态为受限或人工查看，自动启用数为 0。
- **AC-26**：Given 用户查看来源目录，When 某来源只有研究建议而没有运行证据，Then 显示“建议／未连接”，不称已接入。
- **AC-27**：Given `data_mode=seed_demo`，When 用户点击刷新，Then 只重载当前种子快照并继续显示未连接，不触发外部取得。
- **AC-28**：Given live 刷新中部分来源失败，When 其他来源成功，Then 保留成功结果并说明失败范围、最近成功时间和重试入口。
- **AC-29**：Given live 刷新全部来源失败，When 用户查看页面，Then 最近有效 live 快照仍可阅读并显示失败时间；旧数据不伪装成新数据。
- **AC-30**：Given `snapshot.as_of` 距 `observed_at` 超过 24 小时，When 用户浏览，Then 标“可能过期”；超过 48 小时且无成功刷新时不再称“今日”。
- **AC-31**：Given 用户重复触发同一刷新，When 任务运行中或相同输入已完成，Then 不重复产生候选、正式事件、快照、统计或任务。

### 14.6 响应式与无障碍

- **AC-32**：Given 320px 宽度，When 用户浏览今日、全部事件、趋势、开源专题和详情，Then 关键状态与操作可完成且主要内容无需横向滚动。
- **AC-33**：Given 用户仅使用键盘，When 完成窗口切换、筛选、刷新、趋势下钻和打开原文，Then 所有 P0 操作可达，焦点顺序连续，临时层关闭后焦点返回触发点。
- **AC-34**：Given 屏幕阅读器用户查看事件，When 读取标签与置信度，Then 能获知文字状态、来源角色、模式、新鲜度和连接状态，不只依赖颜色或图标。
- **AC-35**：Given 筛选、刷新、来源故障或日报状态动态变化，When 状态更新，Then 辅助技术获得适度播报且不重复打断阅读。
- **AC-36**：Given 页面缩放到 200%，When 用户操作核心流程，Then 内容和操作仍可用，长名称、版本、URL 与时间不遮挡关键状态。

### 14.7 合规、版权与影子运行

- **AC-37**：Given 任一来源准备自动启用，When 检查来源注册，Then 允许范围、访问方式、robots／条款／API、权利基础、保留边界、复核时间与停用责任均有记录。
- **AC-38**：Given 内容来自媒体、Newsletter 或视频，When 生成事件，Then 默认只保留最小元数据、短自写摘要和原文链接，不保存全文、图片、完整字幕或评论。
- **AC-39**：Given 页面、文档、日志或快照可能包含凭证，When 执行交付检查，Then API Key、Token、Cookie、账号、`.env` 和秘密出现数量为 0。
- **AC-40**：Given 尚未完成真实影子运行，When 展示质量指标，Then 显示定义或“未实测”，不得填写推测数字。
- **AC-41**：Given 影子运行达到至少 14 日，When 申请宣布去重稳定，Then precision 不低于 95%、recall 不低于 85%，并公开样本量与范围；否则只能报告未达标。
- **AC-42**：Given 30 日平均每日独立高分事件少于 6 个，When 形成产品结论，Then 必须提出降低数量目标、合规扩大覆盖或停止三类决策，不得静默补入低质量内容。

### 14.8 `seed_demo` 兼容模式（仅 AC-43～AC-58 适用）

- **AC-43**：Given 系统被明确配置为 `seed_demo` 且服务进程能响应但种子快照未加载，When 分别检查健康和就绪，Then 健康可成功而就绪必须失败，二者不得合并。
- **AC-44**：Given `seed_demo` 指定种子快照通过完整性检查，When 检查就绪，Then 返回快照 ID、版本、内容哈希、发布时间和截至时间。
- **AC-45**：Given `seed_demo` 快照缺字段、哈希不符或引用断裂，When 加载，Then 就绪失败且不返回伪空事件列表。
- **AC-46**：Given `seed_demo` 快照已发布，When 查询元数据，Then `data_mode=seed_demo`、`connection_state=not_connected`、`snapshot.as_of`、`snapshot.published_at` 和 `observed_at` 可区分。
- **AC-47**：Given `seed_demo` 同一快照版本再次加载，When 比较内容，Then 内容哈希保持一致；内容变化必须形成新版本，不得原地覆盖。
- **AC-48**：Given `seed_demo` 包含事件，When 查询列表，Then 只返回该快照的演示事件，并回显模式、快照 ID、有效筛选和稳定排序依据。
- **AC-49**：Given `seed_demo` 用户组合合法筛选，When 查询事件，Then 只返回满足条件的演示记录；非法枚举得到字段级可读错误。
- **AC-50**：Given `seed_demo` 事件数量超过单次上限，When 查询列表，Then 使用有界分页或等价机制，稳定排序下翻页不重复、不遗漏。
- **AC-51**：Given `seed_demo` 请求事件详情，When ID 存在或不存在，Then 分别返回完整演示关系或明确未找到，不返回空成功对象。
- **AC-52**：Given `seed_demo` 查询来源目录，When 查看任一来源，Then 明确它是种子元数据而非 live 连接状态。
- **AC-53**：Given `seed_demo` 中来源身份是官方站点，When 查看运行状态，Then 仍显示 `not_connected`，不得仅因“官方”显示已接通。
- **AC-54**：Given `seed_demo` 客户端触发刷新，When 重载完成，Then 只读取当前已发布本地种子快照，不向任何外部来源发出请求。
- **AC-55**：Given `seed_demo` 当前种子重载失败但存在上一份有效快照，When 查询数据，Then 可返回上一份并显示 `degraded/stale`、真实截至时间和失败原因。
- **AC-56**：Given `seed_demo` 客户端尝试修改事件、来源或快照，When 请求发生，Then 不存在可执行写入能力或明确拒绝，种子内容保持不变。
- **AC-57**：Given 审计 `seed_demo` 网络行为，When 完成健康、快照、事件和来源查询，Then 对外部来源、第三方模型、账号和遥测服务的请求次数为 0。
- **AC-58**：Given 当前运行模式从 `seed_demo` 切换为 live 候选，When 评估发布，Then 必须使用独立 live 配置、来源政策、运行证据和快照命名空间；不得沿用 `not_connected` 或种子指标冒充 live。

### 14.9 Live Daily 时间、来源、开放语义与趋势

- **AC-59**：Given 快照 `as_of` 为 Asia/Shanghai 当日某时刻，When 打开“今天”，Then 只按该自然日 00:00:00 至 `as_of` 的 `source_published_at` 归属正式事件。
- **AC-60**：Given 用户切换“过去 24h”，When 窗口计算，Then 边界固定为 `[snapshot.as_of-24h, snapshot.as_of]`，页面停留或刷新响应时间不改变同一快照结果。
- **AC-61**：Given 候选含全部时间字段，When 校验，Then 保留来源原值／时区与规范化值；未来时间、无法解析时区或顺序冲突进入隔离且不计入正式统计。
- **AC-62**：Given 今天首次发现一条三日前发布的有效事件，When 核验通过，Then 它按三日前进入历史并标“补录”，可提示“新发现”但不称今日发布。
- **AC-63**：Given live 快照变旧，When 达到 24h／48h 阈值，Then 分别显示“可能过期”／“最近可用快照”，并同步更新所有今日入口、日报和趋势说明。
- **AC-64**：Given 配置默认调度，When 查看运行计划，Then 可见官方机器源每 1–2 小时、研究／评测每日 1–2 次、Asia/Shanghai 08:30 日报及其实际启用值；未运行时不显示成功。
- **AC-65**：Given 本地设备关机、休眠或服务停止跨过计划窗口，When 恢复，Then 显示中断、遗漏窗口、最近成功和恢复后的实际结果，不保证无条件日更。
- **AC-66**：Given 候选来源未进入当前版本 allowlist 或必要政策字段过期，When 调度准备访问，Then 默认拒绝自动访问并留下可审计原因。
- **AC-67**：Given 候选没有可打开且身份匹配的官方主源，When 尝试晋级，Then 正式事件数量增加 0，不得用社区热度或二手转载替代。
- **AC-68**：Given 社区内容发现潜在线索，When 处理，Then 只能生成发现候选；回到主源完成对象、版本、动作与时间核验后才可晋级。
- **AC-69**：Given 候选属于模型／多模态／推理、开源／工具、API／SDK／平台、Agent／工作流、价格／限额／弃用、开发相关研究评测或重大安全／状态，When 具备开发行动价值，Then 可进入核验；泛营销与无开发影响噪声被排除。
- **AC-70**：Given 事件涉及开放项目或模型，When 展示开放语义，Then 明确区分 `open-source`、`open-weights`、`source-available`，并显示许可证或“未声明／待核验”。
- **AC-71**：Given 新版本事件进入正式区，When 查看详情，Then 版本／tag／可用 commit、breaking、deprecation、`effective_at` 和开发者动作分别显示；不存在时明确未知／不适用。
- **AC-72**：Given 官网、GitHub Release、文档与社区传播同一发布，When 去重，Then 形成一个正式事件并保留各证据角色，不重复计入日榜和趋势。
- **AC-73**：Given 同项目有不同版本、tag、commit、breaking 或生效日期，When 聚类，Then 保持为不同事件或明确版本演进节点，不因标题相似误合并。
- **AC-74**：Given 用户查看 7／30／90 日趋势，When 任一窗口呈现，Then 显示样本量、已接入／allowlist 来源覆盖、缺失天数、规则版本、`as_of` 与已知缺口，并仅称“本雷达已接入来源样本趋势”。
- **AC-75**：Given 来源覆盖、规则版本或去重口径在趋势窗口中变化，When 绘制趋势，Then 显示断点和不可比说明，不输出市场份额、全行业完整趋势或无断点连续结论。
- **AC-76**：Given 正式事件含来源陈述、独立核验和影响判断，When 用户阅读，Then 事实、厂商观点、系统推断和待核验内容逐条可区分且各自关联证据。
- **AC-77**：Given 事件具有开发影响，When 展示行动建议，Then 至少给出动作类别、事实依据、适用对象、截止／生效时间和不确定性；无动作时明确“持续观察／无需动作”。
- **AC-78**：Given 用户使用日期／窗口、发布方、对象、类型、开放语义、许可证、新鲜度、来源状态和开发者动作筛选，When 查询，Then 结果、数量和已生效条件一致且可一键清除。

### 14.10 Live 运行、故障、安全与质量

- **AC-79**：Given 同一用户在同一输入快照和来源状态下重复手动刷新，When 请求重入，Then 共用现有任务或返回同一结果，不重复取得、晋级、发布快照或累计指标。
- **AC-80**：Given `live` 与 `seed_demo` 同时存在，When 查询今日、趋势、来源成功率或刷新历史，Then 两种模式使用独立命名空间与指标，任何跨模式混入数量为 0。
- **AC-81**：Given 部分 allowlist 来源失败，When 刷新完成，Then 发布可用成功结果并标 `degraded_live`、失败来源、覆盖缺口、最近成功和重试入口。
- **AC-82**：Given 全部 live 来源失败，When 用户打开产品，Then 保留上一份有效 live 快照；若从无有效 live 快照则明确未就绪，不以空榜或种子快照冒充成功。
- **AC-83**：Given 当前日没有任何通过硬门的事件，When 生成今日榜，Then 显示 0 条、来源覆盖和刷新状态，不补量且仍可访问历史、趋势限制和来源页。
- **AC-84**：Given Live Daily MVP 候选进入发布验收，When 检查 P0 范围，Then 今日、全部事件、趋势与版本演进、开源／发布专题、详情证据链、搜索筛选、来源连接、刷新和质量覆盖均可实际使用；不能以永久 `disabled`、纯静态占位或假数据通过。
- **AC-85**：Given 移动端、键盘或屏幕阅读器用户访问新增 P0 页面和异常状态，When 完成核心流程，Then 窗口、筛选、趋势、刷新、证据、外链及返回均可操作且状态有文字语义。
- **AC-86**：Given 外部页面、仓库、README、Issue、模型卡或论文包含脚本、提示词或诱导指令，When 系统取得内容，Then 其仅作为不可信数据处理，不执行指令、不改变来源政策、不泄露秘密且外链最终目标可识别。
- **AC-87**：Given 来源涉及 robots、API、登录、凭证、付费、版权或保留限制，When 任一授权条件未知／过期／不匹配，Then 自动取得被阻断；凭证不进入前端、快照、日志、文档或 Git，正文不被未授权保存或再分发。
- **AC-88**：Given 进行 live 发布验收，When 查看运行与质量证据，Then 健康、就绪、调度状态、各来源最近尝试／成功／验证、快照年龄、候选／隔离／正式数量、重复与覆盖缺口均来自真实运行；P0 能力不得用“未实现／disabled”冒充通过。

## 15. 非功能需求

### 15.1 性能与反馈

- 在常见桌面和移动网络条件下，首个可读内容目标为 2.5 秒内；未达成时不得用永久骨架屏掩盖。
- 搜索、筛选、排序和窗口切换应在用户操作后 300 毫秒内产生可感知反馈；需要后台任务时先显示已受理、任务身份和真实进度。
- 外部原文不可用、单一来源失败或趋势窗口缺天不应阻塞其他已发布内容。
- 事件、筛选与分页必须具有稳定次序；相同快照和规则版本下重复查询结果可复现。

### 15.2 兼容性

- 支持当前主流桌面 Chrome、Edge、Safari 的最近两个主要版本。
- 支持 iOS Safari 与 Android Chrome 的近两个主要版本。
- 支持 320px–2560px 宽度和 200% 页面缩放。

### 15.3 安全、可靠性与可观测性

- 外部内容均视为不可信数据；页面与服务不得执行来源中的脚本、指令或提示词。
- 原文链接、重定向后的最终地址、来源域名／仓库组织与官方身份必须可识别。
- 产品必须保留来源停用、候选隔离、事件撤回、失败降级和上一有效快照恢复语义；实现方案由后续架构角色定义。
- 健康、就绪、调度、连接器、快照和内容质量是不同状态；任一成功不得替代其他状态。
- 日报、刷新成功、来源覆盖、趋势和质量指标必须来自可审计运行证据，不得用页面访问或种子加载推定。

## 16. 明确不做项

- 不做“覆盖所有 AI”的绝对承诺、全网爬虫、无限新闻流或必须凑满 10–20 条的内容工厂。
- 不把 `seed_demo` 作为 v1.2 主目标、live 成功证据或趋势数据源；它只用于演示、测试与明确故障隔离。
- 不在未进 allowlist、未核验权利或需要绕过登录／付费／访问控制的来源上自动取得。
- 不在本 PRD 指定技术栈、接口路径、数据库表、模型供应商、连接器实现、调度实现、爬虫框架或云平台。
- 不使用浏览器 Cookie、共享账号、模拟登录或绕过 robots、条款、反爬、付费墙和访问控制。
- 不把 X、Reddit、微博、哔哩哔哩设为 MVP 刚性依赖；社区仅可作为发现线索。
- 不保存或再分发全文、图片、视频、完整字幕、评论、个人资料或付费 Newsletter。
- 不做外部推送、自动发帖、邮件订阅、公开日报、团队协作、商业化、公众服务或生产部署。
- 不把厂商宣传、社区热度、单一榜单、系统推断或本雷达样本趋势展示为未经限定的客观全行业事实。
- 不自动采购付费 API、Newsletter 或聚合服务，不申请账号、创建凭证或扩大权限。
- 不默认持久化偏好、已读、收藏或反馈；该隐私与数据范围需另行批准。
- 本轮不生成或修改 UI Prompt、设计稿、架构、任务拆解、前端、后端、连接器、测试或部署产物；只形成 v1.2 产品定义与必要工作流登记。

## 18. `seed_demo` 兼容与隔离规则

### 18.1 定位

`seed_demo` 只用于无网络演示、契约测试、前端开发夹具和故障隔离，不是 v1.2 的 Live Daily MVP 终态。旧 v1.1 的 seed-only 产品增量未获批准并被本版本取代；其可复用部分仅限本节和 AC-43～AC-58。

### 18.2 快照与查询语义

- 只读取随项目发布、结构与哈希完整的演示种子快照；不读取任意文件、不接受用户 URL、不访问互联网。
- 每次查询都可追溯到 `snapshot_id`、版本、内容哈希、`data_mode=seed_demo`、`connection_state=not_connected`、`snapshot.as_of`、`snapshot.published_at` 与 `observed_at`。
- 服务健康只说明进程响应；种子就绪说明指定快照完整可查询；当前重载失败但有上一有效种子时标降级；无有效种子时明确未就绪。
- 事件、来源、筛选、分页与错误均明确属于种子快照；无匹配结果与快照不可用不得混淆。
- 种子内容不可由客户端写入；偏好和反馈若存在仅限浏览器／会话，不写回快照。

### 18.3 与 live 的硬隔离

- `seed_demo` 连接器数和外部请求数固定为 0，仅描述该模式；这不表示 v1.2 live 目标排除真实连接器。
- `seed_demo` 与 live 使用独立快照身份、模式、来源运行状态、今日数量、趋势、刷新历史与质量指标。
- live 不可用时可以让用户明确切换到演示，但不能自动把种子改名为 live、今日、最近成功或上一有效 live 快照。
- 任何官方来源连接器只属于获批的 live 范围，并仍须满足 allowlist、权利、安全、架构与运行门；不得借用种子模式的通过状态。

## 19. Live Daily 前后端产品契约与拆分边界

### 19.1 后端产品责任

后端候选范围必须提供合规来源注册与 allowlist、来源连接状态、可配置调度与手动刷新、增量观察、规范化、去重、候选／隔离／正式事件晋级、版本化不可变快照、趋势与版本样本、健康／就绪、失败降级、审计与新鲜度证据。是否以及如何实现由后续架构和任务拆解决定，本节不指定接口形式或技术栈。

### 19.2 前端产品责任

前端只消费已发布的产品契约，呈现今日、全部事件、趋势与版本演进、开源／发布专题、详情证据链、搜索筛选、来源连接、刷新和质量状态。前端不得自行抓取外部源、伪造今日数据、在客户端补写主源、推定连接成功、混合 seed/live 或用静态占位代替 P0 功能。

### 19.3 必须可追溯的产品对象

| 对象 | 最小产品语义 |
|---|---|
| 快照 | 身份、版本、模式、内容哈希、`as_of`、`published_at`、规则／覆盖版本、新鲜度与降级状态 |
| 事件 | 身份、类型、对象、版本／tag／commit、摘要、事实标签、置信度、重要性、开发者动作、完整时间契约与更新历史 |
| 证据 | 来源身份、证据角色、原文入口、取得／核验时间、事实关联、访问限制与撤回状态 |
| 来源 | allowlist／政策版本、允许范围、访问级别、连接状态、最近尝试／成功／验证、失败与覆盖缺口 |
| 刷新／调度 | 任务身份、触发方式、计划／开始／结束、各来源结果、遗漏窗口、幂等关系与发布快照 |
| 趋势 | 7／30／90 日窗口、样本量、来源覆盖、缺失天数、规则版本、`as_of`、断点与已知缺口 |
| 服务状态 | 健康、就绪、最新有效 live 快照、调度状态和可读错误；各状态不可互相替代 |

### 19.4 模式与失败信封

每次 P0 数据读取都必须能让前端判断 `live`、`degraded_live` 或 `seed_demo`，并获得 `observed_at`、快照身份、新鲜度、覆盖、错误范围与最近成功。无结果、无快照、未就绪、部分失败、全部失败、过期、隔离和权限阻断是不同产品状态，不能统一返回“0 条成功”。
