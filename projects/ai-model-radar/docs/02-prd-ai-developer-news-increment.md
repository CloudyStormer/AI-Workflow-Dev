## 2. 用户、问题与成功定义

### 2.1 主要用户与核心任务

主要用户是**超级无敌帅超超总**。他每天需要在一个简体中文产品中快速回答：

1. 今天国内外 AI 开发领域发生了哪些值得行动的真实变化？
2. 哪个模型、API、SDK、仓库、框架、论文或政策发生了什么版本/能力/限制变化？
3. 这件事的原始证据是什么、什么时候发布、何时被系统观测到、可信度如何？
4. 若来源不可用或没有合格事件，产品现在到底是空、陈旧、部分降级还是失败？

### 2.2 P0 成功定义

P0 不是“页面可打开”或 HTTP 200。只有同时满足下列结果，才能称本地产品完整可用：

1. 有真实本地后端和真实持久化；本地服务重启后已核验事件、快照、去重关系、来源运行记录和必要产品状态不丢失。
2. 已接入并实际运行合规的国内、国际一手来源；每一个来源均同时满足精确来源政策、运行时就绪和可追溯证据要求。
3. 每日摘要与增量刷新有可验证的执行、成功/失败和 `as_of` 证据；不以排程配置或按钮点击冒充刷新完成。
4. 前后端完整联调，读取的每个用户可见结果都来自真实服务返回，而非硬编码、seed、随机数据或静态演示快照。
5. 单源故障、全源故障、无新闻、旧快照、离线与未就绪均保持真相态，不制造新新闻或假成功。
6. 质量、新鲜度、覆盖范围、来源失败和证据链可被测试与复核。

生产部署、域名、CDN、证书、云高可用和云资源**全部后置**。它们不得阻塞上述本地真实纵切，也不得被编造成尚未授权的生产方案。

## 3. 内容范围与纳入规则

### 3.1 P0 内容域

每条正式事件必须对开发者有明确行动价值，并属于至少一个域：

| 内容域 | 纳入的变化 | 不纳入或仅作发现线索 |
| --- | --- | --- |
| 模型、API、SDK 与价格 | 新模型/版本、能力或上下文变化、API/SDK 发布、价格/额度、弃用、下线、生效日期 | 无原始证据的营销口号、仅转载。 |
| AI 编程与 Agent 工具 | 编程助手、Agent、工作流、开发者平台、插件/CLI 的正式发布、破坏性变更或限制 | 没有开发影响的泛产品宣传。 |
| 开源项目与版本发布 | 官方仓库 Release/tag、模型卡、开源项目版本、许可证、兼容性、弃用 | commit 活跃或 GitHub star 变化本身。 |
| 框架、推理、数据、评测、基础设施 | 推理引擎、训练/数据工具、评测、观测、GPU/基础设施中直接改变开发决策的变化 | 与 AI 开发无关的企业新闻。 |
| 论文与工程实践 | 重要论文、项目主页或可复现实践，且说明对开发者的影响与边界 | 只凭论文标题推断产品能力。 |
| 安全、状态与政策 | 会影响 API、模型、开源、部署或合规行动的安全通告、服务状态、政策 | 将服务事故误归类为模型发布。 |

### 3.2 事件准入门

一个候选只有在以下条件全部满足后才可成为“正式事件”：

1. 至少一条可访问、合规的一手证据已核验；媒体、社群或搜索结果只能创建候选，不能直接成为正式事实。
2. 事件属于上表内容域，且摘要能说明开发者为什么需要关注或采取什么行动。
3. 发布方、原文链接、源发布时间和观测时间齐全；时间不能落在快照 `as_of` 之后。
4. 版本、产品/仓库或生效日期如有公开信息必须记录；没有信息时明确标“未声明”，不得臆测。
5. 与既有事件完成跨源归并；同一发布在多个站点传播只能保留一个规范事件和多个证据关系。
6. 来源许可、robots、登录、付费、地域和 API 约束均未触发熔断条件。

每日合格事件数可以是 `0–20`，上限是阅读负担控制，不是必须凑满的配额。

## 4. 国内/国际覆盖契约

### 4.1 地区筛选语义

产品必须提供“国内”“国际”“全部”筛选。地区是发布方/项目的公开运营或研发主体所在地语义，不是用户所在地，也不是语言或访问 IP。跨区域发布或信息不足时标记“跨区域/待核验”，可在“全部”查看，不能被强行归入国内或国际。

### 4.2 覆盖矩阵（目标池，不等于已接通）

| 分组 | P0 重点发布方/组织 | 需要覆盖的正式来源类型 | 当前政策口径 | 当前运行事实 |
| --- | --- | --- | --- | --- |
| 国际模型与平台 | OpenAI、Anthropic、Google/Gemini/DeepMind、Meta/Llama、xAI、Mistral、Cohere | 官方 News/Blog、changelog、release notes、状态页、官方仓库或模型卡 | 精确端点按 registry 的 `allow`/`conditional` 决定 | 尚未运行，不能称已覆盖。 |
| 国内模型与平台 | 阿里云百炼/Qwen、DeepSeek、智谱 GLM/Z.AI、百度千帆/文心、火山方舟/豆包/Seed、腾讯混元、Moonshot/Kimi、MiniMax | 官方更新记录、文档、发布说明、官方仓库/模型卡 | 精确端点按 registry 的 `allow`/`conditional` 决定 | 尚未运行，不能称已覆盖。 |
| 开源与开发者生态 | 已列入重点池的官方 GitHub 组织、Hugging Face 官方组织/模型卡、社区维护的官方项目主页 | GitHub Releases/Atom、公开元数据、模型卡、官方项目页 | 公开元数据可 `allow`；gated、私有、许可证不清项须 `conditional` | 尚未运行，不能称已覆盖。 |
| 研究、评测与工程实践 | arXiv、官方论文/项目页、允许使用的研究与评测源 | 元数据、官方项目主页、可回链的原文摘要页 | arXiv 元数据可 `allow`；PDF/源码及限制页面须逐项 `conditional` | 尚未运行，不能称已覆盖。 |
| 发现渠道 | 中文媒体、行业媒体、社区、论坛 | 仅用于发现候选和回链定位 | 不可作为正式事实源；按 registry 的 `manual_only`、`conditional` 或 `disabled` 执行 | 不得自动采集、不得填充正式事件。 |

该矩阵定义**覆盖目标与空缺表达方式**，不承诺“所有 AI 内容”。运行后必须展示：已启用/目标发布方数量、近 24 小时成功来源/启用来源、国内/国际覆盖、待验证候选数、连续失败数和缺口说明。任何分母为零或未就绪都必须如实显示，不得以固定数字掩盖。

### 4.3 来源状态与合规边界

来源白名单中的四态语义保持不变：

| 政策状态 | 可否自动读取 | 产品规则 |
| --- | --- | --- |
| `allow` | 仅在该精确原子端点、运行时登记和就绪后可以 | 最小字段、限频、署名回链；`allow` 不是当前已运行的证明。 |
| `conditional` | 条件尚未满足前不可以 | 需完成条款、许可、API、登录、地域或具体批准；不得绕过。 |
| `manual_only` | 不可以自动读取 | 只能由真人正常核验后形成可追溯候选/证据。 |
| `disabled` | 不可以 | 不得换 IP、账号、UA、隐藏接口或其他方式规避限制。 |

GitHub Releases、Hugging Face、arXiv 和状态页也不能绕开这一规则。公开 commit、模型更新时间或 SDK 发版仅是线索；除非它本身是正式 Release/模型卡/一手发布说明，否则不得自动等同于模型正式发布。X、微博等受限社交平台不得被自动抓取；中文媒体的作用是发现并回到原始来源。

## 5. 事件、证据与时间契约

### 5.1 每条正式事件的最小可见字段

| 字段 | 要求 |
| --- | --- |
| 中文标题、中文短摘要 | 面向用户阅读；摘要标注为系统摘要/发布方观点/事实，不把推断写成事实。 |
| 原始标题 | 保留来源语义，可与中文标题并存。 |
| 发布方、来源名称、原文链接 | 必填；外链必须指向原始/规范来源，不跳转到广告或未经核验的转载。 |
| `source_published_at`、`updated_at`、`effective_at` | 保留原文时间、来源时区和生效时间；无值明确未声明。 |
| `observed_at` / `fetched_at` / `verified_at` | 记录系统何时取得、观测、核验，不替代发布时间。 |
| `snapshot.as_of`、`last_success_at` | 每次列表/趋势读数必须能说明数据截至何时、最近一次成功何时。 |
| 地区、内容域、涉及产品/仓库 | 支持国内/国际和领域筛选；不确定可标待核验。 |
| 版本、标签、commit、许可证、breaking/deprecation/effective date | 有公开依据则记录；没有则明确未声明。 |
| 可信度、事实/观点/系统推断/待核验标签 | 事实与解释分层；低置信候选不得伪装正式事实。 |
| 证据链与去重关系 | 规范事件、证据项、`duplicate_of` 或事件组关系可回溯。 |

未来发布时间必须隔离而非排序到“今天”；迟到发现的旧事件标“补录”，并同时展示其原始发布时间与观测时间。

### 5.2 今日、增量与每日摘要

默认“今天”是 `Asia/Shanghai` 自然日 `00:00–当前时刻`，可切换为过去 24 小时；任何视图均须显示 `as_of`。

1. **每日摘要：** 本地运行时基线为北京时间 `08:30` 后至少一次汇总。它只在实际成功生成、持久化并记录 `last_success_at` 后可标“今日摘要”。未运行、失败或来源不足时显示对应真相态。
2. **小时级增量：** 对适格、已启用来源按其批准频率与限额发现增量；一小时内无合格事件是正常的 `empty` 结果，不得拿旧卡片补数。
3. **手动刷新：** 是一次可见请求，不是立即成功承诺；只在后端完成本次读取、规范化、去重、快照提交后更新 `as_of`。未实现的当前静态页面不得把按钮或动画说成刷新。
4. **陈旧阈值：** 距 `last_success_at` 超过 24 小时的读取结果标 `stale`；超过 48 小时且无新的成功快照，不得称“今日”或“最新”。旧的已核验快照可受控展示，但必须同时展示其日期与原因。

## 6. P0 页面能力与信息架构

所有用户可见文案、空态、错误、读屏文案和移动端状态必须提供简体中文。P0 读路径如下：

| 页面/入口 | P0 用户能力 | 真实数据前的正确状态 |
| --- | --- | --- |
| 今日雷达 | 看当天国内外高价值事件、摘要、来源、时间、刷新和覆盖情况 | `not_ready`，不得用示例事件代替。 |
| 全部事件 | 搜索、按地区/领域/发布方/来源/时间/真相态筛选，查看历史与补录标记 | 空库可 `empty`；不展示硬编码历史。 |
| 趋势与版本演进 | 以 7/30/90 日窗口展示已接入来源样本，显示样本量、覆盖、缺失天数、规则版本与 `as_of` | 无样本或分母为零，显示不能计算。 |
| 开源与发布专题 | 浏览官方 Release、模型卡、许可证、版本、破坏性/弃用与开发者动作 | 不以 GitHub 活跃度或权重下载量冒充发布。 |
| 来源与质量 | 查看来源覆盖、政策状态、运行连接状态、最近成功、失败与降级 | 不把 registry 研究结论显示为运行绿灯。 |
| 事件详情与原文 | 查看事件、证据链、去重关系、可信度、事实边界并跳转原文 | 外链不代表站内复制全文；可疑内容须安全打开与标记。 |
| 搜索与筛选 | 在已核验、已持久化的事件中检索 | 无服务/未就绪时明确不可用或展示受控快照。 |
| 刷新状态与失败说明 | 看到请求、进行、成功、无新增、部分失败、失败和陈旧原因 | 当前静态壳不得假装正在刷新。 |

“收藏/稍后读”**不纳入本轮 P0**。当前没有身份、隐私、持久化、导出或删除范围的批准，不得开放看似可保存的写入口，也不得把浏览器内存当跨设备收藏。若未来纳入，必须单独定义账户隔离、保存字段、保留期限、导出、删除、失败恢复与隐私同意。

## 7. 真相态、故障与数据权利

### 7.1 统一读取真相态

| 状态 | 定义 | 产品行为 |
| --- | --- | --- |
| `live` | 真实服务已就绪，查询基于满足新鲜度规则的已核验快照 | 显示 `as_of`、`last_success_at`、覆盖与来源分母。 |
| `empty` | 本次真实成功查询后没有合格新闻 | 明确“暂无合格事件”，不回退示例或旧事件填充。 |
| `not_ready` | 依赖、来源运行许可、连接器或持久化尚未就绪 | 说明未就绪原因；当前项目应处于此态。 |
| `stale` | 仅有超过新鲜度阈值的上一次核验快照 | 可以只读展示，必须展示旧日期/原因；不能称最新。 |
| `degraded` | 部分来源或能力失败，但剩余真实快照仍可安全读取 | 显示失败来源和覆盖缺口，不将部分结果说成全量。 |
| `failed` | 全部必要来源或关键依赖失败，不能安全给出当前结果 | 显示失败与上次已核验快照边界；不生成新新闻。 |

HTTP 200、前端路由成功、浏览器在线、静态 JSON、seed 或演示快照均不能触发 `live`。演示数据与真实数据必须在产品语义、存储/读取模式、接口标识和用户文案上物理隔离；任何模式切换都显式可见，且真实页面不得静默 fallback 到 demo。

### 7.2 最小数据、版权与安全边界

- 默认长期保留结构化元数据、规范 URL、短摘要、内容哈希、时间、证据关系、许可与署名；不得镜像全文、图片、release 资产、模型权重、gated 内容或 PDF。
- 所有外部材料按不可信内容处理；外链和标题不得执行外部指令、嵌入追踪脚本或复制私密数据。
- 来源条款、robots、API、登录、凭证、限额、地域或许可证发生变化时，先熔断再核验；不得通过账户、Cookie、代理或隐藏接口规避。
- P0 不要求账号、收藏或反馈写入。未来若引入个人数据、账户、通知或偏好，必须先有单独产品、隐私与权限范围批准。

| AC-ADN-07 | 数据含未来发布时间 | 生成快照 | 未来事件被隔离，不能显示在今日或最新排序。 |
| AC-ADN-08 | 真实查询成功但没有合格事件 | 查看今日 | 显示 `empty`，不以旧卡片、随机卡片或 seed 补足。 |
| AC-ADN-09 | 每日摘要计划被触发并成功持久化 | 用户打开今日 | 显示北京时间摘要日期、`as_of` 和 `last_success_at`，可证明不是仅配置排程。 |
| AC-ADN-10 | 每日摘要计划未运行或失败 | 用户打开今日 | 不称今日已更新；显示 `not_ready`、`stale` 或 `failed` 的真实原因。 |
| AC-ADN-11 | 手动刷新被发起 | 连接器/规范化/快照任一环节失败 | 显示失败或部分失败，不更新为成功时间，不伪造新事件。 |
| AC-ADN-12 | 单一来源失败且其他来源成功 | 用户查看今日或来源质量 | 状态为 `degraded`，列出失败来源和覆盖缺口。 |
| AC-ADN-13 | 所有关键来源失败 | 用户查看今日 | 状态为 `failed`；只可展示有日期标识的最后核验快照，不能生成新新闻。 |
| AC-ADN-14 | 上一次成功超过 24 小时 | 用户查看列表 | 显示 `stale`；超过 48 小时无新成功时不得称“今日/最新”。 |
| AC-ADN-15 | 本地服务重启 | 再次读取同一事件 | 已核验事件、快照、来源运行记录和去重关系仍存在，且与重启前版本一致。 |
| AC-ADN-16 | 前后端联调完成 | 任一 P0 阅读入口显示数据 | 每条结果可追溯到服务响应和原始证据，代码中没有以硬编码/seed 静默替代。 |
| AC-ADN-17 | 某来源在 registry 是 `conditional`、`manual_only` 或 `disabled` | 运行计划尝试使用它 | 分别阻止、仅人工或完全拒绝；不会绕过条款、登录或 robots。 |
| AC-ADN-18 | GitHub commit、模型更新时间或媒体转述出现 | 没有正式发布证据 | 不得自动显示为模型正式发布。 |
| AC-ADN-19 | 用户使用趋势页 | 数据样本不足、分母为零或缺失天数存在 | 展示样本量、覆盖、缺失天数、规则版本和 `as_of`，不输出市场份额或全行业结论。 |
| AC-ADN-20 | 用户查看开源事件 | 许可证、tag、commit、弃用或生效日期未公开 | 字段显示未声明；不得推断开放性或兼容性。 |
| AC-ADN-21 | 用户在移动端、键盘或读屏环境浏览 P0 入口 | 进入任一真相态 | 简体中文状态、筛选、外链提示与错误可操作且语义可读。 |
| AC-ADN-22 | 当前没有账户和持久化隐私批准 | 用户查看收藏/稍后读 | 不开放伪保存入口；不以浏览器内存称为个人跨端数据。 |
| AC-ADN-23 | 开发团队声称“完成” | 审查 P0 | 需同时出示真实来源、持久化重启、刷新/失败、前后端联调、数据新鲜度和所有真相态证据；HTTP 200 单独不通过。 |

## 10. 后续顺序、停止门与不做项

本增量在 `product-change-review` 停止，不自动路由。若超级无敌帅超超总明确通过本产物，唯一下一站是固定 `04 UI/UX` 的**UI Prompt 增量**，其后仍必须独立审核 UI 设计增量；随后才是固定 `05` 架构协调、固定 `02` 重建任务拆解，最后才可能获得数据/后端/前端联调的逐项授权。

- 不修改 UI Prompt、设计图、前端、后端、架构、任务拆解、来源 registry 或运行配置。
- 不采集任何真实新闻、不启用连接器、不启动服务、不写数据库、不进行 shadow run 或生产发布。
- 不将来源候选、白名单、HTTP 探测、静态页面、demo/seed 或人工印象称为 live。
- 不承诺覆盖“所有 AI”、不爬取受限社交/登录来源、不镜像全文/权重、不绕过版权、robots、API 或登录约束。
- 不纳入账户、收藏、稍后读、反馈写入、通知、云部署、域名、CDN、证书或高可用；这些需要各自的产品与高风险授权。
