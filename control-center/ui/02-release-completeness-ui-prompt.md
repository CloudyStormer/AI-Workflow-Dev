# 【可直接复制给专业 UI 设计模型的完整提示词｜复制开始】

你是一名资深企业级数据产品 UI/UX 设计师。请为“AI Workflow Control Center”生成一套高保真、可落地、完整简体中文的 Web 控制中心设计稿与可点击原型。产品是本地只读的 AI 软件工程治理事实聚合器，不是审批后台、项目写控制台或生产发布器。

设计必须极简、干净、清晰、有强逻辑和高信息密度；显著减少说明性大段文字，以矩阵、时间线、状态轨道、趋势、证据关系和可下钻图表表达项目、角色、阶段进度、审批、产物、事件、Bug／复测、迭代、发布、来源与工作流成熟度。任何数字、百分比、绿灯或“实时”文案都必须有可追溯事实，不得为了画面漂亮补造数据。

## A. 产品目标与首屏任务

主要用户是项目所有者“超级无敌帅超超总”，辅助用户是固定 00 包工头与 01—11 专业角色。用户进入后 10 秒内应能回答：

1. 当前服务是否健康，真实根仓监管数据是否就绪？
2. 已发现多少项目，成功观测多少，哪些项目或数据域失败？
3. 每个项目处于什么阶段、什么审核门、谁负责、哪里阻塞？
4. 哪些审批待决、哪些已经有结构化决定，是否存在审批证据缺口？
5. 哪些产物哈希一致，哪些是工作副本、历史批准版本或哈希不一致？
6. 事件、问题、复测和发布证据是否完整，哪些只是覆盖不可用而不是“0”？
7. 来源是否新鲜，当前快照是否一致，工作树是否有修改？
8. 工作流成熟度是否具备计算依据；若不能计算，缺什么证据？

## B. 不可突破的产品原则

1. **只读零写。** 不提供批准、拒绝、状态迁移、问题流转、发布、回滚、Git、文件修复、备份执行或外部通知写入口。
2. **事实源优先。** 只能使用允许的根仓结构化治理文件和已登记证据；UI 常量、聊天、README 概述和文件夹存在不是监管事实。
3. **健康与就绪分离。** 进程可响应不等于数据可用；健康、就绪、覆盖、新鲜度和业务风险不能共用一个绿色圆点。
4. **未知不等于零。** 未登记、覆盖不可用、解析失败、未观测、筛选无结果和真实 0 必须分别设计。
5. **部分失败可用。** 单项目损坏时保留其他项目结果，整体标“降级可用”，并就近显示失败范围和最后成功时间。
6. **一致快照。** 一次观测只能来自同一 `root_head`；读取期间提交或文件哈希变化时丢弃混合快照并重新读取。
7. **演示隔离。** 演示、静态回退和目标态样例不得混入正式统计，不得静默改名为真实数据。
8. **证据下钻。** 每个汇总数字、状态和图形标记必须能回到项目、源文件、SHA256、根仓提交与观测时间。
9. **完整简中。** 所有导航、状态、筛选、错误、图例、坐标、空态、表格、移动端与无障碍名称使用简体中文；内部键只能放开发附注或中文后的括号中。
10. **不推断人。** 无结构化证据时，不显示角色在线／离线、忙闲百分比、绩效或预计完成时间。

## C. 信息架构

保留 6 个一级导航，避免导航膨胀；审批、产物、事件、问题、发布和来源通过稳定二级路由完整可达，而不是藏在不可发现的弹窗中。

1. **总览**：健康与就绪、覆盖、项目阶段全景、待审、风险、问题／复测、发布和成熟度摘要。
2. **项目与阶段**：全部项目、阶段 0–10、项目详情、审批、产物和事件二级页。
3. **角色协作**：固定 00 与 01—11 共 12 个唯一角色，多项目占用、排队、待审和交接证据。
4. **质量与复测**：结构化问题、审查问题、Bug、修复、复测、覆盖与证据。
5. **迭代与发布**：迭代证据、范围变更、发布记录、环境、门禁、URL、健康与回滚证据。
6. **成熟度与治理**：规则版本、证据覆盖、成熟度、来源目录、新鲜度、错误和监管质量说明。

必须提供以下稳定 P0 目的页／视图：

- `/overview` 总览；
- `/projects` 项目与阶段；
- `/projects/:projectId` 项目证据详情；
- `/roles` 固定角色协作；
- `/approvals` 审批与待审；
- `/artifacts` 产物与哈希；
- `/events` 事件审计；
- `/issues` 问题、Bug 与复测；
- `/releases` 迭代与发布；
- `/sources` 来源、覆盖与新鲜度；
- `/maturity` 成熟度与治理；
- `/system-status` 健康、就绪、错误、降级与快照一致性。

全局顶栏包含：项目范围、时间范围、迭代、来源模式、全局搜索、只读刷新、导出当前查询、服务健康、数据就绪、覆盖、`root_head`、工作树状态和观测时间。移动端将其压缩为可展开的“监管状态条”，不能隐藏关键真相。

## D. 页面设计任务

### D1. 总览：决策驾驶舱

- 首行是持续可见的监管状态条：服务健康、数据就绪、模式、成功项目／总项目、失败项目、最近成功、观测时间、`root_head`、工作树状态。
- 决策 KPI 只显示“可由明细计算”的项目、待审、阻塞、问题覆盖、发布门禁和成熟度；未知显示“— / 暂不可计算”，不用 0。
- 项目 × 阶段矩阵展示阶段 0–10；单元格用文字缩写、图标、边框和颜色四重编码。
- 关键卡片正文最多两行；原因进入 Tooltip、Popover 或右侧详情抽屉。
- 首屏至少出现 4 个真正可决策的图形：项目阶段矩阵、待审老化、来源覆盖／新鲜度、问题与复测或发布门禁。
- `not_ready` 首屏不出现演示 KPI；只显示未就绪原因、已识别范围、恢复动作和可访问的来源诊断。

### D2. 项目与阶段

- 项目列表显示：ID、名称、类型、Profile、当前阶段、状态、当前角色、阻塞、当前审核门、最新批准产物、最新待审产物、前端／后端／真实数据／生产四条独立真实性状态。
- 阶段 0–10 使用最新工作流语义：市场调研、项目初始化、产品定义、UI/UX、架构、任务与验收拆解、小批量开发、持续代码审查、测试／Bug／复测、发布／回滚、验收／迭代／复盘。
- 不用阶段编号换算百分比。只有已登记任务总数和完成数齐全时才显示完成比。
- 项目详情用“概况、审批、产物、事件、问题、发布、来源”七个页签；每个页签保留当前筛选和返回上下文。
- 工作树有修改时显示“工作副本有未提交修改”，但批准事实仍以审批记录为准。

### D3. 固定角色协作

- 展示 00 包工头与 01—11 共 12 个唯一身份，不为项目复制角色。
- 状态只允许：有活动登记、排队、等待审核、阻塞、无结构化记录／未知。
- 使用“角色 × 项目”占用矩阵和按时间／阶段的交接泳道；节点显示入场、执行、交付、审核和等待。
- 工作负载只显示结构化记录数量，不显示臆测百分比。
- 角色详情列出构成状态的项目、变更、门、产物、事件和来源；无证据时明确“实际在线与忙闲未知”。

### D4. 审批与待审

- 将 `state.yaml` 中待审门与 `approvals.yaml` 中已作决定严格分栏。
- 每条审批显示项目、审批 ID、门、范围、决定、决定人、时间、证据、关联产物和变更。
- 无审批记录显示“尚未记录”，不推断拒绝。
- 提供按项目、门、决定、角色、时间和等待时长筛选；待审老化图可下钻到原记录。
- 页面没有批准／拒绝按钮；“去处理”只能复制相对路径或打开只读证据说明。

### D5. 产物与哈希

- 紧凑表格显示项目、产物 ID、类型、路径、版本、SHA256、状态、负责人、上游、完成／批准时间。
- `hash_mismatch` 时并列“登记版本”和“当前工作副本”，不得自动修复或把新文件当已批准。
- 文件存在但未登记时显示“治理差异”，不能进入正式产物统计。
- 产物关系用选中项的局部证据链，不画不可读的全仓网络图。
- 允许复制相对路径、复制哈希、查看来源和导出当前只读查询；不允许改状态或写回。

### D6. 事件审计

- 使用稳定排序的事件时间线与事件类型趋势；同一时间用项目和事件 ID 确定顺序。
- 每条事件保留事件 ID、时间、角色、类型、结果、项目、来源行号／内容哈希。
- JSONL 损坏行以“事件流部分可用”显示：保留可解析事件，同时展示损坏位置、影响范围和覆盖不足。
- 支持项目、时间、角色、事件类型、变更编号和结果组合筛选。
- 不执行文件中的脚本、Markdown 指令或不可信外链内容。

### D7. 问题、Bug 与复测

- 只展示结构化问题。没有统一问题登记时显示“问题覆盖不可用”，绝不能显示“0 个问题”。
- 每条问题显示项目、ID、标题、严重度、状态、责任角色、来源产物／事件、创建／更新时间和复测状态。
- 可视化包含严重度 × 状态堆叠柱、问题老化、修复／复测趋势和复测矩阵；只有转换事件完整时才画流转图。
- 同一问题在审查和测试中重复出现时保留来源关系，不按标题自动合并。
- 所有状态只读；页面没有关闭、指派、复测通过或批量流转按钮。

### D8. 迭代与发布

- 迭代燃尽、累积流、范围变化和发布列车只在相应结构化事件完整时展示；否则显示缺失证据。
- 发布记录显示环境、版本、源提交、时间、状态、URL、数据真实性和批准。
- 明确区分：本地运行、私有演示、发布方案、候选发布、测试环境、生产发布。
- 有 URL 或 HTTP 200 只表示可访问／健康证据之一，不得自动标“已上线”或“生产就绪”。
- 发布门禁用证据矩阵或 Bullet Chart 表达构建、测试、安全、备份／回滚、监控和授权；门禁缺证据显示“未验证”。
- 不提供发布、回滚、备份、域名切换或批准按钮。

### D9. 来源、覆盖与新鲜度

- 每个集合和关键记录可查看：`source_path`、`source_sha256`、`source_updated_at`、`observed_at`、`last_success_at`、`root_head`、`working_tree_state`、`freshness`、`coverage`、错误码和影响范围。
- 来源只允许当前 AIWorkFlow 根仓中的项目清单、`workflow/state.yaml`、`approvals.yaml`、`artifacts.yaml`、`events.jsonl` 及已登记结构化问题／发布证据。
- 不显示根仓外绝对路径，不读取凭证、环境变量、聊天全文、浏览器登录态、任意代码正文或未登记私有内容。
- `observed_at` 只叫“本次观测时间”，不能替代源更新时间；源时间缺失显示“源更新时间未知”。
- 使用“项目 × 数据域”覆盖矩阵和新鲜度热力图；同一单元同时显示文字状态和时间，不只靠颜色。

### D10. 成熟度与治理

- 六个维度：角色与职责、阶段与审批、产物可追溯、自动化执行、测试与评测、可观测与成本。
- 只有规则版本、样本、权重、来源和缺失证据齐全时才计算分数与趋势。
- 无充分证据时显示“成熟度暂不可计算”，列出缺失项；不得固定显示 42 分、雷达多边形或伪精确百分比。
- 有效时优先使用水平评分条、能力 × 成熟度等级矩阵、证据覆盖矩阵和趋势；雷达图只能作为可选概览，必须配等价表和计算公式。
- 改进建议必须标明依据、影响和规则版本，不把模型建议写成事实或自动任务。

### D11. 系统状态与恢复

- 同页对照进程健康与根仓就绪：健康／不健康／未知，和就绪／降级可用／未就绪。
- 展示本次观测、最近成功、失败项目、失败数据域、错误码、重试状态和一致性检查。
- “重新读取”只触发只读观测，具有进行中、成功、部分成功、失败和取消状态；不得声称修复源文件。
- 服务重启且尚无有效观测时显示 `not_ready`；不得返回全零或静态项目伪装成功。
- 有上一份已验证结果时可只读展示 `stale`，必须显著显示快照时间、失败时间和原因。

## E. 数据模式与真相状态

在所有页面首屏和每个图表右上角显示来源徽标。中文主标签如下，内部键只能放括号：

| 内部键 | 用户主标签 | 必须表达的行为 |
|---|---|---|
| `loading` | 正在读取 | 保留上一份有效快照；不可把骨架值读成 0 |
| `live` | 真实根仓观测 | 本次一致观测成功，显示根仓提交、时间与覆盖 |
| `empty` | 查询成功，确实为空 | 显示查询范围、来源和“0”的证据边界 |
| `no_result` | 当前筛选无匹配 | 提供清除筛选，不改变全局真实数量 |
| `not_ready` | 数据未就绪 | 无有效观测，不返回演示项目或伪空成功 |
| `degraded` | 部分数据可用 | 保留成功范围并列失败范围、最后成功与恢复动作 |
| `stale` | 上次成功快照，已过期 | 显示快照时间和当前失败原因，不称实时 |
| `failed` | 读取失败 | 无可用真实结果，显示影响范围和重试 |
| `offline` | 当前离线 | 仅查看有时间标记的缓存，不执行写操作 |
| `unauthorized` | 身份失效 | 不泄露内容，提供重新建立本地授权的说明 |
| `forbidden` | 无权访问 | 保持只读拒绝，不建议绕过权限 |
| `conflict` | 来源冲突 | 并列高优先级证据，不替用户裁决 |
| `hash_mismatch` | 登记哈希与当前文件不一致 | 并列双方哈希，不自动修复 |
| `working_copy_modified` | 工作副本有未提交修改 | 与已批准事实分开展示 |
| `inconsistent_snapshot` | 本次观测不一致 | 丢弃混合结果并重新读取 |
| `coverage_not_available` | 覆盖不可用 | 不能显示“0 个问题／0 次发布” |
| `static_fallback` | 静态回退，非实时 | 全页持续标识，不能贡献真实汇总 |
| `demo` | 演示数据 | 与真实结果物理隔离，不使用“已同步”绿灯 |

状态组件统一包含：发生了什么、影响哪些项目／数据域、仍可使用什么、最后成功时间、来源和下一步。状态不能只靠颜色。

## G. 全局筛选、搜索、详情、刷新与导出

- 全局筛选：项目、时间、迭代、来源模式；项目页再提供角色、阶段、状态和数据域局部筛选。
- 筛选必须真实改变图表、表格和导出结果；筛选无匹配与数据不可用分开。
- 全局搜索覆盖项目、固定角色、审批、产物、事件、问题和发布；结果按对象类型分组，并显示来源与更新时间。
- 点击图表标记交叉筛选；再次点击或“清除筛选”恢复；URL 保留项目、页签与筛选上下文。
- 详情抽屉先显示业务结论，再显示来源路径、哈希、时间、覆盖、错误和相关证据。
- 只读刷新可取消、幂等；根仓变化时放弃混合快照并重读。
- 导出只导出当前真实查询快照，包含筛选、来源、哈希、错误、生成时间与真实性标签；不包含凭证、聊天正文、原始文件正文或根仓外绝对路径。
- 搜索、筛选、详情、刷新和导出是真实只读能力，服务联调后必须可用；通知、审批、问题流转、发布和 Git 写操作不是待解灰能力。

## H. 视觉方向与设计系统

历史视觉基线共同语言：浅灰工作台、白色卡片、深靛侧栏、蓝紫主色、青绿色辅助色、紧凑表格、清晰状态徽标。继承其专业控制室感，但重新统一组件、密度、对比度和真相状态；不要逐像素复制历史图片中的错误数据或旧导航。

视觉关键词：**极简、干净、理性、克制、高密度、可追溯、实验室感、轻量科技感**。

- 页面背景 `#F3F5F8`；卡片 `#FFFFFF`；侧栏 `#171B4B`；主文字 `#17201D`；次文字 `#5E6A66`；边框 `#D8DFE3`。
- 主操作／选中 `#3347B8`；信息 `#2563EB`；真实成功 `#087E68`；警告 `#B65D0A`；危险 `#B42318`；演示／静态 `#6D28D9`；未知 `#667085`。
- 正文 14–16px，桌面辅助文字不小于 12px，移动端正文不小于 16px、辅助文字不小于 14px。
- 8px 基础栅格；卡片圆角 12px；小组件 8px；状态胶囊必须有足够内边距，正文对比度至少 4.5:1。
- 卡片默认无重阴影，以边框和留白分层；禁止玻璃拟态、赛博朋克、游戏化、装饰渐变背景和巨大数字墙。
- 一张卡只表达一个问题；正文最多两行；表格和图表标题直接写结论，不写空泛口号。
- 动效 160–240ms，支持减少动态效果；加载不使用持续旋转造成注意干扰。

## I. 响应式规格

### 1440 × 1024

- 240px 固定侧栏，12 列内容网格。
- 首屏完整显示监管状态条、决策 KPI 和至少 4 个图形模块。
- 图表双列／三列，详情使用右侧抽屉，表格支持固定表头和列优先级。

### 1024 × 768

- 72px 可展开图标侧栏，8 列网格。
- 双列逐步改为单列；矩阵在组件内部横向滚动，页面不横向滚动。
- 监管状态条保留健康、就绪、覆盖、最近成功和错误摘要。

### 390 × 844 与 320 × 568／720

- 为 390 和 320 分别重排，不允许把 390 整体缩放成 320。
- 单列布局；底部导航“总览、项目、质量、更多”，更多菜单可达角色、审批、产物、事件、发布、来源和成熟度。
- 表格改成字段优先级明确的卡片／定义列表；图表提供简化视觉和完整等价表。
- 触控目标至少 44×44px；正文至少 16px；页面级无横向滚动。
- 320 下仍可读取健康、就绪、数据模式、覆盖、最近成功、主要错误、来源与只读恢复动作。
- 项目、审批、产物、事件、问题、发布和来源详情在 320 下不能删掉关键证据字段，只能折叠次要内容。

### 200% 放大

- 按有效 CSS 视口缩半后的真实回流设计，不是只增大少量字号。
- 导航、标题、状态条、筛选、表格／卡片、图例、按钮和抽屉内容均不遮挡、不截断、不丢失。
- 不产生页面级双向滚动；组件内部横向滚动必须有键盘可达和可感知提示。

## J. 无障碍

1. 达到 WCAG 2.2 AA；正文对比度至少 4.5:1，关键非文本边界至少 3:1。
2. 所有入口、筛选、图表数据点、页签、抽屉和导出可由键盘完成；焦点顺序符合视觉顺序。
3. 使用清晰的 2px `focus-visible`；不能用阴影或颜色变化代替焦点。
4. 状态同时使用中文文字、图标／形状和颜色；趋势线同时使用点形、线型或纹理。
5. 每张图提供简短屏幕阅读器摘要和“查看数据表”；等价表包含图中全部字段、数值和状态。
6. 加载、刷新成功、部分失败、全部失败、观测不一致和导出完成使用合适的 `aria-live`；避免重复播报每个子错误。
7. 错误先播报总体影响，再让用户逐项进入失败项目；刷新时不强制把焦点移走。
8. SHA、HEAD 和错误码提供可读名称与复制按钮，读屏不能只读一串无上下文字符。
9. Tooltip 不是唯一信息载体；触屏、键盘和读屏均可取得同样内容。
10. 支持高对比度、减少动态效果和 200% 放大。

## K. 演示与目标态标识

当前设计生成时必须同时体现两套真相，严禁混合：

1. **当前事实板：** 顶部强制显示“当前事实：真实监管后端未实现 · workflow 读取器未实现 · 正式数据联调未完成”；主状态使用“数据未就绪”，不展示虚构真实 KPI。
2. **目标态演示板：** 如需展示 `live`、趋势或完整图表，顶部和每个图表均标“目标态演示数据 · 非当前运行事实”；数据只用于验证布局，不进入当前事实板。

演示数据使用紫色标签和轻纹理，不使用成功绿点表达“已同步”。静态回退持续显示“静态回退 · 非实时”，不能和真实根仓观测合并。未知用“—／未知／覆盖不可用”，不能用 0。

## L. 设计模型必须输出的资产

1. 设计系统与组件状态页 1 张：颜色、字体、间距、栅格、按钮、输入、筛选、徽标、状态条、表格、抽屉、Toast、空／错／降级组件。
2. 1440 桌面核心页 12 张：总览、项目、项目详情、角色、审批、产物、事件、问题／复测、迭代／发布、来源、新鲜度／系统状态、成熟度。
3. 1024 关键页至少 4 张：总览、项目详情、事件／问题、来源／降级。
4. 390 与 320 成对移动关键页至少 8 组：总览、项目、审批、产物、事件、问题、发布、来源／系统状态。
5. 真相状态板至少 4 张：当前 `not_ready`、单项目 `degraded`、上一快照 `stale`、目标态演示 `live`。
6. 图表等价表专页 1 张：覆盖本 Prompt 的 19 类图表，展示同一数据模型的双向对应。
7. 可点击原型：覆盖总览 → 项目 → 审批／产物／事件证据，问题 → 复测证据，发布 → 门禁证据，状态条 → 来源与错误，筛选／搜索／只读刷新／导出。

所有资产使用版本化新路径，不覆盖旧 9 张图。图片文件名、画板标题、`title/desc`、无障碍名称和用户可见字段使用完整简体中文。
