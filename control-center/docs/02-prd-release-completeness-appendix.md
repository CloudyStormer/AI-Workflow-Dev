## 2. 真实数据与只读边界

- 正式模式只能读取 AIWorkFlow 根仓允许的 `project.yaml`、`workflow/state.yaml`、`approvals.yaml`、`artifacts.yaml`、`events.jsonl` 和已登记结构化问题／发布证据。演示数据只能在明确、隔离的演示模式使用，不能混入真实统计或完成证据。
- 根仓结构化文件与 Git 历史是持久事实源。Control Center 可以使用可丢弃缓存，但缓存不是权威数据；服务重启后必须重新观测并从事实源恢复一致结果，不能因自身没有数据库而丢失监管事实。
- 只读服务不得修改业务文件、Git 工作树／索引／远端、审批、状态、事件、问题或发布；也不得通过间接命令、回调、插件或外部系统实现等价写入。
- “真实空集合”必须带覆盖语义：例如没有结构化问题时显示 `coverage=not_available` 或真实 `0` 的证据范围，不能把解析失败、未登记或未观测统称为 0。
- 根仓在一次观测期间发生提交或哈希变化时，本次结果标记不一致并重新读取；不得拼接成看似一致的跨提交快照。

## 3. 前后端联调与受控降级

- 用户可见的项目总览、角色、审批、产物、事件、问题、发布和来源状态必须由真实只读服务提供。正式模式下前端硬编码演示数据、静态 JSON 隐形回退或无效查询数量为 0。
- 所有 P0 导航和筛选入口必须可用；某域确实没有数据时展示带覆盖和来源的真实空状态，不能禁用入口来规避实现。
- 单项目文件缺失、损坏或无权读取时，其他项目继续可查询，整体为 `degraded`，失败项目、来源、错误类型、最后成功观测和重试状态可见。
- 根仓不可识别、没有任何有效项目或关键治理集合无法形成时为 `not_ready`；不得返回演示项目或伪空成功。
- 最近读取失败但存在上一份已验证缓存时，可短时受控读取并标记 `stale`、真实根仓提交、最后成功和失败原因；恢复后重新观测。过期缓存不能成为就绪依据。

## 4. 安全、恢复与统一完成门

Control Center 只有同时满足以下条件才可称为全功能完成：

1. v1.0 全部 P0 AC 和本附录 AC 通过，未关闭 P0／P1 缺陷为 0；
2. 所有用户可见监管域完成真实前后端联调，演示数据、禁用入口、空后端和仅 HTTP 200 不能替代；
3. 服务重启后从持久根仓事实源恢复，加载、真实空、部分失败、过期、未就绪、并发变化和恢复可验收；
4. 简体中文覆盖导航、查询、表格／图表、来源、错误、空状态、移动端和无障碍文案；
5. 320px 移动端、键盘、屏幕阅读器和 200% 放大可完成全部只读监管路径，状态不只依赖颜色；
6. 单元、契约、集成、端到端和回归测试通过，健康、就绪、覆盖、新鲜度、错误与读取延迟可观测；
7. 路径限制、敏感字段、日志脱敏、任意文件读取与所有写入副作用通过安全检查；
8. 根仓治理事实具备可验证备份／恢复点，Control Center 应用版本可回滚；恢复和回滚期间不得修改、丢失或伪造业务事实。

Control Center 的“持久化”不要求另建可写监管数据库：只读聚合结果可由持久工作流文件与 Git 历史重建即满足事实持久性。若未来引入索引或缓存，它仍须可丢弃、可重建且不能取代事实源。

## 5. Given-When-Then 验收标准

- **AC-CC-REL-01 项目完整发现**：Given 根仓有 N 个已登记项目，When 完成一次一致观测，Then 返回 N 个项目或逐一列出失败项目；硬编码演示项目和无说明漏项均为 0。
- **AC-CC-REL-02 角色唯一**：Given 同一固定角色在多个项目有状态，When 查看角色监管，Then 只存在一个角色身份并列出各项目关系，不创建项目专属副本。
- **AC-CC-REL-03 审批真实性**：Given 状态有待审门但无决策记录，When 查看审批，Then 显示待审／未记录，不推断通过或拒绝且不存在写入按钮。
- **AC-CC-REL-04 产物一致性**：Given 登记产物路径存在，When 校验，Then版本、SHA、状态和来源完整；当前哈希不符时显示差异，不静默当作有效。
- **AC-CC-REL-05 事件损坏**：Given 一个项目事件流含损坏行，When 查询，Then 其余真实事件仍可读、损坏位置与覆盖不足可见，静默跳过数量为 0。
- **AC-CC-REL-06 问题覆盖**：Given 项目没有统一问题登记，When 查看问题，Then 显示覆盖不可用而非“0 个问题”；演示缺陷进入真实集合数量为 0。
- **AC-CC-REL-07 发布证据**：Given 只有部署方案、URL 或健康 200，When 查看发布，Then 不形成成功生产发布；只有结构化成功证据和批准才形成相应环境记录。
- **AC-CC-REL-08 前端真实联调**：Given 正式模式，When 遍历项目、角色、审批、产物、事件、问题和发布，Then 100% 数据请求来自真实只读服务，静态演示回退和禁用 P0 入口数量为 0。
- **AC-CC-REL-09 重启重建**：Given 服务重启且缓存清空，When 根仓事实源可读，Then 重新观测后恢复同一监管结果；若尚未观测则 `not_ready`，不返回伪空成功。
- **AC-CC-REL-10 部分失败**：Given 一个项目不可解析，When 查询总体和其他项目，Then 总体为 `degraded`、其他项目可用，并显示失败来源、最后成功和重试状态。
- **AC-CC-REL-11 并发一致性**：Given 观测期间根仓提交或文件哈希变化，When 观测结束，Then 结果标记不一致并重读，不混合两个版本为一个快照。
- **AC-CC-REL-12 只读副作用**：Given 完成全部监管查询、筛选和错误恢复，When 审计副作用，Then 业务文件、Git 工作树／索引／远端、数据库和外部系统写入次数均为 0。
- **AC-CC-REL-13 健康就绪**：Given 进程可响应但根仓不可读或无有效观测，When 检查状态，Then 健康与就绪分离，页面不以 HTTP 200 声称监管可用。
- **AC-CC-REL-14 简中与无障碍**：Given 简体中文、320px、键盘、屏幕阅读器或 200% 放大，When 完成全部 P0 监管路径，Then 导航、数据、来源、状态和错误可达且图形有等价文本／表格。
- **AC-CC-REL-15 备份回滚**：Given 根仓恢复点或应用版本回滚，When 重新观测，Then 可追溯事实在承诺恢复点内完整、来源提交明确，服务不修改或伪造恢复数据。
- **AC-CC-REL-16 完成门**：Given 准备声明全功能完成，When 审查真实数据、联调、重建、异常、测试、安全和恢复证据，Then 全部通过且未关闭 P0／P1 为 0；演示替代、禁用入口、空后端和仅 HTTP 200 证据数量均为 0。

## 6. 不做项与工作流边界

- 不改变只读产品目标；不新增批准／拒绝、路由、状态、问题、Git、发布、备份执行或外部写入能力。

- 不在本轮指定技术栈、接口、索引、缓存、部署拓扑、UI 视觉或实现任务。

- 生产部署继续冻结；本产物通过只批准发布完整性口径，不授权部署。
