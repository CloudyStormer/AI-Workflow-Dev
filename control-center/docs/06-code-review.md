## Major

### CR-P1-001：全局筛选器只改变控件状态，没有筛选页面数据

- 位置：`app/Dashboard.tsx:37-42,59-78,238-257`；`app/dashboard-views.tsx:363-450,876-890`
- 问题：项目、时间范围、迭代和数据来源被呈现为“全局筛选”，但只有项目值传入 `ViewContent`，且仅“项目与阶段”视图消费该值；总览及其余四个视图继续读取固定常量。时间范围只写入 URL，迭代和数据来源未传给任何视图，数据来源变更却提示“筛选已应用”。URL 初始化也只回读 `view` 和 `project`，未恢复 `range`，更未保存迭代或数据来源。
- 影响：用户切换筛选后仍看到未过滤的指标、图表和列表，提示与结果不一致；刷新或分享链接也不能恢复完整筛选状态。违反设计提示词第 109–118、584–592 行的全局工具栏与筛选状态保留契约。
- 建议：建立单一筛选状态模型，明确“全部项目”与单项目语义；由各视图按同一状态派生数据，并完整序列化/校验需保留的 URL 状态。仅在筛选确实生效后显示成功提示。
- 严重性理由：核心决策数据会被错误范围解释，属于主要功能失效。

### CR-P1-002：项目状态筛选依据错误字段，其他筛选无效，筛选后详情还可能指向已隐藏项目

- 位置：`app/dashboard-views.tsx:456-519`
- 问题：状态筛选通过 `project.risk.includes(...)` 匹配风险文案，而不是项目当前阶段状态；“待审批项目”因此不能可靠返回处于待审批阶段的项目。“责任角色”和“数据来源”两个下拉框没有状态或事件处理；“清除筛选”也只重置状态下拉框。`selectedProject` 独立于 `filteredProjects`，所以筛选隐藏当前项目后，下方详情仍展示被隐藏项目。
- 影响：卡片、热力矩阵和单项目详情可同时表达互相矛盾的项目集合，违反设计提示词第 173–178 行的状态、角色、数据来源筛选要求。
- 建议：用结构化字段定义三个筛选维度；从同一过滤结果派生卡片、矩阵和详情，并在选中项目被排除时清空选择、自动选择首个可见项或明确显示空状态。清除操作应恢复全部筛选。
- 严重性理由：主页面关键筛选结果不正确且存在跨模块状态矛盾。

### CR-P1-003：“确认模拟”没有产生页面内状态，却声称已经记录

- 位置：`app/dashboard-views.tsx:590-626,686-715`
- 问题：`simulateStatusChange()` 只关闭对话框并显示“模拟操作已记录在当前页面”，没有修改缺陷状态、流水计数、复测值，也没有保存任何页面内记录。
- 影响：用户确认后看不到任何变化，但收到成功提示；这既是正确性缺陷，也是数据真实性边界缺陷。虽然代码正确声明不会写入真实数据，但“已记录在当前页面”仍与事实不符。
- 建议：若功能目标是可交互原型，应维护明确的本地模拟状态并同步更新受影响视图；若只是展示确认流程，应将按钮与提示改为不暗示状态已经记录的只读演示语义。
- 严重性理由：状态变更类核心操作产生虚假成功反馈。

### CR-P1-004：角色泳道用 `role="listitem"` 覆盖按钮语义

- 位置：`app/dashboard-views.tsx:551-559`
- 问题：每个可点击角色使用原生 `<button>`，同时设置 `role="listitem"`。显式 ARIA role 会覆盖原生按钮角色，辅助技术可能只把它宣布为列表项，不再表达可操作性。
- 影响：读屏用户难以发现或理解“选择角色”操作，阻断核心角色协作视图的 WCAG 2.2 AA 可操作性验收。
- 建议：让列表项作为非交互容器，在其中放置保留原生 `button` 语义的选择控件；同时用 `aria-pressed` 或等效状态暴露当前选择。
- 严重性理由：核心导航式交互对辅助技术失去正确控件语义。

### CR-P1-005：阶段矩阵声明为 ARIA grid，但结构不符合 grid 语义

- 位置：`app/dashboard-views.tsx:255-300`
- 问题：`role="grid"` 的列标题直接作为根级子项，未位于 `row` 中；每个阶段按钮仍是 `button`，没有 `gridcell` 语义；矩阵也没有网格的行列键盘导航或活动单元格模型。
- 影响：视觉上是项目 × 阶段矩阵，读屏器却无法可靠建立行、列与单元格关系。当前每个按钮虽可逐个 Tab 到达，但不等于可理解、可操作的网格。
- 建议：优先采用原生 `table` 表达静态行列关系，并在单元格内保留详情按钮；若必须使用 ARIA grid，则补齐 row/gridcell 层级及一致的方向键键盘模型。
- 严重性理由：产品核心数据矩阵的结构化信息对读屏用户不可可靠理解。

### CR-P1-006：测试仅验证静态源码/SSR 字符串，无法覆盖本批关键交互契约

- 位置：`tests/rendered-html.test.mjs:26-112`；`design-qa.md:32-46`
- 问题：现有 3 项测试验证 SSR 文本、源码正则、常量计数和 hosting 文件，但没有执行筛选、URL 恢复、模拟流转、键盘语义或 390px 运行时行为。`design-qa.md` 第 34 行将项目筛选、时间/迭代/来源筛选和模拟流转全部记为通过，却没有能发现 CR-P1-001～005 的可重复交互证据；第 46 行也明确没有 390px 运行时证据。

- 建议：增加浏览器级回归，至少断言四类全局筛选对各视图的可见结果、三类项目筛选及清除、筛选后详情一致性、模拟流转前后状态、URL 刷新恢复、键盘与可访问树，以及 390px 页面级溢出。
